## 0. 최종 결론 (2026-06-10) — ❌ 방향 종료

**모션 속도/wait 단축은 모터 물리 한계로 불가. 시간 단축은 기존 2m46(SW/JSON)에서 동결.**

실측으로 3방향 모두 막힘 확인:
| 시도 | 결과 |
|---|---|
| 속도 ↑ (중속 1000→2000) | **탈조** — 토크 부족, coarse step loss → FINE 발산 → EMIO 에러(ppc6/pmd5011), 회복에 재부팅 필요 |
| 속도 ↓ | 이동시간 ↑ (1250step: 625→1250ms) → settle 더 필요 (역효과) |
| wait ↓ (zero_settle 1500→1000, fine_step 500→350) | **모터 이동 중 자이로 측정** → 영점 발산(42°) → 전 각도 어긋나 탈조/오버슈트 FAIL |

**격리 검증**: 같은 모터로 MP(기본 wait) #6 = PASS, TEST(wait 축소) #6 = FAIL → 모터는 정상, wait 축소가 원인. `zero_settle_wait`는 **coarse 이동시간(step수×속도)보다 길어야** 한다(자이로를 정지 후 읽기 위해). 무작정 축소 불가.

**핵심 교훈**: settle wait는 임의 상수가 아니라 **모터 이동시간에 종속**. 속도와 wait는 한 묶음이라 독립적으로 못 줄임. EMIO 속도는 `PMS`로 장비 비휘발성에 저장되어 workspace로 격리 안 됨([[feedback_build_test_cycle]] 참고).

실험 코드/JSON 전부 원복 완료(진단 PMR, 중속복원, TEST wait). 아래는 조사 기록(참고용).

## 1. 배경 / 문제 정의

- 모션검사 풀런 ≈ **3m20s(232/485 동일)**, 그중 **모터 물리이동이 68%**:
  - 기울기 8각(#6+#14): ~102s (~51%)
  - 영점(#3+#10): ~35s (~17%)
- 2026-06-09 settle/stream 반감 + X영점 최초1회로 SW/JSON 레버는 소진.
- **남은 단축 = 모터가 각도로 이동하는 물리시간 = EMIO 모터 속도/가속도 영역.**

## 2. 핵심 발견 (근거: 참고 소스 3종 대조)

### 2-1. VibeTilt는 모터 속도/가속도를 한 번도 설정하지 않는다
- `MotionJig.cs`가 EMIO에 보내는 PMS는 **soft limit(PMS07128/08129)·정지토크(PMS050614)뿐.**
- **속도(PMS0712xx)·가속도(PMS06xxx)·해상도(PMS041480) 설정 명령이 코드·JSON 어디에도 없음.**
- 즉 현재 모터는 **EMIO 컨트롤러에 마지막 저장된 값**(이전 셋업 잔재 또는 펌웨어 기본)으로 동작 → **속도가 제어되지 않고 방치된 상태.**

### 2-2. BG-01(검증된 원본)은 검사 시작 시 속도/가속도를 명시 설정
`자이로검사_vs2019/.../BoardLevelMo_BG01.cpp` line 1390~1493, 각 250ms 간격 전송+응답확인:

| 명령 | 의미 | 값 |
|---|---|---|
| `PMS041480` | 모터 해상도 | 480 pulse/rev |
| `PMS0510550` / `PMS0510650` | 이동/유지 토크 | 550 / 650 |
| `PMS071212000` | **고속(High)** | 2000 |
| `PMS071222000` | **중속(Middle)** | 2000 |
| `PMS071231000` | **저속(Low)** | 1000 |
| `PMS06124256` / `PMS06125128` / `PMS0512664` | 가속도 고/중/저 | 256 / 128 / 64 |
| `PMS071121000` / `PMS06113500` / `PMS06114128` | 원점 최고속/최저속/가속 | 1000 / 500 / 128 |
| `PMS071288000` / `PMS08129-8000` | SW리밋 +/- | ±8000 |
| `PMO011` | 원점복귀 | — |

### 2-3. PMD 이동 명령의 2글자 = 속도/가속 프로파일 선택 (문서 근거 확정)
EMIO 프로토콜 문서(`EMIO_V2_프로토콜_사양서_V1.6.doc` §5) 확인:
- `PMD091HM-12345` 예 = **H**igh속도 + **M**iddle가속 + steps. 즉 PMD의 2글자가 속도/가속 프로파일(H/M/L) 선택.
- **★ VibeTilt 이동 명령 `PMD0{len}1ML{steps}` = M(중속) + L(저가속)** ← `MotionJig.cs:1578`
- BG-01 큰이동 `PMD071LL` = L(저속)+L(저가속), 미세조정 `PMD041LL1` = 1 step씩 채널4/5 0.005도까지.

→ **VibeTilt는 모든 이동을 "중속(param22)+저가속(param26)" 프로파일로 수행.**
   특히 **저가속(param26)이 낮으면**(BG-01 기본 64) 가감속이 느려, FineAdjust처럼 짧은 이동이 많은 VibeTilt에서 시간 손실. → **단축 핵심 = param22(중속)·param26(저가속) 값 상향.**

### 2-3b. PMS/PMR 명령 포맷 (문서 근거 확정)
- **PMS (설정)**: `PMS0` + `{len}` + `{축}` + `{param#}` + `{값}` / 응답 `pms0...`
  - 예) 최저속도(param30) 1234 설정: `PMS071301234` → `pms0071301234`
- **PMR (읽기)**: `PMR0` + `{len}` + `{축}` + `{param#}` / 응답 `pmr0` + `07` + `축` + `param#` + `값`
  - 예) param30 읽기: `PMR03130` → `pmr0071301234`
- 속도/가속 파라미터 번호(BG-01 PMS 역산):

  | 항목 | param# | PMR 읽기 | PMS 설정(BG-01값) |
  |---|---|---|---|
  | 고속 | 21 | `PMR03121` | `PMS071212000` (2000) |
  | 중속 ★ | 22 | `PMR03122` | `PMS071222000` (2000) |
  | 저속 | 23 | `PMR03123` | `PMS071231000` (1000) |
  | 고가속 | 24 | `PMR03124` | `PMS06124256` (256) |
  | 중가속 | 25 | `PMR03125` | `PMS06125128` (128) |
  | 저가속 ★ | 26 | `PMR03126` | `PMS0512664` (64) |

  (★ = VibeTilt가 실제 사용하는 프로파일)

### 2-4. pCOM(이대리 원본)도 속도 설정 없음
- `BoardLevelMo.cpp`: PMD/PMP/PMO 이동만, PMS 속도 0개 → 속도가 EMIO 저장값임을 재확인.

### 2-5. 대조 요약
| | BG-01 | pCOM | VibeTilt (현재) |
|---|---|---|---|
| 속도/가속도 PMS | 명시 설정(고속2000/가속256) | 없음 | **없음(누락)** |
| 이동 채널 | 큰이동 07/08, 미세 04/05 분리 | PMD/PMP | 단일 `PMD0{len}1ML` |
| 미세조정 정밀 | 1step, 0.005도 | — | 오차비례 step, 0.03~0.05도 |

> ⚠️ 2026-04-25 `PLAN_모션튜닝`은 `ff_emio/Emio.cs`에 저속 초기화가 있다고 전제했으나 **그 파일은 현재 리포에 없음** → 그 PLAN은 다른 코드 구조 기준. 단 PMS 속도표·wait·파라미터화 아이디어는 본 PLAN이 계승.

## 3. 구현 플랜 (단계적 — 각 단계 실측 통과 후 다음)

### Phase 0 — 현재 속도값 진단 (선행, 비파괴) ★구현 중 (2026-06-10)
- 목적: 지금 EMIO에 저장된 속도/가속도가 얼마인지 확인 (단축 여지 판단의 전제)
- 방법: 영점 초기화 시작 시 **세션 최초 1회** PMR 6종(`PMR03121`~`PMR03126`)을 보내 현재 속도/가속 6개 값을 **로그에만 출력**. 동작 변경 없음(읽기 전용).
- 위치: `MotionJig.cs` `InitMotionZero()` 시작부, `EmioFlush` 직후. static 플래그 `_motorDiagDone`로 1회만.
- 산출물: "현재 중속(22)=? 저가속(26)=?" 실측치. 특히 VibeTilt가 쓰는 **중속/저가속**이 관건.
  - 이미 중속2000/저가속256+ 면 Phase 2 여지 작음, 낮으면 Phase 1/2로 즉효.
- PMR 포맷은 §2-3b에서 문서 근거로 확정 완료 → 추측 아님.

#### Phase 0 결과 (2026-06-10 실기) ✅
PMR 응답 정상(포맷 검증됨). 현재 EMIO 저장값:

| 항목 | param | 현재값 |
|---|---|---|
| 고속 | 21 | 2000 |
| **중속 ★** | 22 | **1000** |
| 저속 | 23 | 500 |
| 고가속/중가속/저가속 | 24/25/26 | **1023 (전부 10bit max)** |

- 속도는 "방치"가 아니라 정상값이 설정돼 있었음(초기 가설 기각).
- **가속도는 이미 최대(1023) → 가속 레버 없음.** 올릴 수 있는 건 중속 1000→2000뿐.

#### 실험A 결과 (중속 1000→2000) ❌ — 속도 무관 확정
| 빌드 | 중속 | test time(232 풀런) |
|---|---|---|
| baseline | 1000 | 2m46s |
| 실험A | 2000 | 2m52s (오히려 +6s, 편차내) |

→ **모터 속도(coarse 이동)는 풀런 시간에 영향 없음**(coarse가 0.2~0.4초로 극소). 실험A 코드 제거. **단축 방향을 §Phase 4(FINE/stream wait)로 전환.**

#### 시간 병목 재확정 (실측 분해)
- 기울기 각도당 ~10-13초 = **FINE 수렴(~5-9초) + stream 측정 핸드셰이크(~4-5초)**.
- coarse 모터 이동은 시간의 극소 부분. → **진짜 레버 = FINE/stream wait 축소.**

### Phase 1 — 속도/가속도 "명시 설정" 추가 (BG-01 검증값으로 고정)
- 위치: `MotionJig.cs` `InitMotionZero()` 시작부 — 영점 최초 1회에 PMS 속도 시퀀스 전송.
  (`_zeroInitialized`로 1회만, 또는 별도 `_motorParamSet` 플래그)
- 전송: BG-01과 동일한 고속2000/중속2000/저속1000/가속256/128/64/원점속도 시퀀스.
- 효과: 속도를 **알려진 검증값으로 고정** → "방치 상태" 해소. 현재값이 더 낮았다면 이 단계만으로 단축.
- 리스크 낮음(BG-01 실기 검증값). 정확도 영향 없음 가정 → 실측으로 확인.

### Phase 2 — 고속 상향 시도 (단축 본체)
- BG-01 기본 고속2000/가속256에서 단계적 상향: 예 2000→3000→4000, 가속 256→384→512.
- 큰 이동(coarse)만 빠르게, **FineAdjust 미세조정 구간은 저속 유지**(오버슈트 방지).
  - 현 VibeTilt는 단일 채널이라 coarse/fine 속도 분리가 안 됨 → **검토: FineAdjust 진입 시 저속 PMS로 전환 후 종료 시 고속 복귀** (BG-01의 채널분리 효과를 PMS 전환으로 모사). 또는 fine는 1 step이라 속도 영향 작음 → 실측으로 결정.
- 각 상향마다 실측: 수렴 step 수↑/리트라이 발생 여부 확인.

### Phase 3 — JSON 파라미터화
- velocity_high/mid/low, accel_high/mid/low, 원점속도, soft_limit을 JSON 파라미터로 노출 + `LoadParams()` 추가.
- 효과: 재빌드 없이 JSON만으로 속도 튜닝. (04-25 Phase 4 계승)
- JSON 수정 시 Debug/Release × MP 동시(규칙). `_comment`로 수치 의미 주석.

### (병행 가능) Phase 4 — wait/FINE 미세 단축
- 04-25 Phase 2 잔여분: `tilt_move_wait`, `zero_settle_wait`, `fine_step_wait` 등 실측 하 추가 축소.
- 속도 상향과 독립적이라 별도 실측.
