1. 배경 / 목표

  • 모션검사 풀런 ≈ 3m20s → 어제(2026-06-09) SW/JSON 단축으로 2m46 달성(settle/stream 반감 + X영점 최초1회).
  • 시간의 68%가 모터 물리이동(기울기 8각 ~102s + 영점 ~35s).
  • 오늘 목표: 모터(EMIO) 속도/가속 또는 wait를 줄여 추가 단축.

2. 조사 (참고소스 3종 + EMIO 프로토콜)

2-1. 모터 속도 설정 현황

  • VibeTilt MotionJig.cs는 모터 속도/가속을 명시 설정하지 않음 → EMIO 컨트롤러 저장값으로 동작.
  • 참고소스 대조:
  • BG-01 (30.SMCS/.../BoardLevelMo_BG01.cpp): 검사 시작 시 PMS로 속도/가속 명시 설정(고속2000/가속256).
  • pCOM (50.pCOM_SRC): 속도 설정 없음.
  • VibeTilt: 속도 설정 없음.

2-2. EMIO 명령 포맷 (프로토콜 문서 §5 확정)

  • PMS(설정): PMS0{len}{축}{param#}{값} / 응답 pms0...
  • PMR(읽기): PMR0{len}{축}{param#} / 응답 pmr0 07 {축}{param#}{값} (예 PMR03130→pmr0071301234)
  • PMD(이동) 2글자 = 속도/가속 프로파일: PMD091HM-12345 = High속도+Middle가속. (단 VibeTilt PMD0{len}1ML의 04/05/06은 프로파일이 아니라 데이터 길이(len=3+자릿수), 1ML=축1+중속(M)+저가속(L))
  • 속도 param: 21고속 22중속 23저속 / 가속 24고/25중/26저.

2-3. PMR 진단 결과 (실기, 1축)

항목 param 현재값
고속 21 2000
중속 ★ 22 1000
저속 23 500
고가속/중가속/저가속 24/25/26 1023 (10bit max)

→ VibeTilt 이동(ML)은 중속(1000) + 저가속(1023) 사용. 가속은 이미 최대.

3. 실험 및 결과

실험 A — 속도 ↑ (중속 1000 → 2000)

  • 코드에 PMS071222000 추가 후 232 풀런.
  • 결과: test time 2m46 → 2m52 (편차 내, 무변화처럼 보임). 하지만 위험:
  • 이후 PMD061ML222(coarse) 탈조 확인 — 222 step인데 14°만 이동(정상 23°).
  • 중속 2000 = 토크 부족으로 step loss(탈조) → FINE이 큰 오차로 시작 → 오버슈트 → soft limit 초과 → EMIO 에러(pmd5011/ppc6) → 연쇄 FAIL, 회복에 EMIO 재부팅 필요.
  • 중속 2000이 EMIO 비휘발성에 저장돼 잔류(workspace로 격리 안 됨) → 중속1000 명시 복원 코드로 처리.

실험 B — wait ↓ (TEST JSON)

  • zero_settle_wait 1500→1000, fine_step_wait 500→350, fine_confirm_wait/tilt_move_wait 축소.
  • 결과: -45° 탈조 FAIL 반복 (재부팅·중속복원 후에도).
  • 원인: zero_settle_wait 1000ms < 영점 coarse 이동시간 1250ms (1250 step @ 중속1000 = 1250ms).
  • 모터가 아직 이동 중인데 자이로를 읽음 → 영점이 42°로 발산 → setzcur 기준 틀어짐 → 이후 전 각도 어긋나 탈조/오버슈트/에러.
  • 아이러니: 중속 2000→1000 복원으로 이동시간이 2배(625→1250ms)가 되며 1000ms settle이 갑자기 부족해짐.

격리 검증 (모터 정상 확인)

같은 모터로: | workspace | wait | 결과 | |---|---|---| | MP | 기본(zero_settle 1500) | ✅ PASS (#6 4각 OK) | | TEST | 축소(zero_settle 1000) | ❌ -45° 탈조 FAIL |

→ 모터는 정상. wait 축소가 FAIL 원인.

4. 결론 — 3방향 모두 물리 한계

속도 ↑  → 탈조 (모터 토크 한계)
속도 ↓  → 이동시간 ↑ → settle 더 필요 (역효과)
wait  ↓ → 모터 이동 중 측정 → 영점/각도 발산
  • 속도와 wait는 한 묶음: settle_wait ≥ 모터 이동시간(step수 × 속도) 이어야 정지 후 자이로를 읽을 수 있음. 독립적으로 못 줄임.
  • 시간 단축은 어제 2m46(SW/JSON)이 실질 최선. 모터가 더 빠른 물리이동을 못 받아줌.

5. 교훈

  1. EMIO 속도/가속은 PMS로 장비 비휘발성 메모리에 저장 → workspace(JSON)로 격리 안 됨. 실험값이 양산본까지 오염시킬 수 있음. → 검사 시작 시 정상값 명시 설정이 안전(BG-01 방식). 단 이번엔 속도 자체를 안 건드리기로 해 미적용.
  2. settle wait는 임의 상수가 아니라 모터 이동시간 종속. 무작정 축소 시 "이동 중 측정" → 발산.
  3. 중속 2000 절대 금지 (탈조 → EMIO 에러 → 재부팅).
