## 1. 시간 본체 (어디서 가나)
| 분류 | 비중 |
|---|---|
| **기울기 8각 (#6+#14)** | **~51%** (~102s) |
| **영점 (#3 X + #10 Y)** | **~17%** (~35s, 특히 X영점 홈센서 22s) |
| 진동 / CAL / 통신 등 | 나머지 ~32% |

- 기울기 1각 ~13s 중 **FINE 수렴(모터 회전+자이로) ~8s가 핵심**, settle/stream은 ~1.5s.

## 2. 단계별 계획 (효과·난이도순)

### 1단계 — stream/settle 단축 (JSON-only, 무위험) ← 먼저
- `tilt_stream_duration` 1000 → **500** / `vibe_stream_duration` 1000 → **500**
- `tilt_settle_wait` 500 → **300** / `gac_settle_wait` 500 → **300**
- 근거: 판정은 tail(기울기 10/진동 5)개만 사용. 500ms@10ms = 50샘플 >> 필요량 → **정확도 손실 0**.
- 예상 절감: 측정 11회(기울기 8 + 진동 3) × ~0.7s ≈ **~7s**
- 재빌드 불필요. JSON 4파일(232·485 × Debug/Release) + (필요시 board 동일).

### 2단계 — FINE 수렴 tolerance 완화 (JSON, 1회 검증)
- `fine_adjust_strict_tolerance` / `fine_adjust_relaxed_tolerance` 0.05 → **0.1**
- 근거: 측정 spec ±0.2(20도)/±0.5(45도)라 마진 충분. 수렴 반복 줄여 각도당 1~3s 단축.
- 예상 절감: 기울기 8각 **~10~20s** (가장 큰 JSON 레버)
- 검증: 1회 풀런 → 시간↓ + 전 각도 여전히 spec PASS 확인 (오차값 여유 확인).
- 리스크: 위치 정밀도 약간↓ but 측정 spec 내. FAIL 늘면 0.07 등 중간값으로 재조정.

### 3단계 — X영점 최초 1회만 홈복귀 (코드, 양산 throughput) ← 별도
- 현재 X영점 22s(홈센서 1250step) / Y영점은 skip_home(~5~13s)
- 밀어내기 연속 양산에서 **첫 대만 홈복귀, 이후 skip_home** → 대당 **~10~15s 절감**
- 코드 필요(홈 완료 상태 추적/플래그). 메모리 TODO `project_motion_zero_optimize`.
- 별도 PLAN으로 분리 진행 (JSON 단계와 독립).

## 3. 진행 방식
- **한 번에 하나씩** 바꾸고 풀런 1회로 시간/PASS 측정 (변수 격리).
- 측정값은 시간기록 md(모션232/485)에 "단축 후" 열로 누적.
- 1·2단계 JSON 변경은 Debug+Release 동시. 확정 후 커밋.

## 4. 진행 순서
1. **(현재) PLAN 확정**
2. 1단계 적용(stream/settle 반감) → 485 풀런 1회 → 시간/PASS 확인
3. 2단계 적용(fine tolerance) → 풀런 1회 → 시간/PASS 확인
4. 232 동일 적용 + 확정 → 커밋
5. 3단계(X영점 최초1회)는 별도 PLAN

## 5. 목표
- 1+2단계(JSON만)로 **~15~25s 단축** 예상 (3m21 → ~3m 내외)
- 3단계까지 가면 양산 대당 추가 ~10~15s

## 6. 외부검토 반영 (2026-06-09) — 효과순 재정렬 + 코드확인
> #9-1/#11-1(REFTEMP/RCONF)은 0도·UART 1~2프레임·각 1초 미만 → **단축 대상 아님**. 시간은 모터 이동 + settle/stream에 있음.

| 순위 | 레버 | 효과 | 코드확인 |
|---|---|---|---|
| **1** | **X영점 홈복귀 절충** — #3 skip_home 없음(홈센서 22s), #10은 이미 skip_home. 연속생산 시 2회차부터 skip_home, **N회마다 1회만 홈복귀** | **~17s/회** | (3단계와 동일, 코드) |
| **2** | **기울기 각도 단조 스윕** — #6 `[-20,-45,20,45]`→`[-45,-20,20,45]`로 방향반전 제거 → settle 안정화↓ + backlash↓ | 중 | ✅ **순서 판정무관** 확인 (MotionJig.cs:914 각도별 독립 판정/이동, _angles_comment "사양서 순서"는 표기일 뿐) |
| **3** | **settle/stream 단축** (현 1단계) stream 1000→500, settle 500→300 | ~7s | ⚠️ all_in_spec 엄격 → 실측 PASS 확인 필수 (현재 테스트 중) |

| **5** | **UART 세션 유지** — Y결합 0도 6단계 연속, 포트 재오픈이면 오버헤드 | 소 | 포트는 프로젝트 시작 1회 Connect 후 재사용 구조로 보임 → 효과 작을 듯(추후 정밀확인) |

**진행 순서 갱신:** 3단계(settle/stream, 현재 테스트) → 4단계(relaxed 0.1) → 2단계(단조 스윕) → 1단계(X영점 절충, 별도 코드 PLAN).
- 2·4는 JSON-only, 코드확인 끝나 바로 적용 가능. 1만 코드.
