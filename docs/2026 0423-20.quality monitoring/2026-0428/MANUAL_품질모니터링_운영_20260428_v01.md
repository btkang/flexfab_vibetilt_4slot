**작성일:** 2026-04-28
**버전:** v01
**대상:** 양산 운영자 / 미니PC 관리자
**프로그램:** `tools/quality_monitor/` (Python · Streamlit)

---

## 0. 핵심 요약

- 검사 프로그램(`flexfab.exe`)은 **그대로**. 모니터링은 별개 Python 프로그램.
- 검사 결과 JSON 폴더만 있으면 동작. SQLite 캐시는 옵션(자동 감지).
- 미니PC 자체에서 띄울 수도, 다른 PC에서 띄울 수도 있음.
- **모니터링은 두 모드 운영:** ① Streamlit 대시보드(분석/관리자용, 모던 브라우저), ② 정적 HTML 리포트(라인 게시용, Edge 92 등 구형 OK).

---

## 1. 설치 (1회)

대상 PC에 Python 3.11+ 설치 후:
```
cd tools\quality_monitor
pip install -r requirements.txt
```

선택: 자동 새로고침 기능(`pip install streamlit-autorefresh`).

---

## 2. 실행

### 기본 (Streamlit 대시보드)
```
streamlit run app.py -- --result-dir "<Result 경로>"
```
브라우저 자동 오픈 → `http://localhost:8501`.

### CLI 요약 (콘솔 한 번)
```
python monitor.py --result-dir "<Result 경로>"
python monitor.py --result-dir "<Result 경로>" --days 7
```

## 3. 운영 시나리오 3종

### 시나리오 A: 검사 PC + 별도 모니터링 PC

```
[검사 PC] flexfab.exe + Result 폴더
   │ SMB 공유
   ↓
[모니터링 PC] streamlit run app.py -- --result-dir "\\검사PC\Result\..."
```

1. 검사 PC: Result 폴더 우클릭 → 속성 → 공유 → 사용자 추가.
2. 모니터링 PC: 위 명령 실행. 데이터는 검사 PC 디스크에 그대로 있고, 모니터링 PC는 SQLite 캐시만 자체 보관.

### 시나리오 B: 미니PC 단독 (랜선/허브 있을 때 동시 검사+모니터링)

```
[미니PC] flexfab.exe + Result 폴더
         streamlit run app.py -- --result-dir ".\Result"
   │
   ├ 본인이 보고싶을 때: localhost:8501
   └ 다른 PC/태블릿에서: http://<미니PC IP>:8501
```

1. 미니PC에서 위 명령 실행 (cmd 별도로).
2. 다른 PC: 같은 네트워크면 `http://<미니PC IP>:8501`로 접속.
3. 미니PC IP 확인: `ipconfig` → "IPv4 주소".

### 시나리오 D: 라인 게시판 (구형 브라우저 미니PC, **양산 권장**)

미니PC 엣지가 구형(예: Edge 92)이거나 회사 정책상 업데이트 불가일 때.
정적 HTML 리포트를 60초마다 갱신 → 단순 HTTP 서버로 미니PC가 보기.

```
[호스트 PC] (Python 환경)
   ├ 창1: make_report.py --watch 60        # report.html 매분 갱신
   └ 창2: python -m http.server 8080 --bind 0.0.0.0   # 정적 서빙
                       ↓ HTTP
[미니PC] 엣지 → http://<호스트 IP>:8080/report.html
```

**호스트 PC 작업 (PowerShell 창 2개):**

창1 — HTML 생성기:
```powershell
cd <프로젝트>\tools\quality_monitor
python make_report.py --result-dir "<Result 경로>" --output "report.html" --watch 60
```

창2 — HTTP 서버:
```powershell
cd <프로젝트>\tools\quality_monitor
python -m http.server 8080 --bind 0.0.0.0
```

**호스트 PC 방화벽 8080 인바운드 허용 (PowerShell 관리자, 1회만):**
```powershell
New-NetFirewallRule -DisplayName "HTTP 8080" -Direction Inbound -Protocol TCP -LocalPort 8080 -Action Allow
```

**미니PC 작업: 없음.**
- 엣지 주소창에 `http://<호스트 IP>:8080/report.html` → 즐겨찾기/바로가기 등록
- HTML 안에 60초 meta refresh 들어있어 자동 갱신
- "안전하지 않음" 표시는 HTTPS 아니어서 정상 (내부망 OK)

**왜 Streamlit이 아닌가:**
- Streamlit은 모던 JS(ES2020+) 사용 → Edge 92에서 빈 화면
- 정적 HTML + matplotlib PNG는 JS 의존 X → 구형 브라우저 OK

**미니PC 엣지 업데이트 권장 (장기):**
회사 정책상 가능하면 Edge 110+ (또는 최신)으로 업데이트해 Streamlit 병행 사용 가능.

| 절차 | 비고 |
|---|---|
| 호스트 PC: https://www.microsoft.com/edge/business/download → MSI 오프라인 인스톨러 (~150MB) | 인터넷 되는 PC에서 |
| USB 복사 → 미니PC에서 더블클릭 설치 | 1~2분, 재부팅 불필요 |
| Edge 110+ 되면 `http://<host>:8501` (Streamlit)도 동작 | 정적 HTML도 그대로 사용 가능 |

업데이트 후 운영 모드:
- **라인 모니터(상시 표시)**: 정적 HTML (`:8080/report.html`, 60초 갱신) — 단순/안정
- **분석/조치(필요 시)**: Streamlit (`:8501`) — 풀 인터랙션

### 시나리오 C: 오프라인 분석 (개발 PC, USB로 가져와서)

1. 미니PC의 `Result` 폴더를 USB로 복사.
2. 개발 PC: `streamlit run app.py -- --result-dir "<USB 경로>" --db data\dev.db`.
3. 개발용 DB는 분리(`--db dev.db`)해 운영 DB와 충돌 방지.

## 5. 데이터 소스 자동 감지

| 상황 | 동작 |
|---|---|
| 첫 실행 (DB 없음) | **JSON 모드** — 폴더 직접 스캔 |
| 사이드바 "DB 캐시 만들기" 클릭 | DB 1회 생성 → 다음 실행부터 **DB 모드** |
| DB 있음 (정상 운영) | **DB 모드** — 시작 시 신규 JSON만 증분 적재 |
| DB 파일 삭제 | 다음 실행 시 JSON 모드로 자동 fallback |
| DB 손상 | 자동으로 JSON 모드 전환 |

→ 운영자는 모드 신경 안 써도 됨. **JSON만 있어도 잘 돌아감**.

## 6. 화면 구성 (탭 10개)

1. **메인** — 전체 KPI, 7일 추이, 측정값 변동, 알람, 시리얼 검색
2. **오늘** — 오늘 PASS/FAIL, 작업자별, 시간대별
3. **TILT 추이** — motion(각도별 오차) / board(절대값) 토글
4. **TILT 분포** — 히스토그램·박스·통계
5. **VIBE** — motion(축간 norm) / board(X/Y/Z/RMS)
6. **DPM** — 24V/3.3V/전류 추이·분포·통계
7. **TILT 삼중값** — value/gyro/vl 비교 (모션 정밀 분석)
8. **관리도(SPC)** — μ±3σ, Cpk, Western Electric Rules 알람
9. **FAIL** — 원인별 막대그래프 + 상세
10. **리포트** — CSV / 오늘 요약 HTML 다운로드

---

## 7. 알람

메인 탭 상단에 자동 표시:
- **연속 FAIL 3회** — 최근 시리얼 3건 연속 FAIL
- **Cpk<1.33 그룹 N개** — 모션 TILT/VIBE 그룹 중 공정능력 부족

관리도(SPC) 탭에서 Western Electric Rules 알람도 별도 확인 가능.

## 9. 주의 / 한계

- **JSON 스키마 변경:** 검사 프로그램이 JSON 필드를 바꾸면 `parser.py` 수정 필요. 코드 의존은 아니지만 데이터 계약.
- **시간대:** 내부적으로 UTC. 화면 표시는 Asia/Seoul 변환 (자동).
- **단일 프로세스 SQLite:** 같은 DB를 여러 프로세스에서 동시 쓰기 X. 평소 운영은 단일 streamlit + 단일 ETL이라 문제 없음.
- **재구축 시간:** 1만 건 JSON ≈ 수 초~십 초.

## 11. 영향 범위 (안심 사항)

- 검사 프로그램 코드/exe/JSON/MongoDB 로직 **모두 무수정**.
- 모니터링 종료/오류/DB 손상이 검사에 영향 주지 않음.
- 모니터링은 Result 폴더를 **읽기만** 함. 새 파일 만들지 않고, 기존 JSON 수정도 안 함.
- SQLite 캐시는 모니터링 폴더 안 (`data/quality.db`). 다른 시스템에서 모름.
