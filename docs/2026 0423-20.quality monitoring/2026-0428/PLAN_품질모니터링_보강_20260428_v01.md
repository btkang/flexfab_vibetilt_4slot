## 3. 데이터 소스 정책 (JSON / SQLite 동시 지원)

### 3.1 두 형태 모두 운영 가능

```
[검사 프로그램]                    [모니터링 (Python/Streamlit)]
   │                                    │
   └── Result/{프로젝트}/{날짜}/*.json ──┤  ← 원본/Source of Truth
                                        │
                                        ├── (선택) SQLite quality.db  ← 캐시·인덱스
                                        │
                                        └── Streamlit / CLI
```

- JSON = 원본. **항상 보존**, 검사 프로그램이 만드는 모든 결과의 단일 진실 출처.
- SQLite = 모니터링 측의 캐시/인덱스. **있으면 빠르고, 없어도 동작**.

### 3.2 자동 감지 (시작 시)

```
1) Result 폴더 확인 → 없으면 에러
2) SQLite 파일 확인
   ├ 없음  → "JSON 모드"로 동작 (폴더 직접 스캔)
   └ 있음  → "DB 모드". 시작 시 신규/수정 JSON 증분 적재 후 DB 쿼리
3) 사이드바에 현재 모드/적재 통계 표시
```

### 3.3 시나리오별 동작

| 상태 | 동작 | 비고 |
|---|---|---|
| **JSON만 있음** (첫 설치) | JSON 모드로 자동 fallback | 누적 적으면 충분 |
| **JSON + DB** | DB 모드, 증분 적재 | 평소 운영 |
| **DB만, Result 없음/비움** | 경고 띄우고 DB만 쿼리 | 폐기 가능성 사용자 인지 |
| **DB 손상** | 자동 폐기 → JSON 모드 fallback | 자가복구 |

### 3.4 사용자 옵션 (`--data-source`)

| 값 | 동작 |
|---|---|
| `auto` (기본) | 위 자동 감지 |
| `json` | DB 무시, 항상 JSON 직접 스캔 |
| `db` | DB 강제. 없으면 새로 만들고 1회 적재 |
| `db --no-etl` | DB만, 적재 단계 skip (개발/디버깅용) |

### 3.5 손실 안전성

- DB 파일이 깨지거나 삭제되어도 **JSON 폴더 재스캔으로 무손실 복구**.
- DB가 영영 없어도 시스템은 계속 동작 (JSON 모드).
- 다른 PC로 데이터 옮길 때 Result 폴더만 복사하면 됨.

- 보드 VIBE: BOARD_VIBE_X/Y/Z_232/485 등

산출:

- 정규화된 `kind`, `axis`, `item`, `value`, `result`, `min`, `max`, `time`, `sn`, `inspector`, `project`, `comm_type`, `project_type` 컬럼 유지.
- 보드 데이터에는 `kind = "DPM"` 등 신규 카테고리 추가, 기존 컬럼 재활용.

검증:

### Phase B — `app.py` 기능 보강

추가 기능:
1. **FAIL 원인 step 빈도** — 어떤 검사가 자주 깨지는지 막대그래프.
2. **작업자/시간대 패턴** — 시간대별 PASS/FAIL, 작업자별 비교 (오전/오후/교대).
3. **자동 새로고침** — Streamlit `st_autorefresh` 또는 mtime watch (옵션, 사이드바 토글).
4. **알람 패널** — 연속 FAIL N회, Cpk 임계 미달, 골든 샘플 드리프트(있다면).
5. **일일/주간 리포트** — HTML/PDF 다운로드 버튼 (Streamlit `st.download_button`).
6. 보드 검사 탭 (Phase A 산출 데이터 시각화) — DPM 추이, 보드 TILT/VIBE 분포.

### Phase C — SQLite ETL (모니터링 단독)

신규 파일:
- `tools/quality_monitor/db.py` — 스키마, 연결, 쿼리 헬퍼.
- `tools/quality_monitor/etl.py` — JSON 폴더 → SQLite 증분 적재.

스키마(초안):
```sql
CREATE TABLE IF NOT EXISTS results (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  sn TEXT NOT NULL,
  project TEXT NOT NULL,
  project_type TEXT,         -- motion/board (가능 시)
  comm_type TEXT,            -- RS-232/RS-485 (가능 시)
  pass_fail TEXT,
  inspector TEXT,
  tested_at TEXT NOT NULL,   -- ISO8601
  duration_sec REAL,
  json_path TEXT NOT NULL,   -- 원본 JSON 경로
  json_mtime REAL NOT NULL,  -- 증분 적재용
  raw TEXT                   -- 원본 JSON 통째 (선택, 분석용)
);

CREATE TABLE IF NOT EXISTS events (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  result_id INTEGER NOT NULL REFERENCES results(id),
  kind TEXT,        -- TILT/VIBE/DPM/COMM ...
  axis TEXT,
  angle REAL,
  item TEXT,
  value REAL,
  gyro REAL,
  vl REAL,
  result TEXT,      -- OK/FAIL...
  min_spec REAL,
  max_spec REAL,
  unit TEXT
);

CREATE INDEX idx_results_tested ON results(tested_at);
CREATE INDEX idx_results_sn     ON results(sn);
CREATE INDEX idx_results_proj   ON results(project);
CREATE INDEX idx_events_result  ON events(result_id);
CREATE INDEX idx_events_kind    ON events(kind, axis);
```

ETL 로직:
- 폴더 재귀 스캔 → 파일 목록 + mtime.
- DB의 `(json_path, json_mtime)` 비교 → 신규/변경된 JSON만 처리.
- 트랜잭션으로 `results` + `events` 일괄 INSERT.
- 삭제된 JSON 처리 정책: 기본 무시(보수적). 옵션으로 prune 모드 제공.

쿼리 인터페이스:
- `db.load_events(filters) -> DataFrame` — 기존 `parser.load_results`와 동일 컬럼 반환.
- 어플리케이션 레이어에서 JSON/DB 어떤 소스든 동일 DataFrame 받음.

### Phase E — 정적 HTML 리포트 (구형 브라우저 호환, **양산 라인 게시용**) ✅ 추가

산출 HTML 구성:

**호환성:** Edge 92 / Edge Legacy / IE11 / Chrome / Firefox 모두 OK.

**의존성:** `matplotlib>=3.7` 추가 (requirements.txt).

검증:

## 8. 검증 계획

### Phase A
- 모션 485 데이터 회귀 테스트 (이전 집계와 동일).
- 보드 검사 샘플 JSON으로 신규 id 인식 검증.
- DPM 24V/3.3V/전류 값 정상 수치인지 stat 확인.

### Phase B
- FAIL 데이터 시뮬레이션 → 원인 그래프 정상 표시.
- 작업자별/시간대별 합계 수동 검산 일치.
- 자동 새로고침 켠 상태에서 새 JSON 추가 → 화면 반영.
- 일일 리포트 다운로드 정상.

### Phase C
- JSON 폴더만 있는 환경 → JSON 모드로 자동 동작.
- DB 생성 후 → DB 모드로 자동 전환, 증분 적재 확인.
- DB 삭제 → 다음 실행 시 JSON 모드로 fallback (자가복구).
- DB 손상 시뮬 → 자동 fallback 검증.
- 1만 건 JSON에서 JSON 모드 vs DB 모드 응답 시간 비교 (목표 5x 이상).

### Phase D
- 미니PC, 같은 네트워크 PC, 개발 PC 3 시나리오 매뉴얼 따라 실행 → 모두 정상.
