VL30 진동기울기센서 품평회 — 회의 정리

2026-05-13 VL30 신모델 사이즈 / 온도 / 소음

핵심: VL30은 RS-485 기반에 온도 측정과 소형화가 더해진 신모델. 센서는 NTC로 가닥(개발4팀), 사이즈는 29×29 → 23×24 가능 → 19×19 목표(대표님). 100°C 초과 환경 생존, 80°C 알람, 모터 베어링 손상 감지(소음 센서) 등 사양 보강 논의.

1. VL 라인업 정리

모델통신특징
VL10RS-232진동/기울기 (현행)
VL20RS-485진동/기울기 (현행)
VL30RS-485 + 온도온도 측정 + 소형화 (신모델)

2. 사이즈

안치수비고
출발29×29"작은 사이즈" 초안
개발4팀 결론23×24NTC 사용 시 가능
대표님 의견19×19"이게 좋겠다"

소형화에 따라 센서 선정·배치 제약이 같이 걸림 → 아래 온도 항목과 연결.

3. 온도 측정

3.1 측정 시스템 구성

구조는 발열원 → 베이스 → 제품 → 내부 센서 흐름. 외부 기준 계측기(타점 온도계)와 비교해 ±3°C 이내 정확도 검증.

① 시험 장비 (외부)

장비역할
펠티어전류 → 최대 100°C 발열. 시험용 열원 (측정 X)
알루미늄 코팅 베이스전도율 높은 소재로 펠티어 열을 제품 바닥에 전달
타점 온도계 (써모커플러)케이스 외부 상판 부착. 시험자가 보는 외부 기준값
⚠ HW 액션 — 타점 온도계 자체 측정 오차 조사 필요
  • 확인 항목: 정밀도 / 레졸루션 / 측정 오차
  • 현재 가설 (HW 담당자): "보통 정밀한 걸로 알고 있다" — 가설일 뿐, 실제 스펙으로 확인 필요
  • 중요한 이유: 타점 온도계가 기준값이므로 이 자체의 오차가 ±3°C에 가까우면 VL30 NTC 검증이 무의미해짐
  • 요구 수준: 목표 오차(±3°C)보다 충분히 작은 정밀도 (예: ±0.5°C 이하)

② VL30 내부 센서 3종

센서위치발열원과의 거리특성
NTC (출하 채택)케이스 안쪽 바닥가장 가까움응답/정확도 우수 → 출하 측정용 결정
MCU 온도MCU 칩 내부 (보드 상)중간다이 온도. 크로스체크 보조
IMU 온도IMU 칩 내부 (보드 탑면)가장 멀음다이 온도. 응답 느리고 오차 큼 → 단독 사용 부적합

③ 열 경로

[펠티어 ~100°C] → [알루미늄 베이스] → [케이스 바닥]
                                          │
                                          ▼
                          [NTC] ← 케이스 안쪽 바닥 (가장 가까움 · 정확)
                                          │
                                       (보드)
                                          │
                          [MCU] ← 보드 상 (중간 거리)
                                          │
                          [IMU] ← 보드 탑면 (가장 멀음 · 오차 큼)
                                          │

NTC 채택 이유: 발열원(바닥)에 가장 가깝게 부착되어 응답 속도와 측정 정확도 모두 가장 우수. IMU는 탑면이라 거리·응답 모두 불리해 단독 측정 불가. MCU·IMU는 크로스체크 보조 (대표님 의견).

3.2 발열 시험 방법

  • 펠티어로 전류 비례 온도 상승 (최대 100°C)
  • 베이스에 전도율 높은 소재 (알루미늄 코팅 검토)
  • 목표 오차: ±3°C (타점 온도계 기준)

3.3 모드별 온도 오차 특성

모드데이터 속도온도 오차
Normal 모드천천히작다
Full 모드빠르게크다

4. 대표님 결정 사항

④-1 센서 선택 — NTC가 맞다. 어느 정도 옵셋 OK. 3개 센서(NTC / IMU / MCU) 크로스체크 활용.
④-2 온도 사양 & 생존성
  • 제품 온도 사양: ~85°C
  • Industry 표준: 105°C
  • 100°C 초과 환경에서도 우리 제품은 살아남아야 한다
  • 케이스 / 케이블 — 난연 필수
  • MCU 셧다운 온도 ↔ Industry 온도 사양 매칭
④-3 출하검사 항목 — 대표님 발언
#대표님 단어내용상태
1"NTC 필터링할지"NTC 데이터 필터링 적용 여부 (노이즈 필터링 / lookup 처리 / 이상치 제거 등 — 정확한 의미 미정)단어 확정 / 의미 미정
2"보정" (단어만 기억)두 번째 항목의 정확한 내용은 미기억. 다만 "보정" 단어가 그 자리에서 언급된 것은 확실미기억

→ 대표님께 재확인 필요: (1) "필터링"의 구체적 처리 / (2) 두 번째 검사 항목 전체

5. NTC 동작 원리 (대표님 → HW 담당자)

질문HW 담당자 답변
NTC 온도가 그릭(따라가는) 되는 원리 설명부착면 전도 속도에 따른다

→ 즉 NTC는 부착면 열 전도 응답이 핵심. 부착 방식(아래 7번)이 측정 정확도에 직결됨.

6. 소음 센서 (추가 검사 항목 검토)

  • 위치: 모터 축에 부착
  • 목적: 베어링 손상 조기 감지
  • VL30 검사 항목 후보: 온도 + 소음 + 진동(모터 이상)
  • RS-232/485 라인은 초음파 측정 어렵다 → 채택 X
  • 측정 후보: NTC, 온도 IC, (그 외 2가지 측정 기 검토)
  • 주의: 소음 추가하면 사이즈 키워야 함 → 19×19 목표와 충돌 가능

7. NTC 고정 방법 조사 (HW 액션)

현재검토
볼팅 + 본딩써멀 패드 + 고정 일체형 / 열전도 NTC 제품 / 국내 공급사 조사

8. 소프트웨어 액션 (양산 검사 측)

출하검사 항목 두 가지(④-3 참조) 모두 SW 분담이 걸려있을 가능성 큼. 의미 확정 전이라 가설 기반 검토.

8-1. 출하검사 #1 — "NTC 필터링" (대표님 단어 확정 / 의미 미정)
  • "필터링"의 가능한 해석:
    • (a) 노이즈 필터링 — 이동평균/메디안/LPF → 보통 펌웨어 책임
    • (b) Lookup 적용 여부 — NTC raw → 선형화 처리 적용 on/off → 펌웨어 + 검사 PC 선택
    • (c) 이상치 제거 — 검사 시 spike 데이터 제외 → 검사 프로그램
  • "필터링할지" 표현 자체가 on/off 선택의 의미 → 워크스페이스 JSON 옵션화 가능성
  • → 대표님 의미 재확인 후 분담 확정
8-2. 출하검사 #2 — "보정" 단어만 기억 / 내용 미정
  • 가설: NTC 개체차 옵셋 보정 (양산 시 펠티어/타점 온도계 기준으로 측정 → EEPROM 기록)
    • FW: NTC raw / 보정값 읽기, EEPROM 옵셋 쓰기 명령
    • 검사 프로그램: 다점 보정 스텝(예: 30/60/90°C) + 펠티어·타점 온도계 연동
    • 워크스페이스 JSON: 보정 포인트 파라미터화
  • → 대표님께 두 번째 항목 자체를 다시 확인 필요 (보정 단어가 #2 내용인지 / 다른 맥락인지)
8-3. 알람 기능 — SW 담당자 검토 필요
  • 온도 max 100°C일 때 80°C 초과 시 알람
  • 검사 프로그램에서 처리 가능한지 / 펌웨어 측에서 처리할지 분담 확인
  • 임계값 JSON 파라미터화 권장 (다른 SPEC과 동일 방식)

9. 출하검사 온도검사 도입 시 SW 부담 시뮬레이션

"NTC 보정"이 풀 캘리브레이션이라면 검사 프로그램이 떠안을 작업은 적지 않다:

풀 캘리브레이션의 본질 (4단계 루프 × N점)
  1. 펠티어로 열원 조작 (목표 온도 도달까지 대기 — 가열 안정화 5~10분)
  2. VL30 NTC 측정값 읽기
  3. 외부 기준(타점 온도계) 값과 비교 → 옵셋 계산
  4. 옵셋을 VL30 플래시 메모리(EEPROM)에 기록

→ 다점이면 위 루프를 3~5회 반복. 양산 라인 시간/장비 부담이 큼.

9.1 부담 줄이는 옵션 (가벼움 → 무거움)

안 펠티어 타점 온도계 보정 EEPROM 쓰기 검사 +시간 검사 프로그램 부담
A. 검증 없음 — — — — +0 NTC raw 읽고 spec 확인만 (3초)
B. 1점 검증만 수동 1점 수동 입력 없음 (PASS/FAIL만) — +5분 비교 + 합/불 판정
C. 1점 옵셋 보정 수동 1점 수동 입력 1점 옵셋 옵셋 1개 +5~10분 측정 + 계산 + EEPROM 명령
D. 다점 풀 캘 수동 3~5점 수동 입력 3~5점 옵셋 다수 +15~25분 다점 흐름 + 검증
E. 다점 + 완전 자동화 자동 제어 자동 입력 풀 캘 풀 옵셋 +10~15분 펠티어/타점 통신 + 풀 캘 + 검증 (가장 큼)

9.2 양산에서 흔히 쓰는 표준 패턴 — 공정 분리

[캘리브레이션 공정]  (1회 / 개당 / 별도 PC + 펠티어 + 타점)
   └─ 풀 캘 → EEPROM 옵셋 기록
                  │
                  ▼
[출하 검사 공정]  (현재 ff_vibetilt가 담당하는 것)
   └─ EEPROM 옵셋 정상 / 보정값 정확도 ±3°C 확인
        └─ 펠티어 없이도 동작 (상온 1점 + EEPROM 신뢰 검증)
핵심 아이디어:
  • 출하 검사 PC는 펠티어 없이 가볍게 동작
  • 캘 공정은 한 PC가 여러 라인 커버 가능 (또는 HW팀 별도 운영)
  • 이 분리만으로 양산 라인 검사 시간을 +0~5분 수준으로 유지 가능

9.3 검사 프로그램(ff_vibetilt) 실제 추가 부담 (안별)

안ff_vibetilt 추가 작업워크스페이스 JSON
ANTC 읽기 1줄 + spec 1개기존에 1스텝 추가
BNTC 읽기 + 타점 입력박스 + 비교기존에 1스텝 추가
CB + EEPROM 쓰기 명령 1개기존에 1스텝 추가
D다점 루프 + 가열 대기 + EEPROM 쓰기신규 워크스페이스 권장
ED + 펠티어/타점 통신 모듈 신규신규 워크스페이스 + 통신 클래스 2개

9.4 단계적 도입 제안

단계내용일정 (추정)
단기 (양산 시작 직후)A안 — NTC raw spec 확인만. 캘은 펌웨어 디폴트 옵셋으로 시작 → 양산 데이터 수집~3일
중기 (수주 확보 후)캘 공정 별도 분리. 출하 검사는 B안 (1점 검증) 유지~2주 + HW팀 캘 공정 셋업
장기 (필요 시)E안 (완전 자동화) 또는 캘 공정 자동화~2개월
대표님 재확인 시 제안할 옵션:
  • "필터링" → 펌웨어 책임으로 빼고 검사는 raw spec 확인만 (가벼움)
  • "보정" → 출하검사가 아닌 캘 공정으로 분리 (양산 라인 영향 최소)
  • 이 분리 패턴이 업계 표준 — 양산 시간/장비 부담 크게 감소

11. 미해결 / 추후 확인 사항

  1. 출하검사 #1 "NTC 필터링"의 구체적 의미 — (a) 노이즈 필터링 / (b) Lookup 적용 on/off / (c) 이상치 제거 / 기타
  2. 출하검사 #2 항목 전체 — 회의 중 미기억 ("보정" 단어만 기억남, 정확한 내용 미정)
  3. 출하검사 항목의 SW/FW 분담 결정 (의미 확정 후)
  4. Full 모드 온도 오차 ±3°C 달성 방안 (모드별 보정 vs 펌웨어 필터)
  5. 3 센서 크로스체크 알고리즘 — 단순 평균 vs 가중치 vs 우선순위
  6. 소음 센서 채택 여부 (사이즈와의 트레이드오프)
  7. 알람 기능 분담 — 펌웨어 자체 알람 vs 검사 PC 측 알람 vs 상위 시스템
