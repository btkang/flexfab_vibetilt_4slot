## 2. 각 검사 항목 Pass 조건 (최종 확정)

### 2-1. VER_232 (버전 통신검사)

**명령:**
```
TX: <VER>
RX: [VER,0,F/W ver.1.0.4]
```

**Pass 조건:**
- 응답 프레임이 `[VER,...]` 형식이고 RV=0이면 PASS
- 예상 응답에 "VER" 문자열 포함 확인

**테스트 결과:**
```
✅ [VER,0,F/W ver.1.0.4] 정상 수신
```

| 진동 Y (1축) | 0.9 ~ 1.1 | |abs| > 0.5 → 1축, else → 0축 |
| 진동 Z (1축) | 0.9 ~ 1.1 | |abs| > 0.5 → 1축, else → 0축 |
| 진동 RMS | 0.5 ~ 0.65 | (선택) |

- `pass_consecutive_count=5` (기본값)
- 5회 연속 PASS 샘플이 나오면 즉시 PASS

**시퀀스:**
```

7. <MODE,0>         → 모드 복귀
```

**최종 Pass 조건 (alive_check 기반):**

```json
{
  "alive_check": true,
  "alive_min_delta_x": 40,
  "alive_min_delta_y": 25
}
```

| 항목 | 임계값 | 판정 기준 |
|------|--------|----------|
| **X 변화폭 (ΔX)** | ≥ 40 | 센서 정상 작동 확인 |
| **Y 변화폭 (ΔY)** | ≥ 25 | 센서 정상 작동 확인 |
| **Pass 로직** | ΔX ≥ 40 **OR** ΔY ≥ 25 | 둘 중 하나만 만족하면 PASS |

**연속 Pass 조건:**
- `pass_consecutive_count=1` (기본값)
- 1회만 PASS 조건을 만족하면 즉시 PASS
- `pass_min_elapsed_ms=0` (최소 경과시간 없음)

**테스트 실제 데이터:**

```
X 범위: 1.06 ~ -39.24  (변화폭 = 40.3)
Y 범위: 1.08 ~ -10.00  (변화폭 = 11.08)

✅ ΔX = 40.3 ≥ 40.0  → PASS 조건 만족
⚠️  ΔY = 11.08 < 25.0 (하지만 X로 이미 PASS)
```

## 부록: Pass 조건 선택 이유

**왜 alive_check(변화폭) 방식을 선택했는가?**

1. **센서 정상 작동 판정**
   - 절대값 범위로는 다양한 환경에 대응 어려움
   - 변화폭으로 센서가 제대로 반응하는지 확인 가능

2. **작업자 조작 의존도 낮춤**
   - 특정 각도(90도, 20도)를 정확히 맞출 필요 없음
   - 충분히 움직이기만 하면 PASS

3. **실측 데이터 기반**
   - 현장에서 실제로 움직인 데이터 활용
   - 임계값에 안전 마진 적용 (60~70%)

4. **향후 Motion 검사 호환성**
   - 지그의 정밀한 움직임으로도 충분히 충족 가능
   - 파라미터만 조정하면 자동화 가능
