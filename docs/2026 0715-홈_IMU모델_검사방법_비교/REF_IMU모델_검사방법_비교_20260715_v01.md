## 1. 모델별 요약

### 1-1. pCOM2 (MPU-6050)
- **IMU 자가진단(보드레벨)**: `<TEST=7B4>` → 응답 `"test 7 ok"` 포함 시 PASS. 펌웨어 내부 I2C self-test, PC는 문자열 판정만. (`BoardLevel.cpp:852~857`)
- **영점/드리프트 검사(세트레벨, 현재 enum 비활성)**:
  1. `MBSET=0→1→2` (영점/모션베이스 세팅, 사이 1000ms)
  2. `MINFO=3/4/5` (Angle X/Y/Z) + `MTEMP` → 기준값 저장
  3. 8000ms 발열 대기(tempaging)
  4. 재측정 후 판정 (`Commtest.cpp:3681~3688`):
     - ΔTemp ≥ **8.0°C** (온도가 충분히 올라야 유효)
     - |ΔAngleX|, |ΔAngleY| ≤ **0.01×ΔT + 0.07** (도, 온도의존 허용오차)
     - |ΔAngleZ| ≤ **0.1도** 고정
- **IMU config 기록/검증(양산 셋업)**: 가속도/자이로 오프셋=0, `tilt_angle=200`, `runout_angle=30`, `impact_gravity=1000`, `VibrationAcc=10`, `low_filter_cut_off=30` 등 config 문자열 echo 일치 검증. (`SetProduct.cpp:111~124`)
- spec 위치: 판정 수치는 소스 하드코딩, 디바이스 config 값은 Config.txt/비교문자열.

### 1-2. pSMC
- **IMU 통신 자가진단**: `<MINFO=0>` 응답에 `=` 구분자 2개 이상이면(파싱 가능하면) PASS — 수치 spec 판정 없음. (`Commtest.cpp:3195~3202, 6345~6355`)
- **온도**: `<MTEMP>` 응답에 소수점 있으면 PASS. (`Commtest.cpp:6357~6366`)
- **영점 안정성 검사(TEMP_ANGLE_CHECK, 현재 `#if 0` 비활성)**: pCOM2와 동일 계열 —
  `MBSET` 영점 → `MINFO=3/4/5`+`MTEMP` 전후 측정 → |ΔX|,|ΔY| ≤ `0.01×ΔT+0.07`도, |ΔZ| ≤ 0.1도, ΔTemp ≤ 8.0°C(방향이 pCOM2와 반대: "8도 이내"). (`Commtest.cpp:6100~6108`)
- 가속도/자이로 원시값·진동 판정 없음. IMU는 각도+온도 형태로만 검사.
- spec 위치: 소스 하드코딩 + 레지스트리 프로파일(버전, 전류상한).

### 1-3. BG01 핸디 (CtsBG01QcMan)
- **IMU 존재 확인**: `<I2C_TEST,MOT_SEN>` → result 0이면 PASS. (`BG01QCDlg.cpp:3440`)
- **기울기 실동작 검사**: `<msopen>` → `<MOTSEN>` 반복 폴링(응답 `[MOTSEN,result,ang_x,ang_y,ang_z]`) → `<msclose>`.
  - 검사원이 손으로 X축, Y축 기울임 → **|각도| > 10도** 넘으면 축별 DONE, 두 축 모두 통과 시 PASS. (`BG01QCDlg.cpp:4155, 4165`)
  - Z각은 표시만, 판정 미사용. 서브스텝 타임아웃 15초.
- 진동/자이로/영점 캘리브레이션 항목 **없음**. 각도 산출·영점은 DUT 펌웨어 몫, PC는 임계 초과 여부만.
- spec 위치: **소스 하드코딩** (ini에는 포트/보레이트/전압·전류 캘리 조건만).

### 1-4. BG01 MOS Tester (회전지그, VibeTilt 모션지그의 직계 선조 격)
- **구성**: 모터 턴테이블(TCP, `PMxxxx` 스텝모터 명령) + DUT X/Y/Z 3보드 동시(UART 57600) + **기준(reference) 경사센서**(UART 38400, `setzcur`/`get---x`).
- **시퀀스**: 지그 초기화(원점복귀 `PMO011`) → 보드 인식(`<msopen>`→`[msclose=OK]`) → 기준센서 0점(`setzcur`) → **+10.5° 이동·측정** → 0° 복귀·0점 재설정 → **-10.5° 이동·측정** → 종료. 측정 retry 3회, 이동 retry 2회.
- **측정/판정**: `<mstest>` 응답 `A=ax,ay,az,ACC=x,y,z,T=temp,GA=gx,gy,gz`를 window 비교 (`BoardLevelMo_BG01.cpp:353~609` angle_measureEach):
  - 기울인 축 각도: **±10.5° ± 0.3°** (내부 ×100 스케일, ±1050±30)
  - 수평 유지 축: **0 ± 0.3°**, Z 방위각: **180.00 ± 0.30°**
  - 가속도: 수평축 **0±0.005g**, 중력축 **≈0.98g±8mg**, 측면축 ≈±0.18g(=sin10.5°)
  - 자이로(GA) 0점 축: **±1.00**
- **영점**: 기준 경사센서 `setzcur`로 지그측 0점만 잡음(구버전엔 1펄스 미세이동 수평트림 로직 존재, `angle_0_init` `:979~1020`). DUT 자체 영점은 0±0.3° window 통과로 간접 확인 — **DUT에 CAL 명령을 쓰지 않음**.
- 진동 항목 없음(Longrun 반복이 내구 대체). spec **전부 소스 하드코딩**, 설정파일 없음.

### 1-5. VibeTilt (기준선, 현행)
- **보드검사** (VL10 232 / VL20 485, 11항목): 24V/3.3V/전류 → 통신 → FW버전 → 센서온도(**20~40°C**, `<SENTEMP,1>`) → Config → LED 육안 → **진동검사**(MODE 스트리밍, judge_mode 1=변화만 확인: 1축 0.5~1.5 / 0축 ±0.3 / RMS 0.1~2.0 완화, motion_threshold 0.05) → **기울기 X/Y**(MODE 6 스트리밍, 5~95도, 작업자 수동 기울임).
- **모션검사** (18항목, X결합→Y결합):
  - **영점 초기화**: 자이로 지그(setdir6/5) + 홈센서(IN1/IN2) + FineAdjust(허용 0.05), home_every_n=10 시간단축
  - **Calibration**: DUT에 OFFSET 명령 후 **AN 0도 ±0.05 검증**(verify_an) — DUT 내장 영점 캘리를 PC가 실행·검증
  - **정지검사**: 1초 GAC 수집, 전축 p2p ≤ 0.05
  - **기울기 측정**: ±20°(±0.2) / ±45°(±0.5), AN 스트리밍 500ms, 마지막 10샘플 **all_in_spec** 판정, retry 3
  - **진동(중력축) 측정**: X/Y/Z 각각 ±90°/0° 자세에서 GAC 해당축 **0.98~1.02g**, 마지막 5샘플 all_in_spec, retry 3
  - 시리얼번호 기록, 센서온도 저장, 출하상태 설정, 파라미터 SAVE, APPCFG 확인
- spec 위치: **workspace JSON** (`_comment` 주석 포함, MP/SER/TCP/TEST × board/motion 조합 파일).

## 3. 관찰 및 시사점

### VibeTilt가 이미 앞서 있는 부분
1. **spec 외부화(JSON)** — 참조 4종 전부 spec이 소스 하드코딩. 라인에서 spec 변경 시 재빌드가 필요했던 구조를 VibeTilt는 JSON+주석으로 해결. 유지.
2. **진동 정량 검사** — 참조 모델 중 진동을 실제로 판정하는 프로그램은 없음(pCOM2는 config 기록만). VibeTilt 고유 항목.
3. **DUT 영점 캘리브레이션의 실행+검증+저장 사이클** — BG01 MOS는 지그측 0점만 잡고 DUT는 window 간접확인, pCOM2/pSMC는 MBSET 후 확인 없음. VibeTilt는 OFFSET→AN ±0.05 검증→SAVE→APPCFG 확인으로 가장 완결적.
4. **판정 통계(all_in_spec N샘플 + retry)** — 참조 모델은 전부 1회성 측정. 순간 노이즈에 강한 구조는 VibeTilt뿐.

### VibeTilt 검토에 참고할 만한 것 (영점검토 관점)
1. **온도-드리프트 검사 (pCOM2/pSMC)**: 영점 세팅 후 발열(ΔT 8°C)시켜 각도 드리프트를 `0.01×ΔT+0.07°`로 판정하는 항목은 VibeTilt에 없음. VibeTilt는 CAL 직후 0도만 확인하므로, **온도 변화에 따른 영점 이동 불량은 현행 검사로 못 잡는다**. 출하 후 필드 이슈 대비로 검토 가치 있음 (단, 사이클 타임 8초+ 추가 부담).
2. **양(+)/음(−) 대칭 2점 측정 (BG01 MOS)**: ±10.5° 양쪽을 측정해 스케일 오차와 오프셋 오차를 분리 감지. VibeTilt 모션검사도 ±20/±45 4점이라 이미 커버 — 동등 이상.
3. **기준 경사센서로 지그 0점 확인 (BG01 MOS)**: VibeTilt는 지그 자이로+홈센서 방식. BG01 MOS의 독립 기준센서(`setzcur`) 방식은 지그 기구 마모/드리프트를 DUT와 독립적으로 검증 가능 — VibeTilt는 `home_skip_max_deg=7`로 부분 대응 중. 지그 노후화 모니터링 관점에서 참고.
4. **Z 방위각 판정 (BG01 MOS, 180°±0.3°)**: 실장 방향(뒤집힘/회전 오조립) 감지 용도. VibeTilt는 Z축 진동값(0.98~1.02g)으로 상하 뒤집힘은 잡히나 수평면 회전 오조립 감지 항목은 없음 — VibeTilt 기구상 해당 불량 모드가 존재하는지 확인 필요 (TODO).
5. **가속도 측면축 sin(θ) 교차검증 (BG01 MOS)**: 기울인 각도와 가속도 측면축(≈sin10.5°=0.18g)을 동시에 window 판정 → 각도 연산부와 가속도 원시값의 정합성을 교차 확인. VibeTilt는 기울기(AN)와 진동(GAC)을 별도 스텝에서 판정하는데, 같은 자세에서 두 값의 정합 확인은 안 함 — 저비용으로 추가 가능한 아이디어.

### 계보 정리
- 프로토콜 계열: BG01 계열(`<msopen>/<MOTSEN>/<mstest>`)과 pCOM/pSMC 계열(`MBSET/MINFO/MTEMP`)의 두 갈래. VibeTilt(`<MODE>/<START>/<GAC>/<AN>`)는 BG01 계열의 후속 세대.
- 지그 진화: 핸디 수동(BG01 QcMan, ±10° 반응) → 턴테이블 자동 2점(BG01 MOS, ±10.5°±0.3°) → **모션지그 자동 4점+진동+CAL(VibeTilt)**.
