# PLAN_모션검사 정지검사 추가 (X결합 우선)

- 작성일: 2026-06-09 / 작성: Claude
- 대상: **모션검사** 232·485 / **X결합만 먼저** (Y결합은 효과 보고 추후 판단)
- 선행: `docs/2026 0604_모션_기능추가전보강/PLAN_모션_0도정지정상필터_20260604_v01.md` (당시 검토)
- 보드 정지검사(`VIBE_STILL`, 0.7.2)는 이미 양산 적용·검증 완료 → **그 핸들러를 재사용**

---

## 1. 목표
0도 정지 상태에서 센서 출력이 출렁이는(노이즈성) 불량을 모션검사에서 검출. 평균 아닌 **전축 p2p(최대−최소)** 로 판정.

## 2. 핵심 결정 — 코드 변경 없음 (JSON-only)
`ff_vibetilt/VibeTilt.cs`의 `VIBE_STILL_Internal`(보드 0.7.2)이 필요 기능을 이미 전부 지원:
- `ResolveUart` 가 `uart_id` 파라미터 오버라이드 지원 (밀어내기 2포트) — VibeTilt.cs:74~80
- 전축 p2p 판정(`still_p2p_max`) + `measure_only` 토글
- 정지 자동측정 (모터 이동 없음)

→ **모션 워크스페이스에 proc 1개 삽입만 하면 됨. DLL 빌드·버전업 불필요.**
→ proc `id`는 핸들러로 라우팅되므로 그대로 **`VIBE_STILL_485` / `VIBE_STILL_232`** 사용.

## 3. X결합만으로 충분한 근거
- 밀어내기(dual): 모든 제품이 **X결합 위치(투입)** 를 거침 → 제품마다 정지검사 1회 보장.
- 정지검사는 GAC(X·Y·Z·RMS) 전축을 읽어 **센서 전체 노이즈**를 봄 (축 결합 무관) → 한 위치 1회로 노이즈 보드 검출.
- single 모드도 X(COM13)만 도므로 X결합 검사로 커버.
- (Y결합 추가는 위치/시점 2회 이중 확인 + Y단독 운용 대비 목적. 지금은 보류.)

## 4. 배치
```
X결합:  ... #5 X축 파라미터 저장(0도) → [신규] #5-1 X결합 정지검사(0도) → #6 기울기
```
- #5(저장) 직후 = 0도·캘 완료·모터 정지 → 추가 모터부담 0, 사이클 +~1초/대.

## 5. 신규 proc 정의

| 항목 | 값 |
|---|---|
| 위치 | 모션검사 `#5`(APPCFG_SAVE) 직후 |
| name | `#5-1 X결합 정지 안정성 검사 (0도)` |
| id | `VIBE_STILL_485` / `VIBE_STILL_232` (핸들러 재사용) |
| uart | X결합 = 핸들러 기본(485=`uart_485`, 232=`uart_232`) → **uart_id 오버라이드 불필요** |

파라미터 (보드 검증값 그대로):
- `duration_ms: 1000`, `sampling_ms: 10`
- `still_p2p_max: 0.05` (전축 변동폭 ≤0.05 PASS / 초과 노이즈 FAIL. 보드 232·485 실측 ≈0.01, 5배 마진)
- `_still_rms_max` 는 `_` 비활성 유지 (RMS는 정지/동작 무관 ≈0.58, 노이즈 판정에 무의미)
- tests(프로토콜): 보드 VIBE_STILL과 동일
  - 232: `<MODE,2>` → `<START>` → `<STOP>`
  - 485: `<MODE,1,0>` → `<MODE,1,2>` → `<START,1>` → `<STOP,1>` → `<MODE,1,0>`
- `_comment` 필수 (의미·임계·완화이유)

## 6. measure_only 롤아웃 (안전)
- 보드는 measure_only=false(판정 ON)로 운용 중이나, **모션 0도(post-CAL) 정상 p2p 실측 데이터는 아직 없음.**
- **1단계:** `measure_only: true`(측정·로깅만, 항상 PASS) 로 삽입 → 정상품 모션 0도 p2p 분포 1회 수집.
- **2단계:** p2p가 0.05 대비 충분히 낮으면 `measure_only: false`(판정 ON)로 전환. 타이트하면 임계만 조정 (코드 영향 0).

## 7. 선결 확인
1. ~~operator_prompt 강제 여부~~ → **확인 완료(2026-06-09):** `VIBE_STILL_Internal`은 **작업자 팝업 없이 자동 측정** (VibeTilt.cs:2211 "정지 상태 자동 측정 — 작업자 팝업 없음"). 모션 자동흐름에 끼어도 멈춤 없음 → `operator_prompt` 생략. ✅
2. **모션 0도 p2p 실측** → 임계 0.05 확정/조정 (measure_only=true 1회로 수집, 아래 6 참고).
