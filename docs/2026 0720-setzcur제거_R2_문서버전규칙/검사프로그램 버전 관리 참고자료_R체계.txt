응용기술팀 검사프로그램 버전 관리 규정 (R 체계)
(2026-07-20 제정 — 팀 문서 리비전 규칙을 검사프로그램에 적용)
참고: 팀 문서 관리 규칙 "검사프로그램 버전.docx"


1. 기본 개념
   버전은 R{n} 과 b{m} 의 조합으로 운영한다.

   - R{n}  : 제조팀(캔탑스엠)으로 공식 배포된 마일스톤. 배포 시마다 n 을 1 올린다.
   - b{m}  : R{n} 정식 배포로 가기 위해 내부에서 다듬는 베타(초안) 단계.
             같은 R 로 가는 동안 수정본이 나올 때마다 m 을 1 올린다.

   흐름 예:  R0  →  R1b1  →  R1b2  →  R1  →  R2b1  →  ...

   - R(숫자)         = 공식 배포된 확정본 (양산 적용)
   - R(숫자)b(숫자)  = 그 다음 배포로 가기 위한 내부 검증본 (양산 미적용)
                       베타 번호는 첫 회부터 b1 로 붙인다 (b1 → b2 → b3, 몇 번이든 규칙 동일)

   ※ 현재 공유본이 공식본(R1)인지 검토중 초안(R1b1)인지 한눈에 구분하는 것이 목적.


2. 개발/양산 구분
   - 양산 라인에는 b 없는 확정본(R1, R2 ...)만 적용한다.
   - b 붙은 베타본(R2b1 ...)은 내부 검증/실기 테스트 용도이며 양산 미적용.
   - 실기 검증·회의 확정이 끝나면 b 를 떼고 R{n} 으로 승격 → 배포.


3. 표기 위치
   - 프로그램 표시/로그      : R 표기 (MODULE_VERSION = "R2b1")
   - 어셈블리 버전(.csproj)  : 숫자 형식 강제 → 매핑 표기
                              <Version>1.0.0</Version>  (목표 R 번호 = Major, R1=1.0.0)
                              <InformationalVersion>R1b1</InformationalVersion>  (실제 표기)
   - 릴리즈 노트            : RELEASE_NOTE_ff_vl.txt (R/b 항목별 상세)
   - 제조팀 배포용 간략문서  : 버전변경이력_ff_vl_README.txt (확정 R 만 기재)
   - 배포 폴더명            : 진동기울기검사_{YYMMDD}_R{n}_ff_vl  (확정 배포 시)

5. 운영 권장 사항

   - 프로그램 파일명/폴더명/로그에 R 표기 명시
   - 소급 개칭(예: 1.0.0 → R1) 발생 시 구 표기를 병기해 추적성 유지
   - 제조팀 공유 문서에는 확정 R 만 기재 (베타 b 는 내부용)
