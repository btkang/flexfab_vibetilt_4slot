PLAN — 워크스페이스 spec 편집기

작성일: 2026-05-13 버전: v01 상태: 계획 (사용자 확인 대기)

1. 배경 / 목적

  • 현재 양산 검사 워크스페이스 JSON을 텍스트 에디터로 직접 편집해야 함
  • 가독성 낮고, 오타·구조 깨짐 위험. 변경 흔적 추적 어려움
  • 자주 바뀌는 운영 옵션(log_level, show_log, serial_duplicate_check 등)을 표 형태로 보면서 안전하게 편집하고 싶음
  • 양산관리자도 익숙해지면 사용 가능한 단순한 UI

2. 사용자 / 사용 범위

사용자 사용 우선순위
본인 (개발자) 항상 1차
양산관리자 알려주는 정도, 익숙해지면 사용 2차 (배움)
작업자 사용 X (원칙) —

3. 핵심 원칙

  • 현재 검사 프로그램(ff_vibetilt)에 영향 없음 — 별도 EXE/스크립트로 분리, ff_vibetilt 코드 무수정
  • 개별 실행 — 워크스페이스 종류(보드 232/485, 모션 232/485) 4가지 각각 따로 열기 가능
  • 단계적 추가 — Phase별로 따로 갈 수 있게 설계 (Phase 1만 먼저 써보고 2/3는 필요 시)
  • 양산 안전 — 편집 전 자동 백업, 잘못된 값은 저장 X

4. 편집 대상 (Phase 1)

4.1 편집 허용 — "테스트 설정 위쪽" 항목

키 타입 의미
log_level "MP_LOG" / "TEST_LOG" 양산용/테스트용 로그
show_log 0 / 1 로그창 표시 여부
fail_continue true / false FAIL 시 다음 검사 진행 여부
serial_auto_increment true / false 시리얼 자동 증가
serial_duplicate_check 0 / 1 / 2 중복 체크 없음/경고/차단

4.2 편집 금지 (고정, 표시만)

키 이유
expected_fw_version FW 출하 버전 고정
uart_*.port (COM 포트) 양산 PC 환경에 박힌 값 — 변경 시 라인 정지
uart_*.baudrate 보드와 매칭, 변경 금지

→ 이 항목들은 회색 표시로 읽기 전용

5. 도구 형태 (별도 EXE/스크립트)

5.1 기술 스택 후보

옵션 장점 단점
A. C# WinForms (.NET 8) 기존 스택 동일, 친숙 신규 프로젝트 빌드/배포
B. Python + Tkinter 단일 .py, 가장 가벼움. 즉시 실행 C# 스택과 다름
C. Python + PySide6/Qt UI 깔끔, JSON 편집 라이브러리 풍부 외부 의존성

1차 추천: B (Python + Tkinter) — tools/ws_editor/ws_editor.py 단일 파일로 시작. 의존성 표준 라이브러리만. 빠르게 PoC 가능. 익숙해진 후 필요하면 C# 이전.

6. 기능 명세

Phase 1 (필수 — 1차 출시)

  1. 워크스페이스 JSON 불러오기 - 시작 시 Debug + Release 두 경로의 JSON을 읽음 - 두 파일이 다르면 경고 + 어느 쪽 기준으로 갈지 선택 (보통 Release)
  2. 편집 가능 항목 표시 (표) - 키 / 현재 값 / 설명 / 허용 값 / 편집 UI(드롭다운/체크박스)
  3. 편집 금지 항목 표시 (읽기 전용) - 회색, 잠금 아이콘
  4. 저장 - 변경 전 백업 자동 생성 (backup/YYYYMMDD_HHMMSS_원본이름.json) - Debug + Release 두 경로 동시 저장 (룰 준수) - 저장 전 JSON 문법 검증
  5. 변경 사항 미리보기 - 저장 직전 변경 항목만 diff로 보여줌 → 확인 후 저장

Phase 2 (선택)

  • 검사 항목(tests 배열) ON/OFF 토글
  • 자주 바뀌는 spec 편집 (VIBE 범위, TILT 범위, timeout 등)
  • 변경 이력 (git log 같은 자동 기록 — 별도 .csv)

Phase 3 (선택)

  • 워크스페이스 비교 (Debug vs Release / 다른 PC vs 본 PC)
  • 양산 PC 원격 편집 (보안 검토 필요 — 1차 범위 아님)

Phase 1 합계 양산 적용 1차 출시 ~3일

10. 검증 방법

  1. 기존 워크스페이스 JSON으로 도구 실행 → 모든 항목 정상 표시
  2. 한 항목 변경 → 저장 → Debug + Release 둘 다 변경됐는지 hash 비교
  3. 백업 파일 생성 확인
  4. JSON 문법 깨진 파일 입력 시 친절한 오류 메시지
  5. 잘못된 값 입력 시 저장 거부 (예: log_level에 정의되지 않은 값)
  6. 검사 프로그램(ff_vibetilt)으로 변경된 JSON 정상 로드 확인

11. 미해결 / 결정 필요 사항

  1. 기술 스택 확정: A(C#) / B(Python Tkinter) / C(Python PySide6) 중
  2. 편집 허용 항목 목록 최종 확정 (4.1 5개로 충분한지)
  3. spec 범위 편집 (Phase 2) — VIBE/TILT spec, timeout 등을 Phase 2에서 다룰지, 별도 PLAN으로 분리할지
  4. 변경 이력 기록 — Phase 1에서 백업만 할지, .csv 이력도 만들지
  5. 양산 환경 권한 — 다른 PC에서 같은 도구를 양산 PC에 들고 가서 쓰는지 / 양산 PC 자체에 두는지
  6. 자주 바뀌는 spec 정확한 목록 — 본인 양산 운영 경험상 가장 많이 변경한 항목들 추출 필요

S&P500이나 나스닥 100, 인도 니프티50 등 평소 선호하시는 지수형 ETF는 훌륭한 장기 성장 자산이지만, 단기적으로는 피할 수 없는 시장 변동성이 존재합니다. 주택 자금처럼 정해진 날짜에 반드시 치러야 하는 자금을 주식형 자산에 전액 투입할 경우, 만약 2027년 하반기나 2028년 초에 예기치 않은 하락장이 찾아오면 원금 손실을 안고 눈물을 머금고 매도해야 하는 치명적인 리스크가 있습니다.

  2. '앞으로 발생할 수익'에 대한 과세 여부 지금 해지해서 손에 쥐는 4,358만 원은 비과세가 맞습니다. 하지만 이 돈을 ISA나 위탁계좌에 넣고 ETF를 매수하여 '앞으로 새롭게 발생할 수익'에 대해서는 배당소득세(15.4%)나 분리과세(ISA 한도 초과 시 9.9%)를 내야 합니다. 반면, 이 연금보험을 깨지 않고 유지한다면 2028년까지 남은 기간 동안 붙게 될 예상 이자 약 174만 원 역시 100% 비과세로 가져가게 됩니다.

결론적으로 이렇게 판단해 보시기를 권해드립니다.

해지 후 투자 (공격형): 이 4,300만 원이 2028년 주택 자금 조달에 없어도 큰일 나지 않는 여유 자금이라면, 지금 해지하여 비과세 이익을 확정 짓고 남은 ISA 한도를 활용해 지수형이나 배당 성장 ETF에 적극적으로 투자하시는 것이 장기적으로 자산을 더 크게 불리는 방법입니다.

현상 유지 (방어형): 이 자금이 2028년 주택 잔금을 치르는 데 필수적인 핵심 자금이라면, 기대 이율이 2.35%로 다소 아쉽더라도 시장이 폭락하든 말든 절대 깎이지 않는 확정된 안전 자산으로 묶어두시는 것이 포트폴리오의 안정성을 위해 훨씬 유리합니다.정확하게 이해하셨습니다. 지금 당장 해지하시더라도 원금과 지금까지 발생한 수익금 전체에 대해 세금을 전혀 내지 않습니다. 10년 유지 요건을 채워 비과세 혜택이 이미 완벽하게 확정된 상태이므로, 예상 해약환급금인 약 4,358만 원을 세금 차감 없이 온전히 받으실 수 있습니다.
