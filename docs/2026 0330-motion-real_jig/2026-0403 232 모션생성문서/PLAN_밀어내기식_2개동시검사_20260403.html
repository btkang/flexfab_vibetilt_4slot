PLAN: 밀어내기식 VL10 2개 동시 검사

작성일: 2026-04-03 | 브랜치: step6-motion-jig-test | 1차 구현 (사양서 유지, 포트 분기)

1. 배경 및 목적

현재: VL10 1개를 X축결합 → Y축결합으로 옮기면서 검사 (팝업 대기 ~10초)
변경: X축결합(COM13) + Y축결합(COM14)에 VL10 2개 동시 장착, 밀어내기식 검사
효과: 제품 이동 불필요, 처리량 증가

2. 밀어내기 흐름

[1회차] 제품A → X축결합(COM13)에 장착, Y축 비어있음
    → X축 검사만 (#0~#6)
    → 제품A X축 결과 → pending_x_result.json 임시 저장
    → Y축: pending 없으므로 스킵
    → 업로드 없음

[2회차] 제품B → X축결합(COM13), 제품A → Y축결합(COM14)으로 밀림
    → 제품B X축 검사(COM13) + 제품A Y축 검사(COM14)
    → 제품A: pending X축 결과 + 이번 Y축 결과 → 12항목 완성 → PASS/FAIL → MongoDB 업로드
    → 제품B X축 결과 → pending 저장

[3회차] 제품C → X축, 제품B → Y축
    → 제품B 완성 → 업로드, 제품C pending 저장
    → ...반복

[마지막] X축 비어있음, 마지막 제품 Y축만 검사
    → 마지막 제품 완성 → 업로드

4. 시리얼번호 관리

항목설명
입력 방식시작 팝업에 X축 시리얼 + Y축 시리얼 2개 입력 필드
자동증가 ON (디폴트)X축: 이전 X축 시리얼 +1 자동 채움
Y축: 이전 X축 시리얼 자동 가져옴 (밀어내기)
자동증가 OFF이전 시리얼 그대로 표시 (증가 없음), 작업자 직접 수정
수정 가능자동 채움 후 작업자가 확인/수정 가능
시리얼 일치 확인Y축 시리얼과 pending 파일의 X축 시리얼 일치 여부 확인. 불일치 시 경고
예시 (자동증가 ON):
1회차: X축=00001, Y축=없음 → 검사
2회차 팝업: X축=00002(+1), Y축=00001(이전X) → 확인/수정 → 검사
3회차 팝업: X축=00003(+1), Y축=00002(이전X) → 확인/수정 → 검사

5. PASS 판정 방식

사이클 단위 판정:
• Y축 완료 시점에 이전 X축 결과(pending) + 이번 Y축 결과 합쳐서 12항목 판정
• 12항목 전부 OK → 최종 PASS → MongoDB 1건 업로드
• 하나라도 FAIL → 최종 FAIL
• 프로그램에서 판정 완결 (DB 조회 불필요)

6. 결과 저장 (pending 파일)

시점동작파일
X축 검사 완료X축 결과 + X시리얼 + 시간 저장pending_x_result.json
Y축 검사 시작 전pending 파일 존재 확인 + 시리얼 일치 확인없으면 Y축 스킵
Y축 검사 완료X+Y 합쳐서 판정 → MongoDB 업로드업로드 후 파일 삭제
프로그램 재시작pending 파일 있으면 자동 복구Y축 검사 가능
