2. single vs dual 비교

항목singledual
제품 수1개2개 (밀어내기)
시리얼 입력SerialMac 폼 (1개 + MAC)DualSerial 폼 (X축 + Y축)
X축 (#0~#6) 포트COM13COM13
Y축 (#0-Y~#12) 포트COM13 (오버라이드)COM14 (uart_232_y)
#1 팝업"제품을 X축 위치에 장착해주세요.""X축: 새 제품, Y축: 이전 제품을 장착해주세요."
#7 팝업"제품을 Y축 위치로 옮겨주세요."없음 (밀어내기식)
pending 파일없음pending_x_result.json
결과 저장SaveLog 즉시 (14항목)pending + 합산 업로드
로컬 저장Result/모션지그검사(RS-232)/날짜/시리얼.json

3. single 모드 동작 흐름

1. SerialMac 폼으로 시리얼 1개 입력
2. #0 FW 버전 → COM13
3. #1 X축 영점 (팝업: "X축 위치에 장착") → COM13
4. #2~#6 X축 검사 → COM13
5. 제품을 Y축 위치로 이동 (같은 COM13 케이블)
6. #0-Y FW 버전 → COM13 (uart_id 오버라이드)
7. #7 Y축 영점 (팝업: "Y축 위치로 옮겨주세요") → COM13
8. #8~#12 Y축 검사 → COM13 (uart_id 오버라이드)
9. 14항목 전부 OK → PASS → 로컬 JSON + MongoDB 업로드

6. FAIL 원인 분석 (디버깅 과정)

증상원인해결
#10에서 불필요한 팝업gyro_dir=setdir5 조건이 #7뿐 아니라 #10~#12에도 매칭proc.id == "MOTION_ZERO_232" 조건 추가
#10 센서 차이 19.96도 FAILY축 proc이 COM14로 통신 → 제품은 COM13에 있음single 모드에서 uart_id를 uart_232로 오버라이드
주의: single 모드에서 제품 케이블은 항상 COM13. Y축 위치로 이동할 때 같은 케이블 유지.
dual 모드에서는 제품 2개가 각각 COM13(X축), COM14(Y축)에 연결.
