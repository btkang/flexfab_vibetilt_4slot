1. 발견된 버그 (3개)

1.1 영점 setzcur(1차) — 가짜 PASS

현상: 지그가 수평이 아닌데 영점 초기화 PASS
원인: FineAdjust 전에 setzcur를 실행 → 자이로가 현재 위치를 0으로 리셋 → FineAdjust가 "이미 0도" 판단 → 즉시 수렴
증거: 수평 상태에서 get---x → -050.352 (이전 수동 테스트의 setzcur 오프셋 잔존)
항목변경 전변경 후
영점 시퀀스1250 step → setzcur(1차) → FineAdjust → setzcur(2차)1250 step → FineAdjust → setzcur(1회만)
FineAdjust 동작자이로 이미 0 → 즉시 수렴 (가짜)자이로 실제값으로 수평 찾기 (53도 → 0도)
이대리 코드setzcur 없이 FineAdjust → 동일 방식

1.2 FineAdjust MoveSteps 실패 무시

현상: 모터 busy(pmd5011) 시 MoveSteps 실패를 무시하고 계속 시도 → 무한 반복
원인: MoveSteps(emio, step, log) 반환값 미사용 (line 657)
증거: 0331 로그에서 177 step × 15회 전송, 모터 안 움직임, 각 10초 timeout
항목변경 전변경 후
MoveSteps 실패무시하고 다음 step2초 대기 후 1회 재시도, 2회 실패 시 FAIL 반환

1.3 MoveSteps timeout 고정

현상: pre_move 400 step 이동 중 다음 PMD 명령 전송 → pmd5011 에러
원인: EmioRecvUntil("pmd0011", 10000) 고정 timeout — 큰 이동도 10초
항목변경 전변경 후
timeout 계산고정 10초|steps| × 20ms + 5초 (최소 5초, 최대 30초)

2. 자이로 오프셋 문제

발견: 어제 개발자 수동 테스트에서 기울어진 상태로 setzcur → 비휘발성 메모리에 저장 → 오늘 수평에서 -50도 출력
해결: 포트몬에서 setzfac 수동 전송 → 공장 영점 복구 → 수평에서 +0.904도 (정상)
결론: setzfac는 코드에 넣지 않음 — 비정상 상황에서만 수동 복구
