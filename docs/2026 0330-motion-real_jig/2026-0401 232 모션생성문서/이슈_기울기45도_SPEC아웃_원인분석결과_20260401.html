이슈: 기울기 45도 SPEC 아웃 원인 분석 결과

작성일: 2026-04-01 | 브랜치: step6-motion-jig-test

결론: 영점 초기화 시 setzcur(1차)가 수평이 아닌 위치에서 실행되어 OFFSET 캘리브레이션이 틀어짐 → 각도 비례 오차 누적.
setzcur(1차) 제거 후 사양서 SPEC(±0.2, ±0.5)으로도 PASS.

1. 문제 현상

항목어제 (0331)사양서 SPEC결과
+20도 오차0.093±0.2OK
-20도 오차0.195±0.2OK (경계)
+45도 오차0.526±0.5NG
-45도 오차0.837±0.5NG

이대리 20개 제품 데이터에서는 45도 부근 avg 0.07~0.14 → 우리만 5~9배 큰 오차

2. 원인

근본 원인: 영점 초기화에서 setzcur(1차)가 FineAdjust 전에 실행됨

이로 인해 OFFSET 캘리브레이션이 수평이 아닌 위치에서 실행 → VL 센서 기준점 틀어짐 → 각도 비례 오차 누적

2.1 어제 영점 시퀀스 (버그)

1250 step 이동 (대략 수평, 하지만 수도 벗어남)
    ↓
setzcur (1차) ← 현재 위치를 0도로 강제 리셋
    ↓
FineAdjust(0도) ← 자이로가 이미 0 → 즉시 수렴 (실제 수평 아님!)
    ↓
setzcur (2차)
    ↓
OFFSET ← 기울어진 상태에서 VL 센서 캘리브레이션 (틀어짐!)

2.2 오늘 영점 시퀀스 (수정)

1250 step 이동 (대략 수평)
    ↓
FineAdjust(0도) ← 자이로 실제값으로 수평 찾기 (53도 → 0.002도)
    ↓
setzcur ← 실제 수평 위치에서 기준점 설정
    ↓
OFFSET ← 실제 수평에서 VL 센서 캘리브레이션 (정확!)

2.3 왜 각도가 커질수록 오차가 커졌나

VL10은 가속도 기반 기울기 센서입니다.
OFFSET 기준점이 틀어지면 arcsin 비선형성 때문에 각도에 비례하여 오차가 누적됩니다.

예: OFFSET이 3도 틀어졌다면:
측정 각도예상 오차
20도~0.1~0.2도
45도~0.5~0.8도
90도~1.0도+
이 패턴이 어제 측정 결과와 정확히 일치합니다.

2.4 이전 잘못된 결론

어제 CODE_오차분석 문서에서 "VL 센서의 가속도 기반 측정 물리적 한계"로 결론 → 틀렸음

실제 원인은 센서 특성이 아니라 OFFSET 캘리브레이션 위치 오류.
이대리 20개 제품 데이터에서 45도 avg 0.07~0.14로 충분히 스펙인이었고, 오늘 수정 후 동일 수준 달성.

4. 추가 발견 사항

4.1 자이로 setzcur 비휘발성 저장

발견: 어제 수동 테스트에서 기울어진 상태로 setzcur → 비휘발성 메모리에 저장 → 오늘 수평에서 -50도 출력

결론: setzfac는 코드에 넣지 않음 — 비정상 상황에서만 수동 복구

4.2 #5 → #6 연속 동작

변경: #6 VIBE_Y에서 pre_move_angle: 45 제거
이유: #5 기울기 검사가 -20 → -45 → +20 → +45도 순서 → 마지막 45도에서 바로 90도로 이동
결과: 불필요한 45도 이동 제거, 검사 시간 단축

6. 교훈

  1. 영점 순서가 중요: 자이로 기준점 리셋(setzcur)은 반드시 FineAdjust 후에 실행
  2. OFFSET은 정확한 수평에서: VL 센서 캘리브레이션 기준점이 틀어지면 각도 비례 오차 누적
  3. "센서 특성" 결론은 위험: 실제 원인은 소프트웨어 시퀀스 오류였음. 이대리 데이터와 비교해서 발견
  4. 참조 코드(이대리) 분석의 중요성: 이대리 코드에 setzcur가 없었던 것이 핵심 단서
