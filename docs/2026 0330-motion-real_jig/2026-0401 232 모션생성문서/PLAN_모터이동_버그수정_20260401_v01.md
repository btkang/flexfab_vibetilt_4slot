# PLAN: 모터 이동 버그 수정

작성일: 2026-04-01 | 브랜치: step6-motion-jig-test

## 발단

어제(0331) 마지막 테스트 로그에서 Y축 진동 측정(MOTION_VIBE_Y_232) 시
pre_move 45도 이동 후 FineAdjust가 모터를 움직이지 못하고 무한 반복하는 버그 발생.

```
PMD071ML-400  → pmd0011 (정상)
  ↓ 2초 후
PMD071ML-176  → pmd5011 (에러: 모터 busy)
PMD061ML177   → pmd5011 × 15회 반복 (모터 안 움직임)
자이로: 20.03도에서 변화 없음
```

## 원인 분석

### 버그 1: pre_move 후 이동 완료 대기 부족
- **위치**: MotionJig.cs line 496-497
- **현상**: `MoveSteps(400 step)` 후 `Thread.Sleep(1000)` → 1초 대기
- **문제**: 400 step = 45도 이동에 수 초 소요. 1초 후 FineAdjust 진입 시 모터 아직 이동 중
- **증거**: FineAdjust 시작 시 current=20.084 (45도가 아닌 20도)

### 버그 2: FineAdjust에서 MoveSteps 실패 무시
- **위치**: MotionJig.cs line 657
- **현상**: `MoveSteps(emio, step, log)` 반환값을 사용하지 않음
- **문제**: pmd5011 에러 → MoveSteps return false → FineAdjust가 무시하고 다음 step 시도
- **결과**: 모터 안 움직이는 상태에서 수십 회 재시도 (각 10초 timeout = 수 분 낭비)

### 버그 3: pmd5011 에러 처리 미흡
- **위치**: MotionJig.cs line 914-917 (EmioRecvUntil)
- **현상**: `pmd5011`을 `continue`로 무시하고 pmd0011만 계속 대기
- **문제**: busy 상태 감지/재시도 로직 없음. pmd5011이 오면 이미 이전 이동이 안 끝난 것

## 수정 계획

### 수정 1: MoveSteps 이동 완료 대기 개선
```
변경 전: EmioRecvUntil("pmd0011", 10000)  — 고정 10초
변경 후: EmioRecvUntil("pmd0011", waitMs) — step 수에 비례
  - 계산: |steps| × 20ms + 5000ms (기본 마진)
  - 최소 5초, 최대 30초
```

### 수정 2: FineAdjust에서 MoveSteps 실패 시 중단
```
변경 전: MoveSteps(emio, step, log);           // 반환값 무시
변경 후: if (!MoveSteps(emio, step, log))       // 실패 시 재시도 또는 중단
         {
             log("[FINE] 모터 이동 실패, 재시도...");
             Thread.Sleep(2000);  // busy 해소 대기
             if (!MoveSteps(emio, step, log))
                 return false;   // 2회 연속 실패 시 중단
         }
```

### 수정 3: pre_move 후 이동 대기 시간 step 비례 계산
```
변경 전: MoveSteps(emio, preSteps, log);
         Thread.Sleep(1000);
변경 후: MoveSteps(emio, preSteps, log);  // 내부에서 pmd0011 대기 포함
         Thread.Sleep(500);                // 안정화 대기만
```
→ MoveSteps 자체가 pmd0011을 받을 때까지 대기하므로, 추가 Sleep은 안정화용 최소한만.
