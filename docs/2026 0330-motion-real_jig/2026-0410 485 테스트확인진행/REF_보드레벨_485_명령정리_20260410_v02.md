## 2. 485 TX 명령어 전체 목록

모든 명령어는 `<명령,주소[,파라미터]>` 형식. **주소는 전부 `,1`**

| 명령어 | 사용 항목 | 용도 |
|--------|-----------|------|
| `<VER,1>` | COMM_485, FWVER_485 | FW 버전 조회 |
| `<SENTEMP,1>` | SENTEMP_485 | 센서 온도 조회 |
| `<MODE,1,0>` | APPCFG_485, VIBE_485, TILT | 모드 0 (기본모드) 설정/복귀 |
| `<MODE,1,2>` | VIBE_485 | 모드 2 (진동모드) 설정 |
| `<MODE,1,6>` | TILT_X_485, TILT_Y_485 | 모드 6 (기울기모드) 설정 |
| `<ATIM,1,10>` | APPCFG_485 | 자동전송 간격 10ms 설정 |
| `<ATIM,1,0>` | VIBE_485, TILT | 자동전송 비활성화 (폴링 모드) |
| `<SAM,1,10>` | APPCFG_485, VIBE_485, TILT | 샘플링 간격 10ms 설정 |
| `<APPCFG,1>` | APPCFG_485 | 현재 Config 조회 |
| `<START,1>` | VIBE_485, TILT | 측정 시작 |
| `<STOP,1>` | VIBE_485, TILT | 측정 중지 |
| `<GAC,1>` | VIBE_485 | 진동 데이터 폴링 (while 루프) |
| `<AN,1>` | TILT_X_485, TILT_Y_485 | 기울기 데이터 폴링 (while 루프) |

고유 명령어: **13개** (파라미터 조합 포함)

## 4. 다중 노드 통신 ID 관리 규칙 (PDF 3.4)

### Common ID
- 공통 ID = **0** — 모든 디바이스에 일괄 명령 전송
- 각 디바이스는 개별 ID 기준으로 응답

```
예) 모든 디바이스 저장
TX: <APPCFG,0,SAVE>
RX: [APPCFG,0,1,SAVE] [APPCFG,0,2,SAVE] [APPCFG,0,3,SAVE] ...

예) 각 디바이스 Baudrate 확인
TX: <BAUD,0>
RX: [BAUD,0,1,921600] [BAUD,0,2,115200] [BAUD,0,3,921600] ...
```

### Start ID (SID)
- 다수 디바이스 간 송신 순서 결정 기준 ID
- SID 디바이스가 먼저 송신, 직전 ID 송신 완료 감지 후 순차 송신 → 충돌 방지
- 동일 인터페이스에서 SID 기준 **연속된 ID만** 사용 가능
  - 허용: SID=5 → ID 5, 6, 7
  - 비허용: SID=5 → ID 5, 7, 8 (연속되지 않음)

## 5. Return Value 코드 (PDF 3.3)

패킷 수신/동작의 실패 여부를 나타냄

| RV | 설명 |
|----|------|
| 0 | 정상 수신 및 동작 |
| 1 | 패킷을 수신할 수 없는 상태 |
| 2 | 유효하지 않은 패킷 (파라미터 미작성 등) |
| 3 | CRC가 일치하지 않음 |
| 4 | 알 수 없는 명령어 |
| 5 | 레지스터에 쓴 데이터가 맞지 않음 |
| 6 | 드라이버 접근 실패 |
| 7 | 레지스터 쓰기 실패 |
| 8 | 레지스터 읽기 실패 |
| 9 | 파라미터 값의 범위가 벗어남 |

## 8. MODE 명령 사양 (PDF 4.1.3)

### 모드 설정

```
명령: <MODE,ID,X>
응답: [MODE,RV,ID,X]

예시:
TX: <MODE,1,01>
RX: [MODE,0,1,01]
```

### 모드 확인

```
명령: <MODE,ID>
응답: [MODE,RV,ID,X]

예시:
TX: <MODE,1>
RX: [MODE,0,1,01]
```

### 모드 목록

| X | 모드명 |
|---|--------|
| 00 | Default (없음) |
| 01 | Raw Accel Gyro Data |
| 02 | G scale Accel Data (GAC) |
| 03 | Rms Accel Data |
| 04 | Threshold Over/Under Accel Data |
| 05 | Max, Min, Avg Accel Data |
| 06 | Angle Data (AN) |
| 07 | Threshold Over/Under Angle Data |
| 08 | Max, Min, Average Angle Data |
| 09 | G scale Accel, Angle Data |

- START 시 설정된 전송 주기(SAM)마다 데이터 연속 출력
- BIN 명령으로 ASCII/Binary 출력 형식 선택 가능

## 9. APPCFG 명령 사양 (PDF 4.2.1)

### Config 확인

```
확인:  <APPCFG,1>
응답:  [APPCFG,0,1/MODE/ATIM/SAM/STD/BAUD]
예시:  [APPCFG,0,1/00/0/10/1/115200]
                      ^^-- ATIM 기본값 = 0 (개발자 확인)
                         ^^-- SAM 기본값 = 10

저장:  <APPCFG,1,SAVE>
응답:  [APPCFG,0,1,SAVE]
```

- `<APPCFG>` 파라미터 외 모든 설정이 저장됨
- 전원 차단 시 저장하지 않은 설정은 초기화

## 10. OFFSET 명령 사양 (PDF 4.2.4)

### Offset 설정

```
명령: <OFFSET,ID,X>
응답: [OFFSET,RV,ID,X]

예시:
TX: <OFFSET,1,1>
RX: [OFFSET,0,1,1]
```

| 파라미터 | 범위 | 기본값 | 비고 |
|---------|------|--------|------|
| X | 0 ~ 1 | 0 (사용 안함) | 1: 현재 설치면 기준 캘리브레이션 |

- OFFSET=1 설정 시 현재 Z축 가속도를 1G로, X/Y축 가속도 및 기울기를 0으로 설정
- OFFSET 전후 비교:
  - `<OFFSET,0>` → `[GAC,0,-0.11,-0.19,0.99,1.01]` / `[AN,0,-10.90,6.41]`
  - `<OFFSET,1>` → `[GAC,0,0.00,0.00,1.00,0.58]` / `[AN,0,0.00,0.00]`

### Offset 확인

```
명령: <OFFSET,ID>
응답: [OFFSET,RV,ID,X]

예시:
TX: <OFFSET,1>
RX: [OFFSET,0,1,1]
```

## 12. ATIM 명령 사양 (PDF 4.2.9)

### 자동 출력 시간 설정

```
명령: <ATIM,ID,X>
응답: [ATIM,RV,ID,X]

예시:
TX: <ATIM,1,3600>
RX: [ATIM,0,1,3600]
```

| 파라미터 | 범위 | PDF 기본값 | 실제 제품 기본값 | 비고 |
|---------|------|-----------|----------------|------|
| X | 0 ~ 100000000 초 | 3600 (1시간) | **0** (제한 없음) | 자동 출력 모드의 시간 제한 |

- 예) 3600 → 1시간 동안 데이터 출력 후 측정 종료
- **ATIM=0**: 시간 제한 없음, STOP 명령까지 계속 출력
- 실제 VL20 V2.0.2.2 제품은 ATIM=0으로 출하 (개발팀 확인 2026-04-10)

### 자동 출력 시간 확인

```
명령: <ATIM,ID>
응답: [ATIM,RV,ID,X]

예시:
TX: <ATIM,1>
RX: [ATIM,0,1,0]
```

## 13. SAM 명령 사양 (PDF 4.2.6)

### 자동 출력 주기 설정

```
설정:  <SAM,ID,X>
응답:  [SAM,RV,ID,X]
예시:  <SAM,1,10>  →  [SAM,0,1,10]

확인:  <SAM,ID>
응답:  [SAM,RV,ID,X]
예시:  <SAM,1>  →  [SAM,0,1,10]
```

| 파라미터 | 범위 | 기본값 | 비고 |
|---------|------|--------|------|
| X (주기) | 1 ~ 10000 ms | **10** | 자동 출력 모드에서 X ms 마다 데이터 출력 |

- Baudrate에 따라 최소 전송 주기 제한 있음:

| Baudrate | 최소 설정 가능 주기(ms) |
|---------|----------------------|
| 9600 | 63 |
| 19200 | 32 |
| 38400 | 16 |
| 57600 | 11 |
| **115200** | **6** |
| 230400 | 3 |
| 460800 | 1 |

> **115200 baud에서 SAM 최소값 = 6ms. SAM=1(1ms)은 불가 → START 에러9 원인**

## 14. GAC 응답 형식 (PDF 4.1.3.2 Output Mode 2)

### 5.1 스트리밍 응답 (MODE 02 → START 후 자동 출력)

```
형식: [GAC,ID,Accel_X,Accel_Y,Accel_Z,Rms_3_axis]  → 6필드
예시: [GAC,1,0.12,0.03,1.00,1.01]
```

| 필드 | 설명 | 범위 |
|------|------|------|
| ID | 디바이스 주소 | 1~ |
| Accel_X | X축 중력가속도(G) | -4.00 ~ 4.00 |
| Accel_Y | Y축 중력가속도(G) | -4.00 ~ 4.00 |
| Accel_Z | Z축 중력가속도(G) | -4.00 ~ 4.00 |
| Rms_3_axis | 3축 RMS | 0.00 ~ 4.00 |

### 5.2 폴링 응답 (`<GAC,ID>` 단건 쿼리)

```
형식: [GAC,RV,ID,Accel_X,Accel_Y,Accel_Z,Rms_3_axis]  → 7필드
예시: [GAC,0,1,0.12,0.03,1.00,1.01]
```

- 스트리밍 대비 **RV(Return Value) 필드가 추가**됨 (RV=0: 정상)

### 5.3 엑셀 사양서 오류

| | PDF 사양서 | 엑셀 보드레벨 VL20 | 엑셀 모션지그 VL20 |
|---|---|---|---|
| 스트리밍 | `[GAC,1,X,Y,Z,RMS]` 6필드 | `[GAC,1,0,0,0.58]` ❌ 5필드 | `[GAC,1,X,Y,Z,RMS]` ✅ |
| 폴링 | `[GAC,0,1,X,Y,Z,RMS]` 7필드 | 미기재 | 미기재 |

- 보드레벨 엑셀 예시 `[GAC,1,0,0,0.58]`은 VL10(232) 5필드를 복사한 오류

## 16. 양산 vs 테스트 차이

| 항목 | 양산 (`_485.json`) | 테스트 (`_485_test.json`) |
|------|-------------------|--------------------------|
| show_log | false | true |
| repeat_all_count | 1 | 2 |
| DPM_24V | 23.28~24.72V | 25.0~26.0V |
| DPM_3V3 | 2.0~3.5V | 5.0~6.0V |
| DPM_CURR | -1.0~500.0mA | 900.0~1000.0mA |
| DPM retry | 1회 | 2회 |

485 명령어 자체는 양산/테스트 **완전 동일**.
