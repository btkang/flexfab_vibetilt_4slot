7.보드검사 COMM_485 통신검사 간헐 FAIL (v0.6.9 후보, 2026-04-23 추가)
 - 증상: 미니피씨 VL20 보드검사 (RS-485) 양산 사이클 중 통신검사 ~30% FAIL
   (예: 7회 중 2회 — 00002, 00006 cycle에서 [VER] 응답 명령 불일치)
 - 잔류 패킷 형식: [AN,1,-0.85,0.40] (MODE,6 = TILT streaming)
 - 근본 원인: TILT_X/Y_485 검사 종료 시 finally 블록에서 MODE,1,0 후 buffer 정리 누락
   → 보드의 MODE,6 streaming이 완전히 멈추기 전 다음 사이클 시작
   → COMM_485의 ClearCommBuffer (1초만 정리)가 잔류 [AN,...] 패킷 못 비움
   → VER 응답 파서가 마지막 [AN,...]을 응답으로 잘못 인식
 - 232는 영향 없음 (full-duplex라 STOP이 line 충돌 없이 전달됨)
 - 485만 발생 (half-duplex 특성으로 boards's TX 중에 호스트 STOP이 깨질 수 있음)
 - 수정 방향:
   A. ff_vibetilt/VibeTilt.cs:498 ClearCommBuffer 강화
      - 시작 시 <STOP,1> 강제 송신 (응답 무시)
      - maxAttempts 10 → 30 (1초 → 3초)
      - 연속 빈 응답 2 → 3 (안전 마진)
      - silence detection (ff_pim/pim.cs:820 ClearUartBufferSafe 패턴 차용)
   B. (선택) ff_vibetilt/VibeTilt.cs:2260~2310 TILT_Internal finally 블록에
      MODE,1,0 후 ClearCommBuffer 추가 호출
 - 양산 임시 대응: "통신검사 FAIL 시 검사 정지 → 다시 시작" 운영 가이드로 커버
 - 시간: 코드 수정 30분 + 빌드 30분 + 미니피씨 검증 (10회 연속) 30분 = 1.5시간
