# PLAN: 485 워크스페이스 수평전개 (VL20)

## 날짜: 2026-04-08
## 상태: 검토 대기

## 배경
- 232 듀얼 워크스페이스 250회 ALL PASS 안정화 완료
- 지금 485를 만들어야 이후 232 수정 시 485도 같이 반영 가능
- 기존 `workspace_motion_485.json` 있지만 구버전 (듀얼 구조, 최신 파라미터 미반영)

## 사양서 확인 결과 (CSV 기능검사탭)

### 232 vs 485 명령어 차이

| 기능 | VL10 (232) | VL20 (485) |
|------|-----------|-----------|
| FW 버전 | `<VER>` | `<VER,1>` |
| UID 설정 | `<UID,VL1-yyyyy>` | `<UID,1,VL2-yyyyy>` |
| Calibration | `<OFFSET,1>` → `[OFFSET,0,1]` | `<OFFSET,1,1>` → `[OFFSET,0,1,1]` |
| 파라미터 저장 | `<APPCFG,SAVE>` → `[APPCFG,0,SAVE]` | `<APPCFG,1,SAVE>` → `[APPCFG,0,1,SAVE]` |
| MODE 설정 | `<MODE,06>` → `[MODE,0,06]` | `<MODE,1,06>` → `[MODE,0,1,06]` |
| START | `<START>` → `[START,0]` | `<START,1>` → `[START,0,1]` |
| STOP | `<STOP>` → `[STOP,0]` | `<STOP,1>` → `[STOP,0,1]` |
| GAC 쿼리 | `<GAC>` → `[GAC,X,Y,Z,RMS]` | `<GAC,1>` → `[GAC,1,X,Y,Z,RMS]` |
| AN 스트리밍 | `[AN,X,Y]` | `[AN,1,X,Y]` |

### SPEC (동일)
- TILT: ±20도=±0.2, ±45도=±0.5
- VIBE: GAC 0.99~1.01
- OFFSET 검증: AN ±0.05

### 485 특성
- baudrate: 115200 (보드레벨과 동일, 460800→115200 확정)
- 단일 포트 (COM3) — 232는 X:COM13, Y:COM14 듀얼
- 자이로: COM6 (232는 COM15)

## 구현 방식
232 듀얼 JSON (`longrun_motion_232_dual.json`)을 복사 후 485용으로 변경.
**코드 변경 없음** — MotionJig.cs의 `isRs485` 분기가 이미 485 명령어 처리함.

## 변경 상세

### libraries 변경

| 232 | 485 |
|-----|-----|
| `uart_232` COM13 115200 | `uart_485` COM3 115200 |
| `uart_232_y` COM14 115200 | **제거** (단일 포트) |
| `uart_gyro` COM15 | `uart_gyro` COM6 |
| ctsp commlib: uart_232 | ctsp commlib: uart_485 |
| vibetilt config: uart_232 | vibetilt config: uart_485 |

### procs 변경 (13개 항목)

| # | 232 ID | 485 ID | 명령어 변경 | 기타 |
|---|--------|--------|-----------|------|
| 0 | FWVER_232 `<VER>` | FWVER_485 `<VER,1>` | 명령 | - |
| 1 | MOTION_ZERO_232 (X축) | MOTION_ZERO_485 | - | ID만 |
| 2 | OFFSET_232 (X축) | OFFSET_485 | `<OFFSET,1,1>` / `[OFFSET,0,1,1]` | 명령+응답 |
| 3 | APPCFG_SAVE_232 (X축) | APPCFG_SAVE_485 | `<APPCFG,1,SAVE>` / `[APPCFG,0,1,SAVE]` | 명령+응답 |
| 4 | MOTION_TILT_X_232 | MOTION_TILT_X_485 | - | ID만 |
| 5 | MOTION_VIBE_Y_232 | MOTION_VIBE_Y_485 | - | ID만 |
| 0-Y | FWVER_232 (Y축) uart_id=uart_232_y | FWVER_485 `<VER,1>` | 명령 | **uart_id 제거** |
| 7 | MOTION_ZERO_232 (Y축) | MOTION_ZERO_485 | - | ID만 |
| 8 | OFFSET_232 (Y축) uart_id=uart_232_y | OFFSET_485 | 명령+응답 | **uart_id 제거** |
| 9 | APPCFG_SAVE_232 (Y축) uart_id=uart_232_y | APPCFG_SAVE_485 | 명령+응답 | **uart_id 제거** |
| 12 | MOTION_VIBE_Z_232 uart_id=uart_232_y | MOTION_VIBE_Z_485 | - | **uart_id 제거** |
| 10 | MOTION_TILT_Y_232 uart_id=uart_232_y | MOTION_TILT_Y_485 | - | **uart_id 제거** |
| 11 | MOTION_VIBE_X_232 uart_id=uart_232_y | MOTION_VIBE_X_485 | - | **uart_id 제거** |

### 485 듀얼 특이사항
- 485는 단일 포트 → Y축 항목의 `uart_id: uart_232_y` 전부 제거
- Y축 전환 시 제품 교체 필요 → operator_prompt 추가 (#7 Y축 영점에)
- 232에서 Y축은 uart_id로 COM14 지정했지만, 485는 같은 포트이므로 불필요
