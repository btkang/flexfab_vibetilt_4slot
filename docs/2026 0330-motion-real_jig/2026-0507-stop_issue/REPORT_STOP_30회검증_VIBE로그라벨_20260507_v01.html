3. 코드 수정 — VibeTilt.cs SendCommand

VibeTilt.cs L428-491 (이전 0.7.0 변경분, 검증으로 확정):

private bool SendCommand(...) {
    // VL20 485 STOP: PDF 사양 — 송수신 충돌 대비 N회 반복 + ret(0) early-exit
    if (isRs485Stop) {
        int repeatCount = GetParamInt(param, "stop_repeat_count", 10);
        int intervalMs  = GetParamInt(param, "stop_interval_ms", 10);
        for (int i = 0; i < repeatCount; i++) {
            comm.Send(...);
            var resp = comm.Recv(timeout=30, "line");
            if (resp.Contains("[STOP,0,")) { gotRet0 = true; break; }
            Sleep(intervalMs);
        }
        return true;  // 무응답이어도 보드는 정지 상태 (사양 준수)
    }
}

5. 무응답 케이스의 후속 명령 검증

STOP x10/10 (무응답) 직후 후속 명령이 정상 응답을 받았는지 로그에서 추적:

13:41:21 TX: <STOP,1> (485 stop x10/10)         ← 무응답
13:41:22 TX: <MODE,1,0>
13:41:22 RX: [MODE,0,1,00]                      ← 정상 응답 ✓
13:41:23 진동검사 RS-485 -> OK

해석: 응답이 안 와도 보드는 STOP을 받아 정지 상태. PC 측 통신 충돌로 응답 패킷만 손실된 것이고 보드 동작에는 지장 없음. 사양 그대로의 동작.

6. 별개 발견 — VIBE 로그 라벨 표시 버그

6.1 문제

SN=00024에서 진동 X 측정값 0.54G가 1축으로 판정되어 PASS 처리됐지만, 로그에는 "0축:-0.3~0.3"으로 잘못 표시됨.

출력표시정합?
JSON진동 X(1축) value=0.54 min=0.5 max=1.5 result=OK정확
로그[VIBE] PASS X=0.54[0축:-0.3~0.3]하드코딩 라벨

6.2 원인

VibeTilt.cs L1843, L1925의 logAction 호출에서 X/Y/Z 축 라벨이 항상 "0축/0축/1축"으로 하드코딩되어 있었음. 판정 로직(L365 Math.Abs(v) > 0.5)은 동적으로 1축/0축을 결정하는데 로그만 정적.

6.3 수정

// VibeTilt.cs L1843 (PASS 로그) / L1925 (FAIL 로그)
// 측정값 |v|>0.5 → 1축(중력축), 그 외 → 0축. 판정 로직(L365)과 동일 분기로 라벨/spec 매핑
string xLabel = Math.Abs(x) > 0.5 ? "1축" : "0축";
string yLabel = Math.Abs(y) > 0.5 ? "1축" : "0축";
string zLabel = Math.Abs(z) > 0.5 ? "1축" : "0축";
double xMin = Math.Abs(x) > 0.5 ? oneMin : zeroMin, xMax = ...;
logAction($"[VIBE] PASS X={x:F2}[{xLabel}:{xMin}~{xMax}] Y={y:F2}[{yLabel}:{yMin}~{yMax}] Z={z:F2}[{zLabel}:{zMin}~{zMax}] RMS=...");
