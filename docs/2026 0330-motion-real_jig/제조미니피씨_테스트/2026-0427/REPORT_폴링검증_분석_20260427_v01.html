1. 배경 및 목적

문제 발생 (2026-04-24): 미니PC 양산 검증 중 보드 RS-485 기울기검사에서 TILT_X 10초 timeout FAIL → 재검사 PASS 사례 발견.

1.1 진짜 원인 (04-24 로그 분석)

S/N 00011의 TILT_X 검사 시 START 후 11초 동안 받은 데이터 60줄이 모두 [GAC,1,...] (가속도 모드 streaming 잔류)이고 [AN,1,...] (기울기 데이터)는 0개. 즉 이전 VIBE 검사 종료 시 STOP이 깨져 GAC streaming이 잔류됐고, MODE,1,6 명령도 보드가 처리 못 함.

1.2 검증 가설

폴링 모드(ATIM,1,0 자동전송 OFF + GAC,1/AN,1 단발 폴링)로 변경하면 streaming 자체가 없으니 잔류 패킷 발생 불가 → 100% 차단 기대.

6. 폴링 한계 분석

6.1 보드가 streaming 모드 갇히는 메커니즘

  • RS-485 half-duplex: 동일 라인을 송수신 양방향으로 사용
  • 보드가 GAC streaming 송신 중에 호스트 명령(STOP, ATIM 등) 송신 시도 → 물리적 충돌
  • 호스트 명령 깨지면 보드는 명령 못 받고 streaming 계속
  • 응답 라인을 보드가 잡고 있어 호스트 명령이 닿지 않음

6.2 폴링이 일부 효과 있는 이유

  • 폴링 모드의 ATIM,1,0이 처음에는 전달되어 자동전송 OFF
  • 그 상태에서 GAC,1/AN,1 단발 폴링 → 보드 단발 응답
  • STOP 시 충돌 발생해도 보드는 어차피 자동 송신 안 함 (잔류 0)

6.3 폴링이 100% 차단 못 하는 이유

  • START 명령 자체가 보드의 측정 모드를 켬
  • 일부 케이스에서 보드 펌웨어가 ATIM,1,0 무시하고 streaming 시작
  • 한번 streaming 시작되면 위 메커니즘으로 빠져나오기 어려움
