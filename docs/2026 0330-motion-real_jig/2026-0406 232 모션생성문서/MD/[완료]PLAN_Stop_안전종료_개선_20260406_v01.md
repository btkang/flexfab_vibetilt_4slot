# [테스트중] PLAN: Stop 안전 종료 개선

## 날짜: 2026-04-06
## 상태: 구현 완료, 테스트 필요

## Context
Stop 버튼 누르면 프로세스가 좀비 상태로 남아 빌드 불가 → 재부팅 필요했음.
원인: Stop 시 CancellationToken만 설정되고, 실행 중인 MotionJig 내부 블로킹 함수
(EmioRecvUntil 최대 15초, InitMotionZero 최대 20초 등)가 timeout까지 대기.

## 핵심 문제
- `buttonStop_Click`에서 `cancellationTokenSource.Cancel()`만 호출
- MotionJig.End() (`_stopRequested=true`)는 finally에서만 호출 → 이미 늦음
- EmioRecvUntil, VlRecv, Thread.Sleep 내부에서 _stopRequested 미체크

## 수정 내용 (2개 파일)

### 1. FlexfabForm.cs (flexfab_mini)

**(A) buttonStop_Click에서 즉시 End() 호출**
- Cancel() 직후 libraries의 모든 IProcess에 End() 호출
- → _stopRequested=true 즉시 설정

**(B) repeatDelay Sleep 분할**
- Thread.Sleep(repeatDelay) → 200ms 단위 분할 + token.IsCancellationRequested 체크

### 2. MotionJig.cs (ff_vibetilt)

**(A) SleepWithStop 헬퍼 추가**
- 100ms 단위로 _stopRequested 체크하며 Sleep

**(B) 블로킹 함수에 _stopRequested 체크 추가**
- EmioRecvUntil 루프
- VlRecv 루프
- InitMotionZero 폴링 대기 (20초 루프)
- RunVibeMeasure GAC 루프

**(C) static 제거**
- EmioRecvUntil, VlRecv, MoveSteps, StartVlStreaming, StopVlStreaming
- _stopRequested 인스턴스 필드 접근을 위해

**(D) 긴 Thread.Sleep → SleepWithStop 교체 (10곳, 500ms 이상)**
