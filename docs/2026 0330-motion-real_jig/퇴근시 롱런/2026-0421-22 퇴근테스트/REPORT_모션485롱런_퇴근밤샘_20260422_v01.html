7. 후속 조치 (제안)

7.1 Windows/하드웨어 측 (우선순위 1 — 실제 범인 라인)

  1. USB-Serial 컨버터 제조사/드라이버 확인: 장치관리자 → COM12 속성 → 드라이버 공급자/버전. FTDI / Prolific / CH340 계열별로 알려진 장시간 프리즈 이슈 존재. 최신 드라이버로 교체.
  2. USB 선택적 절전 외 추가 설정: 장치관리자 → 해당 USB Root Hub → 전원 관리 → "전력을 절약하기 위해 이 장치를 끌 수 있음" 체크 해제 (각 허브 인스턴스마다 별도 설정).
  3. USB 허브 교체 / 직결 테스트: Y축 USB-Serial 컨버터를 미니PC 본체 USB 포트에 직결로 연결하고 동일 롱런 재현.
  4. COM12 USB 케이블 품질/길이 확인 — 1.5m 이상이거나 저품질 케이블이면 교체.

7.2 SW 레벨 보강 (우선순위 2 — 양산에서 반드시 필요)

  • COM 포트 재오픈 워치독: #0 통신검사에서 Y축 NG 감지 시, uart_485_y 커넥션을 Close → Reopen → 재시도 (1~2회). 이번 케이스가 드라이버 핸들 락업이므로 포트 Close/Reopen만으로는 풀리지 않을 가능성도 있어, 플랜 B도 같이 준비.
  • 플랜 B: Windows COM 포트 리셋 호출: Reopen 실패 시 devcon restart 또는 pnputil /restart-device로 해당 USB-Serial 장치 자체를 OS 레벨 재기동. (실질적으로 드라이버 락 해제에는 이 방법이 필요)
  • 연속 FAIL 임계 하드 스톱: 동일 테스트가 N회(예: 3회) 연속 FAIL 시 fail_continue=true라도 롱런 중단 + 경보 + 로그 마킹. 이번처럼 56회 허공 반복하며 지그만 계속 돌리는 상황 방지.
  • 반복 간 Health-ping: 반복 사이에 X/Y 양쪽에 VER 1회 송신, 응답 없으면 다음 반복 진입 전에 복구 시도.
  • 모니터 블랙 방어: HDMI 신호 유지용 더미 플러그(HDMI EDID emulator) 장착 또는 GPU 제어판에서 "DP/HDMI 전원 저장" 옵션 Off.
