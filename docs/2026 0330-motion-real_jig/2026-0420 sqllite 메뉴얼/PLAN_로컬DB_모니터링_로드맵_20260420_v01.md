## 4. DB 설계

### 파일
- 경로: exe 옆 `flexfab.db`
- **WAL 모드** 활성 (검사/모니터링 동시 접근 허용)

### 스키마
```sql
CREATE TABLE IF NOT EXISTS results (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  serial TEXT NOT NULL,
  project TEXT NOT NULL,
  project_type TEXT,            -- motion/board
  comm_type TEXT,               -- RS-232/RS-485
  pass_fail TEXT,               -- PASS/FAIL
  inspector TEXT,
  tested_at TEXT NOT NULL,      -- ISO8601
  duration_sec INTEGER,
  mongo_id TEXT,                -- 업로드 성공 시 _id, 실패 시 NULL
  result_json TEXT              -- 원본 JSON 보존 (재업로드 + 분석용)
);
CREATE INDEX idx_tested_at ON results(tested_at);
CREATE INDEX idx_pass_fail ON results(pass_fail);
CREATE INDEX idx_serial ON results(serial);
CREATE INDEX idx_project ON results(project);
```

## 5. 작업 항목

### A. 검사 프로그램에 SQLite 추가
- **수정 파일**
  - `flexfab_mini/flexfab.csproj` — `Microsoft.Data.Sqlite` NuGet
  - `flexfab_mini/DbHelper.cs` 신규
    - `Initialize()` — 스키마 적용 + WAL 모드
    - `SerialExists(serial, project) → bool`
    - `InsertResult(...) → long id`
    - `UpdateMongoId(id, mongoId)`
  - `flexfab_mini/FlexfabForm.cs`
    - Form_Load에서 `DbHelper.Initialize()`
    - 중복 체크 교체 (라인 2000~2037: 파일 탐색 → `DbHelper.SerialExists`)
    - `SaveLog` 내 JSON 저장 직후 `InsertResult` 호출, Mongo 업로드 성공 시 `UpdateMongoId`
- **영향 범위**
  - 공통 라이브러리 수정 없음
  - workspace JSON 변경 없음
  - 기존 JSON 파일 저장 + MongoDB 업로드 로직 유지 (3중 저장)
  - 과거 Result/ 데이터 마이그레이션 없음 (이제부터만 DB 적재)

### B. 모니터링 프로그램 (신규 별도 프로젝트)
- 별도 WinForms/콘솔 프로젝트 (예: `flexfab_monitor/`)
- 읽기: `flexfab.db` (WAL 동시 접근)
- 쓰기: `mongo_id` 업데이트 (재동기화 성공 시)

#### 기능 구성 (우선순위별)

**🟢 MVP (1차, 필수)**
1. 상태 대시보드 — 오늘 PASS/FAIL 수, 불량률, 프로젝트별 집계, 시리얼 검색
2. 동기화 상태 패널 — `✅ 동기화 완료 / ⚠️ 미업로드 N건 [동기화] / 🔄 동기화 중 (k/N)`, 자동 재시도(5분), 수동 버튼
3. 로그 패널 — `[SYNC] 업로드 완료 3/3` 등
4. Raw Data 내보내기 (레벨 1 메타 CSV) — serial, project, pass_fail, tested_at, duration_sec

**🟡 2차 (편의/분석)**
5. 일별 추이 차트 (최근 7일)
6. FAIL 원인 step 빈도 분석
7. 검사자별/시간대별 통계
8. 결과 JSON 뷰어
9. Raw Data 내보내기 레벨 2 — 측정값 평면화 CSV (tilt_m20_err, vibe_y, an_x ...)

**🔵 3차 (고급)**
10. 센서값 시계열 차트 (TILT 편차/VIBE GAC 추세)
11. 불량 연속 발생 알림
12. 일일 리포트 자동 출력 (HTML/PDF)

**🟣 4차 (품질 분석, 시료 기반 스펙 산출)**
13. 시료군 선택 → 측정값 통계 산출 (30개 등)
    - 평균(μ), 표준편차(σ), 최대/최소, Cp/Cpk, μ±3σ
    - 시각화: 히스토그램 + 정규분포, 박스 플롯, 관리도
    - 스펙 제안: 현재 spec(±0.2, ±0.5 등) vs μ±3σ 비교
    - 대상 측정값: TILT ±20/±45 편차, VIBE GAC X/Y/Z, OFFSET AN
14. Raw Data 내보내기 레벨 3 (JSON 통째로, pandas 등 고급 분석용)

#### 재동기화 로직
```
[앱 시작 + 5분 주기 + 수동 버튼]
SELECT id, result_json FROM results WHERE mongo_id IS NULL ORDER BY id
→ 각 레코드 Mongo 업로드
  ├─ 성공: UPDATE mongo_id
  └─ 실패: 다음 주기 대기
```

#### 참고
- 4차(스펙 산출) UI 구현 전에도 **레벨 2 CSV 내보내기 → 엑셀 `AVERAGE`/`STDEV` → 수동 스펙 산출 가능**
- 차트 라이브러리 후보: LiveCharts / ScottPlot (WinForms 무료)

## 8. 검증 계획 (A 진행 시)
1. Debug 빌드 성공
2. 앱 실행 → `flexfab.db` 자동 생성, 스키마/인덱스 확인
3. 검사 1회 → JSON 파일 + SQLite INSERT + Mongo 업로드 모두 확인
4. 동일 시리얼 재실행 → `serial_duplicate_check` 설정대로 차단/경고
5. Mongo 연결 끊고 검사 → SQLite에 mongo_id=NULL 레코드 남는지 확인
6. Mongo 복구 후 재동기화 스크립트 실행 → mongo_id 업데이트 확인
