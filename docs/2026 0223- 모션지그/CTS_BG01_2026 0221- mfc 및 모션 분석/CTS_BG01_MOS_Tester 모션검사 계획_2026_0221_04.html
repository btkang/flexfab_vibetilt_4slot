1 배경 및 목적

기존 flexfab_VibeTilt C# 프로그램은 수동 보드레벨 검사만 지원한다. 검사원이 지그(보드)를 손으로 흔들거나 기울여서 VibeTilt 센서의 응답을 확인하는 방식이다.

MFC 프로그램(CTS_BG01_MOS_Tester)에는 EMIO 스텝모터 컨트롤러를 이용한 자동 모션 지그가 구현되어 있다. 이 모션 지그를 C# 프로그램에도 추가하여 모션검사(자동)를 지원하는 것이 목적이다.

EMIO 스텝모터 진동검사 기울기검사 신규 ff_motion 모듈

2 현재 구조 vs 추가 구조

현재 — 보드레벨 검사 (수동)

  • 모듈: ff_vibetilt.dll
  • 진동검사: 검사원이 지그를 손으로 흔듦 → GAC 측정
  • 기울기검사: 검사원이 지그를 손으로 기울임 → AN 측정
  • 통신: RS-485 UART
  • 코드 변경: 없음 (유지)

추가 — 모션검사 (자동)

  • 모듈: ff_motion.dll (신규)
  • 진동검사: EMIO 모터가 이동하는 동안 GAC 동시 측정
  • 기울기검사: EMIO 모터가 특정 각도로 이동 후 AN 측정
  • 통신: EMIO(TCP/IP) + VibeTilt(RS-485)
  • 코드: ff_motion 신규 작성

전체 모듈 관계도

flexfab_VibeTilt 솔루션
│
├── ff_common.dll        : Uart (RS-485 통신)
├── ff_vibetilt.dll      : VibeTilt 센서 검사 (수동 보드레벨) ← 변경 없음
├── ff_emio.dll          : EMIO 단독 제어 (보조용)            ← 이미 생성
└── ff_motion.dll        : EMIO + VibeTilt 동시 제어         ← 신규 작성 대상
    ├── 내부 EMIO TCP 연결 (192.168.x.x : 2233)
    └── libraries 에서 uart_485 (IComm) 참조

4 핵심 설계 문제 — 동시 실행 이슈

❌ 문제: Sequential 실행으로는 진동검사 불가

FlexFab 프레임워크는 proc를 순서대로(sequential) 실행한다.

emio.CMD (PMD 전송)
→
pmd0011 응답 대기
→
모터 이미 정지
→
VIBE_485 (GAC 읽기)
→
진동 없음 → FAIL

모터가 PMD 완료 후 정지하면, 그 다음 VIBE_485를 실행해도 진동이 없다.

✅ 해결: PMD 전송 직후 GAC 폴링 동시 시작

PMD 전송 (모터 이동 시작)
→
즉시 GAC 폴링 시작
→
이동 중 GAC 수집 → PASS
→
PMD 완료 응답 수신

모터가 이동하는 동안 가속/감속 구간에서 진동(가속도 변화)이 발생한다. 이 시간 동안 GAC를 폴링하면 진동 신호를 측정할 수 있다.

이 동작은 하나의 proc 안에서 처리해야 한다. → VIBE_MOTION 프로시저가 EMIO TCP + VibeTilt UART를 동시에 제어.

왜 진동이 발생하는가?
스텝모터가 PMD 명령으로 이동을 시작하면 보드가 가속/감속한다. 이때 보드에 탑재된 VibeTilt 센서(가속도계)가 중력 외의 가속도 성분을 측정한다. 수동 검사에서 검사원이 손으로 흔드는 것과 물리적으로 동일한 효과.

// 송신: STX(0x02) + 명령 + ETX(0x03)
private bool EmioSend(string cmd)
{
    byte[] body   = Encoding.ASCII.GetBytes(cmd);
    byte[] packet = new byte[body.Length + 2];
    packet[0]       = STX;
    packet[^1]      = ETX;
    Buffer.BlockCopy(body, 0, packet, 1, body.Length);
    _emioStream.Write(packet, 0, packet.Length);
}

7 VIBE_MOTION 상세 설계

7-1. 동작 원리

PMD071LL{n} 또는 PMD081LL{-n}으로 모터 이동 명령을 전송한 직후, PMD 완료 응답(pmd0011)을 기다리지 않고 즉시 VibeTilt UART로 GAC 명령을 전송하여 가속도 데이터를 수집한다. 모터 이동 중 발생하는 가속/감속이 GAC 신호로 나타난다.

7-2. VIBE_MOTION 처리 흐름

// Step 1: EMIO 이동 명령 전송 (응답 대기 없음)
EmioSend("PMD071LL{move_pulses}");

// Step 2: 즉시 GAC 폴링 시작 (기존 VIBE_485와 동일 로직)
DateTime deadline = DateTime.UtcNow.AddMilliseconds(overallTimeoutMs);
while (DateTime.UtcNow < deadline && !ok)
{
    // RS-485: GAC 자동 스트림 수신
    ReadStep(uart, stepReadTimeoutMs, logAction, ...);

    // GAC 파싱: [GAC,ID,X,Y,Z,RMS]
    // EvaluateVibeSample() → PASS 조건 확인
    // passStreak >= passConsecutiveCount → ok = true
}

// Step 3: EMIO 완료 응답 수신 (이미 완료되었을 수도 있음)
string emioResp = EmioRecv(remainingTimeoutMs);

// Step 4: 종료 명령 (STOP 등 필요 시)

8 TILT_MOTION 상세 설계

8-1. 동작 원리

모터가 특정 위치(각도)로 이동 완료한 뒤 정지 상태에서 AN(각도) 데이터를 읽는다. 수동 검사의 TILT_485에서 alive_check: false로 동작하는 것과 동일하지만, 이동 명령을 자동으로 먼저 보낸다는 점이 다르다.

8-2. TILT_MOTION 처리 흐름

// Step 1: EMIO 위치 이동 (완료 대기)
EmioSend("PMD071LL1500");
string moveResp = EmioRecv(move_timeout_ms);
if (!moveResp.Contains("pmd0011")) → FAIL (이동 실패)

// Step 2: 위치 안정화 대기
Thread.Sleep(settle_ms);  // 기본 500ms

// Step 3: AN 각도 읽기 (기존 TILT_485 로직)
// VibeTilt START → AN 스트림 수신 → [AN,ID,X,Y] 파싱
// x_min ≤ X ≤ x_max  AND  y_min ≤ Y ≤ y_max → PASS

// Step 4: VibeTilt STOP, MODE 0 복귀
// Step 5: EMIO 다음 위치로 이동 (또는 HOME)
