# 모션지그 검사 분리 + PASS 조건 변경 (생성)
작성일: 2026-02-24
브랜치: `step4-motion-jig`

## 1) 목적
- 모션검사 항목 1개를 `진동검사`, `기울기검사` 2개로 분리
- 보드레벨에서 검증 완료된 232/485 판정 로직을 모션검사에 동일 적용

## 2) 적용 범위
- 코드: `ff_vibetilt/MotionJig.cs`
- 모션 workspace:
- `output/Debug/net8.0-windows/workspace_motion_232.json`
- `output/Debug/net8.0-windows/workspace_motion_485.json`

## 3) 검사 항목 분리
- RS-232:
- `MOTION_VIBE_232` (모션지그 진동검사)
- `MOTION_TILT_232` (모션지그 기울기검사)
- RS-485:
- `MOTION_VIBE_485` (모션지그 진동검사)
- `MOTION_TILT_485` (모션지그 기울기검사)

## 4) PASS 조건 변경 핵심
- 기존 MotionJig의 `mstest(A/ACC/GA)` 기반 판정 경로를 축소
- 보드레벨 기준과 동일하게 아래 판정으로 적용:
- 진동: `GAC` 파싱 + `one/zero/rms` 조건
- 기울기: `AN` 파싱 + `x_min/x_max`, `y_min/y_max` 또는 `alive_check`

## 5) 232/485 공통 적용 여부
- 진동(`GAC`)
- RS-232: `[GAC,X,Y,Z,RMS]` 및 예외 프레임 대응
- RS-485: `[GAC,ID,X,Y,Z,RMS]` 대응
- 기울기(`AN`)
- RS-232: `[AN,X,Y]`
- RS-485: `[AN,ID,X,Y]`

## 6) 엑셀(수동검사 양식) 기준 반영 포인트
- 모션검사 진동 기준:
- `1: 0.9~1.1`, `0: -0.1~0.1`, `RMS: 0.5~0.65`
- 모션검사 기울기 기준:
- `X: 85~90`, `Y: -85~-90`

## 7) 구현 메모
- `MOTION_232`, `MOTION_485` 기존 진입점은 호환용 유지
- 분리 실행은 `MOTION_VIBE_*`, `MOTION_TILT_*` 사용 권장
- 모션 JSON은 단일 proc에서 2개 proc로 분리 완료

## 8) 확인 필요
- 현재 작업 환경에서 `dotnet` 미설치로 컴파일 검증 미실행
- 실기기 우선 검증 순서 권장:
1. `MOTION_VIBE_232`
2. `MOTION_TILT_232`
3. `MOTION_VIBE_485`
4. `MOTION_TILT_485`
