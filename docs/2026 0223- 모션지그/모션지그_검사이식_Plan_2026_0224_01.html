모션지그 검사 이식 Plan

브랜치: step4-motion-jig

작성일: 2026-02-24

Context

ff_vibetilt(C#)에 모션지그 검사 기능을 추가한다. - 기존 보드레벨 검사(VIBE_232, TILT_232 등)는 유지 - BG01 MFC 코드(BoardLevelMo_BG01.cpp)의 12단계 모션 시퀀스를 이식 - EMIO TCP + VL 센서 UART + 자이로 UART 3개 통신 채널 동시 운용

지그 구성 (확정)

채널 역할 프로토콜 Baudrate Sampling library key
EMIO 보드 스텝모터 구동 TCP 100.100.100.70:2233 - - tcp_emio
VL10 X축 Target 센서 RS-232 115200 10ms uart_232
VL10 Y축 Master/Ref 센서 RS-232 115200 10ms uart_232_y
VL10 Z축 UM 센서 RS-232 115200 10ms uart_232_z
VL20 X/Y/Z RS-485 버스 (주소 구분) RS-485 460800 (115200×4) 1ms uart_485
SOLAR-360-420 자이로 기준 센서 RS-232 38400 8N1 - uart_gyro

신규 파일

ff_vibetilt/MotionJig.cs

  • ModuleBase, IProcess 구현 (VibeTilt.cs와 동일 패턴)
  • 프로세스 2개 등록:
  • MOTION_232: VL10(232) 모션지그 검사
  • MOTION_485: VL20(485) 모션지그 검사

모션 시퀀스 (12단계, MFC 1:1 이식)

단계 enum 내용
0 JIG_INIT PMS×15 + PMO011 + PML확인(-500) + PMD6000+500
1 OPEN msclose/msopen 전송 → 응답으로 deviceconnected 감지
2 DEGREE_0_CHECK 자이로 setzcur + get---x → 기준각 저장
3 ANGLE_p_10_5_0 PMD071LL1500 → PML=17500 확인 (REPEAT_MOVE=2)
4 MEASURE_ANGLE_p_10_5 mstest × REPEAT_MEASURE(3) + 판정(-1,-1,0)
5 ANGLE_m_10_5_0 PMD081LL-1500 → PML=16000 확인
6 ANGLE_INIT_0 PMD081LL-1500 → PML=14500 확인 + 자이로 보정
7 pCOM_INIT msclose/msopen 재오픈
8 ANGLE_m_10_5_1 PMD081LL-1500 → PML=14500 확인
9 MEASURE_ANGLE_m_10_5 mstest × 3 + 판정(0,0,-1)
10 ANGLE_p_10_5_1 PMD071LL1500 → PML=16000 확인
11 ANGLE_INIT_1 PMD071LL1500 → PML=17500 확인
12 END 결과 반환

자이로 센서 (SOLAR-360-420)

명령 응답 형식 용도
setzcur OK 현재 위치를 기준점으로 설정
get---x ±xxx.xxx 또는 OK±xxx.xxx 현재 각도 읽기
  • 응답 파싱: OK prefix 있으면 제거 후 부호+각도값 파싱 (양쪽 대응)
  • 사용 단계: DEGREE_0_CHECK, ANGLE_INIT_0, ANGLE_INIT_1

자이로 폴링 루프 (ANGLE_INIT 핵심)

PCOM 로그에서 확인된 패턴: - 이동 명령 후 pmd0011 수신할 때마다 get---x 1회 전송 - 각도값이 ±0.005 이내로 수렴하면 루프 종료 (다음 단계 진행) - 수렴 예시: +0.425 → +0.125 → +0.097 → ... → -0.001 → 종료 - 구현: AngleInitLoop(gyro, emio, toleranceDeg=0.005, maxCycles=100)

반복 상수

  • REPEAT_MOVE_COUNT = 2 (위치 확인 재시도)
  • REPEAT_MEASURE_COUNT = 3 (측정 반복)

구현 순서

Step 1: 브랜치 생성

git checkout -b step4-motion-jig

Step 2: MotionJig.cs 골격

  • ModuleBase, IProcess 구현
  • MOTION_232 / MOTION_485 프로세스 등록
  • library key 해석: tcp_emio, uart_232/y/z, uart_485, uart_gyro

Step 3: EMIO 헬퍼

  • EmioSend(string cmd) — STX/ETX 프레임 + TCP 송신
  • EmioRecvUntil(string expected, int timeoutMs) — 목표 응답까지 루프
  • EmioFlushRecv() — 잔여 응답 버리기

Step 4: 자이로 헬퍼

  • GyroSetZero() — setzcur 송신
  • GyroGetAngle() — get---x 송신 + OK±xxx.xxx 파싱

Step 5: 12단계 상태머신

  • RunMotionSequence(emio, vl, gyro, isRs485, ...) 단일 함수
  • 각 단계 순차 실행
  • PASS → 다음 단계, FAIL → 즉시 반환

Step 6: 측정/판정

  • ParseMsTestResponse(string raw) — A/ACC/GA 파싱
  • EvaluateAngle(...) — 축별 임계값 비교 + bitmask 반환

Step 7: Workspace JSON 추가

  • MOTION_232, MOTION_485 프로세스 항목 추가
  • tcp_emio 라이브러리 항목 추가

재사용 가능한 기존 코드 (VibeTilt.cs)

함수 재사용 방법
ResolveUart() uart 키 해석 동일 패턴
ReadStep() VL 센서 응답 수신
ClearCommBuffer() 센서 버퍼 클리어

검증 방법

  1. 실기기 미연결: JIG_INIT까지 EMIO TCP 연결 확인
  2. 실기기 연결: 전체 12단계 실행 + 로그 출력 확인
  3. BG01 로그(BG01_Log__2026-02-11_09H_42M_18S.txt)와 송수신 순서 비교
  4. pmd5011 발생 시 FAIL 없이 계속 진행하는지 확인
  5. VL10(232) / VL20(485) 각각 PASS 확인

미확정 항목 (실기기 첫 연결 시 확인)

  • EMIO 실제 IP (예상: 100.100.100.70)
  • 자이로 SOLAR-360-420 baudrate
  • VL10 Y/Z축 COM 포트 번호
  • pmd5011 발생 여부 (환경마다 다를 수 있음)

BG01 vs PCOM 비교 (중요 차이)

항목 BG01 PCOM 채택
센서 닫기 <msclose> <MCLOSEC3> BG01 (기존 VibeTilt와 동일)
센서 열기 <msopen> <MOPEN7F> BG01
센서 측정 <mstest> <MTEST8D> BG01
자이로 setzcur 응답 ? OK PCOM 기준
자이로 get---x 응답 OK±xxx.xxx ±xxx.xxx 양쪽 파싱 대응
ANGLE_INIT 방식 angle_0_init() 루프 pmd0011마다 폴링 동일 (PCOM이 실증)
