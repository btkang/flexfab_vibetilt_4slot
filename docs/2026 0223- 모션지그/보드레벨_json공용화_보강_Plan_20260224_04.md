# 보드레벨 JSON 공용화 보강 Plan
작성일: 2026-02-24
브랜치: `step4-motion-jig`
진행원칙: **사용자 승인 후 코드수정**

## 1. 배경
- 보드레벨 공용화는 `workspace_parts` + `build_workspace.ps1`로 운용 중.
- 현재 확인된 리스크:
1. DPM proc ID 중복
2. 232의 `ctsp` commlib 누락 가능성
3. 합성 스크립트에 중복 검증 부재

## 2. 목표
- 공용화 구조는 유지하면서, 런타임 충돌 가능성을 제거한다.
- 빌드 단계에서 JSON 품질 문제를 조기 차단한다.

## 3. 변경 계획 (승인 후 적용)
### A. DPM proc ID 고유화
- 파일: `output/Debug/net8.0-windows/workspace_parts/dpm_common.json`
- 변경안:
- `Powertest00`(중복 3개) → `DPM_24V`, `DPM_3V3`, `DPM_CURR`

### B. 232 ctsp commlib 보강
- 파일: `output/Debug/net8.0-windows/workspace_parts/vibetilt_232.json`
- 변경안:
- `ctsp.config.commlib = "uart_232"` 명시

### C. build_workspace.ps1 중복 검증 추가
- 파일: `output/Debug/net8.0-windows/build_workspace.ps1`
- 변경안:
- `libraries.id`, `project.procs.id` 중복 검사 함수 추가
- 중복 발생 시 `throw`로 빌드 즉시 중단

## 4. 적용 순서
1. `dpm_common.json` ID 변경
2. `vibetilt_232.json` commlib 보강
3. `build_workspace.ps1` 검증 로직 추가
4. 스크립트 실행으로 `workspace.json`, `workspace_232.json` 재생성
5. 생성물의 ID 중복 재검증

## 5. 검증 항목
- [ ] `workspace_parts` 내 lib/proc ID 중복 없음
- [ ] 재생성된 `workspace.json`, `workspace_232.json`의 `project.procs.id` 중복 없음
- [ ] 232에서 `ctsp` 초기화/통신 이상 없음

## 6. 승인 요청
- 본 Plan 기준으로 코드수정(A/B/C) 진행할지 확인 요청
