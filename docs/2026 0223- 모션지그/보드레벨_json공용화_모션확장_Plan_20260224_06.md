# 보드레벨 JSON 공용화 모션확장 Plan
작성일: 2026-02-24  
브랜치: `step4-motion-jig`  
진행원칙: **사용자 승인 후 반영**

## 1. 배경
- 보드레벨은 `workspace_parts + build_workspace.ps1` 공용화 구조로 운영 중.
- 모션은 `workspace_motion_232.json`, `workspace_motion_485.json`가 별도 수동 관리되어 보드 기준 변경 시 동기화 누락 리스크가 있다.

## 2. 목표
- 보드 VIBE/TILT 기준 파라미터를 모션에서도 공용으로 사용한다.
- 모션 JSON도 `workspace_parts` 기반 합성 구조로 전환한다.
- 로그 간격 보강(`sample_log_interval_ms`) 기준을 보드/모션에 동일 적용한다.

## 3. 적용 범위
- 스크립트:
  - `output/Debug/net8.0-windows/build_workspace.ps1`
- 파트 JSON:
  - `output/Debug/net8.0-windows/workspace_parts/vibetilt_232.json`
  - `output/Debug/net8.0-windows/workspace_parts/vibetilt_485.json`
  - `output/Debug/net8.0-windows/workspace_parts/motion_232.json` (신규)
  - `output/Debug/net8.0-windows/workspace_parts/motion_485.json` (신규)
- 생성물:
  - `output/Debug/net8.0-windows/workspace.json`
  - `output/Debug/net8.0-windows/workspace_232.json`
  - `output/Debug/net8.0-windows/workspace_motion_232.json`
  - `output/Debug/net8.0-windows/workspace_motion_485.json`
- 코드:
  - `ff_vibetilt/VibeTilt.cs`
  - `ff_vibetilt/MotionJig.cs`

## 4. 변경 설계
### A. 모션 파트 템플릿화
- `workspace_motion_232/485.json`의 구조를 `workspace_parts/motion_232/485.json`로 이관.
- 모션 프로세스별 고유값(`longrun`, 장비/프로세스 ID)은 모션 파트에 유지.

### B. 보드 파라미터 자동 병합
- `build_workspace.ps1`에 모션 합성 함수 추가:
  - 보드 소스 proc 매핑:
    - 232: `VIBE_232`, `TILT_232`
    - 485: `VIBE_485`, `TILT_485`
  - 병합 규칙:
    - 기본: 보드 param
    - override: 모션 proc param (모션에서 명시한 키 우선)
- 결과 생성:
  - `workspace_motion_232.json`
  - `workspace_motion_485.json`

### C. 로그 간격 공용 보강
- 보드/모션 모두 `sample_log_interval_ms` 기본값을 500ms로 적용.
- 필요 시 proc param에서 값 오버라이드 허용.

## 5. 검증 계획
1. 정적 검증
- `build_workspace.ps1`에서 ID 중복 검사 통과
- 생성 JSON에 아래 키 존재 확인:
  - `sample_log_interval_ms: 500`
  - VIBE/TILT 공통 판정 파라미터
2. 기능 검증
- `MOTION_VIBE_232`, `MOTION_TILT_232`
- `MOTION_VIBE_485`, `MOTION_TILT_485`
- 10초 대기 구간 로그량이 기존 대비 감소했는지 확인

## 6. 리스크 및 대응
- 리스크: 보드 파라미터 변경이 모션에 즉시 영향
- 대응:
  - 모션 전용 override는 모션 파트 param에서 유지 가능
  - 긴급 시 기존 `workspace_motion_*.json` 고정 운용으로 롤백 가능

## 7. 롤백 계획
1. `build_workspace.ps1`의 모션 병합 블록 제거
2. `workspace_parts/motion_232.json`, `motion_485.json` 제거
3. 기존 고정 `workspace_motion_232.json`, `workspace_motion_485.json`로 복귀
