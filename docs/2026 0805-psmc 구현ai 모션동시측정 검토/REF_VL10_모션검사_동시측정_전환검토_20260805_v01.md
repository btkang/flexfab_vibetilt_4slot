## 2. 문제 — 지그가 같은 각도로 두 번 움직입니다

| 결합 | 기울기 각도 |
|---|---|
| **X결합** `#6 MOTION_TILT_X_232` | `−20, −45, +20, +45` |
| **Y결합** `#14 MOTION_TILT_Y_232` | `+20, +45, −20, −45` |

**순서만 다르고 각도 집합이 같습니다.**

두 보드가 이미 함께 장착되어 있으므로, 지그를 `−20°`로 기울이면 **X보드와 Y보드가 동시에 그 자세**에 있습니다. 그런데 현재는 X보드만 읽고, 나중에 Y결합 차례가 되면 **다시 `−20°`로 이동**합니다.

각도 하나를 잡는 데 드는 비용이 작지 않습니다.

```csharp
int preSteps = AngleToSteps(preMoveAngle - _currentAngle, moveAxis);
... 스텝 이동 ...
if (!FineAdjust(emio, gyro, targetAngle, axis, maxSteps, strictTol, relaxedTol, out _, log))
```

`FineAdjust`는 **자이로를 읽어가며 목표각까지 수렴시키는 폐루프**입니다. 이 과정이 각도마다 반복되고, 그게 **8회 → 4회로 줄어듭니다.**

## 3. 전환 설계

### 3.1 원칙 — "지그 동작"과 "보드 측정"을 분리

```
[지금]  한 proc = 지그 이동 + 수렴 + 기준센서 읽기 + DUT 1장 읽기 + 판정
[전환]  한 proc = 지그 이동 + 수렴 + 기준센서 읽기 1회
                   └→ DUT 1장 읽기 + 판정   (라벨 X)
                   └→ DUT 2장 읽기 + 판정   (라벨 Y)
```

**기준센서(`uart_gyro`)는 지그에 하나뿐**이고 **지그 자세를 나타냅니다.** 한 자세에서 한 번만 읽어 두 보드가 공유하면 됩니다.

### 3.2 ★부수 이득 — 판정 정확도가 올라갑니다

지금은 X보드를 잴 때의 `gyroAngle`과 Y보드를 잴 때의 `gyroAngle`이 **다른 시점, 다른 이동 후** 값입니다. 지그를 다시 움직여 수렴시킨 결과라 미세하게 다릅니다.

동시 측정하면 **두 보드가 같은 순간의 같은 기준값**으로 비교됩니다. 속도뿐 아니라 **일관성**이 좋아집니다.

### 3.3 합칠 수 있는 것 / 없는 것

| 항목 | 지그 자세 | 합치기 | 비고 |
|---|---|:--:|---|
| `MOTION_TILT_X` (#6) · `MOTION_TILT_Y` (#14) | `±20, ±45` | ✅ | **각도 집합 동일 — 최대 이득** |
| `MOTION_ZERO` (#3 · #10) | `0°` | ✅ | 둘 다 영점 |
| `OFFSET`(CAL) (#4 · #11) | `0°` | ✅ | |
| `VIBE_STILL` (#5-1) · `MOTION_VIBE_Z` (#13) | `0°` | ✅ | 0° 묶음에 포함 |
| `FWVER`·`UID`·`REFTEMP`·`RCONF`·`APPCFG_SAVE`·`APPCFG` | 각도 무관 | ✅ | `0°` 구간에서 일괄 |
| **`MOTION_VIBE_Y` (#7 `+90°`)** · **`MOTION_VIBE_X` (#15 `−90°`)** | `+90` / `−90` | ❌ | **자세가 반대 — 따로 유지** |

### 3.4 재편성 안

pSMC에서 **보드 3장 동시 측정**을 이 구조로 구현해 2026-08-05 12층에서 실기 검증했습니다. 파일: `ff_psmc/PsmcMotion.cs`

### 4.1 JSON 스키마 — 채널 병렬 배열

```jsonc

  "dut_comms":  ["uart_dut_x", "uart_dut_y", "uart_dut_z"],   // 채널 id
  "dut_labels": ["X", "Y", "Z"],                              // 라벨(같은 순서)
  "dut_test_cmd": "1<mstest>",
```

### 4.2 채널 해석 — 없는 채널은 건너뛰고 계속

```csharp
/// <summary>DUT 채널 병렬배열(dut_comms/dut_labels) 해석 → (label, comm) 목록.</summary>
private List<(string label, IComm comm)> MotDuts(IDictionary<string, object> libraries,
                                                 IDictionary<string, object> param, Action<string> log)
{
    var comms  = StrList(param, "dut_comms");
    var labels = StrList(param, "dut_labels");
    var outl = new List<(string, IComm)>();
    for (int k = 0; k < comms.Count; k++)
    {
        var c = ResolveCommById(libraries, comms[k]);
        if (c == null) { log($"[MOTION] DUT 채널 '{comms[k]}' 미해결 — 제외"); continue; }
        try { c.Connect(); } catch { }
        outl.Add((k < labels.Count ? labels[k] : comms[k], c));
    }
    return outl;
}
```

**포인트**: 채널이 하나 없어도 죽지 않고 **나머지로 계속 진행**합니다. 벤치에서 보드 1장만 꽂고 돌릴 때 유용합니다.

### 4.3 측정 루프 — 라벨별 판정, 보드별 재시도

### 4.4 ★VL10에서는 판정부를 바꿔야 합니다

pSMC는 **고정 창**(`win_{라벨}` 18값)이지만 **VL10은 기준센서 대비 편차**입니다. 구조만 가져오고 판정은 VL10 방식을 유지하십시오.

```csharp
// VL10 적용 형태 (의사코드)
//   ① 지그 이동·수렴은 루프 밖에서 1회
if (!FineAdjust(emio, gyro, targetAngle, axis, maxSteps, strictTol, relaxedTol, out _, log)) return FAIL;
if (!GyroGetAngle(gyro, log, out double gyroAngle)) return FAIL;   // ★기준센서 1회 — 두 보드 공유

//   ② 보드별 측정·판정만 루프
bool allOk = true; var details = new List<string>();
foreach (var d in VlDuts(libraries, param, log))        // dut_comms / dut_labels
{
    double specMin = GetParamDouble(param, $"spec_min_{d.label}", defaultMin);
    double specMax = GetParamDouble(param, $"spec_max_{d.label}", defaultMax);

    bool dok = false; string detail = "";
    for (int attempt = 0; attempt <= retries; attempt++)
    {
        if (!ReadVlAngle(d.comm, axisOf(d.label), out double vlAngle)) { detail = "read-fail"; continue; }

        double diff = Math.Abs(gyroAngle - vlAngle);
        if (diff >= sensorDiffError) { detail = $"센서차이 {diff:F2}"; continue; }

        double error = vlAngle - gyroAngle;             // ★기존 판정식 그대로
        dok = (error >= specMin && error <= specMax);
        detail = $"자이로={gyroAngle:F3}, VL={vlAngle:F3}, 오차={error:F3} [{specMin}~{specMax}]";
        if (dok) break;
    }
    log($"[TILT] {targetAngle:+0;-0}도 {d.label}: {detail} {(dok ? "OK" : "NG")}");
    details.Add($"{d.label}:{(dok ? "OK" : "NG")} {detail}");
    allOk &= dok;
}
```

## 5. ★확인이 필요한 것 — 축·부호 대응

**이 문서가 단정하지 않는 부분입니다. 실기로 확인해야 합니다.**

지그를 `−20°`로 기울였을 때

- **X결합 보드**가 자기 X축으로 읽는 값
- **Y결합 보드**가 자기 Y축으로 읽는 값

이 **기준센서 값과 어떤 부호 관계**인지 확인이 필요합니다. 워크스페이스의 각도 순서가

```
X결합 : −20, −45, +20, +45
Y결합 : +20, +45, −20, −45
```

로 **반대 순서**인 것이 단서일 수 있습니다. 단순한 진행 순서 차이일 수도 있고, **부호가 반대**여서일 수도 있습니다.

- **부호가 같다면** → 두 보드 모두 `error = vlAngle − gyroAngle` 그대로
- **부호가 반대라면** → 한쪽에 부호 반전이 필요(`error = (−vlAngle) − gyroAngle` 등). 라벨별 `sign` 파라미터로 처리 권장

```jsonc
"dut_labels": ["X", "Y"],
"dut_sign":   [1, -1]          // 라벨별 부호 (확인 후 확정)
```

**전환 작업 전에 이것부터 실측으로 확정하십시오.** 지그를 한 각도에 두고 두 보드를 모두 읽어 기준센서와 비교해 보면 바로 나옵니다.

## 6. 참고 — pSMC에서 함께 얻은 개선 2건 (VL10에도 적용 가능)

### 6.1 적응형 도달대기 — 검사시간 −35%

pSMC는 지그 이동을 **고정 대기**에서 **도달 확인**으로 바꿔 61.7초 → 40.9초가 되었습니다.

```
[전]  이동 명령 → 무조건 4초 대기 → 위치 확인
[후]  이동 명령 → 150ms 주기로 위치 확인 → 목표 도달 시 즉시 진행 (상한은 기존 4초 그대로)
```

**상한을 기존 고정대기값 그대로 두는 것이 핵심**입니다. 최악의 경우 소요·판정이 종전과 같으므로 **안정성이 나빠질 수 없고**, 정상일 때만 빨라집니다.

VL10의 `FineAdjust`는 이미 자이로를 보며 수렴시키는 구조라 이 방향과 맞습니다. **수렴 판정 후 불필요한 고정 대기가 남아 있다면** 같은 방식으로 줄일 수 있습니다.

### 6.2 종료 시 자세 절대 복귀

pSMC는 **상대이동 체인**이라, 중간 proc이 실패로 건너뛰어지면 이후 위치가 전부 밀렸습니다. 실제로 **"PASS인데 지그가 기울어진 채 종료"** 가 발생했습니다.

대응 2가지를 넣었습니다.

1. **검사 종료 시 실제 위치를 읽어**, 목표 자세가 아니면 **원점부터 절대 복귀** 후 재확인
2. 중간 단계가 실패해도 **모터 이동은 수행**하여 위치 체인이 끊기지 않게 함

VL10은 `_currentAngle`로 현재 각도를 추적하고 `FineAdjust`로 절대각을 잡으므로 상황이 다르지만, **검사 종료 시 0°로 확실히 복귀하는지**는 한 번 점검할 가치가 있습니다. 다음 보드를 기울어진 지그에 얹게 되면 곤란합니다.

## 7. 기대 효과 · 검증 방법

### 7.1 기대 효과

| 항목 | 지금 | 전환 후 |
|---|---|---|
| 기울기 각도 이동·수렴 | **8회** (4각도 × 2보드) | **4회** |
| 0° 정렬 | 2회 이상 | **1회** |
| 기준센서 읽기 | 보드마다 별도 | **자세당 1회 공유** |
| 판정 일관성 | 보드마다 다른 시점의 기준값 | **같은 순간 같은 기준값** |

정확한 절감 초 수는 **VL10 검사 로그(항목별 소요시간)** 를 보면 계산됩니다. `FineAdjust` 수렴에 걸리는 시간이 지배적일 것으로 봅니다.

### 7.2 검증 방법 (pSMC에서 쓴 방식)

1. **전환 전 기준 로그 확보** — 현재 구조로 3회 실행, 항목별 소요시간·판정 결과 기록
2. **전환 후 동일 조건 실행** — **판정 결과가 전 항목 동일**한지 먼저 확인. 시간은 그다음
3. **2연속 실행**으로 재현성 확인(pSMC는 편차 0.1초로 확인)
4. 문제가 있으면 **JSON 플래그 하나로 종전 동작 복귀**가 가능하도록 설계

pSMC는 모든 변경에 되돌림 스위치를 뒀습니다(`adaptive_wait`, `setup_echo_check`, `pulse_strict` 등). **판정에 영향 가는 변경일수록 스위치를 두는 편이 안전합니다.**
