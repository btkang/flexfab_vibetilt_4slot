# PLAN_ 불량보기 창(FailInfoForm) pSMC → VibeTilt 이식

- 작성: Claude / 2026-06-30 / v01

---

## 1. Context (왜)

- pSMC 프로젝트에 **FAIL 발생 시 불량 상세를 보여주는 창(FailInfoForm, "불량 내용")** 을 이미 구현해 둠.
- VibeTilt에는 결과 요약창(PassForm/FailForm, OK/FAIL 카운트만)만 있고, **어떤 항목이 왜 불량인지 보여주는 창이 없음.**
- 현장 작업자가 FAIL 시 원인(측정값 vs 기준)을 즉시 확인할 수 있게 pSMC의 검증된 창을 그대로 가져온다.
- pSMC와 VibeTilt는 **같은 `flexfab_mini` 템플릿에서 갈라진 형제 프로젝트**라 이식 정합성이 높음.

---

## 2. 목표 / 동작 (확정)

- pSMC의 `FailInfoForm`(불량보기 창)을 VibeTilt로 이식.
- 표시 방식: **둘 다** — "불량보기" 버튼은 항상 제공 + FAIL 시 자동표시는 `workspace.json`의 `fail_detail` 플래그로 on/off (pSMC 구조 그대로).
- **기존 PASS/FAIL 흐름은 건드리지 않고 추가(additive)만** 한다.

---

## 3. ⚠️ 공통 라이브러리 수정 고지 (승인 받음)

- 연결부가 `flexfab_mini/FlexfabForm.cs`에 있으며, **`flexfab_mini`는 CLAUDE.md상 공통 라이브러리(Shared Core)**.
- 사용자 승인: **이 프로젝트(VibeTilt)에 한해 수정 진행**. 변경은 추가 위주, 기존 로직 비변경.
- ff_vibetilt(프로젝트 라이브러리)에는 WinForms UI가 없어 창을 거기로 분리 불가 → flexfab_mini가 유일한 위치.

## 5. 상세 구현

### 5.1 `FailInfoForm.cs` (신규)

- pSMC `FailInfoForm.cs`(267줄)를 `namespace flexfab`로 그대로 이식.
  - `FailRecord`(Time/Serial/Item/Summary/Detail), `BuildUI`(DataGridView 4열 + 상세 TextBox + 복사/지우기/닫기), `PopulateGrid`, `ShowDetail` 등 UI 부분은 **동일**.
- **파서만 VibeTilt 구조에 맞게 교체** — 핵심 차이:
  - pSMC retmsg: 줄단위 `{Exp,Rsp}` / `{Item,Measure}`.
  - VibeTilt retmsg: `MakeResult`(VibeTilt.cs)가 만든 **단일 JSON 객체**
    `{"Name":..,"id":..,"data":[{"item":..,"value":..,"min":..,"max":..,"result":"OK|NG"}],"result":"OK|NG"}`.
  - → `BuildFailSummaryDetail(retmsg, failTag, out summary, out detail)`를 다음으로 적응:
    1. `JObject.Parse(retmsg)` → `data` 배열 순회.
    2. `result`가 `NG`/`FAIL`인 항목만 추림.
    3. 각 항목을 `"{item}: 측정 {value} (기준 {min}~{max})"` 형태 문자열로 포맷.
    4. `detail` = NG 줄들 join, `summary` = `failTag` 있으면 그 라벨, 없으면 첫 NG 줄.
    5. data 파싱 실패/비JSON/빈 retmsg → `failTag` 또는 "상세 없음" 폴백(기존 폴백 로직 유지).
- 파일 상단 `using Newtonsoft.Json.Linq;` 유지.

### 5.2 `FlexfabForm.cs` 수정 (전부 추가)

VibeTilt 클래스명은 `MainForm`(partial). 모든 변경은 **추가**이며 기존 메서드 본문은 비변경.

**(a) 멤버 변수 추가** (멤버 선언부, 28~100 영역)
```csharp
private readonly List<FailRecord> _failRecords = new();
private bool _failDetailPopup = true;   // workspace fail_detail 로드값으로 설정
private int  _autoFailInfoIdx = -1;     // 자동표시할 행(-1=없음)
```

**(b) `AddFailRecord` 신규 메서드**
- 시그니처: `internal void AddFailRecord(dynamic proc, string retmsg, string errorMsg)`.
- `proc.name`(항목명), `proc.param`에서 `fail_tag`(있으면) 추출 — VibeTilt proc 구조(`proc.name`/`proc.param` 사용 확인됨: FlexfabForm.cs:2920, 2955).
- `errorMsg`가 있으면(예외/메서드 없음) detail=errorMsg, 없으면 `FailInfoForm.BuildFailSummaryDetail(retmsg, failTag, ...)`.
- `_failRecords.Add(new FailRecord{ Time, Serial=serialNumber, Item, Summary, Detail })`.

**(c) FAIL 지점에서 `AddFailRecord` 호출** (검사 루프, retmsg는 2940~2952에서 이미 추출됨)
- 주 경로: `FlexfabForm.cs:2958` `else failCount++` 직후 → `mainForm.AddFailRecord(proc, rm, null);` (rm = 위에서 읽은 retmsg).
- 보조 경로(상세 없는 FAIL): 예외 2978, 시그니처 미지원 2930, 메서드 없음 2990, 라이브러리 오류 2997 → `AddFailRecord(proc, null, "<사유>")`. (최소 적용: 주 경로 + 예외 경로. 나머지는 errorMsg로 간단 기록)

**(d) run 시작 시 누적 리셋**
- MainDoProject에서 한 회차 검사 시작점(okCount/failCount 초기화 부근)에서 `_failRecords.Clear();` (세션 누적이 아니라 **회차 단위**로 운영 — 현장 혼선 방지). ※ 누적 유지를 원하면 이 줄 생략 가능 — 구현 시 1줄 토글.

**(e) `ShowFailForm` 연쇄** (3363~3381)
- `dlg.ShowDialog(this);` 직후에 추가:
```csharp
if (_failDetailPopup && _failRecords.Count > 0)
{
    int idx = _autoFailInfoIdx >= 0 ? _autoFailInfoIdx : _failRecords.Count - 1;
    _autoFailInfoIdx = -1;
    ShowFailInfo(idx);
}
```
- → 기존 4개 ShowFailForm 호출지점(3018/3062/3159/3181) 전부 자동 혜택, 호출부 비수정.

**(f) `ShowFailInfo` 신규 메서드**
```csharp
internal void ShowFailInfo(int highlightIdx = -1)
{
    if (this.InvokeRequired) { this.BeginInvoke(new Action(() => ShowFailInfo(highlightIdx))); return; }
    if (_failRecords.Count == 0) { MessageBox.Show("불량 없음", "알림"); return; }
    using (var dlg = new FailInfoForm(_failRecords, highlightIdx))
    {
        dlg.StartPosition = FormStartPosition.CenterParent;
        dlg.ShowDialog(this);
    }
}
```

**(g) "불량보기" 버튼**
- 기존 버튼 영역 옆에 프로그래밍 방식으로 1개 추가(Designer 변경 최소화) → `button_FailInfo.Click += (_, __) => ShowFailInfo(-1);` (누적 전체, 자동선택 없음).
- 배치 위치는 구현 시 기존 버튼 레이아웃 확인 후 결정(로그 복사 버튼 근처).

### 5.3 `workspace.json` (Debug + Release 둘 다)

- 워크스페이스 최상위(또는 설정 섹션)에 플래그 추가:
```json
"fail_detail": true,
"_fail_detail_comment": "FAIL 팝업(FailForm) 후 불량보기(FailInfoForm) 자동 표시 | true=자동 / false=버튼으로만"
```
- `_failDetailPopup`은 이 값을 로드해 설정(로드 지점은 다른 워크스페이스 플래그 파싱부 근처).
- CLAUDE.md 규칙: **Debug·Release 두 경로 동시 수정**, spec/플래그에 `_comment` 주석 필수.

## 6. 비파괴 보장

- 기존 PASS/FAIL 판정(`finalResult = failCount==0 ? "PASS":"FAIL"`), PassForm/FailForm 표시, 저장/업로드 흐름 **전부 비변경**.
- 추가되는 것은 (1) 신규 폼 파일, (2) FlexfabForm.cs에 멤버/메서드 추가 및 ShowFailForm 말미 1블록, (3) FAIL 지점 호출 1~2줄.
- `fail_detail=false`로 두면 자동표시는 꺼지고 버튼만 동작 → 기존 동작과 사실상 동일.

## 7. 검증 방법

1. **빌드**: Debug 빌드 성공 (`flexfab` 프로젝트). Newtonsoft 이미 참조라 의존성 OK.
2. **PASS 케이스**: 정상 검사 → PassForm만, 불량보기 안 뜸(레코드 0).
3. **FAIL 케이스 (자동, fail_detail=true)**: 한 항목 일부러 기준 밖 → FailForm OK 후 **불량보기 창 자동 표시**, 해당 NG 항목이 `item: 측정 value (기준 min~max)`로 보이는지 확인.
4. **버튼**: 검사 후 "불량보기" 버튼 클릭 → 누적 불량 목록 표시, 행 선택 시 상세 갱신, 복사/지우기/닫기 동작.
5. **fail_detail=false**: 자동표시 안 뜨고 버튼으로만 열림 확인.
6. **회차 리셋**: 새 검사 시작 시 이전 회차 불량이 비워지는지(or 누적 정책대로) 확인.
7. workspace.json Debug/Release 두 파일 모두 반영 확인.
