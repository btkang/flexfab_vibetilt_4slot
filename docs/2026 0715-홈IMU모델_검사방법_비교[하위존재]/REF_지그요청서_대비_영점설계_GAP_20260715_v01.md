## 1. 결론 요약

1. 지그 제작 요청서 5개 시트 전체에 **"자이로 / gyro / 인클라이노미터 / SOLAR / setz" 언급 0건.**
2. 요청서가 규정한 수평 기준은 **"상용센서"**(시트3)와 **"수평알"**(시트4) 두 가지.
3. 사용자 확인(2026-07-15): 요청서의 **"상용센서" = 현재 사용 중인 SOLAR-360-420**. (회의 전언 — 담당자 미확인)
4. → **센서 선택은 요청서 이탈이 아님.** 유일한 이탈은 **요청서에 없는 `setzcur`(tare) 단계 추가**.
5. **`setzcur` 유래 규명 완료 (사용자 제보 + 소스 대조, 2026-07-16):**
   출처는 **BG01의 `angle_0_init_Revision()`** — 헤더에 **`// Temporarily`** 로 표시된 **미완성 임시 함수**
   (가드·루프 주석처리, dead code 잔존). 요청서 수령 이전에 참조. → 5.5절.
6. **VibeTilt는 배타적인 두 전략을 병합했다.** 구모델(pCOM/MOS)의 **모터 정렬**(`angle_0_init`, setzcur 없음)과
   BG01의 **tare 정렬**(`angle_0_init_Revision`, 모터 없음)은 **같은 목적에 대한 대안**인데,
   VibeTilt는 `FineAdjust`(=모터) **뒤에** `setzcur`(=tare)를 붙여 **둘 다** 수행한다.
   → `setzcur`의 기능적 역할 **없음**. 유일한 효과는 **수렴 잔차(≤0.03°)의 영구 누적**. → 5.5.3절.
7. **★ 원본 설계(pCOM/pSMC)에는 안전장치가 있었다** — 메인폼 체크박스 **`"Ref. Gyro Sensor Init"`**(`IDC_CHECK13`).
   **체크 시에만** `setzcur` 실행(셋업용 1회), **미체크 시 아무것도 안 함.** 매 사이클 정렬은 **모터**(`angle_0_init`)가 담당.
   → **`setzcur`는 원래 "작업자가 켜는 선택적 셋업 단계"였고, 이는 지그 요청서의 모델과 정확히 일치한다.**
   BG01의 `angle_0_init_Revision()`이 **이 체크박스를 우회**(호출부에 게이트 없음)하며 무조건 실행으로 바꿨고,
   VibeTilt가 그 우회된 버전을 물려받았다. → 5.6절.
8. 요청서 기능검사 8항목 vs 구현 17항목. 이 중 `MOTION_ZERO`(#3, #10)가 요청서 무대응.
9. **`setzcur` 제거를 막는 기술적 근거는 발견되지 않음.**
   유일한 옹호 논거였던 "온도 드리프트 상쇄"는 **순환 참조로 기각됨** (5.4절) —
   자이로가 정한 자세에서 자이로를 tare하는 것은 어떤 오차도 제거하지 못한다.
   제거 방향은 **원본 설계(pCOM/pSMC)·지그 요청서 양쪽 모두와 일치**한다.
9. **단, PN(온도보상 여부) 확인은 여전히 필요.** `setzcur` 제거와는 별개로,
   **요청서 ±0.05 스펙 자체가 달성 가능한지**를 가르는 문제이기 때문 (4.2절).

### 4.2 성능 사양 (p.2) — ★ 판단을 가르는 지점

| 파라미터 | 값 |
|---|---|
| Accuracy (@20°C) | **±0.03°** |
| **Accuracy -10~60°C (without compensation)** | **±0.15°** |
| **Accuracy -10~60°C (with compensation)** | **±0.05°** |
| Zero Drift (without comp. / with comp.) | ±0.002 / ±0.001 °/°C |
| Sensitivity Drift (without / with) | ±0.003 / ±0.001 %/°C |
| Long Term Stability | ±0.01° |

## 5. 이탈의 실제 메커니즘 — ★ 정정 포함

### 5.1 코드 실측 흐름 (`InitMotionZero` L698~, `FineAdjust` L1485~)

```
1. 에러클리어 + soft limit ±8000 확장
2. setdir6(X) / setdir5(Y)
3. 홈센서 원점복귀 → 고정 step 이동 (IN1: 1250 step)   ← coarse (개루프)
4. FineAdjust(target=0, strict 0.03 / relaxed 0.05)     ← 자이로 폐루프
5. setzcur                                              ← ★요청서에 없음
6. soft limit ±1600 재설정
```

`FineAdjust`(L1509~)는 **자이로를 읽어 `|target − gyro| <= tolerance`가 될 때까지 모터를 움직이는 폐루프**다
(strict 0.03 → 10초 경과 시 relaxed 0.05로 완화, L1512 `strictDeadline`).

### 5.2 [정정] "기계 자세를 추종한다"는 표현의 정확한 의미

**대화 중 필자(Claude)가 "자이로가 홈센서+1250step 기계 자세의 추종자가 된다"고 말한 것은 부정확했다.**
1250 step은 coarse 시작점일 뿐이고, FineAdjust가 자이로 폐루프이므로 **tolerance를 넘는 기계 틀어짐은 오히려 보정된다.**

정확한 메커니즘은 **REF v02(2026-07-14)의 기술이 옳다** — 핵심은 `사이클당 <0.03도`라는 단서에 있다:

| 사이클당 기계 틀어짐 `m` | FineAdjust 동작 | setzcur 결과 |
|---|---|---|
| `\|m\| > tolerance` (0.03) | 자이로가 0을 가리키는 자세로 **되돌림** | 영점 유지 — **드리프트 없음** |
| `\|m\| <= tolerance` (0.03) | 오차가 허용범위 내 → **모터 안 움직임** | **틀어진 자세가 그대로 새 영점으로 확정 — 1:1 누적** |

→ **tolerance 미만의 미세 틀어짐은 FineAdjust에 보이지 않고, setzcur가 그것을 영구(비휘발) 확정한다.**
사이클마다 반복되면 **복원력 없는 누적**(공장 영점이라는 절대 기준이 첫 setzcur에서 소멸했으므로).
누적이 무작위(√N)인지 단방향 래칫(선형)인지는 접근 방향 편향에 달림 — coarse 착지점이 항상 같은 쪽이면 **래칫**이 되어 더 나쁨.
**→ 실측 필요 (7절 문의항목 및 REF v02의 SPC 제안 참조).**

### 5.4 [기각됨] "`setzcur`가 온도 드리프트를 상쇄한다"는 반대 논거

**초안(2026-07-15)에서 필자는 다음 논거로 `setzcur` 제거에 신중해야 한다고 봤다:**

> `setzcur`는 현재 온도에서 tare하므로 온도 zero drift(±0.002°/°C)를 상쇄한다.
> 공장 영점(20°C 기준)만 쓰면 현장 온도차만큼 오차가 남는다. 따라서 트레이드오프다.

**이 논거는 성립하지 않는다 — 순환 참조이기 때문.**

- tare는 **"지금 이 자세가 참수평"이라고 선언**하는 것이다. 그 선언이 맞으려면 **자이로와 독립된 외부 수평 기준**이 있어야 한다 (수평알, 정반, 별도 기준기).
- 그런데 VibeTilt에서 tare를 치는 그 자세는 **`FineAdjust`가 자이로를 보고 만든 자세**다 (5.1절).
  자이로가 온도로 0.02° 틀어져 있으면, FineAdjust는 **실제로 0.02° 기울어진 자세**를 "0"이라 믿고 거기서 멈춘다.
  거기서 `setzcur`를 치면 그 온도 오차는 **상쇄되는 게 아니라 영점에 각인된다.**
- **자이로를 기준으로 자이로의 영점을 잡는 것은 자기 자신을 참조하는 것이므로 어떤 오차도 제거할 수 없다.**
  제거할 수 있는 유일한 것은 FineAdjust의 수렴 잔차인데, 그건 없애야 할 오차가 아니라 **새로 만들어내는 오차**다 (5.2절).
- → **`setzcur` 옹호 논거 없음.** 4.2절의 온도 정확도(±0.15/±0.05)는 여전히 중요하지만, 그 해법은 `setzcur`가 아니라
  **외부 기준(수평알/기준기) 또는 온도보상 품 채택**이어야 한다.

| `:663 angle_0_init()` | 모터 폐루프 ±0.005, **`setzcur` 없음** — **호출됨** (`:927`, `:1031`) |
| `:781` JIG_INIT의 `setzcur` | **`#if 0`로 컴파일 제외 — 비활성** |
| `:825` DEGREE_0_CHECK의 `setzcur` | 활성 — **사이클 초 1회**, 직후 `get---x`로 `m_RefAngle` 캡처 (기준 설정용) |

→ 구모델 구조: **`setzcur`는 사이클 시작 시 기준점 1회 설정용.** 이후 정렬은 **모터가** 한다.
→ BG01: 그 **모터 정렬을 `setzcur`로 대체** (`angle_0_init` → `angle_0_init_Revision`). BG01의 JIG_INIT `setzcur`도 `#if 0`로 비활성(`:1531`)인 것은 구모델과 동일.

#### 5.5.3 VibeTilt는 배타적인 두 전략을 **합쳤다** — 이것이 근본 원인

| 모델 | 정렬 수단 | `setzcur` 역할 |
|---|---|---|
| 구모델(pCOM/MOS) | **모터** (`angle_0_init`) | 사이클 초 기준점 1회 |
| BG01 | **`setzcur`** (`angle_0_init_Revision`, "Temporarily") | **정렬 수단 그 자체** (모터 대신) |
| **VibeTilt** | **모터** (`FineAdjust`) **+** **`setzcur`** | **잉여** — 정렬은 FineAdjust가 이미 끝냄 |

- VibeTilt는 **구모델의 모터 정렬(`FineAdjust`)** 과 **BG01의 tare(`setzcur`)** 를 **순차로 둘 다** 수행한다.
- 두 방식은 **같은 목적(0도 정렬)에 대한 대안**이지 조합하는 것이 아니다.
- `FineAdjust`가 이미 자이로=0 자세로 만든 **뒤에** `setzcur`를 치므로, `setzcur`가 하는 일은
  **수렴 잔차(≤0.03°)를 영점에 굳히는 것뿐** — **이득 0, 부작용만 100%** (5.2절 래칫).
- **방증:** `MotionJig.cs:861` 주석 원문 —
  > `// 주의: setzcur를 FineAdjust 전에 하면 자이로가 0으로 리셋되어 FineAdjust가 실제 수평을 찾지 못함`
  > `//       (이대리 코드도 setzcur 없이 FineAdjust)`
  작성자는 **구모델 `angle_0_init`에 setzcur가 없다는 사실을 인지**하고 있었다.
  그럼에도 BG01에서 가져온 `setzcur`를 **FineAdjust 뒤에 붙여** 순서 충돌만 회피했다.
  → **의도적 설계가 아니라 두 참조 소스의 병합 사고(merge artifact).**

#### 5.5.4 중간 결론

- `setzcur`는 **BG01의 "Temporarily" 표시된 미완성 함수**에서 유래했고,
- VibeTilt에서는 **정렬을 FineAdjust가 이미 수행하므로 기능적 역할이 전혀 없으며**,
- 유일한 효과는 **수렴 잔차의 영구(비휘발) 누적**이다.

## 5.6 원본 설계(pCOM/pSMC) 대조 — **`setzcur`는 원래 "선택적 셋업 단계"였다** (★ 2026-07-16)

사용자 제보: pCOM과 pSMC는 유사(pSMC가 pCOM 코드를 가져다 씀). **메인폼 체크박스로 기준 영점 동작을 설정.**
소스: `02.ref_IMU모델소스/pSMC_Tester - 1.5m/CTS_pCOM_Tester/`, `CTS_pCOM2_Tester_V2.0.0.1_2019 (3) - 104kb/CTS_pCOM_Tester/`
(두 소스의 `BoardLevelMo.cpp`는 라인번호만 다르고 구조 동일 — pSMC `:843` ↔ pCOM2 `:823`)

### 5.6.1 체크박스 실체

| 항목 | 값 |
|---|---|
| UI 라벨 (`CTS_pCOM_Tester.rc`, UTF-16) | **`"Ref. Gyro Sensor Init"`** (`IDC_CHECK13`, BS_AUTOCHECKBOX) |
| DDX 바인딩 | `BoardLevelMo.cpp:86-87` → `m_cRefSensorInit` / `m_bRefSensorInit` |
| 생성자 초기값 | `:50` `m_bRefSensorInit(FALSE)`, `:51` `m_sRefAngle(_T("000.000"))` |
| 다이얼로그 초기화 | `:143` `m_cRefSensorInit.SetCheck(1);` → **기본 체크 상태** |
| 게이트 지점 | `:843`(pSMC) / `:823`(pCOM2) — `DEGREE_0_CHECK` 스텝 |

### 5.6.2 체크 / 미체크 동작 (pSMC `BoardLevelMo.cpp:843~873`)

```cpp
else if (pCBLM->m_iTestStep == DEGREE_0_CHECK)
{
    if (pCBLM->m_bEnterTheTest && pCBLM->m_bRefSensorInit)   // ← 체크된 경우
    {
        pCBLM->devicesend(3, "setzcur");        // 자이로 tare
        ...
        pCBLM->devicesend(3, "get---x");        // 직후 각도 판독
        ...
        pCBLM->m_Refangle = (float)atof(refangle);   // 기준각 캡처
        pCBLM->TestResult(_T("PASS"));
    }
    else
        pCBLM->TestResult(_T("PASS"));          // ← 미체크: 아무것도 안 하고 통과

```

| 체크박스 | 동작 | 자이로 영점 | `m_Refangle` |
|---|---|---|---|
| **체크** | `setzcur` → `get---x` → 기준각 캡처 | **재설정(tare)** | 새로 갱신 |
| **미체크** | **아무것도 안 함, 그냥 PASS** | **건드리지 않음** | **이전 값 유지** (초기값 `"000.000"` = 0) |

### 5.6.3 정렬은 별도로 **모터**가 한다

- `m_Refangle`은 `angle_0_init()`(`:663`)이 사용 — 자이로를 읽어 `m_Refangle`과 ±0.005 이내가 될 때까지 **모터를 1스텝씩 이동**.
- `angle_0_init()`에는 **`setzcur`가 없다.** 그리고 이 함수가 **실제로 호출된다** (`:927`, `:1031`).
- JIG_INIT의 `setzcur`는 `#if 0`으로 **컴파일 제외** (`:781`).

**→ 원본 설계의 역할 분담이 명확하다:**

| 무엇 | 언제 | 수단 |
|---|---|---|
| **기준 영점 설정** | **작업자가 체크했을 때만** (지그 셋업/기준 재설정 시) | `setzcur` **1회** |
| **매 사이클 0도 정렬** | 항상 | **모터** (`angle_0_init`) |

**즉 `setzcur`는 양산 반복 사이클에서 매번 치라고 만든 명령이 아니라, 지그 셋업 시 작업자가 명시적으로 켜는 선택적 단계였다.**
이것은 지그 요청서의 모델(기준센서 영점 고정 + 지그를 이동/조정)과 **정확히 일치한다** (2절).

### 5.6.4 BG01이 이 안전장치를 우회했다

BG01은 체크박스(`m_bRefSensorInit_BG01`)를 **DEGREE_0_CHECK에서는 그대로 유지**했다 (`BoardLevelMo_BG01.cpp:1611` 부근).
**그러나** 모터 정렬을 tare로 대체한 `angle_0_init_Revision()`의 호출부는 **체크박스로 게이트되지 않는다:**

```cpp
// BoardLevelMo_BG01.cpp:1735~ (ANGLE_INIT_0)
else if (pCBLM->m_iTestStep_BG01 == ANGLE_INIT_0)
{
    if (pCBLM->m_bEnterTheTest_BG01) // Temporarily      ← m_bRefSensorInit_BG01 검사 없음
    {
        if (pCBLM->angle_0_init_Revision() != 0) ...     ← 내부에서 무조건 setzcur
    }
}
// :1862 (ANGLE_INIT_1) 도 동일하게 게이트 없음
```

- → **BG01에서 `setzcur`는 "작업자가 켠 셋업 단계"에서 "매 정렬마다 무조건 실행"으로 성격이 바뀌었다.**
- 호출부 주석에도 `// Temporarily`가 붙어 있다 (`:1738`).

### 5.6.5 유래 사슬 (최종)

| 세대 | 정렬 수단 | `setzcur` 시점 | 게이트 | 상태 |
|---|---|---|---|---|
| **pCOM / pSMC (원본)** | 모터 (`angle_0_init`) | 셋업 시 1회 (DEGREE_0_CHECK) | **`"Ref. Gyro Sensor Init"` 체크박스** | 정상 설계 |
| **BG01** | **`setzcur`** (`angle_0_init_Revision`) | **매 정렬마다 무조건** | **없음 (우회)** | `// Temporarily` — 미완성 |
| **VibeTilt** | 모터 (`FineAdjust`) **+ `setzcur`** | **매 사이클** (`MOTION_ZERO`) | **없음** | 두 전략 병합 |

**결론: 원본 설계에 존재하던 안전장치(작업자 체크박스 + 모터 정렬)가 BG01의 임시 코드에서 제거됐고,
VibeTilt는 그 우회된 버전을 물려받으면서 모터 정렬(FineAdjust)까지 함께 구현해 `setzcur`를 완전한 잉여로 만들었다.**

- **→ `setzcur` 제거의 기술적 장애물은 발견되지 않음.** 오히려 **원본 설계(pCOM/pSMC) 및 지그 요청서 양쪽 모두와 일치하는 방향**이다.
- 단 실기 회귀 검증 필수 (8절).
- **대안 설계(선택지):** 완전 제거 대신 **원본처럼 옵션화**(JSON 플래그 `ref_gyro_sensor_init`, 기본 false)하여
  지그 셋업/기준 재설정 시에만 수동 실행하는 방식도 가능. 이 경우 요청서의 "상용센서 0도 조정" 절차와 대응됨.

### 8.2 회신별 분기

| 쟁점 | 회신 | 방향 |
|---|---|---|
| tare 허용 여부 | 금지/미상정 | `setzcur` 제거 → 요청서 원안(외부 기준) 복귀. 5.5절 근거로 제거 정당성 확보됨 |
