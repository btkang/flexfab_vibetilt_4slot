3. [진동검사에 정지(rest) 측정 1단계 추가 — 노이즈성 센서불량 감지] (2026-06-04 추가, B묶음 / 모션 기능추가 빌드 시)
 - 배경: 6/2 485보드 200건 검토 중 발견. 현재 진동·기울기 검사 둘 다 "움직이는 중"만 측정 + 움직임 요구(require_motion)
 - 사각: "가만히 있는데 값이 출렁(노이즈성)" = 정지 상태를 안 보니 진동·기울기 둘 다 못 잡음
   * 고착/데드 센서는 진동 require_motion이 이미 잡음 (6/2 200건 모션 true) → 남는 진짜 사각은 "노이즈성" 하나뿐
 - 해결: 보드검사 "진동검사 바로 앞"에 [정지 안정성 검사] 별도 스텝 신규 (VIBE 병합 아님 — 독립 strict 판정 위해)
   * 위치: ...LED검사 → [신규 정지검사] → VIBE(흔들기) → TILT
   * 정지("가만히 두세요") → MODE02 GAC ~1초 수집 → 0축 RMS(또는 p2p 변동폭) ≤ 낮은 임계면 PASS
   * retry=0 (간헐 노이즈 안 가려지게) + 전 구간 판정(tail 끝 N개 아님) + ★평균(mean) 금지, RMS/p2p로★
 - 왜 RMS/진동(각도 아님): 정지 노이즈는 AN(각도)가 아니라 진동 GAC의 RMS(진폭)로 봐야 함. RMS는 GAC에 이미 있으나 "흔드는 중+느슨spec(0.1~2.0)"이라 미활용
 - verify_an이 약한 고리인 이유(코드확인 VibeTilt.cs:1286): OFFSET후 AN ~1초 스트림을 "평균"으로 ±0.05 판정 → 대칭노이즈 상쇄돼 못 봄(zero-mean blind). 단발 아니라 평균이라 약함
 - 현재 사각: "정지 안정성 검사" = 보드·모션 통틀어 0개. 큰/지속 노이즈는 모션 all_in_spec(tilt tail10/vibe tail5)이 잡지만, 작은/간헐은 보드·모션 다 통과 가능(verify_an 평균+cal편향, tail 끝구간, retry3)
 - 정지 기준값(예 RMS<0.1, p2p<0.05): 정상보드 정지 실측 후 확정 (현재 데이터 없음 → PLAN 1단계서 수집)
 - 변경범위: VibeTilt.cs(신규 핸들러) + 보드 JSON(232+485, MP/TEST, Debug+Release) + 작업자 프롬프트. 코드+빌드 = 0.7.2

      - 연속 빈 응답 2 → 3 (안전 마진)
