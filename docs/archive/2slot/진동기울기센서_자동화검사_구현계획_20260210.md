# 진동기울기센서(VibeTilt) 자동화 검사 프로그램 구현 계획

 vibetilt.cs의  스타일은 e84a.cs를 기반으로 하면 돼. e84a 스타일은 명령을 하드코딩하지  않고 json 파일에 넣었어.
변경 방향:
  1. 명령을 하드코딩하지 않고 workspace.json의 "tests" 배열에서 동적 읽기
  2. E84a처럼 명령 전송 → 응답 수신 → 판정 의 패턴
  3. 센서 데이터 파싱 + 범위 판정 로직은 유지

> 작성일: 2026-02-10
> 대상 제품: CTS-IOTS-VL01 (진동기울기센서)
> 플랫폼: flexfab (C# .NET 8.0)

---

## 1. 프로젝트 개요

### 1-1. 목적
진동기울기센서(CTS-IOTS-VL01)의 양산 출하 검사를 위한 flexfab 프로젝트별 라이브러리(`ff_vibetilt`)를 신규 개발한다.



### 1-2. 대상 제품군

| 모델 | 통신 방식 | 비고 |
|------|-----------|------|
| VL10 | RS-232 | 주소 없음 |
| VL20 | RS-485 | 주소 "0" 포함 |
| VL30 | RS-485 | 주소 "0" 포함 |

### 1-3. 검사 단계

| 단계 | PC | 설명 |
|------|----|------|
| 보드레벨검사 (1차) | Board PC | 집게핀 지그, 간단한 진동/기울기 검사 |
| 모션검사 (2차/캔탑스입고) | Motion PC | 케이블/케이스 조립 후, 정밀 검사 + Calibration |

현재 운영 상태(2026-02-10):
- **보드검사 우선 운영**
- 모션검사는 지그 준비 후 동일 JSON 항목 파라미터만 전환해서 적용

## 2. 센서 프로토콜 사양

### 2-1. 명령/응답 형식
- **명령 (TX)**: `<CMD>` 또는 `<CMD,arg>` (앵글 브라켓 + 개행)
- **응답 (RX)**: `[CMD,result,data...]` (대괄호, 콤마 구분)

### 2-2. 주요 명령어

| 명령 | 응답 형식 | 용도 |
|------|-----------|------|
| `<SENTEMP>` | `[SENTEMP,0,온도값]` | 센서 온도 확인 |
| `<APPCFG>` | `[APPCFG,0,00/10/1/115200]` | Config 데이터 확인 |
| `<MODE,2>` | - | 진동 측정 모드(Mode2) 설정 |
| `<MODE,6>` | - | 기울기 측정 모드(Mode6) 설정 |
| `<SAM,n>` | - | 샘플링 시간 설정 (n=ms) |
| `<START>` | - | 측정 시작 |
| `<STOP>` | - | 측정 종료 |
| `<GAC>` | RS-232: `[GAC,X,Y,Z,RMS]` | 진동값 읽기 |
|        | RS-485: `[GAC,0,X,Y,Z,RMS]` | (주소 포함) |
| `<AN>` | `[AN,X,Y]` | 기울기값 읽기 |

### 2-3. RS-232 vs RS-485 응답 차이

```
RS-232 (VL10):  [GAC,X,Y,Z,RMS]     ← 주소 없음, offset=1
RS-485 (VL20/30): [GAC,0,X,Y,Z,RMS]  ← 주소 "0" 포함, offset=2
```

### 2-4. Sampling Time 규칙 (VL10 사양서 4.2.4)
- 기준: `진동기울기센서(CTS-IOTS-VL10)_통신사양서_R8_251124.pdf`의 **4.2.4 Set/Get Sampling Time**
- `<SAM,1>`: 1ms 샘플링
- 기본값(Default): 10ms 샘플링
- 통신 속도 조건:
  - 10ms 샘플링: **115200bps**에서 가능
  - 1ms 샘플링: **460800bps**에서 가능

## 3. 검사 항목 및 판정 범위

### 3-1. 검사 항목 목록

| # | 검사 ID | 검사명 | 프로토콜 |
|---|---------|--------|----------|
| 1 | VER_232 / VER_485 | 통신검사 | APPCFG 응답 확인 |
| 2 | SENTEMP_232 / SENTEMP_485 | 센서온도 검사 | SENTEMP 명령 |
| 3 | APPCFG_232 / APPCFG_485 | Config 확인 | APPCFG 명령 |
| 4 | VIBE_232 / VIBE_485 | 진동검사 | MODE2 → GAC 반복 |
| 5 | TILT_232 / TILT_485 | 기울기검사 | MODE6 → AN 반복 |

### 3-2. 판정 범위 (Range)

| 검사 항목 | 수동검사 (Board) | 자동검사 (Motion) |
|-----------|-----------------|------------------|
| 진동 1축 (중력방향) | 0.9 ~ 1.1 | 0.97 ~ 1.03 |
| 진동 0축 (나머지) | -0.1 ~ 0.1 | -0.03 ~ 0.03 |
| 진동 RMS | 0.5 ~ 0.65 | - |
| 기울기 X (수동 90도) | 85 ~ 90 | - |
| 기울기 Y (수동 90도) | -90 ~ -85 | - |
| 기울기 (지그 20도) | - | 19.8 ~ 20.2 |
| 센서온도 | 20 ~ 40 | 20 ~ 40 |

### 3-3. 샘플링/통신속도 정책
- 보드검사(Board):
  - 진동검사 샘플링: **10ms (`<SAM,10>`)**
  - 기울기검사 샘플링: **10ms (`<SAM,10>`)**
  - 통신속도: **115200bps**
- 모션검사(Motion):
  - 진동검사 샘플링: **10ms (`<SAM,10>`)**
  - 기울기검사 샘플링: **1ms (`<SAM,1>`)**
  - 통신속도: 진동 **115200bps**, 기울기 **460800bps**

### 3-4. 작업자 동작(보드검사)
- 보드검사에서는 검사 항목 시작 전 작업자 안내 팝업을 사용한다.
- 적용 방법: 각 proc의 `param.operator_prompt` 문자열 설정
- 시작 방식: 팝업 확인 후 시작 (`OK` 버튼 / `Enter` / `Space`)
- 판정 방식:
  - PASS 조건을 만족하는 샘플이 나오면 **즉시 PASS**
  - `TIMEOUT`(ms)까지 조건 미충족이면 **FAIL**
- 현재 적용 대상:
  - `VIBE_232`: "지그를 앞/뒤 좌/우로 움직여주세요"
    - 팝업에 PASS 조건 표시:
      - 1축: `one_min ~ one_max`
      - 0축: `zero_min ~ zero_max`
      - RMS: `rms_min ~ rms_max`
  - `TILT_232`: "제품 방향을 맞추고 살짝 흔들어 기울기 변화를 확인해 주세요."

    ├── workspace.json                   ← **실제 동작 워크스페이스 (단일 파일 운용)**

### 4-2. 클래스 구조

```
Cantops.FlexFab.VibeTilt : ModuleBase, IProcess
│
├── [생성자] info_ 초기화 (name="vibetilt", procs 10개)
├── Begin() / End()
│
├── [UART 핸들 확보]
│   └── ResolveUart(libraries, param, logAction, configKey)
│       - config_ 또는 param에서 "uart_232" / "uart_485" 키로 IComm 핸들 확보
│
├── [헬퍼 메서드]
│   ├── SendCommand(comm, cmd, logAction)     → "<CMD>\n" 형태로 전송
│   ├── ReadResponse(comm, timeoutMs, logAction) → "[CMD,...]" 응답 수신
│   ├── ParseResponse(raw)                    → string[] 파싱
│   ├── ClearCommBuffer(comm, logAction)      → 수신 버퍼 비우기
│   ├── ChangeBaudRate(comm, newBaud, logAction) → Disconnect→SetConfig→Connect
│   └── MakeResult(success, procId, procName, result, details) → retmsg JSON 생성
│
├── [RS-232 검사 메서드] (VL10)
│   ├── VER_232()      → VER_Internal("uart_232")
│   ├── SENTEMP_232()  → SENTEMP_Internal("uart_232")
│   ├── APPCFG_232()   → APPCFG_Internal("uart_232")
│   ├── VIBE_232()     → VIBE_Internal("uart_232", isRs485=false)
│   └── TILT_232()     → TILT_Internal("uart_232", isRs485=false)
│
├── [RS-485 검사 메서드] (VL20/VL30)
│   ├── VER_485()      → VER_Internal("uart_485")
│   ├── SENTEMP_485()  → SENTEMP_Internal("uart_485")
│   ├── APPCFG_485()   → APPCFG_Internal("uart_485")
│   ├── VIBE_485()     → VIBE_Internal("uart_485", isRs485=true)
│   └── TILT_485()     → TILT_Internal("uart_485", isRs485=true)
│
└── [Internal 구현]
    ├── VER_Internal()      → APPCFG 명령 → 응답 여부 판정
    ├── SENTEMP_Internal()  → SENTEMP 명령 → 온도 범위 판정
    ├── APPCFG_Internal()   → APPCFG 명령 → expected 문자열 포함 판정
    ├── VIBE_Internal()     → MODE0 → MODE2 → SAM10 → START → GAC 반복 → STOP → MODE0 → 축별 범위 판정
    └── TILT_Internal()     → MODE0 → MODE6 → (Board:SAM10@115200 / Motion:baud460800+SAM1) → START → AN 반복 → STOP → MODE0(+baud 복원)
```

## 5. 검사 시퀀스 상세

### 5-1. VER (통신검사)

```
TX: <APPCFG>
RX: [APPCFG,0,config문자열]
판정: APPCFG 응답이 오면 OK
```

### 5-2. SENTEMP (센서온도 검사)

```
TX: <SENTEMP>
RX: [SENTEMP,0,25.3]
판정: 온도값이 min~max 범위 내이면 OK (기본: 20~40)
```

### 5-3. APPCFG (Config 데이터 확인)

```
TX: <APPCFG>
RX: [APPCFG,0,00/10/1/115200]
판정: 응답에 expected 문자열이 포함되면 OK
```

### 5-4. VIBE (진동검사)

```
1. <MODE,0>          → 기본 모드 보정
2. <MODE,2>          → 진동 모드 설정
3. <SAM,10>          → 샘플링 10ms 설정 (Board/Motion 공통)
4. <START>           → 측정 시작
5. <GAC> (반복)      → 데이터 수집 (DURATION ms 동안)
   RX: [GAC,X,Y,Z,RMS]  (RS-232)
   RX: [GAC,0,X,Y,Z,RMS] (RS-485)
6. <STOP>            → 측정 종료
7. <MODE,0>          → 기본 모드 복귀
8. 판정:
   - 중력축(|avg|>0.5): one_min ~ one_max
   - 나머지축: zero_min ~ zero_max
   - RMS: rms_min ~ rms_max (선택)
```

### 5-5. TILT (기울기검사)

```
1. <MODE,0>          → 기본 모드 보정
2. <MODE,6>          → 기울기 모드 설정
3. 샘플링/속도 설정
   - Board: <SAM,10> @ 115200
   - Motion: Baudrate 460800 → <SAM,1>
4. <START>           → 측정 시작
5. <AN> (반복)       → 데이터 수집 (DURATION ms 동안)
   RX: [AN,X,Y]
6. <STOP>            → 측정 종료
7. <MODE,0>          → 기본 모드 복귀
8. Baudrate 115200   → [finally] 반드시 복원 (Motion 시)
9. 판정:
   - X: x_min ~ x_max
   - Y: y_min ~ y_max
```

> **중요**: TILT 검사에서 Motion 조건(1ms 샘플링)으로 baudrate를 460800으로 변경한 경우, 반드시 finally 블록에서 원래 baudrate(115200)로 복원한다.
> uart.cs의 SetConfig 제약: 연결 중에는 설정 변경 불가 → Disconnect → SetConfig → Connect 순서 필수.

## 6. Workspace JSON 설계

### 6-1. 단일 JSON 운용 원칙 (`output/Debug/net8.0-windows/workspace.json`)

- 실제 실행은 `output/Debug/net8.0-windows/workspace.json` 1개만 사용
- 검사 타입(보드/모션)은 **프로시저별 파라미터**로 구분
- 핵심 분기 파라미터:
  - `sampling_ms`
  - `tilt_baud`, `normal_baud`
  - `operator_prompt`
  - 각 항목 range (`one_min/max`, `x_min/max` 등)

### 6-2. 보드검사 기준값 (현재 운영)

| 항목 ID | 핵심 파라미터 | 값 |
|----------|----------------|-----|
| `VIBE_232` | `sampling_ms` | 10 |
| `VIBE_232` | `operator_prompt` | 진동검사 시작 안내 + PASS 조건 + TIMEOUT 문구 |
| `TILT_232` | `sampling_ms` | 10 |
| `TILT_232` | `tilt_baud/normal_baud` | 115200 / 115200 |
| `TILT_232` | `operator_prompt` | 작업자 흔들기 안내 문구 |

### 6-3. 모션검사 전환 시 (지그 준비 후)

- 동일 JSON의 해당 항목 파라미터만 변경
- `VIBE_232`: `sampling_ms=10` 유지
- `TILT_232`: `sampling_ms=1`, `tilt_baud=460800`, `normal_baud=115200`
- 모션용 range로 교체
