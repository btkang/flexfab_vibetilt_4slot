# PLAN_ 시리얼 더미(시작/마감) 처리 + 0 차단 + X=Y 동일 차단

- 작성일: 2026-06-11
- 작성자: Claude
- 대상: `flexfab_mini/FlexfabForm.cs` (호스트, 시리얼 다이얼로그 + 실행 루프)
- 트리거: **FW 2.0.3에서 UID 스펙 변경** — 시리얼 `00000` 거부(최소 00001)

---

## 1. 배경 / 문제

### FW 스펙 변경 (실측 2026-06-11)
- FW **2.0.2**: 시리얼 `VL2-00000`(0번) 수락 → 더미 시료에 사용 가능
- FW **2.0.3**: `<UID,1,VL2-00000>` → `[UID,9,...]` **RV=9 (파라미터 범위 초과)** = **00000 거부**
- 유효 범위: **00001 ~ 9999999** (5/6/7자리)

### 현재(0.7.7) 동작과 문제
- 밀어내기식 듀얼: 첫 사이클 Y에 **더미 시료** 올리고 `00000` 발급 → FW 2.0.3에서 **#9 Y UID FAIL**
- 새 PC(시리얼 파일 없음) 기본값 = X=00001 / Y=00000 (`ShowDualSerialDialog` 2008~2014행 `prevNum-1`, 초기화 버튼 2070행)
- 다이얼로그 검증(접두사·X=Y+1)은 **0을 못 잡음** → 그대로 전송
- 빈 Y는 **자동 스킵 안 됨** — Y proc이 X 시리얼로 fallback(2711행)되어 그냥 돌아감

---

## 2. 요구사항 (3가지)

1. **더미 = 빈칸 인식** — 시작/마감 사이클에서 한 축을 빈칸으로 두면 **그 축 검사 스킵** (0 발급 안 함)
2. **0(범위밖) 차단** — X/Y 시리얼 숫자값이 1 미만이면 진행 차단 + 안내
3. **X=Y 동일 시리얼 차단** — X와 Y가 같은 시리얼이면 검사 진행 불가 (오입력 방지)

---

## 3. 밀어내기식 플로우 (확정)

보드가 X→Y로 밀려가며 2사이클에 걸쳐 완성. **양 끝(시작/마감)에 더미** 필요.

### Day 1 (제품 1~100)
| 사이클 | X | Y | 동작 |
|---|---|---|---|
| 1 (시작) | 00001(보드1) | **빈칸=더미** | 보드1 X검사 / **Y스킵** |
| 2 | 00002 | 보드1 | 보드2 X / 보드1 완성 |
| … | … | … | … |
| 100 | 00100 | 보드99 | 보드100 X / 보드99 완성 |
| 101 (마감) | **빈칸=더미** | 보드100 | **X스킵** / 보드100 완성 |

### Day 2 (제품 101~200) — 동일 패턴
- 시작: X=00101 / Y=빈칸 → 마감: X=빈칸 / Y=00200
- X 시작번호는 시리얼 파일에서 auto-increment(101)로 이어받음

### 스킵 규칙 (대칭)
> **"그 축 시리얼칸이 비면 → 그 축 proc 스킵."**
> - 시작 사이클: Y 빈칸 → Y 스킵
> - 마감 사이클: X 빈칸 → X 스킵
> - 가운데: 둘 다 차있음 → 둘 다 검사
> - 빈칸은 "스킵"이지 "0"이 아님 → 0 발급 원천 차단

---

## 4. 설계

### 4-1. 축 proc 식별 (스킵 대상)
워크스페이스 proc 분석 결과:
- **Y축 proc:** `uart_id`가 `uart_*_y` (예: #8/#9/#9-1/#11/#11-1/#12) **OR** name에 `"Y축"` 포함(모션 #7/#10/#14)
- **X축 proc:** name에 `"X축"` 포함 (#2~#6 등)
- **공통 proc:** #0 통신검사 등 — 스킵 안 함 (양축 모두 대상이거나 무관)
- ⚠️ #3(X)·#10(Y) `id` 동일(`MOTION_ZERO_485`) → **name "X축"/"Y축"으로만 구분**

**식별 규칙 (확정 — 여러 신호 OR, 단일 신호 의존 X):**
- **Y결합 판정** = `uart_id`에 `_y` 포함 **OR** proc `id`에 `_Y_` 포함 **OR** name에 `"Y축"` 포함
- **X결합 판정** = name에 `"X축"` 포함
- **공통**(#0 통신 등, X/Y 표식 없음) = 스킵 안 함
- 셋 중 하나만 맞아도 Y로 인식 → name이 바뀌어도 uart_id/id로 잡힘(견고). JSON 꼬리표 불필요(코드만).

### 4-2. 빈칸 축 스킵 (실행 루프)
- `serialNumberY`가 빈값이면 → **Y축 proc 실행 직전 스킵** (현재 fallback 로직 2711~2723 대신)
- `serialNumber`(X)가 빈값이면 → **X축 proc 스킵** (마감 사이클)
- 스킵 처리는 기존 메커니즘 재사용 가능: 해당 proc을 "Skip"으로 표기(2768~2774행 흐름) + `skipCount++` + continue
- 공통 proc(#0 등)은 X·Y 중 하나라도 있으면 실행

### 4-3. 0(범위밖) 차단 (다이얼로그 검증)
- `ShowDualSerialDialog` 확정(2079~) 후: X/Y 각각 **숫자부가 1 미만이면 차단** + 안내("시리얼은 00001 이상")
- **빈칸은 허용**(=스킵 대상) — 0과 빈칸은 다름
- 상한 9999999는 MaxLength 11로 이미 제한
- Y −버튼 minVal 0→1 (2060행), 손으로도 0 못 내려감

### 4-4. X=Y 동일 시리얼 차단 (다이얼로그 검증)
- X·Y 둘 다 비어있지 않고 **완전히 같은 문자열이면 차단** + 안내("X·Y 시리얼이 동일합니다")
- 기존 "X=Y+1 경고"(2111~)와 별개의 **강한 차단**으로 추가

### 4-5. 기본값/초기화에서 0 제거
- 2013행: `prevNum > 0` → **`prevNum > 1`** (X=1일 때 Y를 0으로 안 만들고 빈칸 유지=첫사이클)
- 2070행(초기화): Y `"00000"` → **`""`**(빈칸)

## 6. 검증 계획 (485 실기)

1. **새 PC 시뮬(시리얼 파일 삭제) 첫 가동:** X=00001 자동 / Y=빈칸 → #9 등 **Y항목 스킵**, 0 전송 없음, FAIL 없음
2. **정상 사이클:** X=N / Y=N-1 둘 다 검사
3. **마감 사이클:** X 빈칸 / Y=마지막번호 → X항목 스킵, Y 완성
4. **Day2 이어받기:** 시리얼 파일 보존 시 X=101 자동
5. **0 차단:** Y에 00000 입력 → 차단 메시지(전송 안 함)
6. **X=Y 차단:** X=00005/Y=00005 → 차단 메시지
7. 회귀: 기존 듀얼 정상 사이클(둘 다 차있음) 영향 없음
