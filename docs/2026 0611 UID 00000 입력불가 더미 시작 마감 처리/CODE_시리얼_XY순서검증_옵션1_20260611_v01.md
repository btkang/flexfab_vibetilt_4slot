## 1. 배경 / 문제

### 기존 X=Y+1 검증이 죽은 코드였음
- 위치(구): `serialNumber.All(char.IsDigit) && serialNumberY.All(char.IsDigit)` 조건
- `VL2-00003` 같은 양산 시리얼은 접두사 `VL2-` 때문에 `All(char.IsDigit)` = **false**
- → 순수 숫자(`00003`)일 때만 발동 → **양산(접두사 필수)에서는 절대 작동 안 함**
- 결과: 실제로는 X와 Y 번호 차이가 얼마든 그냥 통과 (X=Y 동일만 별도 차단)

### 밀어내기식 물리 원리
- 보드가 X자리 → Y자리로 한 칸씩 밀림
- **이번 Y = 직전 사이클의 X** → 정상이면 항상 **X = Y + 1**
- 어긋나는 경우:
  - `Y < X-1` (번호 건너뜀): 보드 빠짐 / 불량 재투입 / 수동 건너뜀
  - `Y ≥ X` (역행): 거의 오입력

## 2. 결정 (옵션 1)

> **Y = X-1만 정상, 어긋나면 경고(진행 가능)**

| 옵션 | 채택 |
|---|---|
| 1. Y=X-1만 정상, 어긋나면 **경고** | ✅ **채택** |
| 2. 어긋나면 차단 | ❌ 정상 재검도 막혀 운영 불편 |
| 3. 역행(Y≥X)만 차단 | ❌ Y가 한참 작은 오입력 못 잡음 |
| 4. 검증 안 함 | ❌ 추적성 없음 |

**선정 이유:**
- 밀어내기식은 X=Y+1이 깨지면 보드 추적 어긋난 신호 → 정확히 1 차이 기준 검증이 의미 있음
- 차단은 과함: 불량 재검·수동 건너뜀 같은 정상 예외에서 라인 멈춤 리스크
- 경고는 작업자에게 판단을 넘김 → 추적성 + 유연성 균형

## 3. 구현 변경점

### 3-1. 죽은 코드 제거 + 위치 이동
- 기존 `X = Y+1` 블록(작은 `MessageBox`, `All(char.IsDigit)` 조건)을 **삭제**
- **X=Y 동일 차단 블록 뒤**로 재배치
  - 차단(동일)이 먼저 → 그 외 어긋남만 경고 → 중복 제거

### 3-2. 새 검증 로직 (FlexfabForm.cs ~2160)
```csharp
// X = Y+1 확인 (밀어내기식: Y=직전 사이클 X → 정상이면 X=Y+1)
// 접두사(VL2-) 떼고 숫자부만 비교. 양 축 모두 있을 때만(시작/마감 단축 사이클은 제외).
// 어긋나면 경고(진행 가능) — 불량 재검·수동 건너뜀 등 정상 예외는 작업자가 Yes로 진행.
if (serialNumber != "Null" && !string.IsNullOrEmpty(serialNumberY))
{
    string xN = serialNumber; int xd = serialNumber.LastIndexOf('-');
    if (xd >= 0 && xd < serialNumber.Length - 1) xN = serialNumber.Substring(xd + 1);
    string yN = serialNumberY; int yd = serialNumberY.LastIndexOf('-');
    if (yd >= 0 && yd < serialNumberY.Length - 1) yN = serialNumberY.Substring(yd + 1);
    if (xN.All(char.IsDigit) && yN.All(char.IsDigit) &&
        long.TryParse(xN, out var xNum) && long.TryParse(yN, out var yNum) &&
        xNum != yNum + 1)
    {
        string hint = xNum <= yNum ? "(역행 의심: X가 Y보다 작거나 같음)" : "(번호 건너뜀)";
        var answer = ShowLargeYesNoDialog(
            $"시리얼 순서가 맞지 않습니다.\nX축: {serialNumber}, Y축: {serialNumberY}\n정상: X = Y + 1  {hint}\n\n계속 진행하시겠습니까?");
        if (answer == DialogResult.No) return false;
    }
}
```

### 3-3. 개선 포인트
| 항목 | 변경 |
|---|---|
| 접두사 처리 | `LastIndexOf('-')` 로 접두사 떼고 숫자부 비교 → **실제 작동** |
| 적용 범위 | `serialNumber != "Null" && Y 비어있지 않음` → 시작/마감 단축 사이클(한 축 빈칸) 제외 |
| 팝업 | 작은 `MessageBox` → `ShowLargeYesNoDialog` (양산 현장용 큰 팝업) |
| 방향 힌트 | `Y≥X` → "역행 의심" / `Y<X-1` → "번호 건너뜀" 구분 표시 |
| 순서 | X=Y 동일 차단 **뒤로** 이동 (중복 경고 제거) |

## 4. 최종 검증 순서 (다이얼로그 확정 후)

1. 접두사 검증 (`serial_prefix_check`)
2. 숫자 < 1 / 5자리 미만 차단 (FW 2.0.3)
3. 양쪽 빈칸 차단
4. **X = Y 동일 차단**
5. **X = Y+1 경고** ← 본 변경 (진행 가능)

## 5. 테스트 케이스

| 입력 | 기대 동작 |
|---|---|
| X=VL2-00006 / Y=VL2-00005 | 경고 없이 통과 (정상 X=Y+1) |
| X=VL2-00010 / Y=VL2-00005 | "번호 건너뜀" 경고 → Yes 진행 / No 취소 |
| X=VL2-00005 / Y=VL2-00010 | "역행 의심" 경고 |
| X=VL2-00001 / Y=빈칸 (시작) | 경고 없음 (단축 사이클) |
| X=빈칸 / Y=VL2-00100 (마감) | 경고 없음 (단축 사이클) |
| X=VL2-00005 / Y=VL2-00005 | X=Y 동일 **차단** (경고 단계 도달 전) |
