  • RS-232(VL10) 대비 RS-485 통신 차이 확인
  • 센서 데이터 정상 수신 및 판정 기준 확립

1.2 전제 조건

  • Step 1 (VL10 RS-232 보드레벨 검사) 완료 ✅

1.3 범위

  • 대상: VL20 보드 (RS-485)
  • 검사 항목: 5개 (VER, SENTEMP, APPCFG, VIBE, TILT)
  • 제외: 제품 레벨 검사, VL30 검사

2. 하드웨어 및 통신 설정

2.1 통신 방식 비교

구분 VL10 (Step 1) VL20 (Step 2)
통신 방식 RS-232 RS-485
COM 포트 COM3 COM10
Baudrate 115200 115200
주소(ID) 없음 ID=1 (고정)
응답 형식 [CMD,data...] [CMD,1,data...]
통신 모드 1 2

2.2 RS-485 특성

  • 멀티드롭 지원: 여러 장비 연결 가능 (주소로 구분)
  • ID(주소): 기본값 1 (읽기 전용, 검사 시 변경 불필요)
  • 송신 명령: RS-232와 동일 (<VER>, <GAC> 등)
  • 수신 응답: 첫 번째 필드에 ID 포함

2.3 하드웨어 연결

PC (COM10) ←→ RS-485 컨버터 ←→ VL20 보드

3. 검사 항목 및 시퀀스

3.1 검사 항목 목록

No 검사 ID 검사명 목적 예상 시간
1 VER_485 버전 통신검사 기본 통신 확인 1초
2 SENTEMP_485 센서온도 검사 온도 센서 동작 확인 1초
3 APPCFG_485 Config 확인 설정값 검증 2초
4 VIBE_485 진동검사 가속도 센서 동작 확인 5초
5 TILT_485 기울기검사 기울기 센서 동작 확인 5초

4. 검사 항목별 상세

4.1 VER_485: 버전 통신검사

목적: RS-485 기본 통신 및 펌웨어 버전 확인

시퀀스:

1. TX: <VER>
2. RX: [VER,1,<버전정보>]
3. 판정: "VER" 문자열 포함 여부

예상 응답:

[VER,1,VL20_FW_v1.2.3]

PASS 조건: - 응답에 "VER" 포함 - RV=1 (정상 수신) - 타임아웃 5초 이내 응답

주의사항: - RS-232 응답 [VER,0,...]과 달리 ID=1 포함

4.2 SENTEMP_485: 센서온도 검사

목적: 온도 센서 정상 동작 확인

시퀀스:

1. TX: <SENTEMP>
2. RX: [SENTEMP,1,<온도값>]
3. 판정: 온도 범위 20~40°C

예상 응답:

[SENTEMP,1,25.3]

PASS 조건: - RV=1 - 온도: 20°C ≤ temp ≤ 40°C - 타임아웃 5초 이내

주의사항: - 응답 파싱 시 ID 필드(offset=2) 고려 - parts[2]에서 온도값 추출

4.3 APPCFG_485: Config 확인

목적: 장비 설정값 검증 (통신 모드, Baudrate 등)

시퀀스:

1. TX: <MODE,0>
2. RX: [MODE,1,00]
3. TX: <APPCFG>
4. RX: [APPCFG,1,00/10/2/115200]
5. 판정: 설정값 일치 여부

예상 응답:

[MODE,1,00]
[APPCFG,1,00/10/2/115200]

PASS 조건: - MODE,0 응답: [MODE,1,00] - APPCFG 응답: 통신모드=2, Baudrate=115200 포함 - RV=1

주의사항: - 통신 모드 필드: RS-232(1) → RS-485(2) - expected_response 비교 시 ID 고려

4.4 VIBE_485: 진동검사

목적: 가속도 센서 정상 동작 및 진동 데이터 범위 확인

시퀀스:

1. TX: <MODE,0>   (초기화)
2. TX: <MODE,2>   (진동 모드)
3. TX: <SAM,10>   (샘플링 10ms)
4. TX: <START>    (측정 시작)
5. 반복: TX: <GAC>, RX: [GAC,1,X,Y,Z,RMS]
6. TX: <STOP>
7. TX: <MODE,0>   (모드 복귀)
8. 판정: PASS 조건 충족 여부

예상 응답 (데이터 수집 중):

[GAC,1,0.05,0.03,1.02,0.58]
[GAC,1,0.04,0.02,1.01,0.57]
...

PASS 조건: - 1축(중력 방향): 0.9 ≤ value ≤ 1.1 - 0축(나머지 축): -0.1 ≤ value ≤ 0.1 - RMS: 0.5 ≤ rms ≤ 0.65 - 연속 5회 PASS 샘플 감지 - 타임아웃: 5초

주의사항: - RS-485 응답 파싱: parts[2~5] = X,Y,Z,RMS (offset=2) - RV=1 확인 (비정상 RV 프레임 무시)

4.5 TILT_485: 기울기검사

목적: 기울기 센서 정상 동작 및 alive 확인

시퀀스:

1. TX: <MODE,0>   (초기화)
2. TX: <MODE,6>   (기울기 모드)
3. TX: <SAM,10>   (샘플링 10ms)
4. TX: <START>    (측정 시작)
5. 반복: RX: [AN,X,Y] (스트림 수신)
6. TX: <STOP>
7. TX: <MODE,0>   (모드 복귀)
8. 판정: alive_check 통과 여부

예상 응답 (데이터 수집 중):

[AN,45.2,1.3]
[AN,45.5,1.4]
...

PASS 조건 (alive_check 모드): - X축 변화폭(ΔX): ≥ 0.2 - Y축 변화폭(ΔY): ≥ 0.2 - 연속 1회 이상 조건 충족 - 타임아웃: 5초

주의사항: - RS-485 응답: [AN,X,Y] (ID 없음, 스트림 데이터) - alive_check=true 설정 확인

5. RS-232 vs RS-485 차이점 요약

5.1 응답 포맷 차이

명령 RS-232 (VL10) RS-485 (VL20)
VER [VER,<ver>] [VER,1,<ver>]
SENTEMP [SENTEMP,0,25.3] [SENTEMP,1,25.3]
MODE,0 [MODE,0,00] [MODE,1,00]
APPCFG [APPCFG,0,00/10/1/115200] [APPCFG,1,00/10/2/115200]
GAC [GAC,X,Y,Z,RMS] [GAC,1,X,Y,Z,RMS]
AN [AN,X,Y] [AN,X,Y] (동일)

5.2 코드 처리 차이

VibeTilt.cs: - isRs485 플래그로 분기 - RS-485: offset=2 (ID 필드 건너뛰기) - RS-232: offset=1

예시 (GAC 파싱):

// RS-232: parts[1,2,3,4] = X,Y,Z,RMS
// RS-485: parts[2,3,4,5] = X,Y,Z,RMS (parts[1]=ID)
