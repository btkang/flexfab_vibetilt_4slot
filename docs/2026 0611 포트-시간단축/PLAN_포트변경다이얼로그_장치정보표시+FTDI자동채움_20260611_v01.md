## 1. 배경 / 문제

현재 포트 변경 다이얼로그는 **COM 번호만** 보여주고, "그 COM이 어떤 장치인지"는
**장치관리자를 따로 열어 하나씩 대조**해야 함. 이 수동 대조 과정에서 X/Y 스왑 사고 발생.

### 실측 하드웨어 (2026-06-11, Get-PnpDevice)

| 디바이스 | COM | 칩 | 식별자 | 고유 시리얼 |
|---|---|---|---|---|
| 232 X | COM13 | Prolific PL2303GC | `VID_067B&PID_23A3` + Hub3-Port1 | ❌ (위치만) |
| 232 Y | COM14 | Prolific | Hub3-Port2 | ❌ |
| 232 자이로 | COM15 | Prolific | Hub3-Port3 | ❌ |
| 485 자이로 | COM16 | Prolific | Hub3-Port4 | ❌ |
| 485 Y | COM4 | **FTDI** | `FTDIBUS\...+A947PITEA` | ✅ A947PITEA |
| 485 X | COM17 | **FTDI** | `FTDIBUS\...+A93OWJK3A` | ✅ A93OWJK3A |

- Prolific 4개: `VID_067B&PID_23A3` 동일, **칩 시리얼 없음** → USB 허브 포트 위치로만 구분.
- FTDI 2개: **칩 고유 시리얼** 있음 → COM 번호 바뀌어도 시리얼로 추적 가능.

## 2. 목표 (이번 작업 범위)

1. **장치정보 인라인 표시** — 다이얼로그에서 각 COM이 무엇인지(칩/시리얼/위치) 바로 보이게.
   장치관리자 왕복 제거.
2. **FTDI 자동채움 버튼** — 485 X/Y를 FTDI 시리얼 기준으로 자동 입력.
   스왑 사고 원천 차단.
3. Prolific(232 전부 + 485 자이로)은 **표시만** (시리얼 없어 자동 불가, 위치 근거 제공).

### 비범위 (이번에 안 함)
- 앱 시작 시 전체 자동바인딩 ❌ (사용자 보류)
- `uart.cs` Connect 재시도/정체성 프로브 ❌ (별도 건)
- 232 Prolific 자동화 ❌ (시리얼 없음 → 라벨링 운영으로)

## 3. 구현 설계

### 3-1. 장치 열거 헬퍼 (신규 파일, read-only) — **결정: 레지스트리 방식 / 별도 파일**
- **새 파일** `flexfab_mini/PortDeviceScanner.cs` (static helper, Form 비의존).
  → 스캐너/매칭 로직은 FlexfabForm에서 100% 분리. FlexfabForm은 이 헬퍼를 호출만.
- **레지스트리 방식 (의존성 0, `System.Management` NuGet 불필요 → .csproj 무변경):**
  - `HKLM\HARDWARE\DEVICEMAP\SERIALCOMM` → 현재 present COM 목록.
  - `HKLM\SYSTEM\CurrentControlSet\Enum\FTDIBUS\...` → FTDI 시리얼.
  - `...\Enum\USB\VID_067B&PID_23A3\...` LocationInformation → Prolific 허브 포트 위치.
- 결과 구조: `{ com, kind(FTDI/Prolific/기타), serial(nullable), location }`.
- ⚠️ 헬퍼 파일은 `flexfab_mini`(공유 코어 폴더)에 위치하나, **신규·자기완결·기존코드 무수정·API 무변경** →
  공유 코어 중 가장 가벼운 추가(다른 프로젝트가 참조 안 함).

### 3-2. 다이얼로그 UI 추가 (`ShowPortChangeDialog`)
- 상단에 **"현재 꽂힌 포트" 목록** 표시 (위 헬퍼 결과).
- 각 입력 행 옆에 **현재 입력된 COM의 정체**를 라벨로 표시 (입력 변경 시 갱신).
- 하단에 **[자동(FTDI)]** 버튼:
  - JSON config의 `serial` 값과 열거된 FTDI 시리얼을 매칭 → 해당 COM을 textbox에 채움.
  - 매칭 실패 시 해당 행에 경고 표시(시리얼 미발견).
- 기존 −/+ 버튼, 적용/취소, JSON 저장 로직은 **그대로 유지** (시그니처/플로우 변경 없음).

### 3-3. JSON 변경 — `serial` 필드 추가
485 워크스페이스의 FTDI UART 2개에 `serial` 추가 (Prolific엔 추가 안 함):
```json
"uart_485":   { "port": "COM17", "serial": "A93OWJK3A", "_serial_comment": "485 X축 FTDI 고유시리얼 — 자동채움 기준, COM 드리프트 무관", ... }
"uart_485_y": { "port": "COM4",  "serial": "A947PITEA", "_serial_comment": "485 Y축 FTDI 고유시리얼", ... }
```
- `serial`은 `uart.cs SetConfig`가 **무시**(알려진 키만 읽음, base.SetConfig는 저장만) → throw 없음, 통신 영향 0.
  ✅ 확인 완료: `_` 접두어 불필요, `serial` 평문 사용.
- **적용 대상 (결정: 모션 먼저):** `MP_workspace_motion_485_VL20.json` +
  `TEST_workspace_motion_485_VL20.json`, **Debug + Release 양쪽**. board/MP·TEST는 후속.
- ⚠️ 시리얼은 **이 PC의 특정 FTDI 케이블 2개에 종속** — 케이블/PC 교체 시 갱신 필요(주석 명기).
