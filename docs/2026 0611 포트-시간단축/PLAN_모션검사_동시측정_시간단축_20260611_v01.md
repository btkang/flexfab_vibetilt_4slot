## 1. 핵심 아이디어 — 두 시료가 같은 플레이트라 "동시 측정" 가능

현재는 **완전 순차**: X결합 시료(COM17) 풀세트 완주 → Y결합 시료(COM4) 풀세트. 그래서 **한 모터가 각도 sweep을 사실상 2번** 한다. 시간의 ~51%가 기울기 8각(X 4 + Y 4) FINE 수렴(모터 회전+자이로)이고, 이건 모터의 물리 이동이라 더 못 줄인다 — 가 기존 결론.

**그러나 지그는 한 강체 빔/한 모터/한 회전축이다.**

### 실물 기하 (사진 확정)
`docs/2026 0330-motion-real_jig/2026-0331 진동모션지그/KakaoTalk_20260331_145300019_02.jpg`
- 왼쪽 모터+원판(홈센서)이 긴 알루미늄 빔을 **장축 기준 롤**.
- 그 한 빔 위에 `X`/`Y` 플레이트가 **나란히 볼트 체결**.
- 빔을 θ 롤 → **두 시료가 함께 기울어짐**. 측정축(X시료 X / Y시료 Y)이 둘 다 빔 가로방향으로 정렬 → 같은 물리 롤이 양쪽에 동일 크기 θ로 나타남(Y는 90° 안착이라 **부호 반전**).

### 사용자 추가 확정 (2026-06-11)
- **기울기**: X결합·Y결합이 물리 방향·순서 동일(왼쪽 2 / 오른쪽 2). JSON 부호 차([-20,-45,20,45] vs [20,45,-20,-45])는 판정용일 뿐, 방문하는 **물리 위치는 동일** → 한 sweep으로 합침.
- **진동**: `#7`(라벨 +90)·`#15`(라벨 −90)이 **같은 물리 위치**. 둘 다 `target_angle:-90, move_axis:Y` → `AngleToSteps(-90,"Y") = -800 step`(오른쪽/시계 90°). 그 한 위치에서 X결합 Y축(1G) + Y결합 X축(1G) **동시 측정** 가능. (라벨만 다르고 step 계산상 동일 — 이전 "동시화 불가" 판단은 라벨만 본 오류.)
- **Z(0°, #13)**: 양쪽 0°라 동시 측정 후보.

### 결론
셋업(영점/CAL/SAVE)을 양쪽 먼저 끝낸 뒤, **모든 모터 정지점(0°·기울기 4각·오른쪽 90°)을 한 번씩만 방문하고 매 정지점에서 양 포트 동시 측정** → 모터 이동 전반 절반.

## 4. 변경 상세 (Phase 1~2)

### (a) MotionJig.cs — 신규 dual 메서드 (기존 재사용 최대)
- `MotionNewInternal`(MotionJig.cs:550 measureType 분기)에 `"tilt_dual"`/`"vibe_dual"` 케이스 추가.
- **`RunVibeMeasureDual`**: `RunVibeMeasure`(~1200) 복제·확장. 한 물리 위치(−800step 또는 0°)로 1회 이동 후 두 포트를 각 `check_axis_index`로 동시 측정·판정. #7+#15가 같은 −800step이라 한 이동으로 둘 다. (90°/0°는 FineAdjust skip이라 setdir 무관 — 가장 깔끔)
- **`RunTiltMeasureDual`**: `RunTiltMeasure`(896) 복제·확장. 변경점만:
  - `vlP=ResolveComm(libraries,primary_uart)`, `vlS=ResolveComm(libraries,secondary_uart)` 둘 다 확보(시그니처에 `libraries` 추가).
  - sweep 루프(952)·coarse 이동·FineAdjust(setdir6/primary 기준)는 **그대로 1회**.
  - 측정 블록(1012-1031)을 **포트별 순차 스트리밍**: primary `(vlP, primary_axis, gyroAngle)`, secondary `(vlS, secondary_axis, secondary_gyro_sign*gyroAngle)`. 모터 정지라 순차여도 시간손해 미미, 버퍼 간섭 0.
  - 판정 switch(1052-1103)를 헬퍼 `JudgeOnePort(...)`로 추출해 두 번 호출(tilt·vibe 공용, 신규 판정로직 없음).
  - retry 루프(1008): **포트별 pass 플래그 latch**. `anglePass = pPass && sPass`. 한쪽 PASS면 재측정서 보존.
- 순수 신규: `RunTiltMeasureDual` + `RunVibeMeasureDual` + `JudgeOnePort`. 스트리밍/파싱 헬퍼는 포트 인자만 바꿔 재호출.

### (b) JSON — 셋업 전진배치 + dual proc (Debug+Release 동시, 232/485 양쪽)
```
#0 COMM(양포트) → FWVER/UID(X) → X영점(setdir6,home) → OFFSET/SAVE/VIBE_STILL(X)
→ FWVER/UID/REFTEMP(Y) → Y영점(setdir5,skip_home) → OFFSET/RCONF/SAVE(Y)
─ 양쪽 CAL/SAVE 완료 (이후 정지점 1회 방문, 매 점 양 포트 동시) ─
→ VIBE_Z_DUAL  (0°: X결합 Z + Y결합 Z. X결합 VIBE_STILL p2p도 0°라 흡수 가능)
→ ★TILT_DUAL   (setdir6 재설정 후 sweep 4각: X결합 X축 + Y결합 Y축 동시)
→ ★VIBE_90_DUAL(−800step=오른쪽 90°: X결합 Y축 1G + Y결합 X축 1G 동시) ← #7+#15
→ APPCFG(Y)
```
- TILT_DUAL param: `measure_type:"tilt_dual"`, `primary_uart/axis`, `secondary_uart/axis`, `secondary_gyro_sign`(Phase0 확정), `gyro_dir:"setdir6"`, `angles:[-20,-45,20,45]`, tolerance/판정 기존과 동일.
- VIBE_90_DUAL param: `measure_type:"vibe_dual"`, `target_angle:-90, move_axis:Y`, `primary_uart=uart_485/check_axis_index:1(Y)`, `secondary_uart=uart_485_y/check_axis_index:0(X)`, vibe_min/max 기존.
- TILT_DUAL 진입 시 자이로 setdir6 재설정(Y셋업이 setdir5로 끝나므로). 안 하면 FINE 발산 가드(30°, MotionJig.cs:1570) 위험.

### (c) 결과 귀속 동기화 (FlexfabForm.cs — 가장 조심)
- 이름 prefix 분기 두 곳(1416-1417, 2976-2978)을 재배치 proc 이름과 동기화.
- dual proc은 X·Y 양쪽 결과 생성 → 이 분기를 "한 proc이 양축 결과 분배" 가능하도록 확장. **러너 핵심 루프는 무변경**, 이 분기만.

## 7. 검증 (end-to-end)

1. **Phase 0**: 현행 빌드 풀런 1회 → 로그/CSV에서 두 포트 AN 부호 관계 + Y시료 spec 적합 확인.
2. **Phase 1**: measure_only dual로 풀런 N회 → secondary 데이터 축적, 재현성(p2p) 확인. 판정 영향 0 확인.
3. **Phase 2**: 판정 ON 풀런 1회 → 전 각도/90° 양 포트 PASS + 시간 측정(목표 ~2m00 이하). FAIL 시 한쪽-FAIL latch 동작 확인.
4. 232/485 각각, Debug 검증 후 **Release 동시 반영(JSON 두 경로)**. 빌드는 사용자 VS2022 Release.
