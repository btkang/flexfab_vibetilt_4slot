## 1. 배경 (Context)

양산 라인 이관(2026-06-22 완료, 6-23 이원준 주임 테스트) 후 작업자 피드백:

- 검사 중 **FAIL**이 나면 *어느 항목이 왜 떨어졌는지* 알려면 오른쪽 **로그창(`listBox_Log`)** 을
  뒤져야 하는데, 로그가 너무 많아 작업자가 읽기 힘들다.
- 작업자는 **검사항목 번호·이름** 정도만 받아 적을 수 있고, 상세 내용은 적기 어렵다.

### 요구사항
FAIL 발생 시 다음을 작업자가 **한눈에 띄게** 볼 수 있어야 한다.
1. **어느 축** (X / Y)
2. **어느 검사항목** (번호 + 이름)
3. **무슨 내용** (측정값 / 스펙 범위)

> 검사항목 이름에 축(X축/Y축) 표기는 **사용자가 이미 정리해 넣음** → 축 구분의 큰 줄기는 해결됨.
> 남은 것은 ① 그 정보를 **눈에 띄는 위치**에 띄우는 것 ② X·Y 동시측정 항목의 **원인 축 구분**.

### 대원칙
- **판정 결과(PASS/FAIL) 자체는 절대 변경하지 않는다.** 표시·분류만 정밀화.
- **workspace JSON 변경 없음.** 프레임워크/플로우/public API 변경 없음.

## 2. 현황 분석 (코드 근거)

### 2.1 검사 실행 루프 — `flexfab_mini/FlexfabForm.cs` `DoProject()` (≈2744~2999)
항목마다 아래 정보를 **이미 보유**한다.

| 정보 | 출처 | 비고 |
|---|---|---|
| 검사항목 번호 | 루프 인덱스 `i` | 그리드 행 번호와 일치 |
| 검사항목 이름 | `proc.name` | 사용자가 정리한 축 표기 포함 |
| 성공/실패 | `isSuccess` (2935~2937) | retmsg.success 기반 |
| 상세 결과 | `res["retmsg"]` (2940) | 측정값/스펙/실패사유 포함 |

- 현재는 **개수만 누적**: `failCount++` (2958, 2978, 2990, 2997, 2930).
  → **실패 항목 목록은 모으지 않음.** (개선 A에서 추가)
- retmsg는 그리드 결과셀 `Tag`에만 저장(2948) → 더블클릭(2422~2441)해야 상세가 보임.

### 2.2 결과 상세 구조 — `retmsg` (각 검사 메서드 `MakeResult` 반환)
```jsonc
{
  "Name": "기울기검사 Y축 RS-485",
  "id": "TILT_Y_485",
  "details": [
    { "item": "기울기 Y", "value": 0.42, "min": 0.50, "max": 0.65, "result": "NG" },
    { "item": "실패사유", "value": "PASS 조건 미충족 (TIMEOUT ...)", "result": "NG" }
  ],
  "result": "NG"
}
```
→ **측정값 / 스펙범위 / 실패사유가 이미 다 들어있음.** 추출만 하면 됨.

### 2.3 FAIL 팝업 — `flexfab_mini/FailForm.cs`
- 빨강 전체배경 + "FAIL" 대형 글자. `label_result` 가 있고 `SetResult(string)` 로 텍스트 주입.
- 현재 `label_result` 는 **"총 결과: OK=.. FAIL=.. SKIP=.."** 만 표시(거의 미활용).
- 호출부: `FlexfabForm.cs` 3160 / 3182, 표시 메서드 `ShowFailForm()` 3363.

### 2.4 로그창 — `listBox_Log`
- 우측 대형 ListBox (Location 810,32 / Size 702x739). 작업자가 "보기 힘들다"는 그곳.
- **Log 표시/숨김 토글 기능이 이미 존재**(버튼 679, 단축키 Ctrl+Alt+X 116) → 재사용.

### 2.5 X/Y 축 구분 현황

## 3. 개선 설계 (권장안: 팝업 강조 + 그리드 자동포커스)

> 새 창을 만들지 않고, **이미 있는 빨강 팝업과 좌측 그리드**에 정보를 더 또렷이 넣는다.

### 표시 위치 (2곳)
```
메인화면
┌───────────────────────────────────────────────┐
│ ┌── DataGridView(좌) ──┐  ┌─ listBox_Log(우) ─┐ │
│ │ 14 │Y축기울기│ FAIL │  │  로그 많음        │ │
│ │    │  ▲자동선택/스크롤│  │  → FAIL시 자동숨김 │ │
│ └─────────────────────┘  └───────────────────┘ │
└───────────────────────────────────────────────┘
        ↓ 검사 종료 시 화면 중앙
   ┌────────── FailForm(빨강 전체배경) ──────────┐
   │   FAIL                                       │
   │   FAIL 항목:                                 │
   │    #14 Y축 기울기값   측정 0.42 / 스펙 .50~.65│
   │            [ OK ]                            │
   └─────────────────────────────────────────────┘
```

### A. 실패 항목 요약 수집 — `FlexfabForm.cs` `DoProject()`
- 루프 밖: `var failItems = new List<string>();`
- 모든 FAIL 지점(2930 / 2958(isSuccess=false) / 2977 / 2990 / 2997)에서 한 줄 누적:
  - retmsg 있으면 details에서 `result=="NG"` 인 첫 측정 행을 뽑아
    `$"#{i}  {proc.name}\n    측정 {value} / 스펙 {min}~{max}"`
  - retmsg 없거나 파싱 실패: `$"#{i}  {proc.name}"` (축·항목명은 이름에 이미 포함)
- retmsg 파싱은 기존 더블클릭 상세표시(2422~2441 인근)의 JSON 파서를 **재사용**.

### B. FailForm 팝업 강조 — `FailForm.cs` + 호출부(3160 / 3182)
- 호출 문자열 변경:
  ```csharp
  SetResult(
    "FAIL 항목:\n" + string.Join("\n", failItems) +
    $"\n\n총 결과: OK={okCount}, FAIL={failCount}, SKIP={skipCount}");
  ```
- `FailForm.cs`: `label_result` **폰트 확대(14~16pt Bold)** + 위치/크기 조정으로 여러 줄이
  빨강 배경에 또렷이. **컨트롤 신규 추가·레이아웃 재배치 없음** (기존 라벨 속성만 변경).

### C. 그리드 자동 포커스 + 로그 자동 숨김 — `DoProject()` FAIL 지점
- FAIL 확정 직후(2954 `UpdateDataGridView` 다음, Invoke 경유):
  ```csharp
  mainForm.dataGridView1.FirstDisplayedScrollingRowIndex = i;
  mainForm.dataGridView1.Rows[i].Selected = true;
  ```
- **첫 FAIL 시** 기존 Log토글을 재사용해 `listBox_Log` 자동 숨김(작업자가 그리드에 집중).
  디버깅용 토글은 유지(수동 복원 가능).
- 즉시중단 옵션(`checkBox_Process`, 2961)과 동작 순서 확인.

### D. (케이스 B) xy 동시측정 축 구분 — `ff_vibetilt/VibeTilt.cs` `TILT_Internal`
- **프로젝트별 라이브러리 → 자유 수정(공통모듈 무관).**
- `avgX`(또는 lastX)의 |값|이 `xMin~xMax` 이내인지, Y도 동일하게 **축별 bool 따로 계산**
  (절대값 판정 규칙 준수 — 부호 무시).
- FAIL 메시지/`details` 에 원인 축 명시: 예) X정상이면 "기울기 X" result=**OK**, "기울기 Y" result=**NG**.
- VIBE 동시측정 항목도 같은 패턴이면 동일 적용(선택).
- 이 축 정보가 retmsg에 정확히 담기면 A의 요약이 더 정밀해짐.
  (단, 대부분 항목은 이름에 축이 이미 있어 **필수는 아님 — 선택 보강**.)

## 7. 검증 절차

1. Debug 빌드 → `output/Debug/net8.0-windows` 에서 실행.
2. 232 / 485 각각 **의도적 FAIL** 유발(스펙 벗어난 기울기/진동):
   - 팝업에 `#번호 + 축포함 항목명 + 측정/스펙` 표시되는가
   - 좌측 그리드가 해당 행으로 스크롤·선택되는가
