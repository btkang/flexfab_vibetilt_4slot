## 1. 배경 / 문제 정의

REF v02 8절에서 확인된 구조적 문제:

1. **영점의 기계 기준 퇴화** — setzcur를 매 사이클 반복하면 자이로 영점이
   중력(공장 기준)이 아니라 홈센서+1250step 기계 자세를 추종. 기계가 서서히
   틀어지면(마모/풀림/침하, 사이클당 <0.03도) 영점이 1:1로 따라가며,
   기존 검사망(verify_an, ±20/±45 상대판정)은 common-mode라 전량 검출 불가.
2. **전원 리셋 무효** — setzcur는 비휘발 저장(datasheet p.2, p.6)이라
   재부팅으로 해소되지 않음. 유일한 소프트웨어 복원 수단은 `setzfac`
   (tare 취소, 공장 영점 복귀) — 현재 코드 미사용.
3. **flash 마모** — setzcur가 매 사이클 NVM write. 연 수만~수십만 회로
   일반 endurance(1만~10만)와 같은 자릿수. datasheet에 한도 미명시.

## 2. 대책 A — setzfac 주기 점검 (드리프트 측정 + 영점 복원)

### 2.1 원리

setzfac 직후 자이로 판독은 공장(중력) 기준 절대각이 된다. 이때 지그를
홈+1250step 자세에 두고 읽으면 **판독값 = 그동안 누적된 기계 드리프트**.

### 2.2 절차 (일 시작 점검, 지그별)

```
1. 홈복귀 + 1250 step 이동 (기존 InitMotionZero 앞부분 재사용)
2. setzfac 전송 → OK 확인
3. 자이로 판독 → drift 기록 (로그 + 결과 JSON)
   - |drift| ≤ 경고값: 정상
   - 경고값 < |drift| ≤ NG값: 경고 (추세 관찰, 품질모니터링 표시)
   - |drift| > NG값: NG — 라인 정지, 정밀 레벨 직접 확인 + 기구 점검
4. FineAdjust(target=0) — 공장 기준으로 진짜 수평 복원
5. setzcur — 복원된 수평을 새 영점으로 등록
6. 이후 기존 시퀀스 동일
```

한계값(안): 경고 0.1 / NG 0.2 — **초안임.** 홈센서 반복정밀도(1 step=0.1125도)가
바닥 노이즈이므로 실측 분포(1~2주 데이터) 수집 후 확정 필요.

### 2.3 구현 방안

- `MotionJig.cs`(ff_vibetilt 한정)에 setzfac 전송 함수 추가
  (`GyroSetZero` 패턴 재사용, 응답 "OK" 확인)
- 점검 전용 process(예: `MOTION_ZERO_CHECK_232`) 신설 또는
  `MOTION_ZERO_232`에 `zfac_check` 파라미터 추가 — **택1 사용자 결정 필요**
- 골든샘플 점검 workspace(`CHECK_workspace_golden_232.json` — 자매 PLAN 4.1)에
  #G2 영점 초기화 앞 단계로 편입하면 시업 점검 1회로 둘 다 수행 가능
- drift 값은 결과 JSON에 `zero_drift` + `_comment`로 기록 (JSON 주석 규칙)

## 3. 대책 B — cal 전 DUT 원시값 SPC 로깅 (상시 통계 감시)

### 3.1 원리 (REF v02 9절 Q6)

개체별 cal 전 원시 AN = 지그 기울기 + 개체 조립 오프셋(랜덤).
모집단 평균은 안정적 → 평균의 이동 = 지그 영점 드리프트. common-mode라
개별 판정으로 못 잡는 드리프트를 통계로 검출.

### 3.2 구현 방안

- `OFFSET_232/485`(VibeTilt.cs)에서 `<OFFSET,1>` 전송 **직전** AN 1초 수집 →
  판정 없이 결과 JSON에 `precal_an` 기록만 추가 (파라미터 `log_precal_an: true`
  옵션으로, 기본 off — 기존 동작 불변)
- 검사시간 영향: 약 +1초/대 (스트리밍 수집). 허용 여부 사용자 판단 필요.
  대안: verify_an 수집 루틴 재사용으로 코드 최소화
- 품질모니터링(tools/quality_monitor)에서 일자별 평균/표준편차 추세 그래프
  - 관리선(안): 이동평균이 초기 기준 대비 ±0.05 이탈 시 경고 — 실측 분포로 확정

## 4. 대책 C — setzcur 호출 빈도 재검토 (flash 마모 + 드리프트 동시 완화)

### 4.1 아이디어

setzcur를 매 사이클 → **일 1회**(대책 A 절차의 5번에서만)로 축소하면:

- flash write가 하루 1회로 감소 (마모 해소)
- 낮 동안 자이로 영점이 중력에 고정 → 매 사이클 FineAdjust가 기계 드리프트를
  흡수하는 대신 **실제로 보정** (8.3의 느린 열화 통과 경로가 사이클 단위로 차단)

### 4.2 대가 / 검토 필요

- 사이클마다 FineAdjust 잔차(≤0.03~0.05)를 setzcur로 지우지 못함 →
  VL cal 자세와 자이로 영점 간 오프셋으로 잔존, ±20/±45 판정 마진을 잠식
- 판정 spec(±0.2/±0.5) 대비 잔차 0.05는 25%/10% 수준 — 수용 가능성 있으나
  **verify_an(±0.05)은 잔차와 같은 크기라 재조정 필요** (예: ±0.08)
- 구조 변경이므로 실기기 검증 필수. 대책 A/B 안정화 후 2단계로 진행 권장
