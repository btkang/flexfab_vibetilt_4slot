1. 영점 초기화 순서 — InitMotionZero (MotionJig.cs:698)

기준(truth source)은 자이로(SOLAR-360-420)이며, 물리 수평을 먼저 찾은 뒤 → 자이로 영점(setzcur) 순서.

  1. 에러 클리어(PPC00) + soft limit ±8000 확장 (원점복귀 방해 방지)
  2. 자이로 방향 설정 — setdir6(X축 지그) / setdir5(Y축 지그)
  3. 대략 수평 복귀 — 자이로 20도 초과 기울면 -각도×0.8 역이동 (케이블 꼬임 방지)
  4. 홈 센서 원점복귀 — PMO011(IN1)/PMO012(IN2), notch 위 ACK4 시 escape 후 5회 재시도.
    완료는 자이로 폴링 "연속 2회 변화 <0.5도"로 정지 판정
  5. 홈 → 0도 고정 step 이동 — IN1: 1250 step, IN2: ~200 step (1 step = 0.1125도)
  6. FineAdjust(target=0) — 자이로 피드백 폐루프, strict ±0.03(10초) / relaxed ±0.05 수렴.
    여기가 "지그 수평" 확정 지점
  7. setzcur — 그 수평 자세를 자이로 0도 기준점으로 저장
  8. soft limit ±1600(=±180도) 운용값 재설정

핵심: setzcur를 FineAdjust보다 먼저 하면 안 됨 (MotionJig.cs:860 주석).
setzcur는 "현재 위치=0" 리셋이므로, 기울어진 상태에서 먼저 하면 기울어진 자세가 영점이 됨.

운용 최적화:
- 영점은 사이클당 1회(_zeroInitialized), FAIL 시 리셋
- X축: home_every_n=10 — 10회마다 1번만 홈복귀, 단 0도에서 7도 초과 이탈 시 강제 홈복귀
- Y축(#10): skip_home=true — X 측정 후 이미 0도 근처라 FineAdjust만 수행

2. 각도 측정 과정 — RunTiltMeasure (MotionJig.cs:896)

angles = X: [-20, -45, +20, +45] / Y: [+20, +45, -20, -45], 각 각도마다:

  1. Coarse 이동 — (목표−현재) 각도→step 환산 이동, 이동량 비례 대기
  2. FineAdjust — 자이로 피드백으로 목표각 ±0.05 수렴
  3. 자이로 실각도 읽기(get---x) → 판정 기준값(gyro_ref). 목표각이 아닌 실측값 기준
  4. VL 스트리밍 — STOP→버퍼클리어→MODE 06→START→settle 후 1000ms 수집, AN 파싱
  5. 안전체크 — |자이로−VL| ≥ 10도면 하드웨어 문제로 즉시 FAIL (리트라이 없음)
  6. 판정 — tail 10개 샘플, error = VL − 자이로 (MotionJig.cs:1057,1094).
    기본 all_in_spec(10개 전부 spec 이내). spec: ±20도→±0.2, ±45도→±0.5 (사양서).
    옵션 노이즈 P2P 체크
  7. 실패 시 스트리밍 재수집 리트라이 (기본 3회)

모터 step은 coarse 위치잡기용일 뿐, "몇 도인가"는 항상 자이로가 결정.
DUT 합격 여부는 자이로 실측값과의 편차로만 판정 → 진짜 상대(VL−자이로) 비교.

주의(혼동 방지): VibeTilt.cs의 TILT_Internal(TILT_232/485, TILT_X/Y)은
별개의 수동 기울기검사 항목이다 (작업자 확인 팝업 → DUT AN을 JSON 고정 범위
x_min~x_max/y_min~y_max와 비교, 자이로 미사용). 모션지그 ±20/±45 판정과 다르므로
문서/대화에서 "TILT"라는 이름만 보고 섞지 말 것.

4. 스펙 값 출처 정리 (0.03 / 0.05 / 0.2 / 0.5)

값 대상 출처
0.03 (strict) 자이로 수렴 (FineAdjust 10초 내) 검사 프로그램 자체 설정
0.05 (relaxed) 자이로 수렴 (10초 후 완화, 무한왕복 방지) 검사 프로그램 자체 설정
±0.05 (verify_an) DUT cal 후 AN 출력 검증 자체 검증값 (사양서 근거 없음 — 아래 참조)
±0.2 / ±0.5 ±20도 / ±45도 기울기 측정 판정 출하검사 사양서

확인된 사실 (2026-07-14): VL10 통신사양서(R8) 전문 검색 결과, OFFSET 절(4.2.4)에는
명령 형식과 동작 설명("Z축 1G, X/Y 기울기 0으로 설정"), 예시([AN,0,0.00,0.00])만 있고
±0.05 허용오차 스펙은 존재하지 않음. 문서 내 "0.05"는 THAC 범위(0.05~4.00G)로 무관.

따라서 기존 문서 CODE_Y축결합지그_최종검사_20260401_v02.html:91의
"(사양서 Calibration 스펙)" 표기는 오기. verify_an ±0.05는 지그 수평 잔여오차(자이로
relaxed 0.05)와 같은 크기로 잡은 자체 sanity check 값임. 본 판정(±0.2/±0.5)보다
타이트한 내부 품질 게이트 역할이라 실무상 문제는 없음.

5. Q&A (1차 — 영점의 의미)

Q1. setzcur의 "영점"이란? 공장초기화 값과 차이는?

영점 = "지금 이 자세를 앞으로 0도라고 부르겠다"는 사용자 기준점 설정(tare).
수평 그 자체가 아니라 "수평이라고 검증된(±0.03) 현재 자세".

자이로는 중력 기준 절대 기울기 센서라 공장 캘리브레이션 기준을 원래 보유.
FineAdjust는 자이로 판독값(현재 유효한 영점 기준)으로 0도를 찾아감.

  • 최초 1회(공장 영점 상태): 공장 기준과 setzcur 기준의 차이 = FineAdjust 수렴 잔차(≤0.03~0.05)
  • 반복 운용 후: 차이 = 누적된 기계 드리프트 (8절 — v02에서 정정/확장된 핵심)

setzcur의 실질 목적: 자이로 영점과 VL 영점을 같은 물리 자세에 일치시켜, 이후
±20/±45 상대 측정에서 잔차가 계통 오프셋으로 남지 않게 하는 것.

Q1-1. 그냥 공장초기화값으로 맞추면 안 되나?

"공장초기화값으로 맞추기"가 곧 FineAdjust다 — 자이로 판독은 공장 캘 기준이고 별도
기준이 없다. 대립하는 두 방법이 아님. setzcur를 생략하면 자이로 영점(공장)과 VL
영점(cal 자세)이 잔차만큼 어긋난 채 시작 → 모든 기울기 측정에 잔차가 계통 오프셋으로
들어가 VL 판정 마진을 잠식한다.

Q2. VL cal 시 자이로가 잘못되면 VL도 잘못되나?

맞음. <OFFSET,1>은 지금 자세를 VL 영점으로 저장.
VL은 자이로 "값"이 아니라 자이로로 수평을 만든 "지그 자세"를 물려받음:

진짜 수평(중력) → 자이로 공장캘 오차 → 자이로 장착(기구) 오차 → setzcur 영점 상태
             → FineAdjust 잔차(≤0.03~0.05) → 이 자세가 VL 영점

측정의 일반 원리: 기준기의 오차는 그 기준으로 검사한 모든 것에 똑같이 들어가고,
그 기준 자신으로는 검출할 수 없다. 판정(2절)이 "VL−자이로" 상대비교라 자이로 오차는
공통모드(common-mode)로 상쇄 — 전 제품이 같은 방향 바이어스로 전부 PASS하는 형태.
→ 자이로 자체를 상위 기준(외부 기준기/setzfac 공장영점)으로 주기 점검해야 하는 이유 (6절, 7절).

Q3. #11 cal 직후 자이로와 VL을 재면? 0.2 / 0.05 벗어날 수 있나?

거의 정확히 둘 다 0. 같은 자세에서 방금 자이로=setzcur, VL=OFFSET 했으므로.
남는 차이 = 센서 노이즈 + AN 분해능(0.01) + 그 사이 지그 미동.
실측(CODE 문서): AN = -0.003 ~ +0.001 수준.

  • 0.05 초과 = 비정상 (OFFSET 미동작/지그 이동/센서 불량) → verify_an이 FAIL 처리
  • 0.2 초과 = cal이 아예 안 된 수준의 고장. (±0.2/±0.5는 기울인 후 측정 스펙이라 국면이 다름)

Q4. 자이로를 수평 기준으로 믿을 수 있나? 베이스(버블수평계)가 틀어지면?

수평의 유일한 기준은 자이로. 버블수평계는 설치 보조일 뿐 검사 로직은 안 봄.

  • 베이스 기울어짐(측정축 방향): 자이로가 절대각을 재므로 FineAdjust가 보정.
    부작용은 홈→0도 고정 step(1250) 불일치로 시간 증가, 극단 시 수렴 실패/soft limit
    FAIL. 단, 서서히 진행되면 8절의 드리프트 흡수 경로로 조용히 통과될 수 있음.
  • 직교축 기울기: 1축 회전 지그라 보정 불가, 자이로(setdir 단축)도 감지 불가.
    <OFFSET,1>은 X/Y 모두 0으로 잡으므로 DUT가 직교 기울기를 영점으로 흡수할 여지.
  • 자이로 자체 오차: 아무도 커버 못 함 — 전량 공통 바이어스, 검사 검출 불가.

점검 우선순위: 버블수평계 < 자이로.

6. 자이로 틀어짐 주기 점검 방법

  1. 골든 샘플(기준 DUT) 점검 — 가장 실용적, 자동화 가능.
    과거 정상 시점에 cal 된 VL을 보관, 주기적으로 영점(#10)만 수행 후 OFFSET 없이 AN 읽기.
    자이로가 틀어졌으면 골든 샘플이 0이 아닌 바이어스 출력. 2개 이상 운용해
    (둘 다 이탈=지그/자이로, 하나만=샘플) 판별. → PLAN_골든샘플_자이로점검_20260714_v01.md
  2. 검교정 정밀 디지털 레벨(0.01도급)로 직접 확인 — 영점 완료 상태에서 회전판에 올려
    0인지 확인. 직교축 방향도 함께 점검. 주/월 정기점검
  3. 180도 반전법 — 자이로를 수직축 기준 180도 재부착 후 2회 읽기.
    (A+B)/2 = 자이로 오프셋. 기준면 불필요, 수작업. 연 단위/이상 의심 시
  4. 시스템 데이터 상시 감시 — 홈→0도는 기계적 상수이므로 FineAdjust 추가 보정량을
    결과 JSON에 남겨 품질모니터링 추세 관리. 이상 시 2번 점검 트리거
  5. setzfac 주기 점검 (v02 추가, 7~8절) — 공장 영점 복귀 후 판독값 = 누적 드리프트의
    직접 측정치. → PLAN_영점드리프트_대응_20260714_v01.md
  6. cal 전 DUT 원시값 SPC (v02 추가, 9절) — 검사시간 추가 없는 상시 통계 감시

권장 조합: 매일(시업) setzfac 점검+골든샘플 / 주·월 디지털 레벨 / 상시 보정량·SPC 추세 / 연 반전법·제조사 교정

7.1 setzcur는 비휘발 저장 — 전원 리셋으로 초기화 안 됨 (확정)

  • p.6: "The settings are all stored in non volatile memory." (명령 전체 공통)
  • p.2: "zero position is adjustable using RS232 commands. Settings are stored in
    non volatile memory and retained after shut down."

→ setzcur로 잡힌 영점은 전원 재인가로 리셋되지 않는다. 8절의 드리프트 흡수 상태가
전원 사이클과 무관하게 무기한 이어진다.

7.2 setzfac — 공장 영점 복귀 명령 존재 (현재 코드 미사용)

  • p.6: setzfac — "Cancels tare function and resets zero to factory setting"
  • tare(setzcur)만 취소. 방향(setdir)/필터/baud 등 다른 설정은 불변.
  • setzfac 직후 홈+1250step 자세에서의 판독값 = 누적 기계 드리프트의 직접 측정치
    (점검 지표로 활용 가능 — PLAN 참조)
  • 현재 코드(MotionJig.cs)는 setzcur만 사용, setzfac 미사용 (grep 확인)

7.3 센서 성능 스펙 (드리프트 상한 판단 근거)

항목 값 의미
Accuracy @20°C ±0.03° 고정 오차 상한
온도 영점 드리프트 ±0.002°/°C (무보상) / ±0.001°/°C (보상) 15°C 변동에도 0.015~0.03°

같은 자릿수. datasheet에 endurance 미명시.

8. setzcur 반복의 동역학 — 영점의 "기계 기준 퇴화" (v02 추가, 핵심)

질문: "매번 setzcur하면 영점이 매번 바뀌는데, 잔차가 서서히 쌓여 큰 각도까지 갈 수 있나?"

8.1 잔차 random walk로는 안 쌓인다

매 사이클: 홈센서 → +1250 step(기계적으로 고정된 자세 M) → FineAdjust → setzcur.
FineAdjust(MotionJig.cs:1508-1529)는 시작 판독이 이미 tolerance(±0.03) 이내면
모터를 안 움직이고 즉시 수렴 처리한다. 직전 setzcur가 M 근처를 0으로 정의해놨으므로
2번째 사이클부터는 사실상 무이동 → 그 자리에서 재-setzcur. 즉 영점은 M에 붙잡혀
(mean-reverting) ±0.03 밖으로 못 나간다. 잔차 누적으로 1도 → 불가.

8.2 대신 영점의 주인이 자이로에서 기계로 넘어간다

위 구조의 뒷면: 최초 setzcur 이후 중력(공장 기준)은 다시 검증되지 않는다.
setzcur가 매번 절대 기준 정보를 지우고, 자이로는 "직전 setzcur 대비 상대 인코더"로
퇴화한다. 영점의 실질 기준 = 홈센서+1250step 기계 자세. FineAdjust는 항상
"시작 오차 0.0x → 수렴 완료"만 찍으므로 로그도 깨끗하다.

8.3 기계 변화의 속도에 따라 갈린다

  • 급격한 변화 (충격 등 한번에 > tolerance): FineAdjust 시작 판독이 0.03을 벗어나
    모터가 실제로 움직여 기존 영점 자세(중력 기준 유지분)로 복원. 뚫리지 않음.
  • 서서히 변화 (마모·풀림·침하, 사이클당 < 0.03): 판독이 항상 tolerance 이내
    → 무이동 → setzcur가 틀어진 자세를 재등록. 소리 없이 통과, 복원력 없음, 계속 누적.

역설: 큰 사고는 잡히고, 양산 장비의 기본 노화 패턴인 느린 열화만 뚫린다.
7.1(비휘발)에 의해 이 상태는 전원 리셋으로도 해소되지 않는다.

8.4 결과 및 검출 불가성

기계 드리프트가 setzcur를 통해 영점에 새겨지면:
- VL cal(#11)이 그 자세를 영점으로 물려받음 (공통모드 — Q2)
- verify_an도 0.00x로 정상, ±20/±45 상대판정도 통과
- 기존 검사망 전체가 검출 불가. VL 출하 품질이 최종적으로 지그 기구 상태에 종속.

→ 대응: setzfac 주기 점검(7.2) + 상시 감시 지표(6절 4·6항).

9. 사고실험 — DUT cal 없이 각도를 재면? + SPC 아이디어 (v02 추가)

Q5(사고실험). 자이로만 영점 잡고 DUT는 cal 없이 각도를 재면? 불량 검출 가능한가?

cal 전 DUT는 자기 조립 오프셋(MEMS 납땜/PCB/하우징/장착 유격, 개체별 상이)을 갖는다.
지그 0도에서 판독 = 오프셋(≠0), +20도에서 = 20+오프셋.

  • 오프셋으로는 판정 불가: 정상품도 오프셋이 있고, 그걸 지우는 게 cal의 존재 이유.
    판정창을 좁히면 양품 사망, 넓히면 불량 통과.
  • 델타(변화량)로는 판정 가능: 0→+20도 이동량은 오프셋이 상쇄되어 cal 없이도 유효.
    감도/직선성/축방향 불량은 잡힘. (현 시퀀스도 cal로 오프셋을 0에 맞춘 뒤의 델타 판정 구조)

Q6. cal 전 원시값의 활용 — 모집단 SPC로 지그 드리프트 검출

개체별 원시값 = 지그 기울기 + 개체 조립 오프셋. 개체 오프셋은 랜덤이지만
수십~수백 대의 평균은 안정적 → 지그 영점이 0.1도 틀어지면 평균도 0.1도 이동.

즉 개별 판정으로 못 잡는 8.4의 common-mode 드리프트를 모집단 통계로는 잡을 수 있다.
cal(#11) 직전 원시 AN 1줄 로깅이면 되므로 검사시간 추가 없음. 품질모니터링 연동 적합.

Q7. 자이로가 잘못되면 VL도 잘못되는 이유 = "기준이라서"?

맞음. 단 VL이 자이로 값을 받는 게 아니라, 자이로가 만든 "지그 자세"에 갇히는 구조(Q2).
기준 사슬의 꼭대기가 현재는 중력이 아니라 사실상 기계 자세(8.2)라는 점까지 포함해야 정확.
