## 0. 기호 설명 — 먼저 읽을 것

이 문서는 그리스 문자를 쓴다. 뜻만 알면 나머지는 어렵지 않다.

### 주요 기호 4개

| 기호 | 읽는 법 | 한 줄 뜻 | 값 |
|---|---|---|---|
| **τ** | **타우** | **이번에 잰 값.** 검사가 "0도"라 부르던 자세를 경사계 공장 기준으로 재면 몇 도인가 | **+0.0903°** (실측) |
| **D** | **디** | **원래 알고 싶던 것.** 출하품의 "0도"가 진짜 수평에서 벗어난 각도 | ≈ 0.06 ~ 0.12° (추정) |
| **μ** | **뮤** | 센서 **장착오차.** 경사계의 감지축이 플레이트 면과 안 맞는 각도 | **미지** (센서 분리로 소실) |
| **ε** | **엡실론** | 경사계 **공장 정확도.** 센서 자체가 가진 오차 | **±0.03°** (datasheet) |

### 이 넷의 관계 — 이것만 이해하면 된다

```
경사계 판독  =  플레이트의 실제 각도  +  μ  +  ε
                                     (장착오차) (센서오차)

지그가 "0도"라 부르던 자세에서 이 판독을 재봤더니  →  τ = 0.090
그런데 그 자세에서 플레이트의 실제 각도가 바로  D

      0.090  =  D  +  μ  +  ε
        τ       ↑알고싶은것  ↑미지  ↑±0.03

  →  D = 0.090 − μ − ε      μ ≈ 0 이면  D ≈ 0.09 ± 0.03
```

**왜 D를 직접 못 재나:** 경사계 자신이 유일한 기준자인데, 그 경사계에 μ와 ε가 붙어 있다.
자를 자로 재는 셈이라 μ는 분리해낼 수 없다. **그래서 D는 τ에서 추정만 가능하다.**

### 보조 기호 (§5 판정에서 사용)

| 기호 | 뜻 |
|---|---|
| **M** | **기구 자세.** 홈센서 복귀 + 1250스텝으로 모터가 도달하는 물리 위치 |
| **Z** | **경사계의 0점.** 경사계가 "여기가 0도"라고 여기는 자세. `setzcur`가 매번 옮겨놓던 것 |
| **ρ** (로) | **잔차.** FineAdjust가 멈춘 시점에 목표와 실제 사이에 남은 각도 |
| **r1 / r2** | `setzfac` **전 / 후** 의 판독값. `τ = r2 − r1` |
| **k** | 모터가 움직인 **격자 칸 수** (정수). 1칸 = 1스텝 = 0.1125° |

### 용어

| 용어 | 뜻 |
|---|---|
| **tare** (테어) | **저울의 영점 조정과 같은 것.** "지금 이 상태를 0으로 쳐라". `setzcur`가 바로 이것 |
| **비휘발** | 전원을 꺼도 값이 유지됨. 그래서 `setzcur`의 결과가 계속 쌓여 있었다 |
| **격자** | 모터가 설 수 있는 자리. **1스텝 = 0.1125°** 간격이라 그 사이에는 못 선다 |
| **centered_mod** | 가장 가까운 격자 자리까지 남는 거리(부호 포함). 항상 **±0.056**(반 칸) 이내 |
| `setzcur` | tare 실행 — 현재 자세를 0으로 등록 |
| `setzfac` | tare 취소 — 공장(중력) 기준으로 복귀 |
| `get---x` | 현재 각도 1개 읽기 (1축 센서라 `get---y`는 없음) |
| `setdir5` / `setdir6` | **축 선택이 아니라 부호 설정.** 값의 +/− 만 뒤집는다 |

## 2. 배경 — 왜 쟀나

`#3`/`#10` 영점 초기화가 매 사이클 경사계에 **`setzcur`**(현재 자세를 0으로 등록)를 보낸다.
이 명령은 datasheet상 **Tare**이고 **비휘발**이라, 경사계의 "0"은 **최초 1회만 공장(중력) 기준**이고
그 뒤로는 **직전 사이클이 정한 자세**였다.

제품은 `<OFFSET,1>`로 **바로 그 자세를 "0도"라고 학습하고 출하**된다. 즉 **τ가 곧 출하품 0도의 오차**다.

그리고 **기존 검사망은 이것을 전혀 못 본다.**

| 검사 | 이유 |
|---|---|
| `#6`/`#14` 기울기 | `VL − 경사계` **상대비교** → τ가 양쪽에 동일 유입 → **상쇄** → 전량 PASS |
| `#4`/`#11` `verify_an` | `<OFFSET,1>` **직후 VL 자기 출력** → 지그가 어디 있든 **항상 0.00x** |

→ **한 번은 재야 했다.** 재지 않으면 setzcur 제거 판단도, 기출하품 판단도 불가능했다.

## 3. 측정 방법 — 차분법 (기존 절차 대체)

### 3.1 경위

측정 시점에 **경사계가 다른 테스트 때문에 지그에서 분리**돼 있었다.
`PLAN_자이로_누적드리프트_측정절차_20260715_v01.md` 4절은 *"지그를 0도 자세로 → 검사 1사이클 돌려
`#3` 직후 정지"* 를 요구하는데, **실행 불가능**했다.

### 3.2 원리 — 자세와 무관하게 τ가 나온다

```
판독(자세 A) = A + μ + ε − τ        μ = 센서 장착오차, ε = 공장 정확도(±0.03)

[1] setzfac 전 : r1 = A + μ + ε − τ
[2] setzfac    : τ := 0
[3] setzfac 후 : r2 = A + μ + ε

      r2 − r1 = τ           ← A, μ, ε 이 전부 소거된다
```

**자세(A)·장착(μ)·공장오차(ε)가 차분에서 모두 소거**되므로, **지그·모터·검사 프로그램이 전부 불필요**하다.
**센서 + 전원 + UART만 있으면 된다.** 유일한 조건은 **`[1]`~`[3]` 사이에 센서가 움직이지 않는 것.**

### 3.3 실제 절차

```
COM6 / 38400 / 8-N-1 / LF          ← 기존 문서의 COM16에서 변경됨 (USB COM 드리프트)

[0] 센서를 단단히 고정. 판독이 ±180 wrap 경계에서 멀 것        ← §6 함정 참조
[1] get---x × 6   → r1
[2] setzfac       → OK                                      ← 되돌릴 수 없음
[3] get---x × 5   → r2
      τ = r2 − r1
```

> `setdir`은 **일부러 건드리지 않았다.** τ가 대체 불가한 값이라 파괴적 명령 전에는 명령 수를 최소화했다
> (`setdir`이 tare를 안 건드린다는 보장이 문서에 없음). 부호 기준은 사후 식별 가능 — §7.

### 계산

```
τ = r2 − r1 = 0.9470 − 0.8567 = +0.0903°       (setdir5 기준 — 아래 참조)
```

### 부호 식별 (사후, 안전)

τ 확보 후 `setdir`을 바꿔가며 읽어 **측정 시점의 부호 기준을 사후 확정**했다.

```
get---x          → +000.951     ← 원래 상태 (명령 치기 전)
setdir6 → OK
get---x          → −000.951     ← 부호 뒤집힘
setdir5 → OK
get---x          → +000.952     ← 원래 값 복귀   ★ 일치
```

| 결론 | |
|---|---|
| 측정 시점 부호 기준 | **`setdir5` (Y결합 기준)** |
| **τ 부호** | **`+0.0903` (setdir5)** / `−0.0903` (setdir6 = X결합 기준 표기 시) |
| 정합성 확인 | 분리 전 **마지막 영점이 `#10`(Y결합, setdir5)** 이었다는 뜻. 검사 1사이클은 `#3`(X, setdir6) → `#10`(Y, setdir5) 순이므로 **마지막에 setdir5로 남는 것이 정상** — 예상과 일치 ✓ |
| 부수 확인 | **`setdir`은 부호만 뒤집는다**(`+0.952` / `−0.951`)가 실측으로 확인됨 (문서에 기술만 있던 내용) |

> `setdir5`에서 **+ = 시계방향**(positive clockwise). 다만 이 "+"가 지그에서 **물리적으로 어느 쪽**인지는
> 장착 방향(μ)을 알아야 하며, 센서 분리로 소실됐다. **판정에는 영향 없다** — 근거는 크기였다.

### 단기 드리프트 관찰

`r2` 측정 시 `+0.947` → 수 분 뒤 `+0.951`. **0.004° 이동.**

- **τ에 영향 없음** — `r1`·`r2`는 연속 측정이었다.
- "노이즈 바닥 0.002"는 **순간 반복도**이고, **수 분 단위로는 약 0.004 흔들린다**는 뜻.
- datasheet ±0.03 이내이고 τ(0.090)의 4% 수준 → 무해.

| 항목 | 값 | 의미 |

| 노이즈 폭 (r1, r2 양쪽) | **0.002** | datasheet 분해능(0.002°)과 정확히 일치 = **1 LSB**. 센서 미동 없음 |

## 5. 판정

### ① 작다 — 소급 확인 불필요

`τ = 0.09°`는 기울기 spec **±0.2°(20도) 대비 45%**, **±0.5°(45도) 대비 18%**다.
0.5° 같은 재앙은 없었다. **기출하품 소급 확인은 불필요하다.**

> 단 요청서의 `상용센서 기준 0 : -0.05 ~ 0.05`는 **넘는다.**
> 그 ±0.05가 **지그 위치 허용오차(A)** 인지 **DUT 출력 spec(B)** 인지는 여전히 미확정 — 담당자 확인 항목.

### ② 격자 위상이 좋다 — 수렴 실패 위험 없음

`REF_setzcur_격자분석_출하영향_v02` §6이 제기한 최대 리스크가 **계산으로 해소**됐다.

```
모터 1스텝 = 0.1125°

τ / step = 0.0903 / 0.1125 = 0.803   →   k = 1
centered_mod(τ, 0.1125) = −0.0222

→ |−0.0222| ≤ 0.03  (strict tolerance)  ✓
```

**setzcur를 빼면 FineAdjust가 딱 1스텝 움직여 잔차 −0.022로 수렴한다.**

| 우려했던 것 | 실제 |
|---|---|
| 수렴 실패 (`[ZERO] FAIL: 0도 미세조정 실패`) | **없음** |
| 10초 relaxed 대기 추가 | **없음** (strict 0.03 이내) |
| 영점 시간 증가 | **사실상 0** (1스텝) |
| 제품간 편차 이중분포(0.1125) | **없음** (격자 경계에서 멀다) |
| **tolerance 0.05 → 0.06 완화 제안** | **불필요.** 현재 값 그대로 진행 |

→ tolerance를 안 건드려도 되므로, **`±0.05` 해석(A/B) 충돌 문제도 같이 사라진다.**

### ③ 누적 랜덤워크가 아니었다

```
τ = 0.0903  <  1스텝 = 0.1125
```

그리고 실측 로그(2026-06-09, n=42)에서 **0도 잔차(0.005)가 기울기 잔차(0.022)보다 4.2배 작다.**
이는 **0도에서 FineAdjust가 격자를 밟지 않는다**(= 이동하지 않는다)는 뜻이고, 곧 `|M − Z| ≤ 0.03`이다.

> **경사계의 0(Z)은 기구 위치(M) 근처 ±0.03에 갇혀 있어 멀리 못 간다.**
> `τ = 0.090`은 사이클마다 쌓인 값이 **아니라**, **기구 세팅(홈센서 + 1250스텝)이 수평에서
> 0.09° 벗어나 있다**는 뜻이다.

`REF_..._v02` §4가 열어뒀던 "무한 누적" 가능성은 **닫혔다.**

## 6. D 추정 및 출하 영향

```
D = τ − μ − ε = 0.0903 − μ − ε          |ε| ≤ 0.03 (datasheet),  μ = 장착오차 (미지)

μ ≈ 0 가정 시   →   D ≈ 0.06 ~ 0.12°
```

**출하품이 대략 0.09° 기울어져 나갔을 것**으로 추정된다.

### setzcur 제거 시 변화

```
제거 후 제품 0도 = (판독 −0.022 지점) → 오차 = −0.022 − μ − ε   →   대략 −0.05 ~ +0.01
현재      제품 0도 = 오차 D                                      →   대략 +0.06 ~ +0.12
```

→ **제거하면 출하품 0도 오차가 절댓값 기준 0.09 → 0.02 수준으로 개선**된다 (격자 위상이 유리하게 걸림).
→ 더 중요한 것은 **오차 상한이 계산 가능해진다**는 점이다. 현재 D는 상한이 없다.

## 7. 현재 상태 — 경사계는 공장 기준이다

`setzfac`가 실행되어 **경사계가 공장(중력) 기준으로 복귀한 상태**다.

### 규칙은 이 한 줄뿐이다

> # **마지막 `setzcur` 이후에 `setzfac`를 한 번 치면 된다.**

```
1. 코드 수정 (setzcur 제거 / gyro_setzcur=false)
2. 빌드 · 배포 · (센서 재장착)
3. setzfac 1회              ← 그동안 쌓인 tare 잔재 제거
4. 검사 시작                 ← 이제부터 영구히 공장(중력) 기준
```

**그 전에 검사 프로그램을 돌려도 무방하다.** `setzcur`가 다시 tare를 걸더라도 `[3]`에서 지워진다.
`setzfac`는 **몇 번이든 반복 가능**하며 파괴적이지 않다.

> **대체 불가능했던 것은 τ 측정 하나뿐이었고, 그것은 완료됐다** (τ = +0.0903).
> 그 시점부터 *"검사 프로그램을 켜지 말라"* 는 제약은 **효력이 없다.**
> (2026-07-16 대화 중 해당 경고를 과도하게 유지했음 — 정정)

**참고:** 현재 공장 기준 상태로 재장착 후 검사를 돌리면, `#3` FineAdjust가 **판독 0 = 진짜 수평**을
찾아가고 거기서 `setzcur`가 걸리므로 **새 tare가 ≈ 진짜 수평에 잡힌다** → 그동안보다 **D가 오히려 작아진다**.
즉 지금 검사를 돌리는 것은 손해가 아니다. 다만 **구조 문제(기준자가 기구가 되는 것)는 그대로**이므로
코드에서 제거해야 하는 결론은 변하지 않는다.

**재장착 시 주의:** 장착오차가 `μ_old` → `μ_new`로 바뀐다. 그래서 `[3]`의 `setzfac`는
**재장착 후**에 하는 것이 깔끔하다 (순서상 코드 수정 후이므로 자연히 그렇게 된다).

### ✅ (완료) 부호 식별 — 2026-07-16 수행. 결과는 §4 참조

τ는 이미 확보돼 위험이 없다.

```
setdir6 → get---x → r3        r3 ≈ +0.947 이면 원래 setdir6 (X결합 기준)
setdir5 → get---x → r4        r4 ≈ +0.947 이면 원래 setdir5 (Y결합 기준)
```

τ의 **부호**가 "지그 0도가 어느 쪽으로 기울어 있었나"를 알려준다.
어차피 제거하면 사라질 정보라 **생략해도 무방**하다.
