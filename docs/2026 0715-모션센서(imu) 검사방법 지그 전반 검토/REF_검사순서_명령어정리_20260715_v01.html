1. 전체 흐름

밀어내기식 2포트 검사. 한 사이클에 DUT 2대가 X결합 → Y결합 순으로 흐른다.

X결합 (COM13) : #0 → #1-X → #3 → #4 → #5-1 → #6 → #7
Y결합 (COM14) : #8 → #9 → #9-1 → #10 → #11 → #11-1 → #12 → #13 → #14 → #15 → #16

명령어가 나가는 곳은 3계통이다. 표의 "주체" 열이 이걸 가리킨다.

주체 대상 포트
DUT 우리 제품 VL10/VL20 COM13(X결합) / COM14(Y결합)
자이로 지그 기준센서 SOLAR-360-420 (1축) COM15
EMIO 모터 제어 보드 TCP 100.100.100.70:2233

2. 검사순서 표 (18항목, 232 기준)

명령어는 JSON에 있는 것 + 코드가 내부에서 보내는 것을 모두 적었다. (코드) 표시는 JSON에 안 보이고 MotionJig.cs/VibeTilt.cs가 자동으로 보내는 명령이다.

X결합 (COM13)

# 검사제목 주체 보내는 명령 설명
#0 통신검사 RS-232 DUT / 자이로 <STOP> → <VER> (X·Y 양 포트)
get---x (자이로)		 검사 시작 전 3계통이 다 살아있는지 인사만 해보는 것. 포트 설정이 틀렸으면 여기서 바로 걸림
#1-X [X결합] FW 버전 확인 DUT <VER> 제품 펌웨어 버전 확인. F/W_ver.1.0.5와 완전일치해야 PASS
#3 [X결합] X축 영점 초기화 (0도) 자이로 / EMIO setdir6 → PPC00 → PMS071/PMS081 → PMO011 → PMD… → setzcur → PMS071/PMS081 지그를 진짜 수평으로 만드는 단계. 홈센서로 원점 찾고 → 1250 step 이동 → 자이로 보면서 ±0.03도까지 미세조정 → 그 자세를 자이로 0도로 등록(setzcur)
#4 [X결합] X축 Calibration (0도) DUT <OFFSET,1>
(코드) <MODE,06> → <START> → <STOP>		 제품에게 "지금 이 자세가 0도다"라고 가르치는 단계. 직후 AN을 1초 읽어 진짜 0이 나오는지 확인(±0.05)
#5-1 [X결합] X축 정지 검사 (0도) DUT <MODE,2> → <START> → <STOP> 가만히 있는데도 값이 떨리는지(노이즈) 확인. 평균이 아니라 변동폭(p2p) ≤ 0.05 로 판정
#6 [X결합] X축 기울기값 측정 DUT / 자이로 / EMIO (각도마다) PMD… → get---x → <MODE,06> → <START> → <STOP> 지그를 −20 → −45 → +20 → +45도로 기울여가며 제품 값과 자이로 값을 비교. 판정 = 제품값 − 자이로값, spec ±0.2(20도) / ±0.5(45도)
#7 [X결합] Y축 진동값 측정 (90도) DUT / EMIO PMD… → <MODE,02> → <START> → <STOP> 90도로 세워서 중력이 Y축에 온전히 걸리게 한 뒤 1G(0.98~1.02) 가 나오는지 확인. 가속도계 축이 제대로 붙었나 보는 것

Y결합 (COM14)

# 검사제목 주체 보내는 명령 설명
#8 [Y결합] FW 버전 확인 DUT <VER> #1-X와 동일. Y결합 포트(COM14) 대상
#9 [Y결합] 시리얼번호 설정 DUT <UID,{serial}> 제품에 시리얼 기록. 232는 VL1- 접두사
#9-1 [Y결합] 센서 온도 저장 DUT <SENTEMP> → <REFTEMP,{temp}> 현재 센서온도를 읽어 기준온도로 저장. 나중에 온도보정의 기준점이 됨. 20~40도 벗어나면 저장 안 하고 FAIL
#10 [Y결합] Y축 영점 초기화 (0도) 자이로 / EMIO setdir5 → (홈 생략) → PMD… → setzcur #3과 같은 동작이되 자이로 방향만 Y축(setdir5). skip_home=true라 홈복귀 없이 미세조정만
#11 [Y결합] Y축 Calibration (0도) DUT <OFFSET,1>
(코드) <MODE,06> → <START> → <STOP>		 #4와 동일. Y축 기준으로 제품 영점 잡기 + AN ±0.05 검증
#11-1 [Y결합] 출하 상태 설정 DUT <RCONF,1> 지금까지 잡은 값(UID+기준온도+양축 cal)을 "출하 상태"로 스냅샷. 나중에 제품을 공장초기화하면 이 시점으로 돌아옴. <OFFSET> 직후·SAVE 직전에 있어야 함(펌웨어 의존)
#12 [Y결합] Y축 파라미터 저장 DUT (sleep 100ms) → <APPCFG,SAVE> 여기까지 한 걸 Flash에 영구 저장. 이걸 안 하면 전원 끄는 순간 다 날아감. 실패 시 500ms 후 1회 재시도
#13 [Y결합] Z축 진동값 측정 (0도) DUT <MODE,02> → <START> → <STOP> 수평(0도)에서 Z축에 1G가 걸리는지 확인. 저장 후 모터를 안 움직였으므로 0도 그대로
#14 [Y결합] Y축 기울기값 측정 DUT / 자이로 / EMIO (각도마다) PMD… → get---x → <MODE,06> → <START> → <STOP> #6과 동일한데 +20 → +45 → −20 → −45도 순서, Y축 대상
#15 [Y결합] X축 진동값 측정 (−90도) DUT / EMIO PMD… → <MODE,02> → <START> → <STOP> −90도로 세워 X축에 1G 확인. #7의 X축 판
#16 [Y결합] Config 확인 (APPCFG) DUT <MODE,0> → <APPCFG> 검사 끝나고 제품 설정이 정상(MODE=00)으로 돌아왔는지 확인. 스트리밍 켜진 채 출하되는 것 방지

3. 명령어 사전 (설명)

3.1 DUT(제품 VL10/VL20) 명령 — < >로 보내고 [ ]로 답한다

명령 이름 설명
<VER> 버전 조회 펌웨어 버전 물어보기
<UID,…> 시리얼 쓰기 제품 고유번호 기록
<SENTEMP> 센서온도 조회 지금 센서 온도 몇 도냐
<REFTEMP,…> 기준온도 저장 "이 온도를 기준으로 삼아라"
<OFFSET,1> 영점 캘리브레이션 "지금 이 자세를 0도로 삼아라." Z축을 1G, X/Y 기울기를 0으로 설정. 제품 출하 영점이 여기서 결정됨
<RCONF,1> 출하상태 저장 현재 설정을 "공장 기본값"으로 스냅샷
<APPCFG,SAVE> 영구 저장 RAM에 있는 설정을 Flash로 굽기
<APPCFG> 설정 조회 현재 설정값 읽기
<MODE,06> 기울기 모드 앞으로 각도(AN) 를 뿌려라
<MODE,02> 진동 모드 앞으로 가속도(GAC) 를 뿌려라
<MODE,0> 정지 모드 스트리밍 끄고 평상시로
<START> / <STOP> 스트리밍 시작/중지 데이터 뿌리기 시작/중단

수신 데이터 2종: - AN = 기울기 각도 (분해능 0.01도) — #6/#14 판정과 verify_an이 쓴다 - GAC = 3축 가속도 (1G 기준) — #7/#13/#15/#5-1이 쓴다

3.2 자이로(SOLAR-360-420) 명령 — 지그 기준센서

명령 이름 설명
setdir6 방향=X축 X결합 지그에서 쓸 측정 방향 지정
setdir5 방향=Y축 Y결합 지그에서 쓸 측정 방향 지정
setzcur 현재값 영점(tare) "지금 이 자세를 앞으로 0도라고 불러라." 수평 그 자체가 아니라 수평이라고 검증된 현재 자세를 0으로 등록. 비휘발 저장이라 전원 꺼도 유지됨
get---x 각도 읽기 지금 몇 도냐 (중력 기준 절대각)
setzfac 공장 영점 복귀 setzcur로 잡은 tare를 취소하고 공장 기준으로 되돌림. 현재 코드 미사용 (7-15 기준 grep 0건)

setzcur는 반드시 미세조정(FineAdjust) 뒤에 와야 한다. 먼저 하면 자이로가 0으로 리셋돼서 실제 수평을 못 찾는다 (MotionJig.cs:862 주석).

3.3 EMIO(모터 보드) 명령

명령 이름 설명
PPC00 에러 클리어 모터 알람 해제
PMO011 / PMO012 원점복귀 홈센서(IN1/IN2)까지 돌려서 기준 위치 찾기
PMD0{n}1ML{steps} 상대 이동 지정 step만큼 회전. 1 step = 0.1125도
PMS07128… / PMS08129… 소프트리밋 ± 회전 한계 설정. 영점 중엔 ±8000으로 풀고, 운용 시 ±1600(=±180도)로 조임 (케이블 꼬임 방지)
PMS050614 속도 설정 원점복귀 속도
PII00 입력 상태 조회 홈센서 비트 확인 — 과회전 감지에 사용

4. 232 vs 485 차이

항목 구성·순서·spec은 완전히 동일(18 procs). 차이는 명령어 형식뿐 — 485는 멀티드롭이라 국번(1)이 하나 더 들어간다.

항목 232 (VL10) 485 (VL20)
버전 <VER> <VER,1>
캘리브레이션 <OFFSET,1> → [OFFSET,0,1] <OFFSET,1,1> → [OFFSET,0,1,1]
시리얼 <UID,{serial}> <UID,1,{serial}>
기준온도 <SENTEMP> / <REFTEMP,{temp}> <SENTEMP,1> / <REFTEMP,1,{temp}>
출하상태 <RCONF,1> <RCONF,1,1>
영구저장 <APPCFG,SAVE> <APPCFG,1,SAVE>
모드/스트리밍 <MODE,06> / <START> / <STOP> <MODE,1,06> / <START,1> / <STOP,1>
기대 FW F/W_ver.1.0.5 F/W_ver.2.0.3
시리얼 접두사 VL1- VL2-

자이로·EMIO 명령은 232/485 동일(지그 쪽 장비라 제품 통신방식과 무관).

5. 조사 중 발견한 불일치 (수정 검토 필요)

문서화 과정에서 JSON/코드 주석이 실제 동작과 어긋나는 곳 4건을 발견했다. 동작에는 영향 없고 전부 표기 문제지만, 다음 사람이 오해할 소지가 있다.

# 위치 내용
1 MP_workspace_motion_*.json → _proc_order X: #0→#1→#2→#3→#4→#5→#6→#7 / Y: #1-Y→#8→…→#15 로 적혀 있으나 실제와 다름. #2·#5·#1-Y는 존재하지 않고(간소화 시 제거), #5-1·#9-1·#11-1·#16은 표기 누락. 실제 순서는 본 문서 1절
2 232/485 #7 항목명 제목은 "Y축 진동값 측정 (+90도)" 인데 target_angle = −90. 제목 또는 값 중 하나가 오기. (#15는 제목 −90 / 값 −90으로 일치)
3 232/485 #6 _angles_comment 주석은 "사양서 순서: +20→+45→-20→-45" 인데 실제 angles = [-20,-45,20,45]. Y축(#14)은 주석과 값이 일치 → X축 주석만 복붙 잔재로 보임. 사양서 순서가 맞다면 X축 값이 사양과 다른 것이므로 확인 필요
4 MotionJig.cs:851 주석 "IN1: 1250 step, IN2: ~400 step" — 코드 기본값은 400이지만 MP JSON이 steps_to_zero_in2: 200으로 덮어씀. 실제 운용값은 200. (단 home_sensor: "in1" 고정이라 IN2 경로는 양산에서 미사용)

2·#3은 값이 틀린 건지 표기가 틀린 건지 사양서 대조가 필요하다. 나머지 2건은 표기만 고치면 된다.
