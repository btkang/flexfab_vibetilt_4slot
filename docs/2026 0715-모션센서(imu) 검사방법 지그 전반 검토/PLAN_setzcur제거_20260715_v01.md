### 2.2 원본도 정리가 덜 된 상태였다

- BG01은 원래 조건부였던 것을 **주석 처리해서 무조건 실행**으로 바꿔놓음:

  ```cpp
  //{

  //}
  ```
- 주석은 `// Slope Sensor Check` 뿐, **왜 필요한지 없음.** 그 상태 그대로 이식됨

### 2.3 존재 이유가 소멸했다

**pCOM/BG01에는 FineAdjust가 없다.** `JIG_INIT`(홈복귀+고정이동) → `DEGREE_0_CHECK`(setzcur+get---x)뿐,
중력을 확인하는 절차가 없다. 그 설계에서 **setzcur는 유일한 영점 수단이라 필수**였다.

우리는 **2026-03-31(`08c276c`)에 FineAdjust를 도입**해 그 역할을 대체했다.
`2026-04-01(0df0ba6)`이 1차 setzcur를 지우며 *"FineAdjust가 자이로 실제값으로 수평 찾기"* 라고
적은 것이 이를 스스로 인정한 것. **그런데 같은 논리를 2차에는 적용하지 않았고, 남긴 근거가 없다.**

### 2.4 사양서에 없다 — 그리고 코드가 먼저였다

- Range: **"상용센서 기준 0 : -0.05 ~ 0.05"** — **"기준"**이라고 명시. 기준자를 바꾸라는 뜻일 수 없음

- **문장이 모호한 것은 사실**이나(자이로가 플레이트에 같이 붙어 회전하므로 "상용센서 0도 이동"은
  자연스러운 표현), **그 모호함이 setzcur를 만든 게 아니라 살려둔 것.** 도입은 이식이 원인

### 2.5 지금 구조의 문제

`setzcur`는 **비휘발**(datasheet p.2, p.6)이라 전원을 꺼도 유지된다.

- 자이로의 "0"은 **최초 1회만 공장(중력) 기준**, 이후로는 직전 사이클이 정한 자세
- VL 영점(`<OFFSET,1>`)이 그 자세를 물려받음 → 자이로 0이 D만큼 틀어져 있으면 **전 제품이 D 바이어스로 출하**
- **기존 검사망은 D를 검출 못 함**: 기울기 판정은 `VL−자이로` 상대비교라 상쇄, `verify_an`은
  OFFSET 직후 VL 자기 출력이라 항상 0.00x
- 기준자(자이로)에 매 사이클 tare를 거는 것 = **캘리퍼스로 잴 때마다 0점을 다시 잡는 것**

## 4. 사이드 이펙트 (코드 전수 확인 완료)

### 4.1 영향 있음

| 항목 | 영향 |
|---|---|
| **±20/±45 판정** | FineAdjust 잔차 **δ(≤0.03)** 가 전 각도에 **일정한 계통 오프셋**으로 유입. spec ±0.2 대비 **15%**. ← **이것이 실측 대상** |
| **자이로 기준** | ⚠ **마지막 tare에 영구 동결.** 코드만 고치면 중력 기준으로 **안 돌아옴** → **`setzfac` 1회 선행 필수** |

`error` 유도 (누적 tare D는 상쇄됨을 확인):
```
자이로 0 = Z (마지막 tare, 고정)
FineAdjust → 실제 자세 = Z + δ   (|δ| ≤ 0.03)
VL OFFSET → VL은 그 자세를 0으로

+20도 이동 → 자이로 판독 = 20 + δ'
             VL 판독     = (Z + 20 + δ') − (Z + δ) = 20 + δ' − δ
error = VL − 자이로 = −δ          ← Z 상쇄. |error| ≤ 0.03 (전 각도 동일)
```
→ **setzfac를 안 해도 δ 실측 테스트 자체는 유효**하다 (재는 것이 δ이지 D가 아니므로).

```
1. setzfac + get---x → D 측정          ← 지그 필요(제조팀). 별도 문서 참조. 수동 진행
```

**1과 3은 순서 무관** (3은 D와 독립적으로 유효). 지그를 못 쓰는 동안 **2번 준비만 해두는 것도 가능.**

⚠ **2번만 하고 MP에 올리면 안 된다** — 틀어졌을지 모르는 영점을 **영구 박제**하게 된다.
