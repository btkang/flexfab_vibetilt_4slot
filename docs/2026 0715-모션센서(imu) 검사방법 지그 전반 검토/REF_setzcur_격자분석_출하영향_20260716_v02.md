## (이력) 0. 긴급 — 센서가 지그에서 분리됨 (2026-07-16 확인)

**경사계가 다른 테스트 때문에 지그에서 분리된 상태다.** 이로 인해:

### 0.1 지금 안 재면 영원히 못 재는 값이 있다

누적된 tare `τ`는 **센서 내부에 비휘발로 살아 있다.** 아직 안 날아갔다. 그러나:

| 사건 | 결과 |
|---|---|
| 다른 테스트에서 **`setzcur` 또는 `setzfac`를 1회라도 전송** | **τ 즉시 영구 소실** |
| **센서를 지그에 재장착** | 장착오차가 `μ_old` → `μ_new`로 바뀜 → **τ의 의미가 달라짐** (§0.3) |

→ **τ는 그동안 양산에 실제로 적용됐던 유일한 증거다.**
→ **기출하품 소급 판단의 근거가 지금 사라질 참이다.**

### 0.2 ✅ 분리된 상태 그대로 잴 수 있다 — 지그 불필요

`PLAN_자이로_누적드리프트_측정절차`의 "지그를 0도 자세로" 요건은 **불필요하다.**
`setzfac` **전/후 판독 차이**로 τ가 그대로 나오며, **자세와 무관**하다.

```
센서를 아무 자세로든 고정 (책상 위 그대로. 절대 움직이지 말 것)

[1] get---x  → r1   (3~5회)     ← 판독 = A + μ + ε − τ
[2] setzfac  → OK               ← tare 취소
[3] get---x  → r2   (3~5회)     ← 판독 = A + μ + ε
                                   ※ [1]~[3] 사이에 센서를 건드리면 무효

      ★ τ = r2 − r1
```

`A`(센서 자세)·`μ`(장착오차)·`ε`(공장오차)가 **차분에서 전부 소거**된다. 그래서 자세가 상관없다.

> **근거:** datasheet — `setzcur` = *"Tare function to set the current position to zero"*,
> `setzfac` = *"Cancels tare function and resets zero to factory setting"*.
> 표준 tare 모델(`판독 = 원시값 − τ`)을 전제로 한 **유도**이며, **실측 검증은 안 됐다.**
> 검증법: [3] 이후 `setzcur` → `get---x`가 `0.000`이면 모델이 맞다 (단 그 순간 τ는 새로 덮인다).

**필요한 것:** 센서 + 전원 + UART(38400/8N1/LF) 연결. **지그·모터·검사 프로그램 전부 불필요. 5분.**

### 0.3 τ와 D의 관계 (v01의 용어 부정확 정정)

```
τ = A* + μ + ε        A* = 마지막 setzcur 시점의 플레이트 각도 (중력 기준)
                      μ  = 센서 장착오차 (센서 감지축 vs 플레이트 면)
                      ε  = 센서 공장 정확도 (±0.03, datasheet)

D = A*  =  τ − μ − ε   ← 출하품 0도의 실제 기울기 오차
```

**v01과 `PLAN_자이로_누적드리프트_측정절차`가 "이 값이 D"라고 한 것은 엄밀히는 `τ`다.**
`μ`를 모르므로 D는 **정확히 복원되지 않는다.** 다만:

- 센서가 플레이트에 잘 맞춰 장착돼 있었다면 `μ ≈ 0` → **`D ≈ τ ± 0.03`**
- **τ가 크게 나오면(예: 0.3° 이상) 그것만으로 "크게 틀어져 있었다"는 결론은 확정**이다.
  μ가 그만큼 클 리는 없기 때문.
- **τ가 작으면(≤0.05)** 그동안 운이 좋았다는 뜻 — 제거 진행에 청신호.

**⚠ 재장착 후에 잰 τ는 재장착 전의 τ와 다른 값이다** (μ가 바뀌므로). **지금 재야 한다.**

### 0.4 즉시 확인할 것

1. **다른 테스트에서 `setzcur`/`setzfac`를 쓰는가?** → 쓴다면 **그 전에** §0.2를 실행
2. 안 쓴다면 → 그래도 **재장착 전에** §0.2 실행 (재장착이 μ를 바꿈)
3. τ 값 + 측정 시각 + `setdir` 상태를 **기록**

## 4. setzcur가 실제로 하는 일

**수평을 만드는 게 아니다. 모터가 이미 서 있는 자리를 "0도"라고 개명하는 것이다.**

```
사이클 N-1 : FineAdjust → 모터가 어딘가 섬 → setzcur → "여기가 0"
사이클 N   : 홈복귀 → 1250스텝 → 거의 같은 자리 → 판독 "0.002" → 0스텝 수렴
             → setzcur → "여기가 0"  ...반복
```

`M_N` = N번째 사이클 기구 자세(홈+1250스텝) / `Z_N` = 경사계 0점 / 판독(자세 P) = `P − Z`

```
FineAdjust 종료   P_N = Z_(N-1) + ρ_N ,  |ρ_N| ≤ tol
setzcur          Z_N = P_N = Z_(N-1) + ρ_N     ← 자기참조 점화식
```

실측 0도 잔차(0.005 ≪ 밴드 0.03)는 `k=0`(무이동)에서만 나오는 값이고, 이는 `|M_N − Z_(N-1)| ≤ 0.03`을 뜻한다.

> **`Z_N ≈ M_N`** — 경사계의 0이 **기구 위치를 추종**한다.
> `ρ_N ≈ M_N − M_(N-1)` = **기구 반복도**. 실측 0.005가 이 지그의 홈센서+백래시 반복도다.

**결과: 기준자가 경사계(중력)에서 기구(홈센서+1250스텝)로 넘어간다.**
경사계는 기준자 지위를 잃고 **"기구 위치를 재현하는 도구"**가 된다. 중력은 최초 1회 이후 루프에 참여하지 않는다.

> ※ `Z_N ≈ M_N`은 실측 0.005를 설명하는 유일한 해로 보이나 **직접 측정된 값은 아니다.** §8 참조.

## 5. 지그가 기울어지면 — 피치/롤을 나눠야 한다 (신규)

경사계가 **1축(피치)**이라 방향에 따라 정반대로 작동한다.

### 5.1 피치(모터 회전축 = 감지축)로 θ 기울어짐 → **제거하는 쪽이 압도적 우위**

| | 동작 | 결과 |
|---|---|---|
| **setzcur 있음** | `M`이 θ만큼 같이 기울고 `Z`가 `M`을 추종 | **θ가 100% 제품에 들어감. 아무도 모름** |
| **setzcur 없음** | 경사계가 중력 기준으로 θ를 봄 → FineAdjust가 −θ 돌려 판독 0 = 진짜 수평 복귀 | **θ 자동 보정** |

**지금은 지그가 피치로 기울면 그만큼 전 제품이 기울어 출하된다.** 빼면 모터가 되돌린다.
이것이 "중력 기준으로 돌아간다"의 실질적 이득이다.

### 5.2 롤(직교축)로 φ 기울어짐 → **변화 없음**

1축이라 센서가 못 보고 모터도 그 축으로 못 돈다. **있으나 없으나 φ는 그대로 제품에 들어간다.**
setzcur와 **무관한 별개 사안**이며 `REF_SOLAR360_1축_...` 소관(버블 수평계 필수).
크게 틀어지면 ±45°에서 **모터 stall → FAIL**로 드러난다 (2026-06-09 실측).

## 6. 제품간 편차 — **유지된다** (신규)

편차의 원천이 양쪽 다 **기구 반복도(≈0.005)**로 같다.

```
있음 : P_N = M_N              → 편차 = M의 반복도
없음 : P_N = Z_0 + ρ̄ + m_N    → 편차 = m_N = M의 반복도   (동일)
```

`ρ̄`(D가 정하는 격자 잔차)는 **상수 오프셋**이라 편차에 기여하지 않는다.

### 예외 — 격자 경계 → **✅ 실측으로 해소됨 (2026-07-16)**

`ρ̄`가 격자 경계(±0.056) 근처면 `m_N`이 격자를 넘나들며 `k`가 튀어 **편차가 0.1125로 이중분포**가 될 수 있다.
D의 격자 위상에 달렸다.

> **✅ 실측 결과 이 리스크는 없다.**
> ```
> τ = 0.0903  →  centered_mod(0.0903, 0.1125) = −0.0222   ≤ 0.03 (strict tol)
> ```
> 격자 경계(±0.056)에서 충분히 멀다. **이중분포도, 수렴 실패도, 10초 relaxed 대기도 없다.**
> 제거 시 FineAdjust는 **1스텝만 이동**하고 잔차 −0.022로 수렴한다.
>
> ~~**해법: 0도 tolerance를 반스텝 이상(0.05 → 0.06)으로 완화**~~ → **불필요.** 현재 값 그대로 진행.
> 따라서 *"±0.05가 DUT 출력 spec(해석 B)이면 tolerance 완화가 spec을 더 먹어 충돌한다"* 는
> 걱정도 **함께 사라졌다.** (단 ±0.05의 해석 A/B 자체는 여전히 담당자 확인 대상)

## 7. 출하 전체 영향 — 결론

DUT는 `<OFFSET,1>`을 **FineAdjust 종료 자세 `P_N`에서** 실행한다. → **출하품의 "0도" = `P_N`**

| | **setzcur 있음 (현행)** | **setzcur 없음** |
|---|---|---|
| 경사계 0 | `Z_N ≈ M_N` (기구 추종) | `Z_0` = 공장(중력) 기준, **고정** |
| 실질 기준자 | **기구** (경사계는 도구) | **중력** (경사계가 기준자) |
| 출하품 0도 오차 | **`D`** ± 기구반복도(0.005) | **`ε + ρ`** |
| 그 오차의 정체 | **미지.** 과거 ε + 기구오차 + 누적이 뒤섞임 | ε ≤ **0.03**(datasheet) + ρ ≤ 0.03~0.05 |
| **오차 상한** | **없음** | **≤ 0.06 ~ 0.08°** — 계산 가능 |
| 지그 피치 기울어짐 | 100% 제품에 유입 | **자동 보정** |
| 지그 롤 기울어짐 | 유입 | 유입 (동일) |
| 제품간 편차 | ±0.017 (실측) | 동일 (§6) |
| 시간에 따른 이동 | **가능** — 홈센서 마모·재조립·센서 재장착 시 이동. 로트마다 달라져도 모름 | 없음 |

### 핵심

지금 제품들은 **아주 균일하게(±0.017) 모여 있다.** 문제는 **어디에** 모여 있는지 아무도 모른다는 것이다.
`D = 0.01`이면 운이 좋았던 것이고, `D = 0.5`면 **양산 전량이 0.5° 기울어져 출하됐는데 검사는 전량 PASS**다.

**setzcur 제거는 ε를 새로 추가하는 게 아니다.** ε는 이미 D 안에 얼어붙어 있다.
**과거의 ε를 현재의 ε로 바꾸는 것**이고, 그 대가로 **상한이 계산 가능**해진다.

### 왜 검사망이 D를 못 잡나

| 검사 | 이유 |
|---|---|
| `#6`/`#14` 기울기 | `VL − 경사계` **상대비교** → D가 양쪽에 동일 유입 → **상쇄** → 전량 PASS |
| `#4`/`#11` `verify_an` | `<OFFSET,1>` **직후 VL 자기 출력** → 지그가 어디 있든 **항상 0.00x** (`VibeTilt.cs:1268~1357`) |
