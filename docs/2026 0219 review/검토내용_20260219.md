## 3. 프로토콜 구조 확정

### 3.1 RS-485 프로토콜 포맷

#### TX (송신)
```
<CMD,ID[,args...]>
```
- CMD: 명령어 (VER, SENTEMP, APPCFG, MODE, START, STOP, GAC 등)
- ID: 보드 ID (VL20의 경우 **기본값 1**)
- args: 추가 인자 (선택)

**중요:** RS-485는 RS-232와 달리 명령에 **ID 필드가 추가됨**

**예시:**
- `<VER,1>`
- `<SENTEMP,1>`
- `<APPCFG,1>`
- `<MODE,1,0>`
- `<MODE,1,2>`
- `<START,1>`
- `<STOP,1>`

#### RX (수신)
```
[CMD,RV,ID,data...]
```
- CMD: 명령어 에코
- RV: Return Value (0=정상, 2=에러)
- ID: 보드 ID (1)
- data: 응답 데이터

**파싱 구조:**
| 필드 | parts[] | 설명 |
|------|---------|------|
| CMD | parts[0] | 명령어 |
| RV | parts[1] | 반환값 (0=정상) |
| ID | parts[2] | 보드 ID |
| data | parts[3+] | 실제 데이터 |

**예시:**
```
[VER,0,1,F/W ver.2.0.1]
     ↑ ↑ ↑            ↑
    [0][1][2]        [3]

[SENTEMP,0,1,26.66]
        ↑ ↑ ↑     ↑
       [0][1][2] [3]

[MODE,0,1,00]
     ↑ ↑ ↑  ↑
    [0][1][2][3]
```

**패턴 일관성:**
- VER과 SENTEMP는 **완전히 동일한 구조**
- 모든 응답에 RV=0 (정상), ID=1 (기본값) 포함
- RS-485의 특징: 명령/응답 모두 ID 포함

### 3.2 APPCFG 응답 구조 (중요!)

#### APPCFG 응답 포맷
```
[APPCFG,RV,config_string]
        ↑   ↑
       [1]  [2] (슬래시 구분 필드)
```

**RV (parts[1]) 판정:**
- `0` = 정상 (PASS)
- `1` 이상 = 오류

#### 초기 상태 vs SPEC 비교
```
SPEC: [APPCFG,0,1/00/3600/10  /1/115200]
실제: [APPCFG,0,1/00/0   /-256/1/115200]
                   ↑     ↑
                  ATIM  SAM (초기값 다름)
```

**판정:**
- RV = 0 → **PASS** (FAIL 아님)
- ATIM, SAM 값은 설정 전 초기값

#### APPCFG 응답 변화 패턴
```
초기:        [APPCFG,0,1/00/0   /-256/1/115200]
ATIM,10 후:  [APPCFG,0,1/00/10  /-256/1/115200]  ← 필드[2] 변화
SAM,10 후:   [APPCFG,0,1/00/10  /10  /1/115200]  ← 필드[3] 변화
ATIM,3600후: [APPCFG,0,1/00/3600/10  /1/115200]  ← SPEC 일치
```

#### APPCFG 명령 (SPEC 문서)

**확인 명령:**
```
TX: <APPCFG,ID>
RX: [APPCFG,RV,ID/MODE/ATIM/SAM/STD/BAUD]
```

**저장 명령:**
```
TX: <APPCFG,ID,SAVE>
RX: [APPCFG,RV,ID,SAVE]
```

**중요!**
- BAUD 외 모든 설정은 저장 가능
- **전원 차단 시 저장하지 않은 설정은 초기화됨**
- 검사 중: SAVE 불필요 (일회성 설정)
- 제품 출하: SAVE 필요 (영구 저장)

#### config_string (parts[2]) 필드 구조
**parts[2]를 `/`로 split:**
```
[APPCFG,0,1/00/3600/10/1/115200]
           ↑  ↑   ↑   ↑ ↑   ↑
          [0][1] [2] [3][4] [5]
```

| 인덱스 | 필드명 | SPEC Default | 초기값 (비저장) | 설명 |
|--------|--------|--------------|-----------------|------|
| [0] | ID | 1 | 1 | Device ID |
| [1] | MODE | 00 | 00 | 모드 |
| [2] | ATIM | 3600 | **0** | Auto Output Time (초) |
| [3] | SAM | 10 | **-256** | Sampling Period (ms) |
| [4] | STD | 1 | 1 | 통신표준 (0=RS-232, 1=RS-485) |
| [5] | BAUD | 115200 | 115200 | Baudrate (저장 불가) |

**초기값 vs SPEC Default:**
- ATIM: 초기값 0 ≠ SPEC Default 3600 (전원 차단 시 0으로 초기화)
- SAM: 초기값 -256 ≠ SPEC Default 10 (전원 차단 시 -256으로 초기화)

**ATIM 상세 (SPEC 문서):**
- 명령: `<ATIM,ID>` → `[ATIM,RV,ID,설정값]` (확인)
- 명령: `<ATIM,ID,X>` → `[ATIM,RV,ID,X]` (설정)
- 범위: 0 ~ 100000000초
- **기본값: 3600초 (1시간)**
- 기능: 자동 출력 모드의 시간 제한
- 예시: 3600 → 1시간 동안 데이터 출력 후 측정 종료

**중요! START 명령과의 관계:**
- `ATIM=0` → `<START,1>` 해도 **데이터 출력 안 됨** (0초)
- `ATIM=10` → `<START,1>` 하면 **10초 동안 GAC 데이터 출력**
- `ATIM=3600` → `<START,1>` 하면 **3600초(1시간) 동안 출력**
- **검사 전 ATIM 설정 필수!**

**SAM 상세 (SPEC 문서):**
- 명령: `<SAM,ID>` → `[SAM,RV,ID,설정값]` (확인)
- 명령: `<SAM,ID,X>` → `[SAM,RV,ID,X]` (설정)
- 범위: 1 ~ 10000ms
- **기본값: 10ms**
- 기능: 자동 출력 모드에서 X ms마다 데이터 출력

**Baudrate별 최소 전송 주기:**
| Baudrate | 최소 주기 |
|----------|-----------|
| 9600 | 63ms |
| 115200 | 6ms |
| 460800 | 1ms |

**중요! START 명령과의 관계:**
- `SAM=10` → `<START,1>` 하면 **10ms마다 GAC 데이터 출력**
- `SAM=100` → `<START,1>` 하면 **100ms마다 GAC 데이터 출력**
- Baudrate=115200일 때 최소 6ms (더 짧게 설정 불가)

**검증 로직:**
- RV = 0 확인 (PASS 판정)
- STD = 1 확인 (RS-485)
- BAUD = 115200 확인
- ATIM, SAM은 설정 후 변경되므로 초기값과 다를 수 있음

### 3.3 GAC 응답 (스트림)

**START 후 자동 스트림:**
```
[GAC,1,-0.01,-0.01,1.00,0.58]
    ↑   ↑     ↑     ↑    ↑
   ID   X     Y     Z   RMS
```

**파싱:**
- parts[1] = ID (1)
- parts[2] = X
- parts[3] = Y
- parts[4] = Z
- parts[5] = RMS

| BAUD | 115200 | 115200 | 115200 | ✅ |

**참고:**
- ATIM, SAM은 설정 명령 전 초기값과 다를 수 있음
- **판정 기준**: RV = 0, STD = 1, BAUD = 115200 확인

## 5. ATIM/SAM 설정과 자동 출력 메커니즘

### 5.1 ATIM과 SAM의 역할

**ATIM (Auto Output Time):**
- **역할**: 자동 출력 **지속 시간** (총 몇 초 동안 출력할지)
- Default: 3600초 (1시간)
- 예: ATIM=10 → START 후 **10초 동안** 데이터 출력

**SAM (Sampling Period):**
- **역할**: 자동 출력 **주기** (몇 ms마다 데이터를 출력할지)
- Default: 10ms
- 예: SAM=10 → **10ms마다** GAC 프레임 출력

**조합 예시:**
```
ATIM=10, SAM=10
→ START 후 10초 동안, 10ms마다 GAC 데이터 출력
→ 총 약 1000개 프레임 출력 (10초 / 10ms)

ATIM=3600, SAM=100
→ START 후 3600초(1시간) 동안, 100ms마다 GAC 데이터 출력
→ 총 약 36,000개 프레임 출력
```

### 5.2 초기값 문제 및 SAVE 명령

#### 디폴트 값 정리

| 구분 | ATIM | SAM | 비고 |
|------|------|-----|------|
| **SPEC 설계값** | 3600초 (1시간) | 10ms | 통신 사양서 기본값 |
| **출하 제품 설정** | **10초** | **10ms** | SAVE 예정 (출하 기본값) |
| **전원 ON 초기값** | **0초** ❌ | **-256ms** ❌ | SAVE 안 된 상태 |

**중요:**
- SPEC 설계값(3600초)과 출하 설정(10초)은 다름
- 출하 제품은 ATIM=10초로 SAVE되어 나갈 예정
- 전원 ON 시 초기값은 ATIM=0, SAM=-256 (미저장 상태)
- **보드 검사 시 ATIM, SAM 모두 설정 필수**

#### 실제 테스트 로그 1 (전원 ON → 설정 → 검사)

**시리얼 포트 모니터 로그:**
```

#### 실제 테스트 로그 2 (전원 OFF->ON 재현성 확인)

**시리얼 포트 모니터 로그:**
```
[02:08:57.687] 전원 OFF->ON - 부팅 시작
B/L ver : 2.0.0

[02:08:58.003] Device id : 1
               Device name : CTS-IOT-VL20
               F/W ver : 2.0.1

[02:09:01.790] <VER,1>
               [VER,0,1,F/W ver.2.0.1]        ✅ 부팅 후 약 4초, 정상 통신

[02:09:02.707] <SENTEMP,1>
               [SENTEMP,0,1,26.63]             ✅ 온도 센서 정상

[02:09:03.643] <APPCFG,1>
               [APPCFG,0,1/00/0/-256/1/115200] ⚠️ 초기값 동일
                           ↑    ↑
                        ATIM=0  SAM=-256  ← 재현성 100%
```

**재현성 확인:**
- ✅ 전원 사이클마다 **일관되게** ATIM=0, SAM=-256으로 초기화
- ✅ 부팅 후 약 4초면 통신 가능
- ✅ VER, SENTEMP 정상 동작
- ⚠️ **매 검사마다 ATIM/SAM 설정 필수**

#### 초기값 문제 분석

**APPCFG 초기 응답:**
```
[APPCFG,0,1/00/0/-256/1/115200]
              ↑   ↑
           ATIM=0 SAM=-256
```

**초기값이 SPEC Default와 다른 이유:**
- SPEC Default: ATIM=3600, SAM=10
- 실제 초기값: ATIM=0, SAM=-256
- **원인**: 전원 차단 시 설정이 저장되지 않아 초기화됨

**문제점:**
- **ATIM=0**: START 해도 **0초 동안** 출력 → 데이터 안 나옴!
- **SAM=-256**: 비정상 값 (범위: 1~10000ms)

**실제 테스트 결과:**
- 전원 ON 후 ATIM=0, SAM=-256 확인 ✓
- ATIM/SAM 미설정 시 START 불가 ✓
- ATIM=10, SAM=10 설정 후 START → **정상 동작** ✓

**해결 방법:**

**A. 보드 검사 시 (step2 - 일회성):**
```
B/L 다운로드
↓
F/W 다운로드
↓
<ATIM,1,10>    → 설정 (10초면 충분)
<SAM,1,10>     → 설정 (10ms)
<MODE,1,2>     → 진동 모드
<START,1>      → 측정
<GAC,1>        → 데이터 수집
<STOP,1>       → 중지
// SAVE 불필요 (다음 보드는 새로 F/W 다운로드)
```

**B. 제품 출하 시 (영구 저장 필요):**
```
<ATIM,1,3600>     → 설정
<SAM,1,10>        → 설정
<APPCFG,1,SAVE>   → 저장 (전원 차단 후에도 유지)
```

**step2 보드 검사 특징:**

- 매 보드마다 F/W 새로 다운로드
- **SAVE 불필요** (일회성 검사)

**참고:**
- BAUD는 저장 불가 (항상 115200 유지)
- 다른 설정(MODE, ATIM, SAM, STD)은 SAVE 가능

// 현재
int modeIndex = isRs485 ? 3 : 2;

// RV = 0 확인

// config[4] = STD (1=RS-485)
// config[5] = BAUD (115200)

if (config[5] != "115200") → FAIL
```

## 9. 참고: RS-232 vs RS-485 비교

| 항목 | RS-232 (VL10) | RS-485 (VL20) |
|------|---------------|---------------|
| 명령 포맷 | `<CMD>` | `<CMD,ID>` ← **ID 추가** |
| 응답 포맷 | `[CMD,RV,data]` (?) | `[CMD,RV,ID,data]` ← **ID 추가** |
| Device ID | 없음 | **1 (기본값)** |
| 통신모드 값 | 0 | 1 |
| APPCFG 필드 | 확인 필요 | 6개 |
| VER 예시 | `[VER,0,...]` (?) | `[VER,0,1,F/W ver.2.0.1]` |
| SENTEMP 예시 | `[SENTEMP,0,...]` (?) | `[SENTEMP,0,1,26.66]` |

**핵심 차이점:**
- RS-485는 멀티드롭 지원을 위해 **모든 명령/응답에 ID 필드 추가**
- VL20의 기본 ID는 **1**
- VER, SENTEMP 등 기본 명령은 **동일한 구조** 유지
