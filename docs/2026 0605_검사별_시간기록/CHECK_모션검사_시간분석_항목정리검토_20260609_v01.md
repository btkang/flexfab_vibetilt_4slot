## 3. 시간 단축 레버 (효과 큰 순)
1. **X영점 "최초 1회만 홈복귀"** ⭐ — 현재 X영점 25s vs Y영점(skip_home) 8s. 밀어내기에서 유닛당 ~17s 절감 가능. (메모리 TODO `project_motion_zero_optimize`)
2. **기울기 stream/settle 단축** — `tilt_stream_duration 1000ms`, `tilt_settle_wait 500ms` 축소. 8각이라 합산 효과(~5-8s). tail=10 샘플 확보 한도 내.
3. retry=3은 PASS 경로 시간엔 무관(FAIL시만).
4. (작음) #5-1 `duration_ms 1000→700` ~0.3s.

## 4. 검사항목 제거 검토 (X축 FW/UID/SAVE)
전제: 밀어내기 dual = 제품 1개가 **X station → Y station** 둘 다 거침. 한 제품 기준 FW/UID가 양 station에서 중복 실행됨.

| 항목 | 판단 | 근거 / 확인필요 |
|---|---|---|
| **FW (#1-X / #8)** | **둘 다 유지** | 사용자 결정: X·Y 양면 확인 측면. (기술적으론 한쪽 redundant지만 싸고 좋은 게이트) |
| **UID 시리얼 (#2 X / #9 Y)** | **X(#2) 제거 후보** | ✅ X-station 측정은 UID 불필요, UID 의존(#9-1/#11-1)은 #9 이후라 충족. ⚠️ **결과추적 pending/serial 매칭이 X UID 없이 도는지 코드 확인 필요** (과거 `pending 시리얼 불일치` 경고 이력) |
| **파라미터 저장 (#5 X / #12 Y)** | **보류 — 확인 후 결정** | ❌ "Y CAL이 X CAL을 overwrite"는 **오해**: X/Y는 **다른 축 offset**, 덮어쓰지 않음. #12 하나로 커버되려면 ①APPCFG SAVE가 X+Y 전체 저장 ②**X→Y 이동 중 제품 전원 유지**(끊기면 X cal 유실 → #5는 전환 전 안전저장이라 필수) 둘 다 성립해야 함 |

## 5. 미결 / 확인 필요 (open)
1. **X→Y station 이동 중 제품 전원 유지되는가?** → #5(X SAVE) 제거 가능 여부의 핵심.
2. **APPCFG SAVE가 전체 config(X+Y offset) 저장하는가?** → 코드 확인 가능.
3. **UID/pending 결과추적이 X UID write에 의존하는가?** → 코드 확인 가능.

## 6. 결론
- 검사항목(FW/UID/SAVE) 제거는 **시간 효과 ~2s로 작음** → 시간 목적이면 우선순위 낮음.
- 진짜 단축은 **X영점 최초1회(~17s) + 기울기 stream/settle**.
- UID/SAVE 정리는 **안전 확인(위 3개) 후** 진행. 추측 제거 금지(양산 사고 방지).
