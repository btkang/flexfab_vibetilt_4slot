# 지그 수평과 기울기검사 FAIL — 원인 정리 (제조팀 교류회용)

- **작성일:** 2026-06-25
- **대상:** VibeTilt 양산 모션검사 #6 X축 / #14 Y축 기울기값 측정 (MOTION_TILT)
- **용도:** 제조팀 교류회 — "지그가 수평이 안 맞으면 기울기검사가 FAIL 나는가" 질의 정리
- **범위:** **지그 자체의 물리적 수평/정렬** 관점 (영점 명령 오조작 이슈는 본 문서 제외)
- **근거:** 실측 로그(output/Release Log) + SOLAR-360-420 데이터시트 교차검증
- **핵심 전제:** 레퍼런스 자이로(SOLAR-360-420)는 **단축(1축) 경사계**다 → 롤(직교) 방향은 모터·자이로 **둘 다 못 봄(사각)**.

---

## 0. 결론 — 물음에 대한 답

**Q. 지그가 수평이 안 맞으면 기울기검사가 FAIL 나는가? 양산에 상관있는가?**

> **A. 난다. 그리고 양산에 상관있다. 버블이 중앙을 벗어났으면 그 상태로 CAL 저장·양산 진행 금지.**

기운 **방향**에 따라 결과가 갈린다:
- **피치(측정축 방향):** 자이로+모터(FineAdjust)가 **~28도까지 거의 완전 보정** → 웬만한 기울기는 **무관**. 단 너무 기울어 극단각(±45/±90)에 모터가 못 닿으면 `TILT_FINE_FAIL`(도달 실패).
- **롤(직교 방향):** **단축 자이로(SOLAR-360)가 못 보는 완전 사각** → 모터도 못 잡음 → ±45°에서 각도비례 오차(`TILT_SPEC_OUT`).
  - 크게 기울면 → SPEC 초과 → **FAIL로 걸러짐**
  - 작게 기울면 → **검사 통과하지만 마진 깎인 CAL이 제품에 저장·출하** ← **양산의 진짜 위험**

**왜 양산에 상관있나:** CAL(OFFSET)은 `APPCFG,SAVE`로 **제품에 영구 저장되어 출하**된다. 기운 채 저장하면 편향이 제품에 박혀, 고객 단에서 오차로 드러나고 온도·경년으로 마진이 빨리 소진된다. **"검사 통과 = 안전"이 아니다.**

**조치:** 셋업 시 **버블 수평계로 지그 수평을 (롤 방향 포함) 사람이 직접 맞춘 뒤** CAL 저장·검사. 롤은 자이로가 단축이라 **소프트웨어로는 못 거르므로 사람의 수평 맞춤이 유일한 방어선.**

## 1. 자이로 보정 원리 (왜 웬만한 기울기는 무관한가)

검사 영점 시퀀스:
1. 모터로 대략 수평 근처 이동
2. **FineAdjust** — 자이로 **실제값**을 읽으며 모터를 돌려 **gyro = 0(진짜 중력 수평)** 까지 수렴
3. 그 수평 위치에서 VL 센서 **OFFSET(캘리브레이션)**
4. 이후 ±20/±45도는 이 진짜 수평 기준 상대 이동

→ 지그 베이스가 몇 도 기울어 있어도, 모터가 그만큼 더 돌아 **OFFSET 기준점은 항상 절대 수평**. 그래서 무관.
→ **단, 이 보정은 "기운 방향이 모터 회전축 방향일 때"만 성립.** (아래 5번이 핵심)

## 2. 기울기검사 FAIL은 3가지 유형 (구분 필수)

로그 `[ERROR_TABLE]` 태그 기준 실측 분류:

| 유형 | 로그 태그 | 모터(FINE) 상태 | 실제 원인 | "지그 수평"과 관계 |
|---|---|---|---|---|
| **A. 미세조정 실패** | `TILT_FINE_FAIL` | **FAIL** (목표각 못 감) | EMIO 모터 이동 TIMEOUT / 소프트리밋 / 케이블 | △ **너무 많이 기울면** 발생 가능 |
| **B. 센서 차이** | `TILT_SENSOR_DIFF` | 수렴 완료(정상) | COM 포트/장착 방향/제품 (VL이 0 읽음) | ✗ 무관 |
| **C. 스펙 초과** | `TILT_SPEC_OUT` | **수렴 완료(정상)** | **지그 수평/정렬 틀어짐(롤·크로스축) → 각도비례 오차** | ✅ **이것이 "지그 수평" 이슈** |

> ⚠️ 혼동 주의: "지그가 기울어져서 FAIL"은 두 뜻이다.
> (a) 지그가 **목표각도까지 못 기울어짐** = A(FINE_FAIL, 모터)
> (b) 지그 **베이스 수평이 안 맞은 채** 검사 = C(SPEC_OUT) ← **본 문서 주제**

## 3. "지그 수평 틀어짐"의 실제 모습 — TILT_SPEC_OUT 지문

실측 로그 예시 (모터는 정확히 도달했는데 VL 읽음값만 벗어남):
```
[FINE] 수렴 완료: target=-20.00, actual=-19.987   ← 모터는 목표각 정확히 도달
[TILT] -20도: 자이로=-19.987, VL=-19.380, 오차=0.607  NG
[FINE] 수렴 완료: target=-45.00, actual=-45.040   ← 모터는 목표각 정확히 도달
[TILT] -45도: 자이로=-45.038, VL=-44.200, 오차=0.838  NG
```
- **모터(FINE)는 완벽히 수렴** → "못 기울어진" 문제가 아님.
- VL 읽음값만 자이로 대비 **20도 0.607 → 45도 0.838로 각도 클수록 오차 증가**.
- 이 **"0도 오차 0, 각도 클수록 오차 큼"(비선형) 패턴이 지그 수평/정렬 틀어짐의 확정 지문.**

### 왜 각도가 클수록 커지나
- 자이로(경사계): 각도 기준 선형 출력.
- VL(가속도): angle = **arcsin**(중력 성분). 지그에 롤(직교) 성분이 남아 있으면, 측정축을 θ로 기울일수록 그 성분이 VL 출력에 섞여 **오차가 각도에 비례해 커진다.** (작은 각도는 거의 안 보이고 ±45°에서 터짐)

### 3.1 왜 양산에 중요한가 — CAL은 제품에 저장되어 출하된다
- #5/#11의 CAL(OFFSET)은 `APPCFG,SAVE`로 **제품 비휘발성에 영구 저장되어 고객에게 출하**된다.
- 지그가 (롤로) 기운 채 CAL+SAVE 하면 그 편향이 제품에 박힌다. 검사(#6/#14)가 1차 안전망이지만:
  - **크게 틀어짐** → ±45° SPEC 초과 → FAIL → 출하 안 됨 (걸러짐)
  - **애매하게 틀어짐(예 ~1°)** → 검사 **통과** but **마진 깎인 CAL이 그대로 출하** ← 진짜 위험
- 출하된 편향 제품은 고객이 (지그와 다른) 평평한 면에 장착해 쓰면 오차가 드러나고, 온도·경년으로 마진이 더 빨리 소진된다.
- → **"검사 통과 = 안전"이 아니다.** 통과해도 출하 마진을 깎으므로, 셋업 수평 맞춤이 통과/불통과와 무관하게 필수.

## 4. 지그 수평(수평계 기포)이 미치는 영향 — 방향이 핵심

### 4.1 피치 vs 롤 (★ 자이로 단축이 핵심)

레퍼런스 자이로 SOLAR-360-420은 **단축(1축) 경사계**다 (데이터시트: *"Single axis measurement"*, *"SOLAR-360 Single axis ... 360° measurement range"*). 측정축(피치) 한 방향만 읽는다. 그래서:

| 구분 | 모터 회전(보정) | **자이로(단축) 측정** | 결과 |
|---|---|---|---|
| **피치 = 회전축 = 측정 방향** | O (돌림) | **O (읽음)** | FineAdjust로 gyro=0 맞춤 → **상쇄됨** ✅ |
| **롤 = 직교 방향** | X (못 돌림) | **X (못 읽음 — 단축)** | 아무도 못 봄 → **그대로 제품에 박힘** ⚠️ |
| **과도한 기울기(전체)** | 수평까지 못 감/소프트리밋 | — | **A. 미세조정 실패(FINE_FAIL)** |

### 4.2 롤은 "완전 사각(blind spot)"

- 롤 방향 기울기는 **모터도 못 잡고, 단축 자이로도 못 본다.** → 검사 시스템은 롤이 있는지 **존재 자체를 모른다.**
- 데이터시트도 단축 센서 출력은 *"includes cross axis errors"* — 크로스축 오차가 측정값에 섞여 들어가 분리 불가.
- 유일한 증상: **VibeTilt(제품) 센서가 ±45°에서 보이는 크로스축 오차** → `TILT_SPEC_OUT`(각도비례 오차)로만 나타남.
  - 롤이 크면 → SPEC 초과 → FAIL로 걸러짐
  - 롤이 작으면 → 검사 통과하지만 **마진 깎인 CAL이 제품에 저장·출하** (3.1 참고)

→ **결론: 롤은 소프트웨어로 절대 못 거른다. 버블 수평계로 사람이 롤까지 맞추는 게 유일한 방법.** 이것이 수평계가 셋업 필수 항목인 진짜 이유다.

## 5. 셋업 SOP / 재발 방지 (제조팀 적용)

1. **셋업 시 지그 수평을 먼저 맞춘다** — 수평계 기포 중앙, **롤 방향 포함**. (표준 항목화)
2. **VL 안착면/지그 정렬**을 함께 확인 — 제품이 비뚤게 안착하면 롤 성분과 동일 효과.
3. **검증은 기울기 4각도(-20/-45/+20/+45) 측정값**으로 한다.
   - -20° 오차가 ~0.05대인지 / -45°가 PASS 마진 안에 드는지 → 연속 3~5회 첫 시도 PASS면 양산 GO.
4. **기울기 FAIL을 SPEC 완화로 덮지 말 것** — 원인은 지그 수평/정렬이므로 수평을 잡아야 근본 해결.
5. FAIL 시 **유형부터 구분**: 로그 `[ERROR_TABLE]` 태그 확인 →
   - `TILT_FINE_FAIL` = 모터/EMIO/소프트리밋 점검 (또는 지그가 과도하게 기울었는지)
   - `TILT_SENSOR_DIFF` = COM/장착 방향/제품
   - `TILT_SPEC_OUT` = **지그 수평·정렬** (본 문서) → 수평계로 롤 포함 재정렬 후 재검

## 6. 권장 안전장치 (향후 개선 제안) — 롤을 DUT로 잡기

롤은 모터·단축 자이로 둘 다 못 보는 사각(4.2)이라 **자이로로는 못 거른다.** 하지만 **DUT(진동기울기센서)는 X·Y 2축 = 중력 절대 기준**이라, 단축 자이로가 못 보는 롤을 읽을 수 있다. → **자이로 대신 DUT로 지그 수평을 본다**는 발상. 두 가지 방식이 있다.

### 6.0 왜 안전장치가 "롤 전용"인가 — 피치는 이미 보정됨 (수치)
피치(측정축)는 FineAdjust가 알아서 끌어와 보정하므로 **별도 안전장치가 필요 없다.** 실제 보정 한도(JSON 실측):

| 항목 | 값 | 각도 환산 | 의미 |
|---|---|---|---|
| `fine_adjust_max_steps` | 250 step | **≈ 28도** | FineAdjust가 끌어와 수평 맞추는 피치 보정 한도 |
| `home_skip_max_deg` | 7도 | 7도 | skip 사이클서 자이로 0±7도 벗어나면 강제 홈복귀(드리프트 가드) |
| 소프트리밋(레지스터 28/29) | ±8000 step | ≈ ±900도 | 매우 넓음 → 피치 제약 아님 |

- 환산 기준: **0.1125 도/step (= 8.9 step/도)**, 검사범위 ±90도 = ±800 step.
- → **피치는 ~28도까지 흡수.** 현실 지그 기울기(몇 도)는 한참 안쪽이라 사실상 완전 보정. (그 이상이면 보정 아니라 `TILT_FINE_FAIL`)
- 그래서 **이 안전장치(A/B)는 피치가 아니라, 자이로·모터가 못 보는 "롤(직교)" 전용**이다.

### 옵션 A — DUT-raw 인터록 (HW 추가 없음, 즉시 적용용)
- **CAL(OFFSET) 저장 직전**, 검사 대상 DUT의 **OFFSET 적용 전 raw**를 읽는다.
- 측정축은 FineAdjust가 이미 0으로 만들었으므로, **raw의 크로스축(롤) 성분**(X검사면 Y축 raw) 또는 **총 기울기 크기**를 본다.
- `abs(롤 성분) > 임계값` 이면 **저장 차단 + "지그 재수평" 알람** → 버블(사람 눈) + DUT raw(센서) 이중 체크.
- **★ 한계:** raw는 캘 *전* 값이라 `raw = 진짜 지그 기울기 + 그 제품 고유 바이어스` → 둘을 못 분리. **정밀 도구 아님, "큰 기울기 잡는 조대(coarse) 2차 그물".** 임계는 제품 정상 바이어스 위로(버블 가시 이탈 ≈ 1~수 도, 제품 바이어스 ≈ sub-0.5도 → 0.5~1.0도 권장, 양산 데이터로 확정).

### 옵션 B — 골든샘플 붙박이 장착 (정석, 권장)
정밀 수평계로 잘 맞춘 **우리 제품 1개(골든)** 를 지그에 **고정 장착**해서 "살아있는 2축 수평계"로 쓴다. 캘됨(개체바이어스 0) + 2축(롤 검출) + 상시(매 사이클 자동) → A의 한계를 모두 해소.

- **만드는 법 (★ 제품 내부 OFFSET을 쓰지 말 것):**
  - 제품 OFFSET(CAL)은 **축별**이고 자세를 바꿔가며(X결합/Y결합) 해야 한다. 한 축만 하면 반대 축이 스펙아웃 FAIL. (근거: `2026-0413 485 테스트/TEST_OFFSET_SAVE후_축별검증_...Y축 OFFSET 후 Y축 PASS, X축 FAIL...html`)
  - 골든은 **한 자세로 붙박이 고정**이라 자세를 못 바꾼다 → **제품 내부 OFFSET 방식은 부적합.**
  - **대신:** 정밀 수평계로 지그를 진짜 수평으로 맞춘 그 순간, **골든이 읽는 raw X·Y값을 "기준 0"으로 한 번 기록** → 이후 그 기준에서 벗어나면 "지그 기울었다" 알람. (제품 캘 안 건드림 → 위 축별 OFFSET 함정 자체를 회피)
- **장점:** 사람 버블 안 봐도 매 사이클 자동, 피치·롤 동시.
- **주의:** ① 골든도 경년·온도 드리프트 → **주기적으로 마스터와 재검증.** ② DUT 안착면과 **동평면·견고·정렬** 장착. ③ 지그(안착면) 수평만 봄 — 개별 DUT 비뚤 안착은 별개(SENSOR_DIFF).
- **자이로(SOLAR-360)와 역할 분담:** 피치 FineAdjust 기준은 SOLAR 유지(검증된 레퍼런스), **골든은 SOLAR가 못 보는 롤 축을 추가** 담당.

### 적용 메모
- 둘 다 코드 변경이라 **착수 전 PLAN 작성 + 임계값 양산 데이터 확정** 필요(현 시점 미구현 제안). A=빠른 임시안, B=정석 권장안.

## 7. 실증 사례 (로그 전수 검증)

`output/Release` 모션 로그 + 배포본 + 제조 셋업 이슈를 전수 검토한 결과. **유형(태그)별로 원인이 다름**을 실측으로 확인:

| 시기 / 버전 | 태그 | 검증 결과 | 지그 수평? |

### 핵심 — 가장 깨끗한 "지그 수평(롤) → FAIL" 실증 = **4/14·17**
- 영점 시퀀스 정상: `[FINE] 수렴 완료 actual=-0.008 → setzcur → OFFSET 검증 AN X=-0.000 OK`
- **0도는 완벽한데 각도에서만 오차** (-20=0.607, -45=0.838) → **영점/소프트웨어 문제가 아니라, 0도 검증으로 안 보이는 롤(직교).**
- 즉 **"코드는 정상인데 지그가 롤로 기울어서 난 SPEC_OUT"** — 본 문서 주장의 직접 증거.

### 참고 — 4/1 setzcur 건과 혼동 주의
"FineAdjust 전에 setzcur 먼저"의 영점 오염 버그는 **4/1 한정**이며 그때 수정됨. 4/13~17은 그 이후라 영점 순서는 정상. (4/1=영점버그 / 4/14·17=물리 롤 — **서로 다른 원인, 증상만 같음**)
