## 1. 개요

setzcur 제거로 경사계 0점이 공장(중력) 기준에 고정됐다. 이제 영점 초기화 때
**경사계 첫 판독 = 기구 자세의 절대 수평 오차**가 그대로 읽힌다 (제거 전에는 0점이
매 사이클 덮여서 항상 0 근처 → 감시 불가능했다).

이 값(r_pre)을 매 사이클 기록하고, 스펙을 벗어나면 **작업자에게 지그 점검 알림**을 띄운다.
홈센서 마모·지그 재조립·센서 장착 틀어짐의 조기 감지.

## 2. 측정 지점 — UART 추가 없음

```
InitMotionZero (MotionJig.cs:700)
 4. 홈 + 1250스텝 이동                    :852
 ★ r_pre = FineAdjust 진입 판독           :1509  ← 이미 읽고 있음. 꺼내기만 하면 됨
 5. FineAdjust(0도 수렴)                  :864
```

- `FineAdjust` 시그니처에 `out double entryAngle` 추가 (private — API 변경 아님)
  - 호출부 4곳: `:864`(사용), `:986`·`:1248`·`:1276`(`out _`)
- `InitMotionZero`에도 `out double jigDev` 추가 → **판정·알림은 호출부(`:677`)에서**
  (알림에 쓸 `confirmCallback`을 호출부가 가짐)

현재 이 값은 `[FINE] 시작:` 로그(`:1515`)에만 나오는데 **IsTest 게이트 안**이라 MP에서 안 남는다.
→ 신규 `[JIG]` 로그는 게이트 **밖**에 둔다. `[FINE] step N` 스텝별 로그는 게이트 유지(양산 노이즈).

## 3. 기준 — 절대값이 아니라 baseline 대비 변화량

```
r_pre = 기구 실제각도 + μ(경사계 장착오차, 미지) + ε(±0.03)
```

setzfac 후 경사계 0 = 중력(진수평). 그러나 판독엔 μ가 항상 섞이므로 **r_pre 절대값은 진수평
대비가 아니다.** 7/16 실측 기준 배포 직후 r_pre는 0이 아니라 **≈ +0.09에서 시작**할 것
(기구가 이미 그만큼 틀어진 상태였음 — τ 실측). 절대값 스펙이면 시작부터 여유가 없어 오탐.

```
판정값 dev = | r_pre − baseline |        baseline: 축별, JSON 기입
```

- **baseline 설정**: 배포(setzfac 후) 첫 정상 10사이클의 중앙값을 회사에서 JSON에 기입
- **갱신 시점**: 지그 재조립, 경사계 재장착(μ 변경), setzfac 재실행 시 반드시 재설정
- 운영 흐름 확인: **setzfac 1회(센서 장착 상태) → 이후 영원히 read만.** 경사계는 중력 기준이라
  센서 자체 누적드리프트 없음(자이로 적분 아님). r_pre가 움직이면 **기구가 움직인 것**

## 4. 스펙 (확정안)

**스펙의 원본은 JSON이다(§6).** 코드는 `GetParamDouble(param, "jig_health_warn", 0.10)` 식으로
읽기만 하고 숫자를 하드코딩하지 않는다 (코드 기본값 = JSON에 키가 없을 때의 fallback, JSON과 동일값 유지).
→ 스펙 변경 = JSON 수정, 빌드 불필요. 근거 주석도 `_comment`로 JSON에 동봉.

```
[JIG] 기구영점 X: read=+0.093 base=+0.090 dev=0.003 (경고 0.10 / NG 0.25) OK
[JIG] 기구영점 Y: read=+0.341 base=+0.088 dev=0.253 (경고 0.10 / NG 0.25) NG — 지그 점검 요망
```

| 구간 | 로그 | 알림 | PASS/FAIL |
|---|---|---|---|
| dev ≤ 0.10 | `OK` | — | 영향 없음 |
| 0.10 < dev ≤ 0.25 | `WARN` | — | 영향 없음 |
| dev > 0.25 **연속 3회** | `NG` | 팝업 | 영향 없음 (기본) |
| \|r_pre\| > 1.0 (절대 가드) | `NG` | 팝업 즉시 (streak 무시) | 영향 없음 |

근거:
- **warn 0.10** — 기구 1스텝(0.1125°) 이동이면 확실히 걸림. 노이즈 0.002·단기요동 0.004(실측)의
  25배 위 → 평상시 오탐 없음
- **ng 0.25** — 2스텝 이상 = 명백한 기구 이동. FineAdjust 보정한계(수십°) 대비 미미해 제품 안전
- **절대 가드 1.0** — baseline 자체가 오염된 경우(센서 탈락·장착 대이변) 대비. baseline 무관 즉시
- 축 구분: `gyroDir`(setdir6=X / setdir5=Y). baseline·임계 모두 축별 JSON
- 양산 판정 불개입 기본 (`jig_health_fail_on_ng: false`). 단 작업자가 팝업 **취소** 시 FAIL·중단

### 원인별 — 이 감시가 잡는 것

| 원인 | r_pre 양상 | 제품 영향 |
|---|---|---|
| 고정볼트 풀림 / 진동에 의한 프레임 이동 | 서서히·계단식 | 없음 (FineAdjust 보정) |
| 홈센서 마모·오염 | 계단식 | 없음 (〃) |
| 모터 탈조·커플링 슬립 | 불규칙 튐 | 없음 (〃) |
| **경사계 장착 풀림 (μ 변화)** | 이동 | **있음 — 출하 영점 바이어스 직결** |

대부분은 FineAdjust가 보정해 **제품은 멀쩡한데 기구만 병드는** 경우 — r_pre가 유일한 감시자.
경사계 장착 풀림은 r_pre만으로 위 원인들과 **구분 불가** → 알림이 "점검하라"(원인 판단은 사람)인 이유.

## 5. 알림 — 기존 confirmCallback 재사용, 신규 UI 없음

`libraries["confirmCallback"]` (`Func<string,bool>`) — `MotionJig.cs:666`, `VibeTilt.cs:3238`에서 사용 중.

억제 2겹 (매 사이클 팝업 = 조건반사 확인 → 기능 무력화):
1. **연속 N회**(기본 3) 이탈에서만 — 1회 튐(접촉/진동)은 무시. OK/WARN 나오면 카운터 리셋
2. **교대당 1회** — 점검 확인 후엔 재알림 안 함. 로그·details엔 계속 NG 기록됨

팝업 문구는 JSON으로 (하드코딩 금지 규칙). 확인 이력은 로그+details에 남음 — 별도 점검이력 시스템 불요.

**팝업에 스펙 전체를 표기한다** — 치환자: `{axis}` `{read}` `{base}` `{dev}` `{warn}` `{ng}` `{streak}`.
작업자가 "얼마나 벗어났고 기준이 뭔지"를 팝업만 보고 알 수 있어야 한다. 문구·스펙 모두 JSON이므로
현장에서 빌드 없이 수정 가능.

```
지그 수평이 점검 스펙을 벗어났습니다. (Y축)

측정: +0.341도 / 기준선: +0.088도
변화량: 0.253도
스펙: 경고 0.10도 / NG 0.25도 (연속 3회 초과)

[점검] 1.지그 고정볼트 2.홈센서 위치/오염 3.경사계 장착
점검 후 확인. 취소 시 검사 중단.
```

## 7. 스펙 검증 (배포 후)

§4 스펙은 실측 τ·노이즈·격자 근거로 정한 확정안이나, **baseline이 아직 없고** 일간 변동폭이
미확인이므로 배포 직후 짧은 검증을 거친다.

1. 알림 off(streak 크게)로 배포 → **첫 10사이클 중앙값을 baseline으로 JSON 기입**
2. 3~5일 수집 → dev 분포 확인. 평상시 dev가 0.05를 넘나들면 warn 상향 검토 (JSON만 수정)
3. 이상 없으면 알림 on
