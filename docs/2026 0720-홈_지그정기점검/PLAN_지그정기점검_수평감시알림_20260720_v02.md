## 1. 개요

setzcur 제거로 경사계 0점이 공장(중력) 기준에 고정됐다. **홈 복귀를 실제 수행한** 영점
사이클에서 경사계 첫 판독(r_pre) = 기구 자세의 수평 오차가 그대로 읽힌다.
이 값을 기록하고 스펙 이탈 시 작업자에게 지그 점검 알림을 띄운다.
홈센서 마모·지그 재조립·경사계 장착 틀어짐의 조기 감지.

## 2. 전제 — r_pre는 홈 수행 사이클에서만 유효 (v02 핵심 수정)

r_pre가 "기구 수평 오차"인 것은 **홈센서+1250step을 실제 수행한 사이클뿐**이다.
홈 생략 시(`goto SkipToFineAdjust`, `MotionJig.cs:748-753`) 진입각은 "이전 사이클이
지그를 놓아둔 위치"다. 생략 경로는 두 갈래로 위험도가 다르다:

- `autoSkip`(home_every_n): 7° 이탈 시 강제 홈복귀 가드 있음(`:737-743`, `home_skip_max_deg`)
- **`skip_home: true`: 가드조차 안 탄다** — 가드는 `if (autoSkip)` 전용(`:737`)이고
  skipHome은 바로 `goto`(`:748`). 진입각이 수 도여도 그대로 FineAdjust로 간다

그런데 MP 실운영 설정(`MP_workspace_motion_232_VL10.json`):

| 항목 | 실설정 | 결과 |
|---|---|---|
| #3 X 영점 | `home_every_n: 10` (:142) | 10사이클 중 1회만 홈 수행 |
| #10 Y 영점 | `skip_home: true` (:338) | **홈 수행이 영원히 0회** |

→ **판정·기록 모두 홈 수행 사이클로 게이트한다.** 게이트 없이는 스킵 사이클마다 dev가
수 도 단위로 튀어 오탐 폭주(절대 가드 1.0 < autoSkip 허용 7.0), 알림이 배포 즉시 무력화된다.

- 홈 수행 여부는 `InitMotionZero`가 이미 안다(`skipHome`/`autoSkip`, `:748`) → `out bool homed`로 노출
- 스킵 사이클: 판정 생략, details에 `jig_homed: false`만 기록
- **감시는 X축(#3)만** (사용자 확정, 2026-07-20): 10사이클당 1점(home_every_n=10) —
  기구 드리프트(마모·풀림)는 일·주 단위라 추세 감시로 충분
- **Y축(#10)은 감시 제외.** `skip_home: true` 유지, 설정 변경 없음, 비용 0.
  근거(하드웨어 확정, CHECK D2): 레퍼런스 경사계는 **1축(피치) 센서**이고 피치=경사 방향.
  X/Y 검사가 **같은 지그·같은 센서·같은 측정축**(`setdir5/6`은 부호 반전뿐 —
  REF_경사계_tau실측결과 §4 실측 `+0.952`↔`−0.951`). 감시가 필요한 모든 변화(기구·홈센서·
  경사계 장착)는 피치 판독에 나타나므로 X r_pre가 전부 커버, Y r_pre는 새 정보 없음

## 4. 기준 — 절대값이 아니라 baseline 대비 변화량

```
r_pre = 기구 실제각도 + μ(경사계 장착오차, 미지) + ε(±0.03)
판정값 dev = | r_pre − baseline |        baseline: 축별, JSON 기입
```

setzfac 후 경사계 0 = 중력(진수평)이지만 판독엔 μ가 섞인다. 7/16 실측 기준 배포 직후
r_pre ≈ +0.09에서 시작할 것(τ 실측). 절대값 스펙이면 시작부터 여유가 없어 오탐 → 변화량 기준.

- **baseline 설정**: 배포(setzfac 후) **홈 수행 사이클 10개**의 중앙값을 JSON 기입
  (X는 home_every_n=10이라 ~100사이클 ≈ 하루 물량, 최초 1회 포함)
- **갱신**: 지그 재조립, 경사계 재장착(μ 변경), setzfac 재실행 시 반드시 재설정
- 운영 흐름: **setzfac 1회(센서 장착 상태) → 이후 영원히 read만.** 경사계는 중력 기준이라
  센서 자체 누적드리프트 없음. r_pre가 움직이면 **기구가 움직인 것**

## 5. 스펙 (확정안)

**스펙의 원본은 JSON이다(§7).** 코드는 `GetParamDouble(param, "jig_health_warn", 0.10)` 식으로
읽기만 하고 하드코딩하지 않는다(코드 기본값 = JSON 부재 시 fallback, 동일값 유지).
→ 스펙 변경 = JSON 수정, 빌드 불필요.

```
[JIG] 기구영점 X: read=+0.093 base=+0.090 dev=0.003 (경고 0.10 / NG 0.25) OK
[JIG] 기구영점 X: 홈 생략 사이클 — 판정 생략            ← IsTest에서만 (양산 노이즈 방지)
```

| 구간 (homed 사이클만) | 로그 | 알림 | PASS/FAIL |
|---|---|---|---|
| dev ≤ 0.10 | `OK` | — | 영향 없음 |
| 0.10 < dev ≤ 0.25 | `WARN` | — | 영향 없음 |
| dev > 0.25 **연속 3회** | `NG` | 팝업 | 영향 없음 (기본) |
| \|r_pre\| > 1.0 (절대 가드) | `NG` | 팝업 즉시 | 영향 없음 |

근거:
- **warn 0.10** — 기구 1스텝(0.1125°) 이동이면 확실히 걸림. 단기요동 0.004(실측)의 25배 → 오탐 없음
- **ng 0.25** — 2스텝+ = 명백한 기구 이동. FineAdjust 보정한계 대비 미미해 제품 안전
- **절대 가드 1.0** — baseline 오염(센서 탈락 등) 대비. homed 사이클만 평가하므로 autoSkip 7°와 무관
- streak 카운터: **homed 사이클만** 증감. OK/WARN이면 리셋.
  **주의: streak 3 = 홈 사이클 3회 ≈ 30사이클 지연**(home_every_n=10 기준).
  유효 표본이 홈 사이클뿐이라 튐 확률도 낮으므로 **streak 2(≈20사이클)로 줄이는 것 검토 — §9-3**
- 양산 판정 불개입 기본(`jig_health_fail_on_ng: false`). 단 작업자가 팝업 **취소** 시 FAIL·중단

### 원인별 — 이 감시가 잡는 것

| 원인 | r_pre 양상 | 제품 영향 |
|---|---|---|
| 고정볼트 풀림 / 진동에 의한 프레임 이동 | 서서히·계단식 | 없음 (FineAdjust 보정) |
| 홈센서 마모·오염 | 계단식 | 없음 (〃) |
| 모터 탈조·커플링 슬립 | 불규칙 튐 | 없음 (〃) |
| **경사계 장착 풀림 (μ 변화)** | 이동 | **있음 — 출하 영점 바이어스 직결** |

대부분은 FineAdjust가 보정해 제품은 멀쩡한데 기구만 병든다 — r_pre가 유일한 감시자.
경사계 장착 풀림은 r_pre만으론 구분 불가 → 알림이 "점검하라"(원인 판단은 사람)인 이유.

억제 2겹 (매번 팝업 = 조건반사 확인 → 무력화):
1. **연속 N회**(기본 3) — 1회 튐(접촉/진동) 무시. homed 사이클만 카운트
2. **교대당 1회** — 점검 확인 후 재알림 없음. 로그·details엔 계속 NG 기록

**팝업에 스펙 전체 표기** — 치환자: `{axis}` `{read}` `{base}` `{dev}` `{warn}` `{ng}` `{streak}`.

```

```

문구·스펙 모두 JSON — 현장에서 빌드 없이 수정 가능.

### 확인/취소 모두 명시 기록 (검증 지적 반영)

기존 팝업 패턴(`MotionJig.cs:665-673`)은 **확인(OK) 시 기록이 없다** — 취소만 로그가 남고,
OK는 "검사가 계속됐다는 정황"뿐. 점검 팝업의 목적이 "점검했다는 이력"이므로 양쪽 다 남긴다:

| 작업자 선택 | 로그 (IsTest 밖) | details | 검사 |
|---|---|---|---|
| 확인 | `[JIG] 작업자 점검 확인 (dev={dev})` | `jig_check_result: "confirmed"` | 계속 진행 |
| 취소 | `[JIG] 작업자 취소 — 지그 점검 필요` | `jig_check_result: "cancelled"` | 항목 FAIL·중단 |

이게 없으면 나중에 "NG 떴는데 점검을 했는지"를 로그로 증명할 수 없다 —
setzcur 침묵 건과 같은 계열(로그가 자기 조건을 증명하지 못하는 문제).

```
1단계  setzcur 판별로그 (별도 PLAN v02) — 선행                    [회사]
2단계  측정·로깅: FineAdjust/InitMotionZero out + JigHealthCheck 헬퍼
       + [JIG] 로그 + details 배관 + JSON #3 (8 or 12파일)         [회사]
       알림 off 배포 → baseline 기입 (§8-1) → 3~5일 검증
3단계  알림 on: confirmCallback + 연속카운터 + 교대1회 억제         [회사]
       → CODE_ 문서 → 커밋
4단계  품질모니터링 추세 연동 (선택)                               [집 가능]
```

원칙: **homed 게이트 없이 알림을 켜지 않는다** (스킵 사이클 오탐 폭주).
baseline 없이도 켜지 않는다 (시작점 ≈ +0.09).
