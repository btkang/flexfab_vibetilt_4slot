# PLAN_보드 정지(rest) 노이즈 검사 추가

- 작성일: 2026-06-04 / 작성: Claude
- 목표 버전: **0.7.2** (현재 최신 0.7.1.60601의 다음)
- 브랜치: **main** (단일 trunk)
- 대상: 보드검사, **진동검사(VIBE) 바로 앞** / VL20 485 우선, VL10 232 동일 센서면 같이

---

## 1. 목적
정지 상태에서 센서값이 출렁이는(노이즈성) 불량을 **보드단에서 조기 검출**. "가만히 있는데 값이 움직이는 것처럼 나오는" 시료를 거른다.

## 2. 배경 — 왜 필요 (현재 사각)
- **정지 안정성 검사가 보드·모션 통틀어 0개.**
- 보드 VIBE/TILT: **흔드는 중만** 측정 + require_motion → 노이즈가 오히려 "움직임"으로 통과.
- 모션 verify_an: OFFSET 후 AN(각도) ~1초 스트림을 **"평균"으로 ±0.05 판정** (`VibeTilt.cs:1286`) → **대칭 노이즈 상쇄(zero-mean blind)**. 가장 약한 고리.
- 모션 tilt/vibe all_in_spec(tail10/5): 큰·지속 노이즈는 잡지만 **tail 끝구간 + retry3** → 작은/간헐은 통과 가능.
- → **작은/간헐 정지 노이즈는 보드·모션 모두 escape 가능.**

## 3. 설계
### 위치 (별도 스텝, VIBE 앞)
```
... LED검사(OPERATOR_CONFIRM)
 → [신규] 정지 안정성 검사 (가만히)      ← 추가
 → VIBE_485 (흔들기, require_motion)
 → TILT_X / TILT_Y
```
- VIBE **앞** = 보드 아직 안 흔든 정지 보장. / **별도 스텝**(VIBE 병합 X) = 독립 strict 판정.

### 측정 방식
- MODE **02(GAC)** 진입 → **정지** 상태 ~1초 스트리밍 수집 (작업자 손 뗌, 안 움직임)
- 지표: **0축(X,Y) RMS** + (선택) **변동폭 p2p(max−min)**
- 판정: `RMS ≤ 임계` (AND `p2p ≤ 임계`) → PASS / 초과 → **FAIL(노이즈)**
- **★평균(mean) 금지 — RMS/p2p로★** (평균은 노이즈 상쇄)
- **retry = 0** (간헐 노이즈 안 가려지게)
- **전 구간 샘플 판정** (tail 끝 N개 아님)
- **require_motion 없음** — 오히려 "안 움직여야" 정상

### 작업자 프롬프트
"센서를 가만히 둔 채 잠시 기다려 주세요 (안정성 측정)"

## 4. 판정 기준값 결정 (선결 과제)
- 정상 보드 정지 RMS/p2p 실측 데이터가 **현재 없음**.
- **1단계: 정상 보드 N대 정지 측정 → RMS/p2p 분포 확인 → 임계 확정** (μ+여유). 잠정값: `RMS < 0.1`, `p2p < 0.05`.
- 가능하면 노이즈 의심 시료로 **FAIL 재현** 확인.

## 5. 변경 범위
### 코드 (`ff_vibetilt/VibeTilt.cs` — 프로젝트별 라이브러리)
- 신규 핸들러 (예: `VIBE_STILL_Internal`) — 기존 VIBE의 GAC 수집/파싱 로직 재사용 + **정지 판정(RMS/p2p, no require_motion, no retry)**.
- proc id 라우팅 추가 (`VIBE_485`→`VIBE_Internal` 패턴 따라): `VIBE_STILL_485` / `VIBE_STILL_232`.
### JSON (보드 워크스페이스)
- 신규 proc를 **VIBE 앞에 삽입**.
- 대상: 232/485 × MP/TEST × **Debug/Release 동시**.
- 파라미터: `rms_max`, `p2p_max`, `duration`(~1000ms), `sampling_ms`, `judge=all_in_spec`, `retry=0` + `_comment`.
### 작업자 프롬프트 / 사이클
- 프롬프트 추가. 사이클 **+1~2초/대** 예상.

## 6. 대상 범위
- **485 우선** (6/2 분석 데이터 있음) → **232는 동일 센서면 같이** (232 정상 보드 정지 데이터도 수집 필요).

## 7. 테스트
- 정상 보드: 정지 RMS/p2p 낮음 → **PASS**.
- 노이즈 시료 확보 시: **FAIL 재현**.
- 사이클 시간 영향 측정.
- 회귀: 기존 VIBE/TILT/전원/통신 영향 없음 확인.

## 8. 버전 / 배포
- **0.7.2.xxxxx**: csproj 버전업 + `ff_vibetilt` 빌드 + 보드 JSON(Debug/Release) + 배포폴더 생성.

## 9. 리스크 / 미결
- **임계값 미확정** (1단계 데이터 필수) — 빡빡하면 양품 오검출, 느슨하면 무의미.
- 232 센서 동일성 확인 필요.
- **노이즈 시료 확보 어려움** → FAIL 검증이 제한적일 수 있음 (정상 PASS만 검증 가능할 수도).
- 작업자가 "가만히" 미준수(건드림) 시 오검출 → 프롬프트 + 적절한 수집 윈도.
- MODE 02 셋업이 VIBE와 별도 → 셋업 2회분 사이클 영향. (병합 대안 대비 trade-off — strict 판정 우선이라 별도 채택)
