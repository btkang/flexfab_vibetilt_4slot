## 0. 한눈에

| 축 | pCOM2 | BG01 (핸디 / MOS) | **VibeTilt (VL)** |
|---|---|---|---|
| **기울기 측정** | 절대측정 없음 — 발열 전후 **드리프트**만 | 핸디: 수동 반응 유무 / MOS: **자동 ±10.5° 2점** | **자동 ±20°/±45° 4점** + 보드 수동 5~95° |
| **영점 처리** | `MBSET` 펌웨어 내부 + config offset=0 확인 | 핸디: 없음 / MOS: 지그측 `setzcur` 1회 | **DUT `OFFSET` 실행 + AN ±0.05 검증 + SAVE** |
| **외부 기준** | 없음 | MOS: 독립 기준 경사센서 | 지그 자이로 + 상용센서(SOLAR-360-420) |
| **정렬 수단** | 모터(`angle_0_init`) | MOS: `setzcur`가 정렬 대체 | 모터(`FineAdjust`) **＋** `setzcur` (둘 다) |
| **판정 통계** | 1회 | 1회(재측정 3회) | **N샘플 all_in_spec + retry 3** |

> 핵심 한 줄: **정렬 전략이 두 갈래(모터 vs tare)인데 VL만 둘을 병합**했고, 그 결과 `setzcur`는 기능적 잉여가 되어 수렴 잔차의 영구 누적만 남긴다. (→ 5장)

> ★ **가장 큰 구조 차이(→ 1장)**: 측정 각도를 **누가 정하느냐**.
> BG01 MOS·pCOM 원본은 **지그 기계식 리밋스위치**가 ±10.5°를 정하고 레퍼런스는 0도 tare만 → DUT는 **절대 window** 판정.
> VibeTilt는 **레퍼런스 자이로 폐루프**가 매 각도를 실시간으로 맞추고 → DUT는 **자이로 대비 상대오차** 판정.

## 1. 절차 흐름 (레퍼런스 ↔ DUT, 시간 순서) ★

각 모델을 **① 0도 영점 확립 → ② 측정 각도 이동 → ③ 그 각도에서 레퍼런스·DUT 측정/판정** 순서로 나열.
(대상: 레퍼런스 센서 + DUT + 모터가 모두 있는 **모터지그 계열**. pCOM2 출하 보드검사의 "발열 드리프트"는 지그·레퍼런스가 없는 별개 정적검사 — 2장 참고.)

**용어**
- 레퍼런스 = 지그에 붙은 기준 경사센서(SOLAR류, port3). 명령: `setdir5/6`(방향) · `setzcur`(현자세=0 tare) · `get---x`(각도 읽기) · `setzfac`(공장영점 복귀)
- DUT(BG01/pCOM 보드) = `<msopen>`/`<mstest>`→`A=ax,ay,az,ACC=...,T=..,GA=gx,gy,gz`/`<msclose>` · 스케일 각도×100·가속도×1000·자이로×100
- DUT(VL) = `<MODE 06>`+`<START>`/`<STOP>` 스트리밍 · `AN`(각도) · `GAC`(가속도) · `OFFSET`(내장 CAL) · `SAVE`
- 모터 = `PMOxxx`(홈) · `PMD07/08`(상대이동) · `PML011`(위치질의→리밋코드) · `PMD04/05`(1스텝 미세이동)

---

### 1-1. pCOM / pSMC — 모터지그 원본 (계보의 뿌리)

| 단계 | 레퍼런스(기준센서) | 모터 | DUT | 비고 |
|---|---|---|---|---|
| **① 0도 확립** | `DEGREE_0_CHECK`에서 **체크박스("Ref. Gyro Sensor Init") ON일 때만** `setzcur`→`get---x`로 기준각 `m_Refangle` 캡처 | 홈복귀(기계원점) | — | **미체크 시 아무 것도 안 함**(공장영점 유지) |
| **② 각도 이동(±10.5°)** | (사용 안 함) | `PMD071LM1500` 상대이동 후 `PML011`로 **리밋스위치 도달 확인**(도달 못하면 재이동) | — | 각도는 **기계 리밋이 규정** |
| **③ 측정·판정** | `get---x` 읽지만 **판정엔 미사용** | — | `<mstest>` → `angle_measure(sign)` | DUT를 **절대 window**로 판정, 불일치 시 재측정 |
| **(0도 복귀)** | — | `angle_0_init()`: `get---x` 읽어 `m_Refangle`과 **±0.005 이내까지 1스텝씩 모터 서보** | — | **여기서만** 레퍼런스로 모터를 정렬 |

→ 레퍼런스 역할: **0도 datum 확립(옵션) + 0도 복귀 시 모터 서보 기준**. 기울기 각도(±10.5°)는 **기계 리밋**이 정하고 DUT는 절대값 판정.

---

### 1-2. BG01 MOS — 원본에서 "우회"된 버전

| 단계 | 레퍼런스(기준센서) | 모터 | DUT | 비고 |
|---|---|---|---|---|
| **① 0도 확립** | `DEGREE_0_CHECK`: `setzcur`→`get---x`로 `m_Refangle` 캡처 | `JIG_INIT` 기계 홈복귀 | 보드 인식(`<msopen>`) | 기계 홈=0°(`pml00516000`) 위에서 레퍼런스 tare |
| **② +10.5° 이동** | (사용 안 함) | `PMD071LL1500`→`PML011`이 **`pml00517500`(+10.5° 리밋) 도달**까지 이동/재이동 | — | 각도=**기계 리밋** |
| **③ +10.5° 측정·판정** | `get---x` 읽지만 **판정 미사용** | — | `<mstest>` → `angle_measureEach(-1,-1,0)` | **절대 window**: 각도 **1020~1080**(10.2~10.8°), 수평축 ±0.3°, Z방위 180±0.3°, 가속도 측면 175~188(=sin10.5°)·중력 ±8mg, 자이로 0축 ±100 |
| **④ 0도 복귀·재tare** | `angle_0_init_Revision()`: `get---x` 읽고 **무조건 `setzcur`**(모터 서보 로직은 주석처리·`// Temporarily`) | (안 움직임) | — | **원본의 모터 정렬을 tare로 대체** |
| **⑤ −10.5° 이동·측정** | 상동(미사용) | `PMD081LL-1500`→`pml00514500` 도달 | `<mstest>`→`angle_measureEach(0,0,-1)` | −쪽 절대 window |

→ 레퍼런스 역할: **0도 datum(tare)만.** 각도는 전부 **기계 리밋**, DUT는 **절대 window**. 원본의 "0도 복귀 모터서보"가 `_Revision()`에서 **tare로 대체**된 미완성 상태.

### 1-3. VibeTilt (VL) — 레퍼런스 폐루프 방식

| 단계 | 레퍼런스(지그 자이로) | 모터 | DUT(VL) | 비고 |
|---|---|---|---|---|
| **① 0도 확립**(`MOTION_ZERO`) | `setdir6/5`(방향) → **`FineAdjust`: 자이로 읽어 \|자이로−0\|≤0.03° 될 때까지 모터 폐루프 서보**(10s 후 0.05 완화) → **`setzcur`**(현 자세 tare) | 홈센서 coarse(고정 step) → FineAdjust 미세이동 | — | 홈은 **coarse만**, 실제 0점은 **자이로 폐루프**가 결정. setzcur는 **잉여**(→5장) |
| **①' DUT 영점**(`OFFSET`, Calibration) | — | (0도 유지) | `<OFFSET,1>` 실행 → `AN` 스트리밍 **0도 ±0.05 검증**(verify_an) → `SAVE`→`APPCFG` | **DUT 내장 CAL을 실행·검증·저장** (참조모델엔 없음) |
| **② 각도 이동(±20°/±45°)** | — | coarse `AngleToSteps(target−current)` → **`FineAdjust`: 자이로가 target±0.05 될 때까지 폐루프 서보** | — | 각도를 **자이로가 실시간 규정**(기계 리밋 아님) |
| **③ 측정·판정** | `get`으로 **자이로 실제각 `gyroAngle` 확정** | — | `<MODE06><START>`→AN 스트리밍 수집→`<STOP>`, 마지막 N샘플 | **상대오차** `error = VL − gyroAngle` 를 **±0.2°(20°)/±0.5°(45°)** 로, 마지막 N개 **전부(all_in_spec)** 통과 판정, retry 3 |
| **(안전체크)** | `\|gyroAngle − VL\| ≥ sensor_diff_error` 면 즉시 중단(하드웨어 이상, 재측정 무의미) | — | — | 레퍼런스·DUT 정합 크로스체크 |

→ 레퍼런스 역할: **매 측정 각도의 실시간 기준(truth).** DUT를 **자이로 대비 상대오차**로 판정 → 지그 각도 오차가 자이로에도 같이 실려 **common-mode 상쇄** 위험(→5·6장).

### 1-4. 세 방식 한 장 요약

| 질문 | pCOM/pSMC 원본 | BG01 MOS | **VibeTilt** |
|---|---|---|---|
| **0도를 누가 정하나** | 기계 홈 + 레퍼런스 tare(옵션) | 기계 홈 + 레퍼런스 tare(무조건) | **자이로 폐루프**(FineAdjust) + tare |
| **측정각(±)을 누가 정하나** | **기계 리밋스위치** | **기계 리밋스위치** | **레퍼런스 자이로**(실시간 서보) |
| **DUT 판정 기준** | **절대 window** | **절대 window** | **레퍼런스 대비 상대오차** |
| **측정각서 레퍼런스 읽나** | 읽지만 판정 미사용 | 읽지만 판정 미사용 | **읽어서 판정 기준으로 사용** |
| **DUT 내장 CAL** | 없음 | 없음 | **OFFSET 실행+±0.05 검증+SAVE** |
| **측정점 / spec** | ±10.5° 2점 / 절대 ±0.3° | ±10.5° 2점 / 절대 ±0.3° | ±20/±45 4점 / 상대 ±0.2·±0.5° |

**해석**
- 절대 window(BG01/pCOM)는 **레퍼런스와 DUT가 독립** — 지그(기계 리밋)가 참각도의 근거라 지그 기구정밀도에 의존하지만, DUT 불량은 레퍼런스와 무관하게 절대 기준으로 걸러짐.
- 상대오차(VL)는 **레퍼런스가 곧 참값** — 각도를 유연하게(임의 각도) 세울 수 있고 지그 기계 리밋이 불필요하지만, 레퍼런스(자이로)의 영점/드리프트가 판정에 직접 섞임. VL이 `setzcur`로 자이로 영점을 사이클마다 굳히는 구조라 이 리스크가 실재(→5장).

## 2. 기울기(Tilt) 측정 비교

| 비교 항목 | pCOM2 | BG01 핸디 | BG01 MOS | **VibeTilt (VL)** |
|---|---|---|---|---|
| 측정 방식 | 절대 각도 판정 없음 — 발열 전후 **각도 변화량(드리프트)** | 검사원 수동 기울임 | **모터 턴테이블 자동** | **모션지그 자동**(X/Y 결합) + 보드검사 수동 |
| 측정 자세/점수 | 정치 1점(전·후 Δ) | 1점(반응 유무) | **±10.5° 정적 2점** | 모션 **±20°/±45° 4점**, 보드 5~95° |
| 판정 spec | \|ΔX\|,\|ΔY\| ≤ 0.01×ΔT+0.07° / \|ΔZ\| ≤ 0.1° | \|각도\| **> 10°** 초과 여부 | 기울인축 **±10.5° ± 0.3°**, 수평축 0±0.3°, Z방위 180±0.3° | **±20° → ±0.2° / ±45° → ±0.5°** (분해능 0.01°) |
| 온도 조건 | ΔTemp ≥ **8°C**(발열 유효 전제) | 없음 | 표시만 | spec 20~40°C 판정 + DB 저장 |
| 통계 방식 | 1회 측정 | 폴링 중 1회 초과 | 1회(불일치 시 3회 재측정) | **마지막 N샘플 all_in_spec + retry 3** |
| 가속도 교차검증 | 없음 | 없음 | 측면축 ≈sin10.5°(0.18g)·중력축 0.98g±8mg window | 진동(중력축 0.98~1.02g) **별도 스텝** |
| 진동 검사 | 없음(config 기록만) | 없음 | 없음(Longrun 대체) | **있음**(보드 감지 / 모션 정량) |
| spec 관리 | 소스 하드코딩 + Config.txt | **소스 하드코딩** | **소스 하드코딩(설정파일 없음)** | **workspace JSON(주석 포함)** |

**요약**
- pCOM은 기울기를 *절대값*으로 보지 않고 **발열 드리프트**로만 본다(온도 이슈 특화).
- BG01 핸디는 "±10° 넘게 반응하나" 수준의 **유무 판정**, MOS에서 비로소 **±0.3° 정량 2점**으로 발전.
- VL은 **±20/±45 4점 + 진동 정량 + N샘플 통계**로 가장 정량적. 다만 기울기(AN)와 가속도(GAC)를 **다른 스텝**에서 판정 → MOS식 *동일 자세 교차검증*은 없음(저비용 추가 아이디어).

## 3. 영점(Zero / Calibration) 처리 비교

| 비교 항목 | pCOM2 | BG01 핸디 | BG01 MOS | **VibeTilt (VL)** |
|---|---|---|---|---|
| 영점 확립 수단 | `MBSET=0→1→2` 펌웨어 내부 영점 | **없음**(펌웨어 몫) | 지그측 기준센서 `setzcur` | **DUT `OFFSET` 명령 실행** |
| 외부 수평 기준 | 없음 | 없음 | **독립 기준 경사센서**(UART 38400) | 지그 자이로(setdir5/6) + 상용센서(SOLAR) |
| 정렬(수평 맞춤) 수단 | **모터**(`angle_0_init`, 폐루프 ±0.005) | — | **`setzcur`(tare)** 가 모터 정렬 대체 | **모터**(`FineAdjust`, ±0.03/0.05) **＋ `setzcur`** |
| DUT CAL 검증 | 없음(MBSET 후 확인 안 함) | 없음 | 없음(DUT 0±0.3° window로 간접) | **AN 0도 ±0.05 검증(verify_an) → SAVE → APPCFG** |
| `setzcur`(tare) 운용 | 원본은 **체크박스 게이트**("Ref. Gyro Sensor Init") — 셋업 시 **선택적 1회** | — | **매 정렬마다 무조건**(`angle_0_init_Revision`, `// Temporarily`) | **매 사이클**(FineAdjust **뒤**) |
| 영점 복원성 | config offset=0 echo 검증 | — | 지그 0점만, DUT 무관 | **모터가 이미 정렬 완료 → setzcur는 잉여**(잔차 누적) |
| 정지(노이즈) 검사 | 없음 | 없음 | 없음 | **있음**(1초 GAC, p2p ≤ 0.05) |

**요약**
- pCOM: 영점은 **펌웨어 내부(MBSET)** + config offset=0 확인. 외부 기준 없음. (원본 모터지그 버전엔 `setzcur` **체크박스 선택 1회** + 모터 정렬)
- BG01 핸디: 영점 CAL **없음**(각도·영점 전부 DUT 펌웨어 몫, PC는 임계 초과 여부만).
- BG01 MOS: **지그 0점만** `setzcur`로 잡고 DUT엔 CAL 안 씀 → DUT 영점은 window로 간접 확인.
- VL: **DUT 영점을 실행(OFFSET)·검증(±0.05)·저장(SAVE)** 하는 유일한 완결 사이클. 단 정렬을 FineAdjust가 끝낸 뒤 `setzcur`를 또 침(→ 5장).

## 4. 계보(Lineage) — 영점 전략의 두 갈래

| 세대 | 정렬 수단 | `setzcur` 시점 | 게이트 | 상태 |
|---|---|---|---|---|
| **pCOM / pSMC (원본)** | 모터(`angle_0_init`) | 셋업 시 **1회**(DEGREE_0_CHECK) | **"Ref. Gyro Sensor Init" 체크박스** | 정상 설계 |
| **BG01** | **`setzcur`**(`angle_0_init_Revision`) | **매 정렬마다 무조건** | **없음(우회)** | `// Temporarily` — 미완성 |
| **VibeTilt (VL)** | 모터(`FineAdjust`) **＋ `setzcur`** | **매 사이클**(MOTION_ZERO) | **없음** | 두 전략 병합 |

- **원본(pCOM/pSMC)**: 매 사이클 정렬은 **모터**가, `setzcur`는 **작업자가 켜는 셋업용 선택 단계**(기본 미동작). → 지그 요청서의 "상용센서 0도 이동·조정" 모델과 일치.
- **BG01**: 모터 정렬을 tare로 대체한 임시함수(`_Revision`)가 체크박스를 **우회**해 `setzcur`를 매번 무조건 실행.
- **VL**: 구모델의 **모터 정렬(FineAdjust)** 과 BG01의 **tare(setzcur)** 를 순차로 **둘 다** 수행.

---

## 5. VL의 setzcur 잉여 문제 (핵심 시사점)

두 정렬 방식은 **같은 목적(0도 정렬)의 대안**이지 조합 대상이 아니다.
`FineAdjust`가 이미 자이로=0 자세로 만든 **뒤에** `setzcur`를 치므로:

- `setzcur`의 기능적 역할 = **없음** (정렬은 FineAdjust가 이미 완료)
- 유일한 효과 = **수렴 잔차(≤0.03°)를 비휘발 영점에 각인** → 사이클마다 **복원력 없는 누적**

| 사이클당 기계 틀어짐 `m` | FineAdjust 동작 | setzcur 결과 |
|---|---|---|
| \|m\| > 0.03° (tolerance) | 자이로 0 자세로 **되돌림** | 영점 유지 — 드리프트 없음 |
| \|m\| ≤ 0.03° | 허용범위 내 → **모터 안 움직임** | **틀어진 자세가 새 영점으로 확정 — 1:1 누적** |

- 모든 기울기 판정이 `error = VL − 자이로` **상대 비교**라, 자이로 영점이 틀어지면 DUT cal도 같은 기준을 물려받아 **common-mode 상쇄 → 전량 PASS 위험**.
- **"온도 드리프트 상쇄" 옹호 논거는 순환 참조로 기각** — 자이로가 정한 자세에서 자이로를 tare하는 것은 어떤 오차도 제거하지 못함(외부 수평 기준 없음).

**방향**: `setzcur` 제거(또는 원본처럼 **옵션화**: JSON 플래그 `ref_gyro_sensor_init` 기본 false)는 **원본 설계·지그 요청서 양쪽과 일치**. 단 실기 회귀 검증 필수, 그리고 온도 오차(±0.15/±0.05, PN 확인)는 **별건**으로 분리 처리.

## 6. VibeTilt가 이미 앞서 있는 부분 (참조 3모델 대비)

1. **spec 외부화(JSON+주석)** — 참조 모델 전부 소스 하드코딩(라인 변경 시 재빌드 필요).
2. **진동 정량 검사** — 진동을 실제 판정하는 프로그램은 VL이 유일(pCOM은 config 기록만).
3. **DUT 영점 실행+검증+저장 사이클** — MOS는 지그 0점만, pCOM은 MBSET 후 확인 없음. VL은 OFFSET→±0.05 검증→SAVE→APPCFG로 가장 완결적.
4. **판정 통계(N샘플 all_in_spec + retry)** — 참조 모델은 전부 1회성 측정. 순간 노이즈 내성은 VL뿐.

## 7. VL 검토에 참고할 만한 것 (영점 관점)

1. **온도-드리프트 검사(pCOM/pSMC)**: 영점 후 발열(ΔT 8°C) → `0.01×ΔT+0.07°` 판정. VL엔 없음 → 온도에 따른 영점 이동 불량 미검출. (사이클 8초+ 부담)
2. **독립 기준 경사센서로 지그 0점 확인(MOS)**: 지그 기구 마모/드리프트를 DUT와 독립 검증. VL은 `home_skip_max_deg=7`로 부분 대응.
3. **Z 방위각 판정(MOS, 180°±0.3°)**: 실장 방향(뒤집힘/회전 오조립) 감지. VL은 수평면 회전 오조립 감지 항목 없음(해당 불량모드 존재 여부 확인 필요 — TODO).
4. **동일 자세 각도-가속도 교차검증(MOS)**: 기울인 각도와 측면 가속도(sinθ)를 함께 window 판정 → 연산부·원시값 정합 확인. VL은 별도 스텝 → 저비용 추가 아이디어.
