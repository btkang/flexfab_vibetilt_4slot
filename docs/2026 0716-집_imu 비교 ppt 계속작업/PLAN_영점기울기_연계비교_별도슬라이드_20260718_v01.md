# PLAN_영점·기울기 「연계」 비교 — 별도 메인 슬라이드

- 작성: Claude / 2026-07-18 (집 작업)
- 요구(사용자 NOTE): "레퍼런스센서·DUT 와 [영점 잡고 → 기울기 측정] 같이 비교. VL/pCOM/BG01.
  pCOM·BG01 메인폼의 체크/미체크 옵션도 같이. **이걸 별도로** 만들고 싶다 —
  이게 IMU 검사방법 **메인**이니까. 기존 슬라이드는 **특징들의 연계가 안 됨.**"
- 상태: **설계안 — 사용자 승인 후 PPT 구현**

## 0. 이 슬라이드가 풀어야 할 것 (기존 대비 무엇이 다른가)

기존 v14의 S11~S14는 "레퍼런스", "영점", "캘", "측정"을 **항목별로 나눠** 보여준다.
→ 각 특징이 **왜 그렇게 묶이는지(연계)** 가 안 보인다.

이 별도 슬라이드의 논지는 **한 줄**:

> **"레퍼런스 영점(setzcur)을 끌 수 있느냐"가 곧 "기울기 판정이 레퍼런스에 의존하느냐"를 결정한다.**
> pCOM·BG01은 메인폼 체크박스로 **끌 수 있다 → 판정은 절대 window(레퍼런스 독립).**
> VL은 **끌 수 없다(체크박스 없이 매 사이클 강제) → 판정은 레퍼런스 상대오차(레퍼런스 의존) → common-mode 리스크.**

즉 **체크박스의 유무 자체**가 판정 구조(절대 vs 상대)의 증거다. 이게 "연계"다.

## 1. 소스 확정 사실 (이번에 1차 소스 재확인 — REF 정정 포함)

| 항목 | pCOM / pSMC | BG01 MOS | VL (VibeTilt) |
|---|---|---|---|
| 레퍼런스 영점 게이트 **체크박스** | **"Ref. Gyro Sensor Init"** (`IDC_CHECK13`) | **"Ref. Gyro Sensor Init"** (`IDC_CHECK13_BG01`) | **없음** |
| 체크박스 **기본값** | **체크(ON)** — `OnInitDialog` `SetCheck(1)` | **체크(ON)** — 동일 | — |
| 체크 시 동작 | `DEGREE_0_CHECK`에서 `setzcur`→`get---x` (레퍼런스 tare) | 동일 | (해당 없음) |
| 해제 시 | **아무 것도 안 함 → 공장영점 유지(절대)** | 동일 | (해당 없음) |
| setzcur 실제 호출 | `BoardLevelMo.cpp:843` (게이트: `m_bRefSensorInit`) | `BoardLevelMo_BG01.cpp:1605` (게이트: `m_bRefSensorInit_BG01`) | `MotionJig.cs:872` **무조건** |
| 0도 복귀 재tare | (원본 모터서보 `angle_0_init`) | `angle_0_init_Revision` **무조건 setzcur** (`//` 서보 주석) | FineAdjust 폐루프 |

> ★ **REF 정정**: `REF_영점기울기_3모델비교_..._v01.md`·`REF_VL특징_..._v01.md`는 pCOM/pSMC 체크박스를
> "기본 OFF"로 서술했으나, `OnInitDialog`의 `SetCheck(1)`로 **실제 기본은 ON**이다.
> (→ 이 슬라이드는 "기본 ON, 끌 수 있음"으로 서술. REF 2건도 이번에 같이 정정 예정.)

나머지 수치(측정각·판정 spec)는 REF/기존 슬라이드와 동일:
- pCOM/BG01: 기계 리밋 **±10.5° 2점**, **절대 window ±0.3°**
- VL: 자이로 폐루프 **±20/±45 4점**, **레퍼런스 상대오차 ±0.2/±0.5°**

## 2. 슬라이드 구성 (1장, 별도)

**제목:** `III. IMU 검사방법 핵심 — 레퍼런스 영점 ↔ 기울기 판정 「연계」 (VL · pCOM · BG01)`
**부제:** `레퍼런스 영점을 끌 수 있나 = 판정이 레퍼런스에 의존하나 · 메인폼 "Ref. Gyro Sensor Init" 체크박스`

### (A) 상단 — 흐름 스트립 (3열, 좌→우 시간축)

각 모델 1열, 4단계를 화살표로 연결. 각 단계 칸에 **ON/OFF·강제 배지**를 얹어 연계를 시각화.

```
              ① 레퍼런스 영점        ② DUT 영점         ③ 측정각 이동        ④ 기울기 판정
pCOM/pSMC  [ setzcur ☑선택(기본ON) ] → [ 없음(MBSET) ]  → [ 기계리밋 ±10.5° ] → [ 절대 window ±0.3° ]
BG01 MOS   [ setzcur ☑선택(기본ON) ] → [ 없음(window) ] → [ 기계리밋 ±10.5° ] → [ 절대 window ±0.3° ]
VL         [ setzcur ●강제(체크박스無)]→[ OFFSET+검증+SAVE]→[ 자이로폐루프 ±20/45]→[ 레퍼런스 상대오차 ±0.2/0.5° ]
```

### (B) 중단 — 핵심 비교표 (행=연계 사슬, 열=3모델)

| 연계 사슬 | pCOM / pSMC | BG01 MOS | **VL (VibeTilt)** |
|---|---|---|---|
| **레퍼런스 영점 켜고/끄기** | 체크박스로 **선택** (기본 ON) | 체크박스로 **선택** (기본 ON) | **불가 — 매 사이클 강제** |
| 끄면 어떻게 되나 | 공장영점(절대) 유지 | 공장영점(절대) 유지 | 끌 수단 없음 |
| DUT 영점(내장 CAL) | 없음(MBSET 펌웨어) | 없음(window 간접) | **OFFSET 실행→AN±0.05 확인→SAVE** |
| 측정각을 누가 정하나 | 기계 리밋스위치 | 기계 리밋스위치 | **레퍼런스 자이로 폐루프** |
| 기울기 판정 기준 | **절대 window ±0.3°** | **절대 window ±0.3°** | **레퍼런스 대비 상대오차 ±0.2/0.5°** |
| **레퍼런스 영점이 판정에 미치는 영향** | 판정과 **독립** (그래서 꺼도 됨) | 판정과 **독립** (그래서 꺼도 됨) | **판정 기준 그 자체** (그래서 못 끔) |

### (C) 하단 — 결론 박스 (연계 한 줄)

> **체크박스가 있다 = 레퍼런스 영점이 판정에 필수가 아니다(절대 window).**
> **체크박스가 없다 = 레퍼런스 영점이 곧 판정 기준이다(상대) → VL은 레퍼런스 영점 틀어짐이 DUT 판정에 직결(common-mode 상쇄 위험).**
> ※ 대응 방향: VL도 `setzcur`를 원본처럼 **옵션화**(JSON 플래그, 기본 off) → 레퍼런스가 절대기준 유지. (실기 회귀검증 필요)

## 3. 확인이 필요한 결정 1건

**Q. 이 "별도" 슬라이드를 어디에 둘까?**
- **(권장) A안**: 우선 **단독 1장짜리 새 pptx**로 만들어 디자인을 빠르게 확정 →
  확정 후 본 덱 v14에 **S11 앞(섹션 III 도입부)** 으로 삽입해 v15 생성.
  (이게 "메인"이라는 요구에 맞게 섹션 III의 얼굴 슬라이드가 됨)
- B안: 곧바로 v14 덱에 새 슬라이드로 삽입(v15).
- C안: 완전 별개 파일로만 유지(덱에 안 넣음).

→ 별다른 지시 없으면 **A안**으로 진행.
