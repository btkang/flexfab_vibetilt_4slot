## 1. 치명 (Critical) — 이대로 발표하면 반박당함

### C-1. `setzcur`는 정의상 tare다. tare는 절대영점을 만들 수 없다

**위치:** S16 표 `VL` 행 `결과 성격` 칸 / S17 표 `VL` 행 `판정`·`근거 / 의미` 칸 / S17 하단 핵심정리 2번째 불릿

**현재 (틀림):**
- S16: `절대영점 / 0점 = 실제 수평`
- S17 판정: `절대영점 / (중력 기준)`
- S17 근거: `영점의 기준이 지그가 보증하는 물리 0도. / 출하품의 0도 = 실제 수평 보장`

**반박:**
1. datasheet가 `setzcur`를 **"Tare function"** 이라고 명시한다. tare는 **현재 자세를 0으로 만드는 상대화 조작**이며, 정의상 절대 기준을 생성할 수 없다.
2. `setzcur`는 **비휘발**(datasheet p.2, p.6)이라 매 사이클 자이로의 0을 덮어쓴다.
   → 자이로의 0은 **최초 1회만 공장(중력) 기준**이고, 그 뒤로는 **직전 사이클이 정한 자세**다.
3. 즉 VL의 절대성은 **자이로의 공장 캘리브레이션**에서 나오는 것이고,
   `setzcur`는 그 절대성을 **만드는 게 아니라 덮어쓴다.** PPT는 인과가 거꾸로다.
4. **`출하품의 0도 = 실제 수평 보장`은 실측 근거가 0이다.** 누적 이동량 D는 아직 측정된 적이 없다
   (`PLAN_자이로_누적드리프트_측정절차_20260715_v01.md` = **실행 대기** 상태).
   게다가 **기존 검사망은 D를 검출할 수 없다** — 기울기 판정이 `VL − 자이로` 상대비교라 D가 양쪽에서 상쇄된다.

**수정 지시:**

| 칸 | Before | After |
|---|---|---|
| S16 `VL` 결과 성격 | `절대영점 / 0점 = 실제 수평` | `절대영점 지향 / 단, tare 누적으로 0점의 절대성 미검증` |
| S17 `VL` 판정 | `절대영점 / (중력 기준)` | `절대영점 지향 / (검증 대기)` |
| S17 `VL` 근거/의미 | `영점의 기준이 지그가 보증하는 물리 0도. / 출하품의 0도 = 실제 수평 보장` | `설계 의도는 지그가 보증하는 물리 0도. / 단 setzcur가 자이로 공장기준을 매 사이클 덮어써 / 0점의 절대성은 미측정 (D 실측 예정)` |
| S17 핵심정리 2번째 불릿 | `절대영점(VL): 지그가 물리 0도를 보증해야 성립 — FineAdjust(±0.05°)로 수평을 만든 뒤 setzcur로 자이로 기준점 고정` | `절대영점(VL): 지그가 물리 0도를 보증해야 성립. FineAdjust가 그 역할을 하나, / 뒤이은 setzcur가 자이로 공장기준을 덮어써 절대성이 유지되는지는 미검증 — 2026-07 확인 예정` |

### C-2. S16 "2단 구조" 논리가 자기모순 — 상대에게 그대로 무기가 됨

**위치:** S16 하단 `의미` 2번째 불릿

**현재:**
> • VL: 자이로의 절대각으로 수평을 찾은 뒤(FineAdjust) → setzcur로 기준 고정 — 2단 구조.
>    **순서를 뒤집으면 자이로가 0으로 리셋되어 수평 탐색 불가** (MotionJig.cs:860 주석) → 이후 ±20/±45/±90° 측정과 DUT OFFSET이 전부 절대 기준 위에서 수행

**반박 — 이 문장은 setzcur가 유해하다는 자백이다:**

"FineAdjust **전에** 하면 자이로가 리셋되어 수평을 못 찾는다"가 참이라면,
**FineAdjust 후에 해도 자이로는 똑같이 리셋된다.** 이번 사이클에 한 번 써먹은 뒤일 뿐이다.
그리고 **비휘발**이므로 **다음 사이클은 리셋된 기준으로 시작**한다.

즉 이 불릿은 "순서가 중요한 정교한 설계"가 아니라,
**"setzcur는 자이로의 절대 기준을 파괴한다"** 를 우리 손으로 적어놓은 것이다.
적대적 청중이 이 한 문장만 집어도 슬라이드 16·17 전체가 뒤집힌다.

**수정 지시:** 해당 불릿을 아래로 교체.

> • VL: FineAdjust가 **자이로 공장기준(중력)으로** 수평을 찾는다 — 절대성은 여기서 나온다.
>    뒤이은 setzcur는 잔차(≤0.03°)만 제거하는 대신 **그 공장기준을 현재 자세로 덮어쓴다(비휘발).**
>    → **순서를 뒤집으면 수평 탐색 자체가 불가**(MotionJig.cs:862-863 주석)라는 사실이,
>       역으로 setzcur가 기준을 파괴함을 보여준다. **현재 제거 검토 중** (PLAN_setzcur제거_20260715)

### C-3. setzcur가 수평을 만든다는 서술 — 실제 기여도는 잔차 0.03°뿐

**위치:** S16 `VL` 행 `실행 시점` 칸 / S17 `VL` 행 `영점 방식` 칸

**현재:**
- S16: `홈센서 복귀 → FineAdjust로 물리 수평 / 확립(±0.05°) 후 실행 (MotionJig.cs:870)`
- S17: `지그가 홈센서+자이로 FineAdjust로 물리 수평(0도) 확립 / → 자이로 기준점 setzcur → DUT OFFSET → AN ±0.05 검증 → SAVE`

**반박:** 코드 실행 순서가 이렇다.

```
MotionJig.cs:864   FineAdjust(emio, gyro, target=0, strict=0.03, relaxed=0.05)
                   → 자이로가 0을 읽을 때까지 이동. 종료 시점에 이미 |자이로| ≤ 0.03
MotionJig.cs:872   GyroSetZero(gyro)   ← setzcur. 여기서 자이로는 이미 ~0을 읽고 있다
```

`setzcur`는 **이미 0인 지점을 다시 0으로 쓰는 것**이다. 수평 확립 기여도는 **0**이고,
실제 효과는 **잔차 δ(≤0.03°) 제거**뿐이다. "기준점 고정"이라는 능동적 역할로 그리면 안 된다.

**수정 지시:**

| 칸 | After |
|---|---|
| S16 `VL` 실행 시점 | `홈센서 복귀 → FineAdjust가 자이로 공장기준으로 / 수평 확립(±0.03°) → 그 지점에서 실행 / (MotionJig.cs:872) — 잔차 ≤0.03° 제거가 실효` |
| S17 `VL` 영점 방식 | `홈센서 + FineAdjust로 물리 수평(0도) 확립 (자이로 공장기준) / → setzcur (잔차 ≤0.03° 제거, 단 공장기준을 덮어씀) / → DUT OFFSET → AN 응답 확인 → SAVE / ※ setzcur는 사양 미규정 — 제거 검토 중` |

### C-4. "AN ±0.05 검증"은 검증이 아니다 (동어반복)

**위치:** S18 `VL이 유일하게 갖춘 것` ① / S13 `DUT 영점` 칸 / S14 `DUT 영점` 칸 / S15 `캘리브레이션` 칸 / S17 `VL` 영점 방식 칸 / S4 `#4`·`#11` 판정 칸

**현재:**
- S18 ①: `IMU 영점의 실행 → 검증(AN ±0.05) → 플래시 저장(SAVE) → 재확인(APPCFG) 완결 사이클`
- S13: `VL: OFFSET 실행 → AN ±0.05 검증 → SAVE(플래시) → APPCFG 재확인 (완결 사이클)`

**반박:** `verify_an`은 `<OFFSET,1>` **직후** VL **자기 출력**을 읽는다 (`VibeTilt.cs:1268~1357`).

```
<OFFSET,1>  →  DUT가 "지금 이 자세 = 0도"로 기록
   직후
<MODE,06> → <START> → AN 수집  →  당연히 0.00x
```

OFFSET이 방금 현재 자세를 0으로 만들었으니 **AN은 지그가 어디에 있든 항상 0.00x**다.
독립 검증이 아니라 **"방금 0으로 설정했는데 0이 맞나?"** 확인이며, 잡히는 건 **FW/통신 이상뿐**이다.
`PLAN_setzcur제거_20260715_v01.md` **4.2절**이 이미 "항상 0.00x"로 확인해 두었다.

이것을 **"완결 사이클"의 핵심**이자 **VL 유일 우위 ①번**으로 내세우면,
회의에서 **"그게 뭘 검증합니까?"** 한 마디에 무너진다.

**수정 지시:**

### H-3. tare 앵커의 비대칭이 빠짐 — 이게 VL/BG01의 진짜 차이다

**위치:** S16 하단 `의미` 3번째 불릿 / S17 하단 핵심정리 4번째 불릿

**현재:**
- S16: `BG01: ... 측정 사이마다 setzcur 재실행(3회)으로 누적 오차 리셋`
- S17: `BG01 자동지그는 중간형: 영점을 써주지 않고 '절대각이 spec 안인가'로 양품 선별`

**반박 — PPT가 놓친 핵심:** 두 모델의 차이는 *실행 시점*이 아니라 **tare를 거는 자세를 무엇이 결정하느냐**다.

| | tare 앵커 | 성격 |
|---|---|---|
| **BG01** | 모터 **원점복귀 위치** = 기구적으로 반복되는 **외부 기준** | 매 사이클 같은 곳에 앵커 → 누적 없음 |
| **VL** | **FineAdjust 종료 자세** = *자이로가 0이라고 말하는 곳* = **자이로 자신** | **자기참조** → `Z_N = Z_(N-1) + δ` 구조 |

즉 **누적 위험은 BG01이 아니라 VL 쪽에 있다.**
S16의 `재실행(3회)으로 누적 오차 리셋`이라는 표현은 **원인을 잘못 짚었다** — BG01이 누적을 안 만드는 건
*횟수* 때문이 아니라 **앵커가 외부(기구 원점)이기 때문**이다.

**단, 실제 누적 여부는 단정 금지.** 기구 위치 M과 자이로 0 사이에 **±0.03° 데드밴드**가 있어
`|M − Z| ≤ 0.03`이면 FineAdjust가 움직이지 않고 `Z_N = M`으로 스냅백된다.
→ **이론만으로 결론 불가. `setzfac` + `get---x`로 D 실측이 필요하다** (미실행).

**수정 지시:** S16 3번째 불릿을 아래로 교체하고, 4번째 불릿으로 신규 추가.

> • BG01: 수평을 만들지 않고 현재 자세를 0 선언 — 테이블 잔여 기울기가 0점에 흡수되지만,
>    DUT에 영점을 써주지 않고 window(±0.3°) 선별만 하므로 성립.
>    **tare 앵커가 모터 원점복귀 위치(기구적 외부 기준)라 매 사이클 같은 곳에 다시 걸린다.**
>
> • **앵커의 비대칭(핵심):** BG01은 **기구 원점**에 tare를 걸고, VL은 **자이로가 0이라 말하는 자세**에 건다.

### H-4. S17 BG01 행 — 같은 행 안에서 "상대"와 "절대"가 충돌

**위치:** S17 표 `BG01 (자동지그)` 행

**현재:**
- 영점 방식: `기준 경사센서 setzcur — 수평 확립 절차 없이 / 현위치를 0으로 선언(**상대**)`

**반박:** 기준자가 상대인데 **거기서 잰 각도를 "절대각"이라 부를 수 없다.** 같은 행에서 모순이다.

**수정 지시:** 판정 칸 `(절대각 검증만)` → **`(DUT 공장캘 각도를 window로 선별)`**
— 주어를 명시해 모순을 없앤다. 표현 정리이지 사실 변경이 아니다.

### H-5. `gyro_spec_*` — 숫자 출처가 뒤바뀐 흔적 (PPT 단정 금지 근거)

**위치:** S4 `#4`·`#11` / S13·S14·S15·S17의 `±0.05` 서술 전반

**사실:** 코드가 verify_an 결과에 남기는 필드명이 이렇다 (`VibeTilt.cs:1353-1354`).

```csharp
{ "gyro_spec_min", anMin },   // 재는 대상은 VL의 AN 출력
{ "gyro_spec_max", anMax },   // 그런데 이름은 gyro_spec_*
```

재는 건 **VL의 AN**인데 이름은 **`gyro_spec`(=상용센서 spec)** 이다.
요청서 `상용센서 기준 0 : -0.05 ~ 0.05`에서 숫자를 옮겨오며 **대상이 바뀐 화석**으로 보인다.

→ PPT는 현재 **"AN 0도 ±0.05 검증"으로 단정**하고 있다. 담당자 확인 전까지 단정하면 안 된다.
   (C-4의 문구 수정으로 대부분 해소되나, 구현 AI는 §4를 반드시 읽을 것)

## 4. 미확정 — **구현 AI는 이 항목을 "수정"하지 말 것**

담당자 확인이 **다음 주**로 예정돼 있다. 아래는 **답이 안 나온 상태**이므로,
PPT에서 **어느 한쪽으로 단정하는 문구만 제거**하고 결론은 비워 둔다.

### U-1. 요청서 `상용센서 기준 0 : -0.05 ~ 0.05`의 대상

요청서 `#2 Calibration` 행 원문:

| 칸 | 내용 |
|---|---|
| Range | `상용센서 기준 0 : -0.05 ~ 0.05` |
| 검사방법 | `<OFFSET,1>` → `[OFFSET,0,1]` **응답 일치 확인** (측정 명령 없음) |
| 비고 | `모션 지그 X축 결합 고정 → 상용센서 0도 이동 및 조정 후 진행` |

두 해석이 모두 살아 있다.

- **(A) 지그 위치 허용오차** — "상용센서가 ±0.05 안에 들어오게 조정한 뒤 OFFSET을 쳐라."
  코드 `FineAdjust` relaxed=**0.05**와 숫자가 정확히 일치.
- **(B) DUT 출력 spec** — Range 칼럼의 다른 행(`#4: -20 : -20.2~-19.8`)이 전부 **DUT AN 출력 spec**이다.
  같은 패턴이면 `0 : -0.05~0.05`도 DUT 출력이고 "상용센서 기준"은 *무엇을 0으로 보느냐*의 수식어.
  `#2`엔 측정 명령이 없지만 **`#4` 비고 "영점 → -20도 → -45도…"에 영점 측정이 포함**돼 있어 거기서 잰다고 볼 여지.

**단, 어느 쪽이든 `setzcur`는 "조정"이 아니다** — 이건 확정이다.
- (A)라면: 조정의 완료 조건이 "상용센서 ±0.05". setzcur는 조정이 아니라 **눈금을 옮기는 것**.
- (B)라면: 더 나쁘다. "상용센서 **기준**"으로 DUT를 검증한다는 건 **상용센서가 진짜 수평을 알려준다는 전제**에
  전적으로 기대는데, setzcur는 그 전제를 파괴한다.

**결정적 논거 (양쪽 공통):**
> `setzcur`를 하면 `get---x`는 **언제나 0.000**이다. 즉 "상용센서 기준 0"이 **측정 없이 자동으로 참**이 된다.
> 요청서가 굳이 **±0.05라는 허용오차를 준 것 자체**가 "지그가 0에 정확히는 못 선다"는 전제이며,
> 곧 **"상용센서 눈금은 건드리지 않는다"** 는 묵시적 전제의 증거다.
> 눈금을 옮길 수 있다면 허용오차를 줄 이유가 없다.

**구현 AI 지시:** ±0.05 **숫자는 유지**하되, **"AN 검증"으로 단정한 문구만** C-4대로 중립화.
(A)/(B) 중 어느 쪽으로도 쓰지 말 것.

## 5. 발표 리스크 — 슬라이드 밖 사안 (사용자 판단 필요)

```
비고       : [성능개선팀 :영점추가함]                            ← 우리 팀이 추가했다고 명시
```

- 파일명은 `20260326`인데 붙은 로그는 **03-31자** → 개정 후 우리가 덧붙인 행이다.

- 즉 요청서를 setzcur 근거로 인용하면 **우리가 붙여넣은 로그를 우리가 다시 근거로 드는 순환**이 된다.

**옵션:**

3. 발표자 노트에만 기재

→ **사용자 결정 대기.**
